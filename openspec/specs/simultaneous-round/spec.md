# simultaneous-round Specification

## Purpose

新玩法（simul-a 段 A，Jungle v0.1 交接稿 §4–§10）：与现有轮流决策模式并列的新增模式。统一回合、全员同时决策，同格靠战力争夺；全灭不判负；占满即终局。
实现唯一落点是 `Siege.Core.Simul`（阶段机 `SimulFlow`、规则纯函数 `SimulRules`），现有模式的任何路径不变。
裁决来源：任务 `11-24-simul-a` 的 prd.md（Q02–Q16、G1–G6）与 design.md（J1–J6、K1–K6）。

下文"单位"即盘面上的一枚部署，"整体"即气边相连的同主单位集合，"出生岛"即出生座位（整块出生棋盘），"活形内部格"即已确定活形的眼空间格。

## Requirements

### Requirement: 建局与插旗

（Q16、K4）新玩法只开链接小图（`link:<地图种子>:<人数>`，人数 2–4 且等于地图人数）；大图与人数不符一律拒绝建局。插旗沿用现有原型插旗（`flag-pick` 盲选、座位互斥）或人工选座；锁定后开始第 1 回合。不做存档续局；地图信物刷新与带入带出关闭（K1）。

#### Scenario: 链接小图可以开局并跑完一回合
- **WHEN** 2 / 3 / 4 人各在 `link:1:<人数>` 上建局、盲选插旗，每人在自己的出生岛部署 1 个单位并提交
- **THEN** 结算后进入第 2 回合，每人场上各有 1 个整体

#### Scenario: 大图与人数不符拒绝建局
- **WHEN** 用 4 人图开 2 人局；或用大图开局
- **THEN** 都拒绝建局，大图的原因写明"只开小图"

### Requirement: 回合开始与结算顺位

（v0.1 §6、§7.1；Q05）每回合开始时系统 SHALL 固定本回合的结算顺位、记下回合开始盘面 S0，并按顺位逐人开启准备。

- 第 1 回合的顺位由 `setup` 子流洗出（与现有锁定插旗同一做法：先洗顺位、再洗种子兜底名次）。
- 第 2 回合起沿用现有先手值与同值链（`InitiativeOrder`）：势力名次高者先；同势力看上回合顺位，**上回合更晚者先**（第 1 回合的顺位是随机的，不计）；再看种子兜底名次。势力取上回合结束时的新玩法势力（含活形领地修正）。
- 认输者没有顺位。本回合的部署校验与冲突战力只读 S0。

#### Scenario: 首回合顺位由种子决定
- **WHEN** 同一张图、同一种子建两局并以相同座位锁定
- **THEN** 两局第 1 回合顺位相同，且顺位恰含全部玩家各一次

#### Scenario: 之后按上回合势力排名
- **WHEN** 3 人局第 1 回合结束时 P2 势力最高、P1 次之、P0 最低
- **THEN** 第 2 回合顺位为 P2、P1、P0

#### Scenario: 同势力首回合后按种子兜底
- **WHEN** 3 人局第 1 回合（顺位取种子兜底顺序，且它不是编号顺序）结束时三人势力相同
- **THEN** 第 2 回合顺位仍按种子兜底名次（第 1 回合的随机顺位不算"上回合顺位"）

#### Scenario: 第二回合起同势力上回合更晚者先
- **WHEN** 接上例，第 2 回合结束时三人势力仍相同
- **THEN** 第 3 回合顺位是第 2 回合的倒序

### Requirement: 同时准备与提交

（v0.1 §6、§8；Q09）准备阶段全体参赛玩家各自整理手牌、征召、暂放。暂放可以随意改；提交后锁定（手牌与暂放都不能再动），揭晓前可撤回到可编辑状态。非法批次不能提交，也不消耗手牌。全体参赛玩家都提交后才可统一揭晓。公开视图对每人只给"未提交 / 已提交"，结构上不含任何人的暂放内容。

#### Scenario: 全员提交后才能揭晓
- **WHEN** 2 人局只有 P0 提交
- **THEN** 揭晓被拒绝；P1 也提交后揭晓成功

#### Scenario: 提交后锁定撤回后可改
- **WHEN** P0 提交后再暂放
- **THEN** 被拒绝；撤回提交后可以暂放、整理与征召

#### Scenario: 非法批次不能提交也不消耗手牌
- **WHEN** P0 暂放了不在可部署范围内的格并提交
- **THEN** 提交被拒绝并给出原因，P0 仍是未提交，手牌数量不变

#### Scenario: 公开视图只显示提交状态
- **WHEN** P0 已提交、P1 未提交
- **THEN** 公开视图里 P0 为已提交、P1 为未提交，且公开视图的类型结构里没有任何暂放字段

### Requirement: 部署校验

（v0.1 §8.3；Q02、G2、G3、K3）每人只按 S0 与本人批次校验，**不判自杀，不判同形**：

1. 落点在合法范围内：前 3 回合只能部署在自己的出生岛上，第 4 回合起全图（`PublicRules.LegalRange`）。
2. 落点在 S0 上是空格；批内不重格。
3. 落点不是任何活形内部格，**包括本人的**（双方禁入）。
4. 枚数 ≤ 部署上限 3（每回合恒为 3，不随回合分阶段）；每类 ≤ 手牌库存。
5. 八邻禁落：本人同一回合的任意两个落点若在同一"区"内，切比雪夫距离 ≥ 2。区：每座出生岛（整块出生座位，不是 3×3 核心区）一个区，不属于任何出生岛的格合为一个公共区。
6. 地形改造只有匠人能带，按 S0 地形与改造范围判定合法，批内不重目标。

#### Scenario: 只按回合开始盘面校验
- **WHEN** P0 与 P1 都暂放同一个 S0 上的空格
- **THEN** 两人的批次都合法（谁落下由冲突决定）

#### Scenario: 自杀式部署可以提交
- **WHEN** P0 把一个单位暂放在四邻全是 P1 单位、且不提任何子的格里（E7）
- **THEN** 批次合法，可以提交

#### Scenario: 八邻禁落同岛相邻拒绝
- **WHEN** P0 在同一座出生岛上暂放 X 和 X 的斜邻（E5）
- **THEN** 校验不通过，原因是八邻禁落

#### Scenario: 八邻禁落隔一格接受
- **WHEN** P0 在同一座出生岛上暂放 X 和与 X 隔一格的格
- **THEN** 校验通过

#### Scenario: 八邻禁落跨区互不影响
- **WHEN** 第 4 回合 P0 暂放出生岛边缘的格与它斜邻、属于公共区的格
- **THEN** 校验通过

#### Scenario: 八邻禁落按整座出生岛不按核心区
- **WHEN** P0 暂放出生岛核心区里的一格与它斜邻、在同一座出生岛但不在核心区里的一格
- **THEN** 校验不通过，原因是八邻禁落

#### Scenario: 八邻禁落只约束本人
- **WHEN** P0 暂放 X，P1 暂放 X 的斜邻
- **THEN** 两人的批次都合法

#### Scenario: 撤回一枚后重新判定
- **WHEN** P0 暂放的两格互为斜邻，随后撤回其中一枚
- **THEN** 撤回前校验不通过，撤回后通过

#### Scenario: 活形内部格双方禁入
- **WHEN** P0 有已确定活形（E10），P0 与 P1 都暂放它的内部格
- **THEN** 两人都被拒绝，原因写明"活形内部格"

#### Scenario: 前三回合只能部署在出生岛
- **WHEN** 第 1 回合 P0 暂放出生岛外的公共区格；第 4 回合再暂放同一格
- **THEN** 第 1 回合被拒绝，第 4 回合通过

#### Scenario: 不能挂带入信物
- **WHEN** P0 的暂放挂了带入信物
- **THEN** 校验不通过（K1：段 A 不使用信物），不静默丢掉

#### Scenario: 改造只有匠人能带且按回合开始地形判定
- **WHEN** P0 让普通单位带烧林；改成匠人；再把目标改成不是林地的格
- **THEN** 依次为"非匠人不能带改造"、通过、"改造不合法"

#### Scenario: 部署上限恒为3
- **WHEN** 第 7 回合 P0 暂放 4 个互不相邻的单位；只暂放 3 个
- **THEN** 4 个被拒绝（超过部署上限），3 个通过

### Requirement: 揭晓与扣牌

（v0.1 §8.2；G2）全员提交后一次性公开全部批次。提交的单位一律从手牌扣除，冲突落败的也扣。提交 0 枚即本回合不部署，**不撤销**本回合征召。

#### Scenario: 冲突落败照样扣牌
- **WHEN** P0、P1 在同一格冲突，P1 落败（E1）
- **THEN** P1 的单位不落下，P1 的手牌照样少 1

#### Scenario: 零部署不撤销本回合征召
- **WHEN** P0 本回合征召了 1 个单位、提交 0 枚
- **THEN** 结算后这个单位留在 P0 手牌里

### Requirement: 同格冲突

（v0.1 §9；Q06、Q14、G1）两名及以上玩家选了同一格即发生冲突。每名投入者的战力 = 该单位类型的基础战力（堡垒 4，其余 1）+ S0 上与该格有气边相接的本人单位数（每个 +1）；本回合其他新部署一律不算。最高战力唯一者胜出；最高战力并列时只有这几人掷 d6，点数低的出局，最高点仍并列只让这几人重掷，直到决出一人。骰子用 `simul-dice` 子流：冲突格按坐标字典序（先行后列），同一格内按玩家编号升序，每次 `NextInt(6) + 1`；没有并列时不消费。

#### Scenario: 冲突比战力
- **WHEN** P0、P1 同回合都在 X 部署普通单位，S0 上 P0 在 X 四邻有 2 个单位、P1 有 1 个（E1）
- **THEN** P0 战力 3、P1 战力 2，P0 胜，X 上是 P0 的单位

#### Scenario: 本回合新部署不支援
- **WHEN** 接上例，P1 同回合还在 X 的另一个四邻格 Y（属于另一个区）成功落下（E2）
- **THEN** P1 在 X 的战力仍是 2，P0 胜，不掷骰

#### Scenario: 堡垒基础战力
- **WHEN** P0 投堡垒、X 四邻没有己方单位；P1 投普通单位、X 四邻有 2 个己方单位（E3）
- **THEN** P0 战力 4、P1 战力 3，P0 胜

#### Scenario: 多人并列掷骰
- **WHEN** P0、P1、P2 争同一格，战力 2 / 2 / 1（E4）
- **THEN** P2 先出局；P0、P1 掷骰，第一次 3 : 3，重掷 5 : 2，P0 胜

#### Scenario: 没有并列时不掷骰
- **WHEN** 冲突的最高战力唯一
- **THEN** `simul-dice` 子流一次都不消费

#### Scenario: 掷骰按冲突格坐标字典序消费
- **WHEN** 同一回合两格都发生并列冲突，一格行号较小、另一格列号较小
- **THEN** 行号较小的那一格先消费骰子

### Requirement: 落下与地形改造

（v0.1 §8.4；K2）冲突结束后，所有存活的部署同时放上正式盘面，再应用存活的地形改造（改造先于围杀）。改造跟着所属部署走：部署在冲突中落败，改造作废。两份生效的改造指向同一目标时，结算顺位靠前者生效，后者作废，其单位照常落下。

#### Scenario: 冲突落败的改造作废
- **WHEN** P0 的匠人带着烧林在冲突里落败（E11）
- **THEN** 林地不变，报告里这份改造标为"冲突落败作废"

#### Scenario: 冲突胜出的改造生效
- **WHEN** P0 的匠人带着烧林在冲突里胜出
- **THEN** 林地变草地

#### Scenario: 同目标改造顺位靠前者生效
- **WHEN** 顺位 P1、P0，两人的匠人都落下且都烧同一块林地
- **THEN** P1 的改造生效、P0 的作废，两枚匠人都落下

### Requirement: 按顺位围杀

（v0.1 §7.2；Q03）落下与改造之后，按结算顺位对每名参赛玩家 P 依次提走全部**非 P** 的无气整体；认输者没有顺位，但他们的整体会被别人提走。顺位都走完后再做孤立自绝：移除仍然无气的整体，不论属于谁。每一步记录被移除的整体与执行的顺位。

#### Scenario: 互相堵死按顺位
- **WHEN** P0 的整体 GA 与 P1 的整体 GB 相邻、各只剩一口气；P0（顺位 1）堵 GB 的最后一口气，P1（顺位 2）堵 GA 的最后一口气（E6）
- **THEN** P0 的顺位先提走 GB，GA 因此重获气并保留

#### Scenario: 顺位对调结果相反
- **WHEN** 同上局面，顺位改为 P1、P0
- **THEN** P1 的顺位先提走 GA，GB 保留

#### Scenario: 自杀式部署结算后移除
- **WHEN** P0 把单位部署到四邻全是 P1 单位、且不提任何子的格里（E7）
- **THEN** 结算后这个单位被移除，P0 的手牌照样少 1，P1 的单位不受影响

#### Scenario: 孤立自绝移除仍然无气的整体
- **WHEN** 顺位上没有任何能提走某个无气整体的玩家（测试接缝把顺位只留其所有者）
- **THEN** 孤立自绝这一步把它移除，记录为孤立自绝

### Requirement: 活形锁定与势力

（v0.1 §5.2；Q06）围杀之后重算活形与势力。势力沿用现有算法（计分领地 + 军势），另加一条只对新玩法生效的修正：活形内部空格算所有者领地——领地 = 现有独占空格里不是别人活形内部格的那些，再并上本人的活形内部格；荒漠照旧不计分。势力一律 `BigInteger`。

#### Scenario: 活形内部空格算所有者领地
- **WHEN** P0 的活形围住 3×3 的眼空间，中间 4 格离 P0 单位 ≥ 2 格、现有算法下无人覆盖
- **THEN** 现有独占空格不含这 4 格；新玩法领地含全部 9 格，势力比现有算法多 4

#### Scenario: 别人的活形内部格不算自己领地
- **WHEN** P1 站在崖上向下覆盖 P0 活形的内部格，其中两格在现有算法下是 P1 的独占空格
- **THEN** 新玩法里这两格归 P0，P1 的势力比现有算法少 2

#### Scenario: 没有活形时与现有势力相同
- **WHEN** 盘面上没有已确定活形
- **THEN** 每名玩家的新玩法势力等于现有算法的势力

### Requirement: 终局与排名

（v0.1 §10；Q07、Q08、Q10、Q11）每回合结算后按以下顺序判终局，先命中的为准：

1. 参赛中（未认输）玩家 ≤ 1 → 最后一人；
2. 占满：结算后不存在非活形锁定的空可部署格（活形内部格不需要补）；
3. 本回合无人提交任何单位；
4. 达到大回合上限（小图缺省 100）。

终局名次沿用现有比较链（势力 → 信物数 → 独占空格 → 单位数，`FinalStandings`），认输者固定排在末位；胜利名额 2 / 3 / 4 人局取 1 / 1 / 2 名，名额边界上的并列按种子兜底名次打破。

#### Scenario: 剩余空格全是活形内部格即占满
- **WHEN** 结算后剩下的空格全是活形内部格（E9a）
- **THEN** 终局原因为占满

#### Scenario: 全员零部署即终局
- **WHEN** 某回合全员提交 0 枚（E9b）
- **THEN** 终局原因为无人部署

#### Scenario: 有人部署就不触发无部署终局
- **WHEN** 某回合只有 1 名玩家部署了 1 枚
- **THEN** 不终局，进入下一回合

#### Scenario: 达到大回合上限终局
- **WHEN** 大回合上限为 2，第 2 回合有人部署
- **THEN** 第 2 回合结算后终局，原因为大回合上限

#### Scenario: 四人局前两名为胜者且认输者排末位
- **WHEN** 4 人局终局，认输者的势力比其余三人都高（E9c）
- **THEN** 认输者排第 4，胜者是其余三人里势力前 2 名

#### Scenario: 全员同分按种子定胜者名额
- **WHEN** 2 / 3 / 4 人局全员势力为 0 时全员零部署终局
- **THEN** 胜者恰为 1 / 1 / 2 名，按种子兜底名次选出

### Requirement: 全灭不判负与认输

（v0.1 §10.1；Q11、G2）没有势力归零出局：场上单位全被围杀的玩家照常参赛（能征召、能部署）。任意时刻都可以认输：认输者本回合未揭晓的暂放直接作废、不扣牌；单位留在场上，继续挡路，也可以被围杀；不再有顺位、不再征召；认输后参赛中玩家 ≤ 1 即直接终局。

#### Scenario: 全灭不判负
- **WHEN** P0 场上的单位全部被围杀（E8）
- **THEN** P0 仍是参赛中，下一回合在顺位里，能征召、能部署并落下

#### Scenario: 认输者的暂放作废不扣牌
- **WHEN** P1 暂放并提交后认输
- **THEN** P1 的手牌不变，单位留在场上，下一回合顺位里没有 P1

#### Scenario: 认输者的单位可被围杀
- **WHEN** 已认输的 P1 的单位只剩一口气，P0 堵上它
- **THEN** P1 的单位被提走

#### Scenario: 认输后只剩一人直接终局
- **WHEN** 2 人局 P1 认输
- **THEN** 立即终局，原因为最后一人，P0 是胜者

### Requirement: 可复现

（determinism.md）新玩法只用 `setup`（首回合顺位与种子兜底）、`flag-pick`（盲选插旗）、`recruit`（征召候选）与新子流 `simul-dice`（冲突掷骰）。征召候选在回合开始时按结算顺位一次给全员生成（K5），与界面操作的先后无关。

#### Scenario: 同种子同决策逐回合相同
- **WHEN** 同一种子、同一组决策的两局各跑 3 回合（含冲突与掷骰）
- **THEN** 两局逐回合的报告与盘面相同

#### Scenario: 打开征召面板的先后不影响候选
- **WHEN** 两局同种子，一局 P0 先打开征召面板，另一局 P1 先打开、P0 不打开
- **THEN** 两局 P1 的候选相同，P0 打开时的候选也相同
