## Context

`life-shape` 的三态判定只看眼值之和，不看棋串规模。v5 地图岩石、深水密集，一枚棋子贴着地形就能围出两个单格眼，开局第 1 大回合即成"永久安全"的活形；与 `ai-eye` 的活形硬约束 / 停手阈值叠加后几乎不再有提子（见 proposal）。负责人在五种方案的 50 局对比实验后选定 K1（单子不受保护）。

实验实现与本设计相同（`LifeShapeReport.Analyze` 内，算完三态后对 1 枚子的"活"降为"未定"），实验代码未保留，按本 change 正式实现。

## Goals / Non-Goals

**Goals**
- 单子棋串永不受活形保护，规则一句话可说清、可测试。
- 保持"活形 / 禁入只有一处实现"：改动只在 `LifeShapeReport` 的三态判定处，预演、合法落子范围、公开视图、表现层、AI 自动跟随。

**Non-Goals**
- 不处理贴地形小空区眼（K2 / K3 不采用）。
- 不改眼值表与 `EYE_SPACE_MAX`；不做 AI 校准。

## Decisions

### D1 在三态判定处加上限，不改眼值

单子的眼空间、眼值照常计算并对外可查（AI 的 `Eye` 维仍能看到"这块快成形了"），只把状态上限定为"未定"。备选"单子的眼空间不算封闭"会连带改变共享眼空间与相邻多子棋串的判定，影响面大，不采用。

### D2 共享眼空间照旧

封闭空区是贴着它的同一玩家每条棋串的眼空间（`life-shape` D1）。单子与多子活形棋串共享的眼空间，经由多子棋串照常禁入；单子本身仍为未定。这样"补一子连成两子"就能成活，符合"做活要花子"的直觉。

### D3 破坏活形检查无需改动

"不得破坏他人活形"按原棋子所在棋串重查是否仍为活。立栅把两子活形切成两枚单子，两枚单子都是未定 → 失活 → 非所有者的批次被拒。性质测试（种子 1–200）继续守门。

## Risks / Trade-offs

- [第 3 大回合领先者胜率升高（实验 76%，n=50）] → 只报告不拦截，交给 `ai-eye` 段 D 在 200 局上观察；若校准后仍明显偏高，另开 change。
- [贴地形小空区眼仍占多数（实验 80%）] → 接受，Non-goal；校准后数据再议。
- [既有测试夹具用单子做"活"算例] → 改夹具为多子棋串（只改盘面，不改期望），逐条记录。
- [`terrain-surfaces` 分支也改 `LifeShape.cs`] → 本 change 改动集中在三态一处，合并时由主会话解决冲突并复跑活形测试。

## Migration Plan

规则变更、无存档迁移（活形不入存档）。黄金哈希与对局基线按"规则变更"重建并记录归因；`ai-eye` 默认权重仍标未校准。
