## Context

`round-cap` 已经保证对局一定会结束，但结束方式只有"所有人都不想下了"（整轮 Pass，75%）与"时间到"（达上限，25%）。设计文档 §12.3 条件 1 想表达的"打赢"在这套补给规则下不可达：出局要求盘面与手牌同时为空（§12.1），而征募每回合补牌（§5.3），200 局零出局。

本 change 不去修补出局条件——那要动私人征募这条核心机制——而是给强势方一个**用现有势力体系表达的终结目标**：势力 ≥ 其余参赛玩家之和。势力值本就是 §13.1 的始终公开信息，所有玩家随时能看到离碾压还差多少，既是进攻目标也是防守目标。

## Goals / Non-Goals

**Goals:**
- 强势方能主动终结对局，不必等所有人 Pass 或耗到上限。
- 判定只用现有势力值与参赛状态，不引入新资源、新数值、新界面概念。
- 触发点公开可推算：任何玩家都能从公开排名算出"谁离碾压还差多少"。
- 终局原因与名次规则与既有四类保持同一套实现。

**Non-Goals:**
- 不改出局条件、不改征募补给。
- 不改大回合上限（兜底保持 15）。
- 不为碾压做专门的 UI 演出（结算面板已有胜负结论行，自动覆盖）。
- 不调 AI：AI 是否会主动追求碾压，由回归数据回答。

## Decisions

**D1：判定式取 `本人势力 ≥ 其余参赛玩家势力之和`，用 `≥` 不用 `>`。**
备选 `>`：在 2 人局里 `A > B` 等价于"领先一点就赢"，太松。`≥` 在 4 人局意味着"你一个人顶得过其他三个加起来"，在 2 人局意味着"你至少是对手的两倍"——两种人数下都是"压倒性"的直觉。取等号触发是为了让边界可被算例钉死，不留 `204 vs 205` 这种模糊地带。

**D2：只统计参赛玩家。**
弃赛者与出局者的势力不计入"其余之和"，他们本人也不能获胜。理由：§10.2 已规定弃赛者"不参与行动顺序或获胜判断"；若把弃赛者的高势力计入分母，会出现"有人弃赛反而让别人更难赢"的反直觉，也给了弃赛以战术意义。

**D3：判定时机复用既有的"每次结算与 Pass 后重算势力"。**
§10.2 要求每个合法批次结算后与 Pass 后立即重算势力与排名，碾压检查挂在同一处，不新增触发点，也不需要额外重算。

**D4：优先级 只剩一人 > 碾压 > 整轮 Pass > 棋盘填满 > 达上限。**
"只剩一人"是无可争议的终局；碾压排第二是因为它描述的是盘面事实且指定了获胜者，比"大家都不下了"更强的结论。整轮 Pass 与棋盘填满不指定获胜者，只触发排名。达上限是兜底，永远垫底（`round-cap` D2 已确立）。

**D5：终局原因新增一值，名次复用 `FinalStandings` 的唯一实现。**
碾压获胜者必然是势力最高者，所以按既有比较链排名时他自然是第 1 名——不需要为碾压写第二套排序。测试要钉住这一点（构造"碾压触发时获胜者恰好与第 2 名势力相同"是不可能的，因为 `A ≥ B+C+D` 且势力非负时 A 必 ≥ B）。

## 接口契约

**输入：** 每次结算 / Pass 后的 `PowerSnapshot`（参赛玩家的势力与状态）。

**输出：**

| 输出 | 变化 | 消费者 |
|---|---|---|
| 终局原因 | 新增「势力碾压」 | `match-telemetry` 终局原因分布、结算面板文案 |
| `MatchResult` | 触发轮次与名次 | 对局日志、`add-tactical-ui` |
| 平衡报告 | 新增碾压胜占比 / 平均触发大回合 / 势力比 | 数值调整决策 |

## Risks / Trade-offs

- **[碾压把先手滚雪球放大]** → 领先者本就更容易继续领先，碾压给了它一个提前锁定的出口。回归必须同时看第 3 大回合领先者胜率（当前 38%，目标 ≤ 50%）；若被推高到 50% 以上，要么调阈值（如 1.2 × 其余之和），要么回退。
- **[4 人局早期难触发、2 人局过早触发]** → 本轮只有 4 人图，2/3 人图在 §18.2 之外；阈值形式与人数无关，等做 2 人图时再评估。
- **[AI 不会追求碾压]** → AI 的评价函数里没有"离碾压还差多少"这一维。本 change 不调 AI；若回归显示碾压几乎不触发，再决定是给 AI 加一维还是调阈值。
- **[与大回合上限的相互作用]** → 预期碾压会吃掉一部分"达上限"的局；若达上限占比没降，说明对局普遍陷在势力接近的僵局，那是另一个问题（冲突偏少），不要靠调碾压阈值掩盖。

## Migration Plan

1. 终局原因枚举 + 判定挂到既有检查点 + 名次复用。
2. Sim 终局原因分布与新分析段落。
3. 设计文档 §12.3 增补条件 5 与优先级说明，文末变更记录加一行。
4. 200 局回归（种子 1–200，Standard，上限 15），与本次基线对照：碾压胜占比、达上限占比、平均结束大回合、第 3 大回合领先者胜率。
5. 回滚：回退提交；日志向后兼容（旧日志没有该原因）。

## Open Questions（建议裁决）

1. **阈值形式** → 建议 `≥ 其余之和` 起步；若回归显示触发过早（如平均第 6 大回合以前）或领先者胜率被推过 50%，改为 `≥ 1.2 × 其余之和` 或追加"须保持一个完整大回合"。
2. **是否给 AI 加"碾压进度"维度** → 建议先不加，用回归数据判断。
3. **2 人局** → 本轮不评估。

## 裁决记录（已确认）

1. **判定式 `本人势力 ≥ 其余参赛玩家势力之和`，取等号即触发**（2026-09-15，项目负责人确认）：边界由算例钉死（210 ≥ 205 触发、204 < 205 不触发），不留模糊地带。
2. **只统计参赛玩家**：弃赛与出局者的势力不计入其余之和，本人也不能靠碾压获胜；避免"有人弃赛反而让别人更难赢"。
3. **判定挂在既有的"每次结算后 / 每次 Pass 后重算势力"检查点**，不新增触发时机、不额外重算。
4. **优先级**：只剩一人 > 势力碾压 > 整轮 Pass > 棋盘填满 > 达大回合上限。
5. **名次复用 `FinalStandings` 唯一实现**：碾压获胜者必然势力最高，自然排第 1，不写第二套排序。
6. **实现顺序**：本 change 先于 `growth-pass-1`（项目负责人选择先做"有人能赢"），因此 4.2 的 200 局回归对照的是 cap-multiplier + round-cap 之后的基线（达上限 25%、平均结束 12.5 大回合、领先者胜率 38%、峰值军势 1511、首次冲突 7.11）。
