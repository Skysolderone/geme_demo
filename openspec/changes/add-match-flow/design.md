## Context

本 change 是把前五层拼成"一局游戏"的状态机。它自己几乎不做计算，但它决定了**每件事发生的时机**，而这个玩法里几乎所有精妙之处都藏在时机里：

- 信物快照在小回合**开始**时读一次 → 先手夺资源对后手当回合生效（§5.1）。
- 先锋在大回合**结束**时读 → 本大回合最后一手抢到的先锋立刻影响下一轮顺序（§8.1）。
- 出局保护**逐玩家**解除 → 先手玩家清空后手棋子不会让后手直接出局（§4.2、§12.1）。
- 整轮 Pass 的计数必须**跨回合重置** → 否则零散的 Pass 会累积成误判的终局。

这一层写错不会崩溃，只会让对局体验静默走样——所以每一条时机都必须有显式测试。

本轮规格保持实现无关。

## Goals / Non-Goals

**Goals:**
- 一份顶层状态机，所有时机在一处决定。
- 逐玩家出局保护的正确实现，有专门用例覆盖"先手误伤后手"。
- 先手值公式与三级同值判定链完全可复现。
- 三类终局条件与四级名次比较链完整实现。
- 对局顶层状态可持久化与恢复。

**Non-Goals:**
- 不实现联网同步、断线处理与匹配。
- 不实现带入带出与弃赛收益结算（只保证快照可记录）。
- 不实现 AI 决策逻辑（只定义何时请求决策）。
- 不实现顺序层可视化。
- 不做 2/3 人地图的对局验证。

## Decisions

**D1：出局保护用"每玩家一个布尔 + 解除条件"，不用全局回合号判断。**
状态为 `开局保护中 / 已解除`。解除动作只在"该玩家完成第 4 大回合的小回合"这一个点上触发。任何写成 `if 当前大回合 >= 4 then 全体解除` 的实现都是错的。
必须有的用例：第 4 大回合先手玩家清空后手玩家 C 的棋子与手牌 → C 不出局；同一大回合内 A 已解除、C 未解除（两人状态不同）。

**D2：整轮 Pass 用"连续 Pass 计数"，落子即清零。**
维护一个跨小回合的连续 Pass 计数器。任一玩家确认 ≥1 枚落子即清零。当计数器达到当前参赛人数时触发终局条件 2。
为什么不用"本大回合内是否人人 Pass"：参赛人数会因出局而中途变化，按大回合分桶会在人数变化的那一轮产生歧义。连续计数对人数变化天然健壮——出局发生时把计数器与新的参赛人数重新比较即可。

**D3：势力名次与并列由本层裁决，`add-territory-power` 只输出并列信息。**
§11.2 的同值判定链需要"先手修正"与"上一大回合行动位置"，这两项都是流程层的数据。让计分层去取这些数据会造成反向依赖。所以计分层输出"并列组"，本层用三级链打破。

**D4：先手修正在大回合结束时向 `add-relic-system` 单次拉取，不缓存。**
理由同 §8.1 的读取时机规定。缓存会让"最后一手抢先锋"这个战术失效。

**D5：合法落子范围由本层计算并下发，出生区数据本身不带限制。**
与 `add-board-core` 的 D5 呼应。本层按当前大回合序号返回格集合：1–3 大回合返回该玩家锁定的出生区格集合，第 4 大回合起返回全图可落子格集合。`add-batch-deployment` 只消费这个集合，不关心为什么。

**D6：小回合阶段机是显式状态，不是函数调用序列。**
五个阶段做成可查询的显式状态（当前玩家、当前阶段），理由有三：强制弃牌门需要"停在整理手牌阶段"这个可观察状态；UI 需要知道当前阶段以决定显示什么；调试 AI 的人工接管（§15.3）需要在任意阶段介入。写成一串函数调用就没有介入点。

**D7：终局名次比较链是一个纯函数。**
输入：全部玩家的（状态、势力值、控制信物数、独占空格数、盘面棋子数、出局顺序、弃赛时势力值）。输出：最终名次（允许并列）。做成纯函数便于逐例测试这条四级比较链 + 三类玩家分组。

**D8：15 秒同时插旗的规则照常写进 spec，但本轮只在单机/AI 路径验证。**
§4.1 的匿名插旗是联网体验的一部分，§18.2 又把正式联网排除在外。取舍：把规则完整定义（避免将来重新设计），实现上提供"原型依次插旗"路径产出等价状态。这样联网落地时只需替换输入路径，不改状态模型。

## 接口契约

**输入：**

| 输入 | 来源 |
|---|---|
| 出生区格集合、可落子空格查询 | `add-board-core` |
| 结算完成事件、Pass 事件 | `add-batch-deployment` |
| 势力值、势力名次（含并列信息）、独占空格数 | `add-territory-power` |
| 效果快照、先手修正、控制信物数 | `add-relic-system` |
| 手牌是否为空、超限种数 | `add-recruit-hand` |
| 对局种子的 `setup` 子流 | 对局初始化 |

**输出：**

| 输出 | 消费者 |
|---|---|
| `当前合法落子范围` | `add-batch-deployment` |
| `小回合阶段状态`（当前玩家、当前阶段） | `add-tactical-ui`、`add-heuristic-ai`（决策请求点） |
| `小回合开始 / 结束`、`大回合结束` 事件 | `add-relic-system`（快照、先锋读取）、`add-recruit-hand` |
| `玩家状态`（参赛 / 已弃赛 / 已出局、保护中?） | `add-territory-power`、`add-relic-system`、`add-tactical-ui` |
| `下一大回合行动顺序` + `先手值明细` | `add-tactical-ui`（顺序层）、`add-heuristic-ai` |
| `终局结果`（原因、最终名次、并列信息） | 遥测（§17）、`add-tactical-ui` |

## Risks / Trade-offs

- **[出局保护写成全局解除]** → 本 change 最高危的实现陷阱，直接造成"开局被围死就出局"的体验事故。用"先手误伤后手"与"同回合内两人保护状态不同"两条用例强制覆盖。
- **[整轮 Pass 误判]** → 用"前两人 Pass、第三人落子 → 计数重置"锁死；再加一条"出局导致参赛人数变化"的用例。
- **[先手正反馈形成不可逆滚雪球]** → §17 已列为重点监控。本层需输出每大回合的先手值明细（名次、修正、先手值），供批量跑局回归"第 3 大回合领先者最终胜率 ≤ 50%"这一目标（§16）。
- **[先手修正被缓存]** → 断言"最后一手抢到先锋，本大回合结束即生效"。
- **[弃赛者被误排除出覆盖/势力计算]** → 弃赛只影响行动与获胜判断，不影响盘面计算。用例：弃赛者势力仍显示、其棋子仍制造争议。
- **[阶段机与事件双轨导致时序漂移]** → 事件只由阶段机在阶段切换点发出，不允许其他模块自行发出流程事件。

## 裁决记录（已确认）

1. **15 秒同时插旗实现为可配置超时**（默认 15 秒）；单机与 AI 路径把超时设为立即，不阻塞批量跑局。规则完整保留、实现留钩子，联网落地时只需接入真实输入源，不改状态模型。硬编码 15 秒会让 5000 局跑局光插旗就耗掉约 20 小时。
2. **保护期内允许主动弃赛**。弃赛是玩家的权利，且保护期弃赛与保护期外弃赛在规则上无差别（遗留棋子照常产生覆盖与势力）。禁止它等于引入一条与规则无关的限制，且也阻止不了玩家挂机。
3. **终局条件 2 用连续 Pass 计数器实现**：任一玩家确认 ≥1 枚落子即清零，计数达到**当前**参赛人数即触发。对出局导致的参赛人数中途变化天然健壮，规避了"这一轮应该有几人 Pass"的歧义，无需按大回合分桶。
4. **第 4 大回合盘面为空的玩家可从任意合法空格重新进入，不加任何额外限制**，按 §4.2 字面执行。若跑局显示"自爆后空降敌后"破坏体验，再补限制——限制在原出生区会让被清空的玩家几乎无法翻盘，等同于把出局条件前置。
5. **弃赛快照记录完整的玩家私有状态 + 该时刻的盘面序列化**：手牌两段账、效果快照、控制信物列表全记。粒度宁可过细——将来设计带入带出时裁剪容易，补记困难（旧对局的数据已经丢了）。
