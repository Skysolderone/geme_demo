## Context

同形比对当前直接比较 `GameBoard.Serialize()`，其中含棋子类型（`board-topology` 旧要求"供同形禁则直接比较"）。多人互提循环中，回填方每轮换类型即可让序列化结果不同。`Serialize()` 另被存档、日志、`SettlementDriver` 结算核对、弃赛快照使用，这些用途需要类型。

## Goals / Non-Goals

**Goals**：同形比对忽略棋子类型；序列化与存档格式不变；比对键只有一处实现。
**Non-Goals**：不引入"最近 N 手"之类的额外循环判定；不改 AI。

## Decisions

### D1 比对键由序列化结果投影，一处实现

在 `Siege.Core/Board` 提供一个纯函数，把序列化结果投影为比对键（每格只留占用者，去掉类型；设施与地表原样保留）。`BoardHistory` 继续存序列化结果（存档不变），`FindDuplicate` 与预演第 8 步都经该投影比较。备选"新增一个独立的 `SuperkoKey()` 序列化"会出现第二份逐格遍历，与序列化格式漂移，不采用。

### D2 历史集合按比对键索引

`BoardHistory` 内部维护"比对键 → 最早提交序号"的索引，读档时由存档里的序列化结果重建索引；返回的历史序号语义不变（仍是最早一次）。

## Risks / Trade-offs

- [合法的"原地换类型"被禁] 只有当结算后全盘占用者、设施、地表都与某历史提交相同才触发，正常对局中几乎只在循环里出现 → 接受。
- [走法分叉] 黄金哈希等可能变化 → 按规则变更重建并用探针归因。
- [简单难度仍超标] 74 局首回合一子不落是阈值问题、与本 change 无关 → 复跑后如实报告，另行裁决。

## Migration Plan

存档格式不变；读档时重建比对键索引。旧日志回放：同形判定变化可能使旧日志在某步被拒 → 日志首部没有规则版本字段，分歧在被拒那一手所在行报出（不在首部）；旧日志只作数据留档，不补规则版本字段。
