## Context

基准文档的活形算法（`core/board/groups.gd`）写在一个没有地形的棋盘上：眼 = "空格四邻全属同一玩家，障碍 / 边界视为己方墙"。本仓库有崖壁、深水、栅栏、林地与匠人改造，连接与气一律沿**气边**计算（`terrain`「气边」），且栅栏可以把一条棋串切成两条、搭桥可以把"墙"变成空格。活形判定与活棋禁入必须在这套地形语义上重新定义，并堵住匠人绕过禁入的路径。

现有 `GroupSafety`（AI 用）已有一个"单点气"近似：某口气沿气边的全部邻格都是己方棋子即算眼点。它与本 change 的单格眼定义一致，但没有眼空间与三态分类。

约束：邻接 / 气 / 覆盖各只有一处实现；全量重算、不存历史状态；规则只读公开盘面。

## Goals / Non-Goals

**Goals**
- 给出在地形上无歧义、可测试的眼 / 封闭眼空间 / 活形三态定义。
- 已确定活形一旦成立，非所有者无法通过**任何**手段（落子、立栅、搭桥）使其失去活形。
- 玩家在落子前就能看见哪些格禁入、哪些棋串已活。

**Non-Goals**
- 不追求围棋意义上的死活正确性（假眼、双活、劫活都不处理）。
- 不改 AI。

## Decisions

### D1 眼空间沿气边 flood fill，"墙"由气边的缺失自然给出

- **空区**：空的可落子格沿气边连通的极大集合。
- 棋串 G 的**候选眼空间**：与 G 的某口气同属一个空区的那个空区。
- 空区 R 对玩家 P **封闭**，当且仅当：与 R 中任一格有气边相连的每个被占格，其占据者都是 P；且 `|R| ≤ EYE_SPACE_MAX`（12）。
- 没有气边的方向（障碍、未架桥深水、崖壁、栅栏、棋盘外沿）不产生邻格，天然是墙——不另写"墙"的判定，直接复用气边邻格查询。林地格有气边，可以是眼空间的一部分。
- 封闭空区可以同时贴着 P 的多条棋串：它是其中**每一条**的眼空间（与基准文档"四邻全属同一玩家"一致，不要求同一棋串）。

### D2 活形三态与形状判定用气边图，不用几何形状

对棋串 G，取其全部封闭眼空间，逐个按大小给**眼值**：

| 空区大小 | 形状（气边图） | 判定 | 眼值 |
|---:|---|---|---:|
| 1 | — | 单格眼 | 1 |
| 2 | — | 死形，不计 | 0 |
| 3 | 任意 | 未定 | 1 |
| 4 | 四格在气边图上成环（方四） | 死形，不计 | 0 |
| 4 | 其余（直四 / 曲四 / 丁四） | 活 | 2 |
| 5 | 任意 | 未定 | 1 |
| 6–12 | 任意 | 活 | 2 |
| > 12 | — | 不算眼空间 | — |

`life(G)`：眼值之和 ≥ 2 → **活（2）**；= 1 → **未定（1）**；= 0 → **死（0）**。只有活（2）受保护。

- "方四"用气边图定义（四格成 4-环）而不是几何 2×2：几何 2×2 中间若有栅栏或崖壁，气边图上是一条折线，按"其余"处理。
- 基准文档对"一个单格眼 + 一个三格空区"未明说；按眼值相加判活（1 + 1 = 2）。见 Open Questions 3。

### D3 活棋禁入检查在预演第 1 步，基于正式盘面

禁入格集合 = 正式盘面上所有 `life = 2` 棋串的封闭眼空间之并，按所有者分组。预演第 1 步：暂放落点若落在**他人**的禁入格 → 非法，原因「活棋禁入」，附该格坐标与所属活形棋串。判定基于本批次开始前的正式盘面（与第 1 步其他判定同一时点）。

所有者自己可以落进自己的眼空间——主动拆眼是允许的；拆完若不再是活形，禁入随下一次全量重算自动解除。

### D4 不得破坏他人活形：结果导向的一条检查，堵住所有改造路径

只禁落子不够。匠人可以：① 在活形棋串的两枚棋子之间立栅，把它切成两条各一眼的棋串；② 在眼与棋子之间立栅，让眼不再是该串的气；③ 在充当墙的深水格上搭桥，让封闭空区漏出去。逐条枚举禁止目标既啰嗦又容易漏。

改为**结果导向**：预演在"应用改造、同时提子"之后，对正式盘面上每条 `life = 2` 且所有者不是当前玩家的棋串 G，检查结算后盘面上 G 原有的每一枚棋子所在的棋串是否仍为 `life = 2`。任一不满足 → 整批非法，原因「破坏活形」，附受影响棋串坐标与触发的落子 / 改造。

- 该检查同时兜住落子路径（即使某种落子绕过了 D3，也会在这里被拒）。
- 活形棋串**可能**在第 5 步被提走：外气此前被逐步填满是合法的，随后一个批次用数枚匠人立栅隔断它与各个眼之间的全部气边（贴着崖壁 / 水边的眼只有两条这样的边），该棋串即无气。因此第 6 步 MUST 把"原棋子已不在副本上"视为失活并拒绝整批；这是规则的一部分而不是防御性代码，由性质测试守门。
- 所有者自己的批次不受此约束。
- 成本：只复查"结算前为活形的非己方棋串"，通常是个位数。

### D5 状态全量重算，不设"永久"标记

活形状态不入存档、不累积：每次结算后由盘面重算。"永久"由 D3 + D4 保证——非所有者没有任何合法手段使其失效；所有者自己拆掉则当即失效。弃赛者的活形无人能拆，事实上永久留存（设计文档 §12）。

### D6 公开与展示

活形状态、封闭眼空间与禁入格由公开盘面唯一决定，属于始终公开信息。棋串读法中活形棋串加"已活"标记，禁入格对非所有者显示为不可落子并可查原因；合法落点高亮自动扣除禁入格（走合法落子范围契约，界面不自行判断）。

### D7 与 `GroupSafety` 的关系

本 change 在 `Siege.Core/Board` 提供规则级的活形分析；`GroupSafety.EyePoints` 保持不动（AI 启发式，语义与单格眼一致）。`ai-eye` 负责让 AI 改用规则级查询，届时再决定 `EyePoints` 的去留。两者在本 change 期间并存，但 MUST 共用同一个气边邻格查询。

## 接口契约

| 方向 | 对象 | 契约 |
|---|---|---|
| 输入 | `terrain`「气边」、`board-topology`「棋串构成」「气的计算」 | 空区、棋串、气均沿气边；本 change 不新增邻接语义 |
| 输入 | `restore-go-core-rules` | 结算顺序第 6 步；`information-visibility` / `tactical-layers` / `match-telemetry` 的新基线 |
| 输出 → `capture-resolution` | 预演 | 第 1 步新增「活棋禁入」；第 5 步（提子）之后、第 6 步（自杀手）之前新增「破坏活形」 |
| 输出 → `turn-sequence` | 合法落子范围 | 在原范围上扣除当前行动玩家的禁入格 |
| 输出 → `ai-eye` | 活形查询 | 给定盘面（含预演副本）→ 每条棋串的 `life`、封闭眼空间、眼值；给定玩家 → 禁入格集合 |
| 输出 → 遥测 | 事件 | 活形确立 / 失去（棋串代表坐标、大回合、小回合、所有者）；两类拒绝原因 |

## Risks / Trade-offs

- [活形过易形成 → 盘面早早锁死] 12 格以内围出 6 格空区即永久安全，批次制下 2–3 个小回合就能围成 → 由跑局数据观察"首次活形确立的大回合"与"终局时禁入格占比"；数值不在本 change 调。
- [出生区里一块小空区被自己围住即成活] 这是预期行为：保护期内在自家出生区做活，正是"有出生点包含"的含义。
- [边疆档大平台] 25–81 格的平台空区 > 12，独占平台不算活；玩家必须在平台里再围小眼。如实写进玩法说明。
- [预演耗时] AI 每回合数百次预演，每次多一次活形复查 → 复查范围限定为"结算前已活的非己方棋串"；若仍偏慢，活形分析按空区缓存（同一盘面指纹只算一次），留给 `ai-eye` 评估。
- [假眼] 不识别假眼意味着某些围棋里会死的形状在这里是活的 → 接受；规则表就是规则。
- [与盘面同形禁则的交互] 禁入减少了可行落点，同形触发概率下降，无冲突。

## Migration Plan

1. `restore-go-core-rules` 归档后开始。
2. 顺序：活形分析（纯函数 + 测试）→ 预演两步检查与原因码 → 合法落子范围 → 公开视图 / 预演提示 → 表现层 → 遥测与分析。
3. 旧存档：活形不入存档，无迁移；旧日志缺活形事件，分析按既有约定整局排除并计数。

## Open Questions（建议裁决）

1. **匠人能否破坏他人活形？** 建议：不能（D4）。备选是"禁入只管落子、活形每次重算"，实现更简单，但匠人可以立栅切串 / 搭桥漏眼，与裁决 #8"活棋落子无意义"的初衷相悖。**已确认（裁决 16 / 17）。**
2. **眼的"墙"怎么定？** 建议：凡无气边的方向都是墙（D1），不单列障碍 / 边界。**已确认（裁决 16 / 17）。**
3. **眼值是否相加？** 基准文档只写了"≥ 2 个单格眼"与单个大眼空间两种活法。建议：相加（单格眼 1、三格 / 五格 1、活形四格与 6–12 格 2），和 ≥ 2 即活。默认按建议执行。
4. **`EYE_SPACE_MAX = 12` 在边疆档是否放宽？** 建议：不放宽，原样采用（裁决 #11 默认）。默认按建议执行。
5. **所有者落进自己的眼空间后仍为活形时，禁入是否保持？** 建议：保持——状态由结算后盘面决定，与谁落的子无关。默认按建议执行。
