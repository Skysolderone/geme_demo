# 设计与裁决记录：merge-board-layer

## 1. 依据

用户在试玩截图上圈出底部按钮栏的领地、气、势力三个按钮，标注"重复"。实测确认领地与气这两层点亮的空格集合恒等（21 对 21，双向差集为空），原因是定义等价：覆盖 = 棋子的四邻接相邻格，气 = 棋串的空邻格，所以"被某方覆盖的空格"就是"某条棋串的气"。

势力层不在本次范围：它与右上角排名面板的重复性质不同（面板给汇总数值，层给每格贡献与倍率热区），需要单独评估。

## 2. 裁决

### D1：合并为一层两读法，不是"同时显示"

两种呈现都成立。同时显示（底色给归属、点与描边给气）一眼看全、不用切换，代价是同一格上叠三种视觉编码。层内切换画面更干净，代价是想同时判断"这块争议地是谁的气"要来回按两次。

用户选择层内切换。

### D2：键位顺延，不留空号

`1` 盘面、`2` 势力、`3` 信物、`4` 顺序；手柄 DPad 同步顺延一位，原先绑给顺序层的 LeftShoulder 空出。

备选是保留原有编号、让 `2` 空着，好处是势力 / 信物 / 顺序的键位完全不变。用户选择顺延——原型阶段肌肉记忆的代价小于按钮栏跳号的长期代价。

### D3：按住显示模式下，读法切换不能绑在层键上

用户选的"再按同一个键循环"在点击切换模式下成立，在**按住显示**模式下不成立：键正被按住，没有"再按一次"可言。而按住显示是默认模式。若照搬，按住显示的玩家将被永久锁死在一种读法里。

处理：
- **点击切换**模式按用户的选择实现三态循环：关闭 → 归属 → 棋串 → 关闭。
- **按住显示**模式下层键只管显示与隐藏，读法由独立键 `Tab` 切换。`Tab` 在两种模式下都可用，所以按住模式的玩家先用 `Tab` 选好读法，再按住层键看。

规格把这一条写成 MUST NOT（不得把读法切换绑在层键上），因为它是从"按住"这个交互本身推出来的约束，不是实现细节。

### D4：读法是持久状态，不随层关闭重置

关掉层再打开，回到上次的读法。理由是读法表达的是玩家当前关心什么（谁占了地 / 谁要被吃），这个关注点不会因为松开一次按键就改变。若每次打开都回到归属读法，按住显示模式下每看一眼都要重按一次 `Tab`。

### D5：枚举合并而不是保留两个值共用一个按钮

`TacticalLayer` 去掉 `Territory` 与 `Liberties`，新增 `Board`；读法另用 `BoardReading { Ownership, Groups }` 表达。

保留两个枚举值、只在界面上共用一个按钮，改动更小，但会留下一个谎言：状态机认为它们是两个互斥的层，而界面表现为一个层的两种读法。往后任何读这段状态的人都要先解开这个不一致。互斥规则作用于层，读法作用于层内部，这两件事在类型上就该分开。

## 3. 不做的事

- 不合并势力层。
- 不改覆盖与气的规则。
- 不改「一次只显示一层」的互斥规则——它约束的是层，读法不在其管辖内。
- 不改按住显示 / 点击切换这两种输入模式本身。
