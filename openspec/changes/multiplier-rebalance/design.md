## Context

`cap-multiplier`（封顶 5）与 `growth-pass-1`（封顶 4）两次降封顶都没有降低倍增子选择率（86.9% → 84.8% → 85.8%）。对 growth-pass-1 之后 200 局的终局盘面做势力归因：倍增子占全部势力 76.3%、每颗平均 53.0，普通子 1.0、堡垒子 4.0、连珠子 2.2、协同子 8.3。

根因在公式结构：`⌊(基础 + 位置加值) × 1.5^e⌋` 让倍率同时放大基础军势与连珠、协同的加值——任何加强其它棋子的改动都会在倍增串里被一起乘上去。降封顶只削顶部，不改变"凡有价值的东西都要挂在倍增串上"这个结构。

## Goals / Non-Goals

**Goals:**
- 倍增子势力占比从 76% 降到约一半，堡垒、协同、连珠的独立价值上升。
- 保留每枚 ×1.5 与 §10.1 标准算例（无位置加值的情形结果不变）。
- 仍只改唯一的倍率实现与势力组装一处，所有调用方不变。

**Non-Goals:**
- 不改倍数 1.5、不改连珠与协同的加值公式、不加强普通子、不调碾压与部署。

## Decisions

**D1：倍率只放大基础军势，位置加值取整后直接相加。**
备选 A：继续降封顶到 3，其它不变——离线估算倍增子仍占 67%。备选 B：每枚 ×1.25——最均衡（39%），但改 §10.1 核心数与标准算例。备选 C：加强普通子——离线估算 74–76%，无效。
选定"只放大基础 + 封顶 3"：离线估算 51%，保留 1.5 与标准算例。"位置加值不被放大"让连珠、协同回到"加法组合"，它们不再必须依附倍增串才有价值。

**D2：取整只作用于"基础 × 倍率"。**
位置加值本就是整数，`⌊基础 × 倍率⌋ + 加值` 与 `⌊基础 × 倍率 + 加值⌋` 数值相同；规格写成前者，让"加值不参与取整"一目了然。唯一的"乘倍率并取整"实现仍在 `Multiplier.Apply`，只是传入值从"基础 + 加值"改为"基础"。

**D3：封顶 4 → 3，仍只改 `Multiplier.MaxExponent` 一处。**

**D4：势力明细结构不变。**
明细字段已含基础、加值（及来源）、倍增子数、生效指数、倍率、军势；新增一条"明细可复算棋串军势"的 Scenario，钉住新公式在明细层面自洽。

## 接口契约

**输入：** 每条棋串的基础军势总和、连珠加值、协同加值、倍增子数量（来自 `piece-effects`）。

**输出：**

| 输出 | 变化 | 消费者 |
|---|---|---|
| 取整后军势 | 公式改为只放大基础 | 名次、先手、碾压判定、AI 评价、界面势力层 |
| 倍率显示字符串 | 最大 `3.375` | 界面、遥测 |
| 势力明细 | 字段不变，军势计算方式改变 | 界面、Sim 日志 |

## Risks / Trade-offs

- **[离线估算与真实对局有偏差]** → 离线重算用的是旧规则下 AI 摆出来的盘面，新规则下 AI 会换打法。以 200 局回归为准：倍增子势力占比（Sim 报告须能输出这一项，或用离线脚本在回归日志上复算）、各棋子选择率。
- **[势力整体下降使碾压更难触发]** → growth-pass-1 之后碾压胜已只有 30.5%、达上限 10.5%。回归若达上限显著回升（例如 > 15%），另开 change 调碾压起始或阈值，本 change 不预调。
- **[协同子相对价值上升]** → 协同子选择率已 92%；回归若协同子势力占比成为新的一家独大，记录并留给下一轮。
- **[既有算例大面积改写]** → 所有"含倍增子且含位置加值"的算例都要按新公式重算；无位置加值的算例（含 §10.1 标准算例）数值不变。实现方逐条列出，不得改实现语义凑绿。

## Migration Plan

1. `PowerCalculator` 组装改为 `Multiplier.Apply(基础) + 位置加值`；`MaxExponent` 4 → 3。
2. 按新公式改写受影响算例；新增"位置加值不被放大""明细可复算棋串军势"两条测试。
3. 设计文档 §9.2、§10.1 与变更记录。
4. Sim 报告增加"各棋子势力占比"段落（按 proposal 中的归因口径），供回归直接读数。
5. 200 局回归，与 growth-pass-1 之后的数据对照。
