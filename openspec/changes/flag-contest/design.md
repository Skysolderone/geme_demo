## Context

`PrototypeZoneAssignment.Assign` 是原型选区的唯一实现：区数 ≤ 地图人数上限时按编号顺排，否则用 `GameSeed.ZonePick` 子流在空闲区均匀抽取；两支都保证 AI 互不同区。

## Decisions

### D1 冒险判定叠加在现有两支之上

对每名未由人指定的玩家，按编号顺序：若此前已有旗，先用新子流 `GameSeed.FlagRisk` 抽一次 `[0,100)`，小于 p 则在"已有人的出生区"（按区号升序去重）中用同一子流均匀选一个；否则走原有分支（顺排 / `ZonePick` 抽取）选空闲区。原有分支的状态（顺排游标、`ZonePick` 子流、空闲列表）只在"走原有分支"时推进——p = 0 时 `FlagRisk` 子流虽被抽取但不影响其余状态，结果逐项不变。

备选"同时独立 + 按估值加权随机"：对称图上约九成对局出现同区，开局生态剧变，未采用（负责人裁决）。

### D2 配置与记录

p 放入对局配置（与停手阈值同层级的批量配置字段 + `MatchOptions`），日志首部记录；缺字段的旧日志按 0 重建（p = 0 与旧行为一致）。CLI `--flag-risk <0-100>`。终端版 / Godot 用缺省值，不加选项（沿用 `ai-eye` R12 的做法）。

### D3 分析

分析器从 `FlagsLocked` 与首部读出每局是否有同区、同区玩家集合；报告"同区对局数 / 占比"与"同区玩家的平均名次、胜率"。只报告。

## Risks / Trade-offs

- [既有种子走法变化] 缺省 p = 15 使部分既有种子开局改变 → 依赖走法的测试写死 p = 0（`testing.md`「依赖 AI 实际怎么走的断言要把权重写死」同理），不挑种子凑绿。
- [同区后 AI 不会针对性应对] 保护期共享范围已由规则支持，AI 评价不变 → 冒烟数据只报告，是否需要 AI 调整另议。
- [边疆图空闲区更多] 冒险只在已有旗时触发，逻辑与区数无关。
