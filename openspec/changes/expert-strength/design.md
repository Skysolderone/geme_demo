## Context

- **现状**（`expert-lookahead` D1–D12，v1.16；阈值 20 见 `v2-recalibration`，v1.17）：专家 = 高难的候选生成（N 24 / M 32、同一 `ai-<玩家>` 扰动子流）+ 一层前瞻。前瞻集 = 去掉空批次、按 `CandidateSelection` 排序的前 W = 4 个；每个候选 c 预演得 B1，用标准启发式（D 枚普通子、M = 1 不扰动）模拟下一名对手得 B2，以决策起点为"前"、B2 为"后"、同一评价器 `Evaluate` 重打分（被提走的起点棋子按 ≤ 1 口气危险计入），选最高者、同分取原次序。停手阈值与活形硬约束只在前瞻之前生效。守门：W = 1 时与高难逐步相同；专家的扰动消费与高难相同；耗时中位数 ≤ 4 × 高难（计时测试 `专家前瞻耗时计时Tests` 与默认套件里的预演次数代理，上限都已是 4）。
- **贪心组批**（`HeuristicTurnController.Greedy`）：从空批次的评价出发，按给定顺序逐个暂放单点；预演不合法、整批被活形硬约束淘汰、或边际提升不大于停手阈值即撤回；同格只取排序最靠前的选项；直到部署上限。k = 0 用原排序，k ≥ 1 用扰动排序（窗口 3）。
- **实验**（`sim-out/expert-strength/`，v5、V2、阈值 20、1 被测 + 3 标准、种子 1–20）：H0 高难 3 / 20、名次 2.50；E0 现专家 4 / 20、2.45、改变选择 2.9%、与高难逐种子 好 1 / 同 19 / 差 0；E4 多样候选（前 8 个不同落点"强制首位"的无扰动贪心 + 前瞻集按格集合去重）2 / 20；E5 近似两层（λ = 1）5 / 20、2.35、被提子 18（高难 26）、改变选择 11.4%、好 4 / 同 14 / 差 2、耗时 2.17 × 高难；E6 = E5 + E4 4 / 20、改变选择 24.7%、耗时 2.0 ×。E1（W = 8）、E2（模拟到专家下一手前的全部对手）、E3（按公开手牌类型集合建模对手）无改善。实现参考 `variants.patch`（环境变量开关）。
- **诊断**（139 次已前瞻决策）：① 前 W 个候选落点格完全相同 92 次；② 模拟回应与候选无关 124 次；③ 对手收益对所有候选是同一常数，排名不变；④ 看到了威胁，却没有能避开的候选。
- **测试约定**：计时测试 `[Trait("Category","Perf")]` + `SIEGE_PERF=1`；慢测试 `[Trait("Category","Slow")]` + `SIEGE_SLOW=1`，都不进默认套件。既有专家测试的夹具在 `tests/Siege.Core.Tests/LookaheadFixtures.cs`（停手阈值写死 80）。

## Decisions

### D1 形态：仍是"候选之间重排"，两层加分不是第二层搜索

专家的决策仍是"候选生成 → 前瞻集 → 逐个模拟下一名对手 → 重打分选一个"。本 change 只改两处：前瞻集从哪里来（D2 / D3），重打分加什么（D4）。

- 两层加分只看"专家自己下一手的最佳**单点**增量"：不组批、不模拟之后的对手、不递归，是一个静态评价项，不是 §18.2 的博弈树，也不是多层搜索（Non-goals）。
- 前瞻仍不引入 Pass、不改变候选的内容；被选候选按原落点、类型与改造目标复摆。
- 多样补充候选不是"前瞻产生的新候选"：它们与原排序候选一样由贪心组批在同一停手阈值与活形硬约束下产出，只是排序输入不同（D2）。因此"前瞻只重排"对前瞻本身仍成立，改变的是候选生成的输入。

### D2 多样候选：排除重跑

**问题**：诊断 ① 说明 32 条扰动贪心几乎收敛到同一组格子，只是类型或改造不同；诊断 ④ 说明即使前瞻看到了某一格留下的叫吃，也没有"不下那一格"的候选可选。

**做法（排除重跑）**：对锚候选 a 的某个落点格 x，把 x 格的全部单点（全部类型与改造选项）从原排序里拿掉，用剩下的原排序（k = 0，不扰动）跑一次贪心组批，停手阈值、活形硬约束、部署上限都不变。

- **必然不同**：结果不含 x，格集合一定与 a 不同——除非结果为空批次（丢弃）。这正对应诊断 ④：对每一个"可能出问题的格"，都有一个"不下那一格"的替代方案。
- **口径不变**：每一枚落点仍须通过同一停手阈值的边际检查，前瞻之前的停手口径（`expert-lookahead` D4）原样成立；补充候选不会含有高难不会下的"阈值以下"的落点。
- **零随机**：不消费 `ai-<玩家>`，不引入新子流；专家对扰动子流的消费仍与高难相同。
- **只用自己的评价**：输入只有本次决策的单点排序与评价器。

**E4 "强制首位"为什么只有一半有效**（由代码推得的机制，非实测）：E4 把单点排序里前 8 个不同落点逐个放到首位再跑贪心。① 首位落点仍要过 `next − current > 停手阈值` 的边际检查，不过就被撤回，这次重跑退化为 k = 0 的原排序，得到与第一名完全相同的批次；② 前 8 个不同落点中通常有 3–4 个本来就在第一名候选里（部署上限多为 3–4），把它们放到首位，贪心照样会把其余高分格补回来，格集合与第一名相同。两者叠加，约一半的补充是重复。若要让首位"强制保留"，就得绕过停手阈值，违反 D4 口径。

**备选与取舍**：

| 备选 | 取舍 |
|---|---|
| 强制首位（E4） | 见上，约一半重复；强制保留会绕过停手阈值。放弃。 |
| 排除重跑（采用） | 格集合必然不同、口径不变、实现只多一个"排序过滤"参数；代价是替代方案可能只差一格（"近邻"而非"另一片战场"）。 |
| 按区域或棋串分簇（每簇取最佳） | 能得到"另一片战场"的候选；但规则里没有"区域"的定义，要引入簇的划分口径（出生区？到己方棋串的距离？）与参数，且依赖地图，需另行扫档。列为后续备选（Non-goals）。 |
| 扩大 W（E1，W = 8） | 格集合相同的候选再多也无用，实测无改善。放弃。 |
| 前瞻集只按格集合去重、不补足 | 前瞻集常常只剩 1–2 个候选，诊断 ④ 仍在。放弃。 |

### D3 前瞻集：去重、补足与次序

1. **基础候选**：与同一局面、同一配置下的高难完全相同（含扰动子流的消费）。
2. **去重**：去掉空批次，按 `CandidateSelection` 排序；按落点格集合去重，每个格集合只留排序最靠前的一个。去重后取前 W 个，来源记为"原排序"。
3. **补足**（去重后不足 W 个时才做）：锚依次取前瞻集的成员（从第一个开始，包括补足过程中新追加的成员）；对锚的每个落点格 x，按锚批次的落点次序（即贪心接受的次序，单点价值高者在前），做一次排除重跑；结果非空、且格集合与前瞻集已有成员都不同，即追加到前瞻集末尾，来源记为"多样补充"。前瞻集达到 W 个、补充贪心次数达到上限 S、或锚与格都已用尽，即停止。
4. **次序**：原排序成员在前（按 `CandidateSelection`），补充成员按追加次序在后。**前瞻集第一个始终是同一局面上高难的选择**（高难在含空批次的集合上选，任何非空候选的总分都严格大于空批次，`expert-lookahead` D1 的前提仍成立）；前瞻记录"是否与前瞻集第一个不同"的含义不变；同分取前瞻集靠前者，即偏向原排序。
5. **只在不足时补足**：去重后已有 W 个不同格集合时不跑补充，额外耗时为 0；诊断 ① 说明多数决策会触发补足。
6. **开关**：多样补充上限 S = 0 表示"多样候选关闭"——既不去重也不补足，前瞻集与改动前完全相同（守门 G1 的前提）。专家预设 S = 8（与 E4 的补充次数相同；不扫档）。

备选"总是跑满 S 次补充，再与原排序候选一起按自身总分取前 W"：更多样，但补充候选可能排在第一，前瞻集第一个不再是高难的选择，G2 与遥测口径都要改；耗时也总是满额。列为待裁备选。

### D4 近似两层加分

对前瞻集的每个候选 c：

- **局面**：B2（下一名对手模拟回应之后；回应为 Pass 时 B2 = B1）。
- **专家的下一手**：大回合 = 当前大回合 + 1（每名玩家每个大回合只行动一次，无论专家本大回合是否末位，其下一手都在下一大回合）。
- **下一手单点集合**：
  - 落子范围：公开合法落子范围（与对局流程同一实现），按专家的出生区、下一大回合与 B2 上的禁入格；
  - 部署上限：专家在下一大回合、B2 上的公开部署上限（与模拟对手同一实现：分阶段基础值 + B2 上控制的已揭示军令）；为 0 则加分为 0；
  - 类型：决策起点时专家本人批次上下文中数量 > 0 的类型（不扣除 c 的落子）；
  - 改造：不带改造（匠人按不改造计）；
  - 候选格上限：本局生效的候选格上限大于 0 且合法空格多于它时，按单点排序同一预筛口径（代表类型、七维格分）先收窄；`siege-4p-base-v5` 不触发，与 E5 相同。
- **单点增量**：以 B2 的投影公开视图为"前"新建评价器（同一权重、同一难度口径、同一活形缓存设置），对每个单点预演（同形历史 = 决策起点盘面、B1、B2），预演合法并通过活形硬约束（`TryEvaluate`）者取九维加权总分；取最大值，没有则为 0。
- **加分**：两层加分 = ⌊λ‰ × max(0, 最大单点增量) / 1000⌋，整数运算（`BigInteger`），先取下限 0 再乘权重、再向下取整。
- **前瞻后分数** = 一层分数（即 `expert-lookahead` 的前瞻后分数：B2 上、决策起点为"前"、含被提走棋子的危险修正）+ 两层加分。
- **不计算的情形**：λ = 0 时不做两层扫描（不预演，预演次数与改动前相同，G1 的前提）；专家在 B2 上已出局或没有出生区时加分为 0。
- **无对手的候选**：前瞻集中至少一个候选有下一名对手时，每个候选都计两层加分，没有下一名对手的候选在 B1 上计；全部候选都没有下一名对手时，每个候选都不模拟、不计加分，前瞻后分数等于自身总分，与 `expert-lookahead`「只剩自己时退化」一致（前瞻记录的状态仍按原口径记"已前瞻"，不改记录格式）。E5 实验补丁对无对手候选记 0，会系统性压低"打掉最后一名对手"的候选，这里改掉。
- **可选缓存**：同一决策内两层加分只取决于 B2 的盘面序列化（揭示状态不变、流程状态由盘面推得），可以按 B2 序列化缓存。缓存不得改变任何结果；只在计时超限时启用（D8）。

**为什么这样能改变选择**：诊断 ②③ 说明对手回应常与候选无关、对手收益对各候选是同一常数，一层分数的差异几乎全部来自候选自身。两层加分给"让自己下一手还有好点可下"的候选加分（例如保留叫吃对方的机会、不把自己的扩张空间堵死），这一项因候选而异，能打破一层分数的并列。E5 被提子 18（高难 26）也说明它间接减少了被动局面。

**权重的整数表示**：λ 以千分数整数（λ‰）写入配置与首部，保证序列化逐字节稳定、运算完全确定；扫档的 0.25 / 0.5 / 1 即 250 / 500 / 1000‰。

### D5 两层加分的已知近似

1. **征募未知**：专家下一大回合的征募（新类型、补充数量）不可知；类型集合取决策起点手中已有的类型，不扣除 c 用掉的枚数。
2. **只看一名对手**：B2 之后、专家下一手之前其余对手的行动不建模（E2 已证模拟全部对手无益）。
3. **单点而非批次**：只取一枚落点的增量，不组批、不看部署上限内的多枚配合。
4. **不带改造**：匠人的地形改造不枚举。
5. **阈值以下的增量也计入**：裁决"下限 0"的字面口径；真实决策中边际提升不超过停手阈值的单点不会落下，这一偏差至多为 λ × 停手阈值（阈值 20 时 ≤ 20）。
6. **未揭示信物**：B2 上首次覆盖的未揭示信物只按分区期望估值，不读内容；B2 上控制的内容未知的军令按不提供部署上限计（与模拟对手同一口径）。
7. **同形历史**：只以"决策起点盘面、B1、B2"为历史（`expert-lookahead` D8 的同一近似）。

### D6 替代守门：G1 与 G2 都要

原守门"前瞻宽度为 1 时与高难逐步相同"在多样候选与两层加分打开后不再是完整的回归守门。改为两条：

- **G1（一层回归）**：两层权重为 0 且多样补充上限为 0、其余与专家预设相同的配置，与改动前的专家在同一种子、同一座位下逐步相同——决策序列、扰动消费、前瞻记录的确定性文本逐项相同。它保护一层前瞻的全部既有行为，也是旧专家日志能照常回放的依据（D7）。
  - **基线必须先取**：段 A 第一步在改动任何代码之前，用现有实现在 `siege-4p-base-v5` 种子 1–3（1 专家 + 3 标准，停手阈值按 `LookaheadFixtures` 写死）各跑一局，记下专家的决策序列与每条前瞻记录确定性文本的哈希，写入测试作为黄金值。
- **G2（高难回归）**：前瞻宽度为 1 且多样补充上限为 0 的配置，与高难逐步相同（两层权重取任意值——W ≤ 1 时不做模拟，也不计两层加分）。它保护"候选生成与高难相同"。
- 附带性质（不单列守门）：按 D3 第 5 条，W = 1 时去重后必有 1 个成员，从不补足，所以即便多样补充上限 > 0，W = 1 也与高难相同。

### D7 配置、序列化与旧记录

- `AiSearchConfig` 新增两项：两层权重（千分数，非负整数，构造缺省 0）与多样补充上限（非负整数，构造缺省 0）；`Validated()` 拒绝负数。
- 预设：`Easy` / `Standard` / `Hard` 不变（两项为 0）；`Expert` = `Hard with { 前瞻宽度 4, 多样补充上限 8, 两层权重 λ* }`。段 B 扫档选定 λ* = 1000‰（与段 A 暂取值相同，见 D10 实测）。
- 序列化：两项为 0 时不写出（先例：前瞻宽度、停手阈值）；三档旧难度的配置记录与日志首部逐字节不变。旧记录缺字段按 0 读。
- **旧专家日志**：首部只有前瞻宽度 4、没有两项新字段 → 读为"一层配置" → 按 G1 与改动前的专家逐步相同，回放与逐条核对前瞻记录照常通过。
- 入口：两项与前瞻宽度一样，只经配置文件的 `Search` 指定，不开命令行选项（`expert-lookahead` D9）；终端、Godot 选专家即得预设。

### D8 性能

- **上限**：单次部署决策耗时中位数 ≤ 4 × 高难（`ai-decision`「专家前瞻的确定性与耗时」原值；负责人所说"比值上限改为 4"与现行规格、两处测试一致，本 change 不改上限）。
- **确定性代理**（默认套件）：同一局面集上统计专家与高难每次决策的预演次数；专家一方 MUST 计入补充贪心的预演、模拟对手的预演与两层扫描的预演；断言总次数之比 ≤ 4，输出实际比值与三部分各自的占比。
- **计时测试**（`SIEGE_PERF=1`、Release、ABBA、丢前 3 个预热）：不改测法，只把专家换成新预设；跑一次，结果写进 implement 记录。
- **估算**：补充贪心至多 S = 8 次 × N = 24 次预演 ≈ 192 次（高难的 32 次贪心约 768 次，另加单点排序）；两层扫描每个候选约"合法空格 × 持有类型"次预演，是主要开销——E5 整局耗时 2.17 ×、E6 2.0 ×。单次决策的中位数未单独测过。
- **超限处理**：先启用 D4 的 B2 缓存（行为不变，须有"缓存开关不改变专家决策"的测试）；仍超限则停下报告，不私自降 W、S、λ。

### D9 遥测

- 前瞻记录的每个候选增加：**候选来源**（原排序 / 多样补充）与**两层加分**（整数）。前瞻后分数的含义改为"一层分数 + 两层加分"，一层分数 = 前瞻后分数 − 两层加分，可由日志推得。
- 来源为原排序、两层加分为 0 时不写出这两个字段：G1 配置下的前瞻记录与改动前逐字节相同，旧日志的回放核对不受影响。同一规则也适用于 `LookaheadEntry.ToString()` / `LookaheadRecord.ToText()` 的确定性文本投影（G1 黄金值按它取哈希），否则 G1 会因格式而不是行为变红。
- 首部的两项新配置按 D7 写出。
- 只写确定性内容，不写墙钟时间。分析器不新增分析项；段 B 的报告用一次性脚本汇总。

### D10 λ 扫档与选档准则

- **批次**：`siege-4p-base-v5`、内容集 V2、停手阈值 20、带入 0、小回合上限 600、种子 1–20；座位 1 为专家（前瞻宽度 4、多样补充上限 8、两层权重分别为 250 / 500 / 1000‰，经配置文件 `Search` 显式给出），其余三座为标准。每档 20 局。
- **配对基线**：高难批次 `hard-s01-20`（同一配置、座位 1 为高难，也是扩样的第 1 组），先跑；其确定性文本与既有 `sim-out/expert-strength/H0` 逐局比对，应逐字节相同（高难未被本 change 改动的实测证据）。
- **"好 / 同 / 差"**：同一种子上专家（座位 1）的名次小于 / 等于 / 大于高难（座位 1）的名次。名次沿用 `expert-lookahead` 冒烟与 `expert-strength` 实验的名次口径。
- **选档准则**（依次比较，前一项并列才看下一项）：
  1. 截断 ≤ 1 / 20，不满足的档淘汰；

## Risks / Trade-offs

- **[组合未实测]** 负责人裁决的组合"多样候选 + 近似两层"只以 E6（多样候选用的是较弱的强制首位）测过，4 / 20 不如 E5 单独的 5 / 20。新的排除重跑首次在扫档中实测；20 局样本噪声很大，这正是扩样的目的。
- **[近似偏差]** D5 列出的七项近似都可能让两层加分偏离真实价值；λ 小于 1 时偏差按比例缩小，这也是扫档的意义之一。
- **[耗时]** 两层扫描是主要开销，多样候选让前瞻集更常满 W 个、B2 更少重复，耗时可能高于 E5。计时守门、预演次数代理与 D8 的超限处理约束。
- **[近邻替代]** 排除重跑的替代方案可能只与锚差一格；若扩样显示多样补充很少被选中，分簇（D2 备选）另议。
- **[小样本]** 120 局的胜率置信区间仍约 ±12 个百分点；配对设计与符号检验只能说明方向。结论只报告，不据此调任何数值。
- **[统计口径]** 名次按局内 4 名玩家排出，专家与高难不在同一局对弈，配对比较的是"同一种子、同一座位下换 AI 后的名次"，其余三名标准 AI 的走法也会随之改变。
