## Context

- 计分：`PowerCalculator.Evaluate` 对每条棋串求 `baseTotal + (line + synergy + highGround)`，经 `Multiplier.Apply` 整体乘 `3ⁿ/2ⁿ` 后向下取整；`GroupPower` 携带三项来源拆分。连珠、高地已经只走 `GameBoard.LibertyNeighbors` 与唯一覆盖查询。`PowerCalculator.Compute(board, roster)` 只看盘面，不接触信物。
- 征募：`RecruitWeights.Order` 六档、`BaseTable = [40,20,18,12,10,10]`，匠人一档由对局配置替换；`EffectSnapshot.AdjustedWeight` 以 `基础 × (4 + 3 × 数量)` 调权，`WeightedPick` 按整数累积权重抽取（不要求总和为 100）。
- 信物：`RelicWeights` 两张**百分制**整数表（`[45,20,15,8,7,5]` / `[30,15,10,15,15,15]`），稀有度 `10000 / 权重`；`RelicEstimate` 以 `PercentScale = 100` 求期望，`ValueOf` 对未知类型直接抛。`RelicGenerator.Draw` 的随机消费顺序固定为"类型 → 升级（公共区才消费）→ 徽记绑定 `Enum.GetValues<PieceType>()`"。
- 快照：`EffectSnapshot` 是小回合开始时生成的不可变值对象，只含结构参数与徽记数量；先锋另读。
- 改造：`TerrainEditRules.LegalTargets(map, cell)` / `Reject` 是改造合法性的唯一实现，AI、界面、预演都经它；格目标只取几何四邻。
- 存档：`MatchFlow.Restore` **只存种子，恢复时用 `RelicGenerator.Generate(map, seed)` 重新生成信物分布**，征募子流按消费次数推进。任何对生成表或征募表的改动，都会让旧存档恢复出另一份信物分布——这是本 change 必须处理的兼容点。
- 盘面序列化：每格两字符（所有者十六进制 + 类型码 `B F L M S A`），类型码在 `GameBoard.TypeCode / TypeFromCode` 唯一定义。

## Decisions

### D1 四种新棋子只作为位置加值来源，唯一实现放在 `PieceEffects`

`BannerBonus / ChainBonus / SentryBonus / BoundaryBonus` 与 `LineBonus`、`HighGroundBonus` 并列：旗手读 `map.RelicCells`（静态位置）与 `LibertyNeighbors`；铁链只读棋串大小；哨兵读 `LibertyNeighbors` 上的非己方占用者；界碑读 `LibertyNeighbors` 与 `CoverageMap` 的独占结果。`GroupPower` 扩为七项来源，`PowerCalculator.GroupPowerOf` 公式不变，只是位置加值多四项。

- 备选"按覆盖关系判定邻接"：与负责人"一律沿气边"冲突，且哨兵会隔河计分，放弃。
- 备选"折算成基础军势"：不会被高地 / 连珠等来源区分，明细无法溯源，放弃。
- 新四种基础军势取 1（负责人只说"只提供位置加值"，按"不另给基础军势"理解为与普通子同为 1，列为待确认）。

### D2 界碑按"空格归属三态"的独占判定，荒漠计入

复用 `CoverageMap.ExclusiveCellsOf`，不做地表过滤。归属三态本就不看地表，荒漠只在"归属 → 领地分"一步被滤掉（`terrain-surfaces` D1）。备选"只计计分独占格"：需要在界碑里复制一次荒漠过滤，且"邻接领地"与"领地分"混为一谈；列为待确认，缺省计入。

### D3 连营 / 犄角是"计分信物"，势力计算时按当前控制读取

`PowerCalculator.Compute` 增加一份"已知信物内容"输入（坐标 → 类型）；控制由同一次计算里已有的 `CoverageMap` 与占用判定得出（`relic-control` 的判定本就只依赖盘面）。正式结算传真实内容，预演与 AI 传**批次开始前已揭示**的公开内容。已结算盘面上两者必然一致：控制要求覆盖或占据，覆盖与占据在结算第 4 步必然触发揭示。连营额外加值并入连珠来源、犄角并入协同来源，不新增来源项。已弃赛 / 出局玩家不享受。

- 备选"进效果快照"：势力是对全部玩家同时、随时计算的盘面函数，快照是"某玩家在某小回合"的值；放进快照会让同一盘面在不同玩家回合得出不同势力，破坏 `power-score`"只评价当前盘面"，放弃。
- 备选"预演也用真实内容"：会让预演泄露未揭示信物内容（`batch-preview`「未知信物在预演中只显示"将揭示"」），放弃；代价是首次揭示计分信物的那一批，预演与结算不同，写进规格。

### D4 驿站：快照时"受控信物总枚数 − 1"，逐枚驿站各算一次

每枚驿站计除自身以外的全部受控信物（含其他驿站与先锋，先锋只作计数），不看强度；争议 / 无人控制不计。k 枚驿站 + m 枚其他 → `k × (k − 1 + m)`。
备选"不计其他驿站"（`k × m`）：抑制驿站互相放大，但与"每控制一枚其他信物"的字面不符；列为待确认。

### D5 工坊：直线距离 2、只扩格目标、不叠加

`TerrainEditRules.LegalTargets(map, cell, workshop)` / `Reject(map, cell, edit, workshop)` 增加布尔参数；`workshop` 为真时格目标候选 = 几何四邻 ∪ 同行 / 同列距离 2 的格（至多 8 格），中间格不设条件（"隔一格"的本意就是越过它）。边目标仍是 16 条。批次层按玩家本小回合快照传入。多枚工坊等同一枚（新信物没有强度，布尔即可）。

- 备选"曼哈顿距离 ≤ 2（含 4 个斜角）"：斜角与落点之间没有"被隔开的那一格"，不符合"隔一格"；目标数翻倍，AI 枚举增长更多。列为待确认。
- 备选"工坊同时扩立栅边目标"：负责人只点名搭桥 / 烧林；T-11 刚把边目标定为 16 条，再扩会把一枚匠人的候选边推到 30+，放弃。
- 备选"每多一枚工坊再扩一格"：与"新信物没有 +2"的思路相悖，放弃。

### D6 生成权重改千分制，稀有度刻度同步放大

新表（‰）：出生区 360 / 160 / 120 / 64 / 56 / 40 + 50 × 4；公共区 216 / 108 / 72 / 108 / 108 / 108 + 70 × 4，均恰好合计 1000，是负责人"新四类各 5% / 7%、原六类按比例缩减"的精确表达。`RarityScale` 由 10000 提到 100000（千分制最小权重 40，保持与原先相当的整除精度）；`RelicEstimate` 的归一分母由 100 改为 1000（取自表的合计，不写死）。

- 备选"四舍五入回百分制"：出生区征召 6.4、军令 5.6 都变 6，失去原有先后；公共区 21.6 / 10.8 / 7.2 无法保持"四个 15 相等"，放弃。
- 备选"保持原表整数、只追加新四类的非百分制权重"：需要 ×18 之类的放大系数，表不可读，放弃。

### D7 新四类不升级、不消费升级抽签

`Draw` 中升级判定只对原六类执行；新四类强度恒为 1，`RelicContent` 构造拒绝新四类的强度 2。
备选"照常抽签但忽略结果"：保留每枚信物三次消费的形状，但 v2 表已整体改变，保形无收益，且"抽了却不用"的代码更易被误改，放弃。

### D8 对局内容集 v1 / v2：旧存档兼容与零变化基线

`MatchOptions.ContentSet`（缺省 v2），写存档、日志首部、批次配置。v1 = 原六种棋池、原百分制两表、徽记绑定原六种（显式列表，不再用 `Enum.GetValues`），与改动前逐步相同；v2 = 十 + 十。存档 / 日志缺字段按 v1（沿用 `ArtisanWeight` 缺字段回填的做法并留痕）。计分、控制、改造规则两者共用。

- 备选"存档写入完整信物分布"：只解决信物，不解决旧日志回放时的征募序列（征募表也变了），仍需要旧表；且改存档结构更大，放弃。
- 备选"不兼容，旧存档报错"：违背负责人"旧存档照常读取"，放弃。
- 附带收益：依赖走法的黄金哈希写死 v1 即可保持不变，行为回归与新内容分开归因。

### D9 枚举只在末尾追加，类型码与终端符号

`PieceType` 追加 `Bannerman, Chain, Sentry, Boundary`；`RelicType` 追加 `Encampment, Pincer, Relay, Workshop`（存档 JSON 可能按整数写枚举，插在中间会改变旧值含义）。盘面类型码 / 终端字母：旗手 `N`、铁链 `C`、哨兵 `T`、界碑 `K`（与 `B F L M S A` 不撞；中文快捷输入"旗 / 链 / 哨 / 碑"）。终端信物字母：连营 `y`、犄角 `j`、驿站 `r`、工坊 `w`。固定类型次序（征募表、预筛代表类型）= 枚举次序。

### D10 AI：估值初值、Growth 不动、校准口径标注

`RelicEstimate.ValueOf`：驿站 6、工坊 4、连营 3、犄角 3（原六类不变），标注未校准。连营 / 犄角取低值，因其计分效果已进入"即时势力增量"，信物维只反映"占到它"的一次性价值。v2 未揭示期望：出生区 5152‰ → 5，公共区 5692‰ → 5（v1 仍为 5 / 6）。"组合成长"维沿用原口径（不含新来源与计分信物），避免与势力增量双计。改造枚举（完整枚举与 K 预筛的匠人回退）把快照工坊标记传给 `LegalTargets`。`EvaluationWeights` 数值不变，`CalibrationStatus` / `CalibrationOf` 按 `ai-decision`「规则变更使校准失效」补注"more-pieces-relics 扩展计分后未重扫"，守门测试同步。

### D11 表现：四种新轮廓

`PieceSilhouette` 追加 `Pennant`（细高竖杆 + 杆顶方旗，全组最高）、`ChainLinks`（两枚竖立扁环相扣，中空）、`CrossedSpears`（两支长矛交叉成 X）、`Stele`（矮宽直立石碑，顶部圆弧）；`SilhouetteLanguage` 追加对应四值。易混对：铁链 vs 连珠（相扣环 vs 双球连杆）、界碑 vs 堡垒（矮宽单板 vs 高塔体块）、旗手 vs 匠人（竖直对称杆 + 旗面 vs 斜柄槌头）。人工检查清单与灰度截图放 `art/more-pieces/`。具体造型可在段 D 截图后由负责人改，规格只锁"语言 + 灰度可辨"。

### D12 遥测

日志首部加内容集；棋串记录加四项来源；快照记录加驿站来源与工坊标记；改造记录加"经工坊扩展"。分析器增第 12 项，v1 对局在该项单列"不适用"。旧日志缺字段按 v1 / 0 / 否。

## Risks / Trade-offs

- [类型槽压力] 十种类型对 5 个槽：面板更分散、整类弃牌更频繁 → 只报告冒烟中的弃牌次数与选择率，不改槽位。
- [出生区预算收敛率] 新四类稀有度（100000 / 50 = 2000）远高于徽记（277），出生区总稀有度方差变大，"生成未收敛"可能增多 → 段 B 用 10000 个种子只跑生成（不跑对局）报告收敛率；超出现有水平时提给负责人，不私调容差。
- [数值膨胀] 哨兵 / 铁链 / 旗手与倍增子叠乘，势力绝对值上升；精确整数运算已不封顶 → 不改公式，冒烟报告军势峰值。
- [预演与结算不一致] 首次揭示计分信物的那一批，预演偏低 → 规格写明且界面显示"将揭示"，是信息边界的有意代价。
- [接口变更] `LegalTargets` / `Reject` / `PowerCalculator.Compute` 签名变化，调用点多 → 旧签名保留为 `workshop: false` / "无计分信物"的重载，逐处替换并以既有测试守门。
- [AI 性能] 势力计算多四项来源与信物控制，工坊使每个匠人落点至多多 8 个格目标 → 冒烟记录小回合耗时，不做优化，除非超出现有两倍。
- [校准失效] 计分扩展后 ai-eye 校准不再严格成立 → 按规格标注口径，不扫档（负责人裁决）。

## Migration Plan

1. 枚举末尾追加；类型码 `N C T K` 只新增不改旧码，旧盘面串照常解析。
2. `MatchOptions.ContentSet` 缺省 v2；存档 / 日志 / 批次配置缺字段按 v1 并留痕（`ContentSetBackfilled`）。
3. 弃赛快照存档中的 `EffectSnapshot` 新增字段（驿站来源、工坊标记）缺省为 0 / 否。
4. 依赖走法的黄金哈希 / 期望：写死 v1 保持原值；需要 v2 基线的新测试另建，并在 tasks 里逐项归因。
5. 设计文档 v1.13 → v1.14；主规范在归档时由 delta 合并。
