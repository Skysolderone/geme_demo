## Decisions

### D1 停手阈值复核的条件与批次

- **条件**：
  - `siege-4p-base-v5`，4 名标准难度，内容集 V2，带入 0，小回合数截断 600，种子 1–20，每档 20 局，冒险概率取缺省。
  - 九维权重在配置文件里逐玩家写死为当前 `Default`。
  - `PassThreshold` 在配置文件里写死为 0 / 20 / 40 / 80，共 4 批 80 局。
- **管道**：一律用官方 `Siege.Sim run --config`，不用诊断跑局器；不传 `--difficulty` / `--players`（testing.md：这两项会重建玩家列表、丢掉权重）。每批跑完打开 `config.json` 逐项核对地图、内容集、阈值与每名玩家的权重，不一致即作废重跑。
- **忠实性对照**：阈值 80 / 0 两批与诊断 b06 / b07 同配置，逐局结果应一致（无提子 8/20、3/20；总提子 31、107）。不一致先归因再继续，不当作新数据。这项对照不增加局数。
- **备选**：直接复用 b06 / b07 的数据，只补跑 20 / 40 两档。
  - 否决理由：诊断跑局器不在 `siege.sln`，数据目录与配置格式也不同；四档走同一条管道，口径才统一。
  - 复用只省 40 局，而且逐局比对本身就是一次免费的管道一致性检查。

### D2 停手阈值的选档准则（ai-eye D6 在四档、20 局下的精确化）

按顺序：

1. **截断过滤**：截断率 ≤ 5%（20 局中 ≤ 1 局）的档进入下一步。四档都不达标则停下报告，不再选档。
2. **无提子带**：
   - 取整局无提子局数最少的档，记其比例 p_min = k_min / 20。
   - 带宽 SE = √(p_min × (1 − p_min) / 20)，比例 ≤ p_min + SE 的档都进带。
   - p_min = 0 时 SE = 0，带宽退化为严格并列（与 ai-eye R24 的"并列带宽约 1 个标准误"同口径）。
3. **结束大回合**：带内按"已终局局的平均结束大回合到区间 [7, 10] 的距离"排序（落在区间内距离为 0）。截断局不计入平均。
4. **离现值最近**：距离仍并列（例如都在 7–10 内），取离现值 80 最近者。80 本身在带内且距离并列时即维持 80。

- 第 3 大回合领先者胜率、总提子、Pass 率只记录，不参与选档（缺省表的 ai-eye 口径不变，见 D11）。
- **备选**：沿用 ai-eye 的 5–6 档双向扫档。
  - 否决理由：裁决把档位定为 0 / 20 / 40 / 80。
  - 代价：80 在档位上界，80 以上没有 V2 数据；V1 的 160 档无提子陡升到 73.5%，只作参照（见 Risks）。

### D3 阈值变化时简单、专家两档的冒烟

阈值对四档难度共用（ai-eye R1），`ai-decision`「难度分级」也要求停手阈值对全部难度生效。评估如下：

- **简单难度对阈值最敏感**：它只有三维，单枚落点的边际提升小。ai-eye R26 的教训是，阈值一高就一子不落；阈值降低则落子更多，多人近循环的机会也更多（诊断 Q3）。
- **专家的停手口径与高难相同**（`ai-decision`「前瞻中的停手口径」），Pass 由高难候选生成决定。专家冒烟同时覆盖了高难的停手行为，所以高难不单跑。

结论：

- **选定值仍为 80 时，不跑冒烟**。四档的阈值预设不变，走法逐步不变，由「三档旧难度逐步不变」的黄金值守门。
- **选定值不是 80 时，各跑 20 局**（v5、V2、种子 1–20，带入 0）：
  - 简单 × 4，对照诊断 b08（阈值 80：截断 0/20，最长 44 大回合）；
  - 1 专家 + 3 标准，对照 `sim-out/expert-lookahead/smoke20/`（阈值 80：截断 0）。
- **"不回退"的判据**：截断 ≤ 1/20；简单难度不出现"第 1 大回合全员一子不落即终局"。
- **回退时**：停下报告，交负责人裁决，不调阈值、不给简单难度单配阈值。
- 局数上限为 +40 局。

### D4 地图覆盖表放在 AI 层，按地图标识登记

在 `Siege.Core/Ai` 里、`EvaluationWeights.Default` 旁边，新增一张只读登记表"地图标识 → 整表权重"，以及唯一的解析函数"按地图标识取权重"：登记了就返回覆盖，否则返回 `Default`。另配一个按地图标识取覆盖校准口径的函数，和 `CalibrationOf` 并列。

- **键**：用 `MapData.Id`，也就是日志首部记录的地图标识。
  - 内置 2 人图的标识是 `siege-2p-base-v1`。
  - 生成图（`gen:*`）、边疆图、3 人图、v5 都不登记。
- **覆盖值的写法**：写成"缺省表 + 显式差异"，例如 `Default with { Eye = …, EnemyLoss = … }`。这样没被覆盖的维度跟随缺省表，差异一眼可见。
- **备选**：
  - (a) 写进地图 JSON 或 `MapData`：裁决明确否决。覆盖是 AI 配置而不是规则，写进地图会让地图层知道 AI。
  - (b) 在 `MapCatalog` 的内置图表加一列：否决。`MapCatalog` 只负责"标识 → 地图"的解析（frontier-map D5），加一列就把地图目录和 AI 耦合了；而且地图文件路径载入的图不走那张表。
  - (c) 放进 `AiSearchConfig.ForMap`：否决。`AiSearchConfig` 管的是搜索参数（N / M / K / 阈值 / W），权重是另一份记录；混在一起，日志首部的 `Search` 字段语义会变。
  - (d) 放进 `HeuristicTurnController` 的 `weights ?? Default` 回落：否决，理由见 D6。
- **边界**：`.trellis/spec/core/boundaries.md` 要求 Godot 只引用 Core / Presentation。登记表放在 Core，三个入口才能共用。

### D5 优先级与"整表"语义

优先级从高到低：

1. **显式权重**：配置文件 `Players[].Weights`，或回放时日志首部记录的权重。
2. **地图覆盖**：该局地图在登记表里有条目。
3. **缺省表** `EvaluationWeights.Default`。

- **整表生效**：显式权重是一整张表，优先时整张原样生效，不与覆盖逐维合并。扫档与复现最常见的需求是"这张表就是全部"；逐维合并会让同一份配置文件的效果随覆盖表变化，破坏"配置记录即实际口径"（simulation-harness「批量跑局」）。
- **命令行重建玩家列表**：给了 `--difficulty` / `--players` 时，玩家列表被重建，配置文件里的权重会丢掉，此后按地图覆盖、再按缺省表取值。这是既有行为，testing.md 已记为坑；本 change 只在规格与用法说明里写明，不改。
- **备选**：地图覆盖高于显式权重。否决：扫档要在 2 人图上显式试 Eye 100 / 50，覆盖若优先，扫档本身就做不了。

### D6 落成点：入口层解析，AI 层回落不变

| 入口 | 取权重的方式 |
|---|---|
| 批量跑局（新局） | `RunConfig.ResolvedFor(map)` 对 `Weights == null` 的玩家，**仅当该地图有覆盖登记时**落成 `Weights = 覆盖表`。于是批次 `config.json` 与日志首部如实记录实际生效的权重，与 `PassThreshold` 落成是同一先例 |
| 批量跑局（回放） | 不经 `ResolvedFor`：首部有权重就按首部；首部权重为 `null` 即旧日志，按 `Default` 重建，**不套覆盖** |
| 终端 `play` | `weights ?? 按地图取权重(map.Id)` |
| Godot | 建 AI 时传入 `按地图取权重(match.Map.Id)`，`MatchSession` 签名不变 |

- **为什么 AI 层的 `?? Default` 回落不能改成按地图取**：旧的 2 人图日志首部权重为 `null`，回放时 AI 会改按新覆盖决策，中途分歧。
- **为什么只对有登记的地图落成**：v5 / 3 人图 / 边疆图 / 生成图的首部与 `config.json` 逐字节不变，既有黄金哈希不动。
- **每局换图的批次**：`MatchSession.Create` 对每局的实际地图各调一次 `ResolvedFor`。生成图不登记，所以不落成。批次 `config.json` 按批次起始地图解析，而生成图同样不登记，因此一致。
- **测试接缝** `MatchSession.ForMatch` 绕过 `ResolvedFor`，是有意保留的：脚本测试自己写死权重。它不是入口。
- **诊断跑局器** `research/diag/` 不在 `siege.sln`，不改。

### D7 覆盖作用于全部难度

- 权重表本来就不分难度，`Default` 也是四档共用。覆盖沿用这一点：简单难度只读其中三维（PowerGain / EnemyLoss / Eye），专家与前瞻中的模拟对手用专家本人的权重（expert-lookahead 裁决 ⑤）。覆盖经同一条路径到达这些地方，不另做处理。
- **备选**：覆盖只作用于标准及以上。否决：要引入"按难度 × 地图"的二维表，而扫档只在标准难度上做，其余难度没有数据，二维表也没有依据。
- **遗留风险**：覆盖会改变 2 人图上简单难度的 Eye 与 EnemyLoss，见 Open Questions 1。

### D8 覆盖只管评价权重，不管停手阈值与搜索参数

- 阈值是全局的，四档共用；2 人图扫档就在段 A 选定的阈值下做（裁决 2）。诊断 b01–b03 显示阈值对 2 人图几乎没有影响，按地图覆盖阈值没有收益。
- 候选格上限 K 仍按可落子格数自动取（`AiSearchConfig.DefaultCellLimitFor`），与覆盖无关。

### D9 2 人图扫档与选档准则

- **条件**：`siege-2p-base-v1`，2 名标准难度，内容集 V2，带入 0，截断 600，种子 1–20，每批 20 局，`PassThreshold` 写死为段 A 的选定值，权重逐玩家写死在配置文件里。
- **批次**（总数 ≤ 8）：

| # | Eye | EnemyLoss | 说明 |
|---|---|---|---|
| 1 | 200 | 8 | 基线（= 当前 `Default`） |
| 2 | 100 | 8 | 眼位单维 |
| 3 | 50 | 8 | 眼位单维（诊断 b09 在阈值 80 下为无提子 11/20、领先者 20/20） |
| 4 | 200 | 16 | 敌损单维 |
| 5 | 200 | 24 | 敌损单维 |
| 6 | e* | l* | 2 × 2 组合的第四角（条件触发） |
| 7–8 | 邻点 | 邻点 | 只在第 6 批优于两条单维时补（条件触发） |

- **2 × 2 组合的定义**：{Eye 200, e*} × {EnemyLoss 8, l*}。e* 是 Eye 100 / 50 中按下列准则较优的一档，l* 是 EnemyLoss 16 / 24 中较优的一档。四角里有三角已经跑过，只补 (e*, l*) 一批。
- **第 6 批的触发条件**：e* 与 l* 各自比基线的无提子比例至少低 1 个二项标准误（按基线比例计）。只有一维有效时不做组合。
- **第 7–8 批**：第 6 批按准则优于 e*、l* 两条单维时，最多再补两个邻点——另一档 Eye × l*，以及 e* × 另一档 EnemyLoss。
- **选档顺序**：
  1. 截断 ≤ 1/20。
  2. 整局无提子取最低档，带宽算法同 D2。
  3. **第 3 大回合领先者胜率 MUST NOT 为 20/20**：在带内剔除 20/20 的档。带内全部被剔除时，在剩余档（仍须满足第 1 条）里按第 2 条重新取带，再剔除，直到非空或候选耗尽。
  4. 已终局局的平均结束大回合离 [7, 10] 最近。
  5. 仍并列时，取与基线差异维数最少者，再取离基线最近者（先比 Eye 的相对变化，再比 EnemyLoss）。裁决没有给这一条，这里补出来，保证选档结果唯一。
- **候选耗尽**：没有任何档通过第 1、3 条时，停下报告，不登记覆盖。
- **选中基线时**：选中第 1 批，即覆盖值等于 `Default`，按 Open Questions 2 的缺省处理。
- **"第 3 大回合领先者"的口径**：与诊断 `research/summarize.py` 相同，即第 3 大回合结束时总势力唯一最高者；并列局不计入分母，报告里写明分母。
- **备选**：直接照搬诊断 b09 的 Eye 50。否决：它造成 20/20 全胜，正是裁决第 3 条要排除的情形。

### D10 校准记录、守门与占位

- **段 B 第一步就登记 2 人图条目，取值暂等于 `Default`**。校准口径标注"占位：取值同缺省表，待 v2-recalibration 段 B 扫档"。这样：
  - 落成、优先级、回放、三入口的测试可以先红后绿；
  - 走法一子不变，与段 A 的阈值变化彼此隔离。
- **扫档选定后**：改为选定值，把占位口径换成正式记录："v2-recalibration 段 B：siege-2p-base-v1、2 名标准、内容集 V2、种子 1–20、每档 20 局、停手阈值 X；各档'截断 / 整局无提子 / 平均结束大回合 / R3 领先者胜'；数据目录"。
- **守门**：扩展 `默认评价权重的校准Tests`：
  - 钉住覆盖表的键集合（只有 `siege-2p-base-v1`）；
  - 钉住它与 `Default` 的每一维差异；
  - 断言校准口径文本里含地图、"种子 1–20"、"20 局"、"V2"与数据目录，且不含"占位"；
  - 断言源码里的注释与口径常量一致。
- **阈值守门** `默认停手阈值被改动`：改钉新值与新口径（"v2-recalibration""V2""种子 1–20""20 局""sim-out/v2-recalibration/pass-"，以及选定值在档位清单"0 / 20 / 40 / 80"里）。即使选定值仍为 80，口径文字也要改。

### D11 规格口径的调整

- **放宽 200 局要求**：`ai-decision`「默认评价权重的校准」原文要求"任一默认权重或默认停手阈值的变更 MUST 附……不少于 200 局的前后对照"。改为"不少于 200 局，或经负责人裁决的更小规模；小规模时校准记录 MUST 写明局数，并注明小样本、胜率类只看方向"。
- **四档不算完整双向扫档**：原文要求四项"各自双向扫档不少于 5 档"。这是 ai-eye 那次校准的历史要求，照原样保留；V2 复核按裁决只扫四档，在规格里写明它不算完整双向扫档。
- **"领先者胜率不作否决"的适用范围**：ai-eye 这一句限定为只适用于缺省表的选档；地图覆盖的选档准则写在 ADDED「地图专属评价权重覆盖」里，其中领先者胜率是否决项。两条互不覆盖。
- **截断守门的 Scenario 拆成两条**：
  - 默认套件版：种子 1–20，≤ 1 局，这条会真跑；
  - 慢测试版：种子 1–200，≤ 10 局，标明本 change 不跑、阈值变更后未复核（裁决 6）。

### D12 依赖走法的既有测试（testing.md「依赖 AI 实际怎么走的断言要把权重写死」）

- **审计**：落地新阈值或覆盖值之前，先找出读缺省阈值或缺省权重、并且断言依赖走法的测试。至少包括：
  - `难度分级Tests.三档旧难度逐步不变` 与预设断言；
  - `候选格上限Tests` 的黄金哈希；
  - `默认评价权重的校准Tests.校准后截断率达标`（这条本来就该跟随缺省值，不在钉死之列）；
  - 终端脚本测试；
  - 以 `TwoPlayerBaseMap` 为夹具跑 AI 的测试，以及 small-maps 冒烟相关测试。
- **处理**：
  - 保真度测试把阈值写死为 80、权重写死为改动前的值，断言与黄金值一字不改；
  - 钉校准值本身的守门测试跟随新值；
  - 不重生黄金值，不换种子凑绿。

## 接口契约

| 方向 | 对象 | 契约 |
|---|---|---|
| 输入 | `MapData.Id` | 覆盖表的键。与日志首部记录的地图标识相同 |
| 输出 → 批量跑局 | `RunConfig.ResolvedFor(map)` | 有覆盖的地图，把未显式配置的玩家落成覆盖表；其余地图原样返回。幂等 |
| 输出 → 日志 / 配置记录 | `Header.Config.Players[].Weights`、`config.json` | 有覆盖的地图写实际权重；其余地图与改动前逐字节相同 |
| 输入 ← 回放 | 首部 `Players[].Weights` | 有值即按值重建；`null` 按 `Default` 重建，不套覆盖 |
| 输出 → 终端 / Godot | 按地图取权重的唯一实现 | 入口未给权重时调用，结果交 `HeuristicAi.Create` |
| 输出 → 专家前瞻 | 专家本人权重 | 覆盖经专家本人权重流入模拟对手，前瞻代码不改 |
| 输出 → 设计文档 | §15.2 / §3.3 / §16 | 阈值值与口径、覆盖一段、V1 标注、已知问题改写 |

## Risks / Trade-offs

- **[20 局样本分辨率低]** 1 个二项标准误约为 2 局（p = 0.4 时约 2.2 局），四档可能大面积并列，最终落在"离 80 最近"。→ 这是裁决接受的代价。记录里写明小样本，胜率类只看方向；不补局数。
- **[阈值最优点可能在 80 以上]** 四档的上界就是现值 80，80 以上没有 V2 数据。V1 下 80 → 160 无提子从 32% 陡升到 73.5%，方向上不支持提高。→ 选定 80 时如实写明"上界未扫"，不补档。
- **[新阈值影响全部地图]** 阈值全局共用，边疆图与生成图不再复核（200 局复核本就延后）。→ 在 §15.2 口径里写明只在 v5 上复核；D3 的简单 / 专家冒烟只覆盖 v5。
- **[覆盖按标识键]** 地图文件可以自带与内置图同名的 `id`，这时会被套上覆盖。→ 首部有 `MapDigest`，事后可以核对。本 change 不按摘要做键：摘要会随地图的任何修改变化，维护成本高，而地图文件复用内置标识本来就是误用。写进 §15.2 的覆盖一段。
- **[覆盖改变 2 人图上的简单难度]** 简单难度的三维里有两维（Eye、EnemyLoss）会被覆盖改动，而扫档只做了标准难度。→ Open Questions 1。
- **[诊断的 Eye 50 全胜现象可能在组合档复现]** → 选档第 3 条是硬否决；全部候选被否决时不登记覆盖、停下报告。
- **[走法测试大面积变红]** → 按 D12 先审计、再钉值；不重生黄金值。

## Migration Plan

1. **段 A**（阈值）：扫档 → 选档 → 按需冒烟 → 审计并钉住走法测试 → 替换 `DefaultPassThreshold` 与口径 → 守门转绿 → 默认套件回归。
2. **段 B**（2 人图覆盖）：
   - 先写机制测试（先红），以占位值（= `Default`）登记 2 人图，三入口与落成转绿，走法不变；
   - 在段 A 选定的阈值下扫档、选档；
   - 审计并钉住 2 人图的走法测试，写入选定值与校准记录，守门转绿。
   - 段 B 的机制部分可以与段 A 并行；扫档必须等段 A 的阈值落地。
3. **段 C**：设计文档 v1.16 → v1.17，全量回归（不跑 Slow），`openspec validate v2-recalibration --strict`。
4. **回滚**：
   - 阈值：改回 80，口径恢复为 ai-eye 的文字；
   - 覆盖：删掉 2 人图条目，机制保留、效果为零；
   - 旧日志的回放不受任何一步影响。
