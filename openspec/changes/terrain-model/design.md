## Context

现行地形是二值的：格子要么可落子，要么是障碍；障碍唯一的规则作用是封住气。四邻接对所有规则一视同仁——连接、气、覆盖、围杀走的是同一条邻接。这正是"像围棋"的根源：地形没有任何东西能被规则读到，全盘只剩"落子 → 断气 → 提子 → 数领地"一件事。

用户在 2026-09-16 用 27 条编号裁决把改造定了下来（见文末裁决记录），并明确**保留气与提子**。改造分三轮：

| 轮 | change | 内容 |
|---|---|---|
| ① 本轮 | `terrain-model` | 地形进入规则：格属性 + 边属性，导出气边与覆盖关系；v3 地图；Godot 地形渲染。**计分不动** |
| ② | `scoring-sites` | 据点计分取代领地；相对高度军势加值 |
| ③ | `artisan-terrain-edit` | 第六种棋子「匠人」：搭桥 / 立栅 / 烧林；设施纳入同形禁则 |

本轮只动第一行。计分照旧的后果是已知的：13×13 且仍按领地计分，对局会比 v2 长。这是**预期结果**，本轮不修，也不据此调参——Safety=20 那一课的教训是别在没归因的数字上盖楼。

## Goals / Non-Goals

**Goals:**
- 地形属性能被规则读到：高度差决定两格通不通；深水、栅栏切断气；林地、崖壁（单向）、一格宽深水改变覆盖。
- 气边与覆盖关系各自只有一处实现，都在几何四邻之上导出，实时重算不缓存。
- v3 基准图：13×13、C4 旋转对称、四家高台出生、中央低地水系、三层高度 / 深水 / 桥 / 栅栏 / 林地齐全，通过全部静态校验。
- Godot 层能看出地形：分层地砖、崖壁侧面、水、桥、栅栏边、林地；不同高度的格能被拾取；13 列坐标标注正确。
- 地形数据结构为第三轮"设施可变"留好接口：桥与栅栏是设施，与静态地表分开存。

**Non-Goals:**
- 据点、领地退役、高地军势加值、匠人、任何对局内地形改造。
- AI 权重、保护期、部署上限、倍率、终局条件。
- 浅滩、开凿、第 4 层高度、2 人 / 3 人地图。

## Decisions

**D-A：格属性 + 边属性，邻接由属性实时导出（裁决 D1、F1）。**
备选「只换皮」（地形只在表现层）否决：三条围棋味一条也解决不了。备选「加属性但不动邻接」否决：高度、河、桥全部退化成加值，地形永远影响不了"围"。
格属性四项：高度 0/1/2、地表（草地 / 土路 / 林地 / 深水）、障碍、预置桥。边属性一项：栅栏，只存在两个几何相邻格之间，两侧仍可落子。栅栏做成边而不是格，是因为做成格会吃掉一整格空间、立多了又回到"填满盘面"；做成"可落子的格设施"则站上去的棋子永远零气。

**D-B：几何四邻不变，之上导出两套关系（裁决 D2、D6、D7 的必然结果）。**
栅栏"挡气不挡覆盖"与林地"挡覆盖不挡气"互为镜像，等于宣告气与覆盖不再走同一条边。于是 `Adjacency` 保留几何邻居枚举（唯一实现不变），新增两个导出：
- **气边**（对称）：两格都可落子（非障碍、非未架桥深水）∧ |Δh| ≤ 1 ∧ 无栅栏。
- **覆盖关系**（可不对称）：t 可落子且非林地 ∧ (h_t − h_s) ≤ 1；若 t 是未架桥深水，则看沿同方向的下一格 u，u 满足同样条件即覆盖 u（只穿一格水）。栅栏不影响。
"生存"与"影响力"从此是两个可以分别操作的维度，这是本轮对决策空间最深的一刀。

**D-C：高度差决定连通，三层（裁决 D2 = B、D3）。**
备选 A「高度只加值」否决：观感立体、玩法不立体。备选 C「高地不被低地围」否决：围杀从对称变非对称，§6 结算与 AI 全部重做，玩家无法心算一手棋的后果。三层是最小可同时表达缓坡（0↔1）与崖壁（0↔2）的层数。高度对分数的影响（相对高度 +1，进位置加值段）留给第二轮。

**D-D：深水整格、桥是设施、覆盖穿一格水（裁决 D4、D5、E4 修正）。**
深水语义与障碍相同（不可落子、断气），差别只在覆盖可以穿过一格宽的水。这样一格宽的小河能隔岸争信物（第二轮起争据点），宽河不行；桥有了"打通路"之外的第二个理由。桥标在深水格上，架桥后该格按普通格处理，高度由地图给定——为第三轮的"搭桥"留接口：第三轮只需允许运行时给深水格加桥。

**D-E：v3 地图——13×13、C4 对称、四家高台、中央低地水系（裁决 D18、D19、E2）。**
沿用 11×11 否决：85 格里塞三层高度 + 水系 + 12 据点 + 14 信物，每种地形只能给几格，读不出地貌。15×15 否决：领地计分下对局明显拉长。D2 镜像对称否决：立体地貌做双轴镜像会很假，山脊与河道走向被强行折叠；C4 旋转仍保证四家完全对等，河流可以是风车形。四家出生在 h=2、背后是崖壁：开局安全由地形提供而非规则禁止，保护期规则未来可能整条删掉（裁决默认 5：三轮都不动，基线后再议）。
距离容差仍为 1，但最短路改沿气边算——崖壁挡住的路不算路。

**D-F：取消"障碍占比 25%–35%"校验，新增桥 / 栅栏合法性与出生区连通性校验。**
深水与崖壁同样在压缩空间，只数障碍已无意义；密度由可落子格区间（95–110）把控。新增：桥必须在深水上；栅栏必须在相邻格之间；每个出生区必须有气边通路到中央入口——否则高台出生区可能被崖壁完全封死，对局无法开始。

**D-G：盘面层两种读法不再恒等，差集要能由地形解释（`merge-board-layer` 的前提被本轮推翻）。**
原合并理由是"覆盖 = 气"，本轮把两者拆开了。仍合为一层（都是同一批棋子对周边空格的作用），但把"两集合恒等"的断言改为"平地区域恒等 + 差集可由崖壁 / 栅栏 / 深水 / 林地解释"。

**D-H：Godot 层在本轮而非后置。**
不做的话本轮结束游戏可玩但看不出地形，等于白做。渲染：高度 → 地砖层数与崖壁侧面；深水、桥、林地 → 地表材质 / 造型；栅栏 → 沿格边的低多边形木栅。`BoardGeometry.Center` 要带高度；`TryPick` 要能拾取不同高度的格（按射线与各层平面求交，取最近的命中格）。坐标标注在边缘格高度不同时仍要可读——统一放在棋盘外一圈的 h=0 平面上。

## 接口契约

**输入：** 地图静态数据（格属性、栅栏边、出生区、信物格、中央入口、咽喉）。

**输出：**

| 输出 | 变化 | 消费者 |
|---|---|---|
| `MapData` | 新增每格高度 / 地表 / 桥、栅栏边集合；`Obstacles` 保留 | 校验、棋盘、表现层、JSON |
| `Adjacency.Neighbors` | 几何邻居，不变 | 两个导出关系、表现层 |
| `Adjacency` 新增气边 / 覆盖关系导出 | 唯一实现 | 棋串、气、围杀、`CoverageMap`、AI、校验器 |
| `GameBoard` | 落子合法性加"非未架桥深水"；棋串与气改走气边 | 预演、结算、AI |
| `CoverageMap` | 改走覆盖关系 | 空格归属、唯一覆盖、信物发现 |
| `MapValidator` | 区间改、障碍占比删、桥 / 栅栏 / 连通性加、距离与口袋沿气边 | 地图加载 |
| `FourPlayerBaseMap` | v3，C4 对称生成 | 全部对局、跑局、界面 |
| `maps/siege-4p-base-v3.json` | 导出物；v2 保留为历史存档（不再能加载） | 设计师维护 |
| `Coord.ColumnLetters` | 不变（已支持到 25 列）；所有写死 11 的地方改读宽度 | 日志、标注 |
| `Siege.Presentation` 盘面层视图模型 | 归属 / 棋串读法各自按新关系取集合 | Godot HUD |
| `BoardGeometry` | `Center` 带高度；`TryPick` 分层拾取；标注锚点在外圈 | `BoardView`、`Hud` |

**与后续 change 的接口：**
- 第二轮读格高度算相对高度加值；据点作为新的静态标记加进 `MapData`，不动本轮结构。
- 第三轮需要：运行时给深水格加桥、给边加栅栏、把林地改草地。本轮把"桥"与"栅栏"存为设施而非地表本身，第三轮只需开放写入口并把设施纳入盘面快照。

## Risks / Trade-offs

- **[气的来源变少，围杀过早、过容易]** 崖壁 + 深水 + 栅栏都在削气 → 本轮基线看首次提子大回合与"整局无提子局"比例；若首次冲突早于第 3 大回合，减少 v3 的栅栏与一格宽水段，而不是改规则。
- **[对局变长]** 13×13 + 领地计分 → 已知、预期、本轮不修；写进基线报告的口径说明。
- **[13×13 下 AI 变慢或评估失真]** AI 只随拓扑自动适应，不改权重 → 跑 200 局看每步耗时与 Pass 率，只记录不调。
- **[C4 对称 + 容差 1 调不出来]** → 以校验器为准绳迭代；实在不行用地图数据的显式放宽字段并写明理由。
- **[覆盖关系不对称让"唯一覆盖"出现反直觉结果]** 高台棋子控制山下信物、山下棋子无法反制 → 这是设计意图（E5），但要在盘面层归属读法里能看出来源；基线看高台信物的控制权分布是否一边倒。
- **[大量既有测试写死 11×11 / 85 / 36 / D2 / 两读法恒等]** → 换坐标重构用例，不改期望值；恒等断言按 D-G 改写；逐条列入提交信息。
- **[`src/godot/` 不在 sln 里，守门测试对它隐身]** → 补源码级扫描：Godot 层不得自己算邻接或地形过滤，只消费 `Siege.Presentation` 的视图模型与 `BoardGeometry`。
- **[分层拾取误点]** 高台边缘的射线可能先命中低处格 → 拾取取最近命中；自动演示脚本（`--auto-demo`）要在 v3 上跑通。

## Migration Plan

1. `MapData` / `MapFile` 加格属性与栅栏边；`Adjacency` 加两个导出关系（先 TDD 出 `terrain` 规格的全部算例）。
2. `GameBoard` 棋串 / 气 / 落子合法性改走气边；`CoverageMap` 改走覆盖关系；扫掉所有直接判断 `Terrain.Obstacle` 或手写邻居遍历的地方。
3. `MapValidator` 按新规则改；坐标记法泛化。
4. v3 地图设计与生成（C4 轨道展开），校验通过，导出 JSON；旧 v2 JSON 保留。
5. `Siege.Presentation` 盘面层视图模型；Godot 渲染、拾取、标注。
6. 改写既有测试；设计文档 §3 / §7 / §14.2 / §20 与变更记录。
7. 200 局回归，只记录不调参；报告口径写明"13×13 + 领地计分，对局变长为预期"。

## Open Questions（建议裁决）

1. **v3 出生区形状**：高台上 13 格的具体轮廓。建议：每区一块 h=2 平台（约 3×5 减角），一侧通过 2–3 格 h=1 缓坡下到中央，其余边缘直接落到 h=0（崖壁）。由实现方按校验器迭代，不再回问。
2. **土路的位置**：只作视觉，建议沿四条缓坡到中央的主路铺设，帮玩家读出"下山的路"。
3. **信物揭示补占据触发**：现行 `relic-control` 只写"首次进入覆盖范围时揭示"，林地不接收覆盖，林地上的信物若不补"占据即揭示"会永远揭不开。建议补为"首次被覆盖**或被占据**时揭示"，本轮一并写进 `relic-control` 增量。
