# 设计与裁决记录：board-coordinates

## 1. 背景

`board-topology`「坐标记法」把围棋记法定为权威标识，并要求"面向人的输出 MUST 使用该记法"。日志、错误信息、终端版 play 都照做了，3D 界面没有。结果是界面成了唯一无法指称格子的地方：玩家看到一个格子，无法与日志、规格、或旁人的口头描述对上。

## 2. 裁决

### D1：标注由 `BoardGeometry` 推出，不在视图层另算

`BoardGeometry` 已经是 `Coord` ↔ 3D 的唯一映射。标注的位置与文本都从它取——列字母来自 `Coord` 的既有记法转换，位置来自格心加一个固定的边距偏移。

在 `BoardView` 里另写一份"第 n 个格子对应第 n 个字母"的循环，是把跳过 `I` 这条规则复制了第二份。`I` 迟早会漏掉一次，而那时界面与日志会指向不同的格子——这类错误极难发现，因为两边各自看起来都对。

### D2：标注正对相机，不随棋盘翻转

标注是给人读的文字，不是棋盘上的物件。相机转到棋盘背面时，若标注跟着翻，玩家读到的是镜像字符。做法是让标注始终面向相机（billboard），位置仍锚在棋盘四边。

代价是相机在背面时"列字母在上下边"的视觉关系会左右对调。这是可接受的：字母仍在上下边、数字仍在左右边，读出来的坐标仍然正确。

### D3：验证靠人工看图，并写清检查清单

这一项的正确性是视觉性的：不遮挡、不倒置、不镜像、与日志一致。单元测试能覆盖的只有"文本序列跳过 I"这一条纯逻辑，其余必须人工核对截图。

因此本 change MUST 产出一份检查清单与对应截图（正面、旋转 180°、边缘格有棋子三种情形），不能只报"实现完成"。参考 `art/style-exploration/README.md` 既有的人工检查清单写法。

## 3. 不做的事

- 不做坐标点击定位、跳转、搜索。
- 不改相机控制与棋盘朝向。
- 不为尚未制作的 2 人 / 3 人地图适配。

## 2.1 D2 修订（实现后回填）：标注平铺在棋盘平面，不用 billboard

初稿的 D2 要标注始终面向相机（billboard）。实现时发现两件事，因此改为平铺。

**其一，Godot 的 Label3D 在 billboard 下渲染的是文字面的背面，四边标注全部左右镜像。** `BillboardModeEnum.Enabled` 与 `FixedY` 都如此：billboard 让节点的 −Z 轴指向相机，而 Label3D 的文字画在 +Z 面，于是朝向相机的是背面。数字里的 `1`、`0`、`8` 字形左右对称，看不出异常，`2`、`3`、`5`、`7` 和字母 `B`、`K`、`L` 才暴露出来——这类缺陷靠"看一眼截图"很容易漏掉，必须逐字辨认。

**其二，对局相机是固定的**（`BoardView` 里 `Position = (0, 9.0, 10.4)`、`Fov = 54`，`InputBindings` 没有任何相机旋转绑定），初稿设想的"相机转到背面"根本不会发生。为一个不存在的情形付出镜像的代价，不划算。

改为绕 X 轴 −90° 平铺在棋盘平面上，与地砖共面，像围棋棋盘边缘印刷的坐标。文字面朝上，固定俯视相机下正向可读。`FixedSize = true` 保证近边的 `A` 与远边的 `A` 一样大——坐标是读数不是景物，不该有近大远小。

规格中「相机旋转时保持正对玩家」相应改为「平铺在棋盘平面，在对局相机下正向可读」，Scenario「旋转后仍可读」改为「不镜像不倒置」。

**将来若引入相机旋转**：平铺的标注会随视角倒转，届时要么给标注加随相机翻转的朝向逻辑，要么改用预渲染纹理的 Sprite3D 绕开 Label3D 的背面问题。不要简单地把 billboard 打开——那会直接回到镜像。
