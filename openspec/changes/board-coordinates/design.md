# 设计与裁决记录：board-coordinates

## 1. 背景

`board-topology`「坐标记法」把围棋记法定为权威标识，并要求"面向人的输出 MUST 使用该记法"。日志、错误信息、终端版 play 都照做了，3D 界面没有。结果是界面成了唯一无法指称格子的地方：玩家看到一个格子，无法与日志、规格、或旁人的口头描述对上。

## 2. 裁决

### D1：标注由 `BoardGeometry` 推出，不在视图层另算

`BoardGeometry` 已经是 `Coord` ↔ 3D 的唯一映射。标注的位置与文本都从它取——列字母来自 `Coord` 的既有记法转换，位置来自格心加一个固定的边距偏移。

在 `BoardView` 里另写一份"第 n 个格子对应第 n 个字母"的循环，是把跳过 `I` 这条规则复制了第二份。`I` 迟早会漏掉一次，而那时界面与日志会指向不同的格子——这类错误极难发现，因为两边各自看起来都对。

### D2：标注正对相机，不随棋盘翻转

标注是给人读的文字，不是棋盘上的物件。相机转到棋盘背面时，若标注跟着翻，玩家读到的是镜像字符。做法是让标注始终面向相机（billboard），位置仍锚在棋盘四边。

代价是相机在背面时"列字母在上下边"的视觉关系会左右对调。这是可接受的：字母仍在上下边、数字仍在左右边，读出来的坐标仍然正确。

### D3：验证靠人工看图，并写清检查清单

这一项的正确性是视觉性的：不遮挡、不倒置、不镜像、与日志一致。单元测试能覆盖的只有"文本序列跳过 I"这一条纯逻辑，其余必须人工核对截图。

因此本 change MUST 产出一份检查清单与对应截图（正面、旋转 180°、边缘格有棋子三种情形），不能只报"实现完成"。参考 `art/style-exploration/README.md` 既有的人工检查清单写法。

## 3. 不做的事

- 不做坐标点击定位、跳转、搜索。
- 不改相机控制与棋盘朝向。
- 不为尚未制作的 2 人 / 3 人地图适配。
