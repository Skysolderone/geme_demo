## 1. 段 A——九维结构与活形中性（Siege.Core/Ai）

- [x] 1.1 `EvaluationDimension` / `EvaluationWeights` / `EvaluationBreakdown` 扩为九维（`Eye`、`Threat`），新两维权重先取 0。验证：权重为 0 时，种子 1–20 的 4 AI 对局与改动前逐步相同（决策序列比对）；分解值为九项；日志首部写入 AI 评价版本。
- [x] 1.2 先写测试再实现「眼位」：原始值 = 己方眼值之和（每个眼空间只计一次）+ 己方已确定活形棋串数 × 3，取前后增量；数据只来自 `life-shape` 查询。测试：`ai-decision`「做出第二个眼获得眼位正贡献」（= 4）、「自填眼位不得分」、直三点中间（眼值 1 → 2，未成活形时增量 1；成活形时 +3）。验证：全绿；变异（改成绝对值时"自填眼位"应红）。
- [x] 1.3 先写测试再实现「威胁」：敌方非已确定活形、气数 ≤ 3 的棋串棋子总数的增量。测试：「叫吃获得威胁正贡献」（= +5）、「不攻打活棋」（= 0）。验证：全绿；变异（不排除活形敌串应红）。
- [x] 1.4 `GroupSafety`：删除自带的眼点循环，`TwoEyePotential = min(2, 眼值之和)` 取自活形查询；已确定活形棋串的 `Score` 取公式上界常数。测试：「已确定活形的评价中性」三个 Scenario。验证：全绿；守门（源码扫描）——`Siege.Core/Ai` 下不再出现"邻格全为己方棋子"式的眼判定；变异（活棋补气仍加分应红）。
- [x] 1.5 `EnemyLoss` 的潜在价值（若有）排除敌方已确定活形棋串。验证：单元测试；既有 `ai-decision` 测试全绿。

## 2. 段 B——活形硬约束与停手阈值

- [x] 2.1 先写测试：「活形硬约束」六个 Scenario（不拆活形；不填单格眼；点直三中间不淘汰；为提子填眼放行；改造拆活形淘汰；全部淘汰则 Pass）+「难度分级」的"简单难度也不拆自己的活形"。验证：先红。
- [x] 2.2 在单点排序与贪心组批两处加候选过滤（预演合法之后、打分之前）；被淘汰的候选不进入 `LastPointRanking`。验证：2.1 全绿；变异（改成扣分而非过滤时"不进入排序"的断言应红；去掉"无提子"条件时"为提子填眼放行"应红）。
- [x] 2.3 先写测试再实现「停手阈值」：`AiSearchConfig.PassThreshold`，保留条件 `next − current > PassThreshold`；初值 `2 × PowerGain 权重`，带未校准标注。测试：七个 Scenario（0 / 15 / 20 / 21 边界；无保留则 Pass；阈值 0 时与严格提高逐步相同；进入日志首部）。验证：全绿；`Validated()` 拒绝负值。
- [x] 2.4 阈值写入批次配置记录与日志首部；回放按首部重建，缺字段按 0。严格 CLI 新增 `--pass-threshold`。验证：往返测试；旧日志回放测试保持绿。
- [x] 2.5 难度：简单难度只用两维，但同样走硬约束与阈值；眼位 / 威胁从标准难度起生效。验证：「难度分级」三个 Scenario 全绿；「高难度不越权」的既有守门保持绿。
