## Context

现有 AI（`Siege.Core/Ai`）的流程是：对每个（合法格 × 持有类型 × 改造选项）做真实预演并打分 → 按分排序取前 N → 贪心组批（总分**严格提高**才保留一枚）→ 多个扰动次序各出一个候选批次 → 确定性择优。评价是七维加权和，每维都是"结算后 − 结算前"的增量。它在结构上已经等价于基准文档的"单点评分 + 贪心组合"，且更强（真实预演每种类型、批次级评价、难度分级、确定性并列打破）。

缺的是基准文档 II §4.4–§4.7 里四件**规则级**的事：眼位增量、活形硬约束、对敌威胁、停手阈值。`GroupSafety` 目前用"单点气"近似两眼潜力，对已活的棋仍计危险、仍奖励补气——规范「启发式评价维度」里记录的"安全权重与收敛性非单调"正是这个原因。

`life-shape` 已提供规则级活形查询（可作用于预演副本）。

## Goals / Non-Goals

**Goals**
- AI 会主动做活、不拆自己的活形、不攻打提不动的活棋、无利可图时停手。
- 4 人同强度 AI 对局在没有任何轮数上限的规则下收敛：`turn_limit` 截断率 ≤ 5%。
- 眼判定全仓库只有 `life-shape` 一处。
- 全部默认权重有跑局依据，解除"未校准"标注。

**Non-Goals**
- 不重写架构、不做前瞻、不改征募评分、不调活形规则与地图规模。

## Decisions

### D1 新增两个维度，保持"全部为增量"

| 维度 | 原始值（对预演前后各算一次，取差） |
|---|---|
| 8. 眼位 `Eye` | 己方全部棋串的眼值之和（每个眼空间只计一次，不按相邻棋串重复计）+ 己方已确定活形棋串数 × 3 |
| 9. 威胁 `Threat` | 敌方**非**已确定活形、且气数 ≤ 危险气数（3）的棋串的棋子总数 |

- 眼位必须是增量：基准文档明确警告，用绝对值会让"自填眼位"（眼变棋子）也得分。现有 `BatchEvaluator` 的 before / after 结构天然满足。
- "活形数 × 3"沿用基准文档的系数，作为原始值的一部分；维度权重另行校准。
- 威胁用"危险气数 3"而不是围棋的打吃（1 气）：批次制下对手一回合能落 3 子，沿用 `GroupSafety.DangerLiberties` 的既有论证。已确定活形的敌串提不动，MUST 排除。
- 备选：把威胁并入 `EnemyLoss`——否决，两者量纲不同（已实现的损失 vs 潜在的损失），合并后无法单独扫档。

### D2 `Safety` 的活形中性

`GroupSafety.Score` 对已确定活形的己方棋串恒为一个常数（不随气数、分散气变化）；常数取该公式的上界，使"做活"在 `Safety` 上也是净收益，而做活之后任何补气都不再加分。敌方已确定活形棋串不进入 `EnemyLoss` 的潜在价值与 `Threat`。

两眼潜力 `TwoEyePotential` 改为 `min(2, 该棋串眼值之和)`，数据来自 `life-shape` 查询；`GroupSafety.Analyze` 内自带的眼点循环删除。

### D3 活形硬约束是候选过滤，不是扣分

在单点排序与贪心组批两处，预演合法之后、打分之前检查：本批次**无提子**，且（己方任一原已确定活形棋串在副本上不再是已确定活形，或任一落点是批次开始前己方的一个单格眼）→ 该候选直接丢弃。

- 只针对**单格眼**（对应基准文档的 `was_own_eye = is_eye(落点)`）：落进多格眼空间可能正是在做眼（直三点中间 → 两个单格眼），不能一刀切；填多格眼空间的无意义落子由停手阈值拦下（领地 −1、军势 +1，势力增量为 0）。

- 有提子时放行：为了吃子而填自己的眼可能是对的，交给打分。
- 对全部难度生效（含简单）：它不是"更聪明的评价"，而是"不做蠢事"的底线；简单难度若会拆自己的活形，对局无法收敛。
- 备选：基准文档的 −999 扣分——等价但污染分解值与日志，过滤更干净。

### D4 停手阈值

`AiSearchConfig` 增加 `PassThreshold`（非负整数，加权总分单位）。贪心组批的保留条件由 `next.Total > current.Total` 改为 `next.Total − current.Total > PassThreshold`。阈值为 0 时与现状逐步相同。

- 作用在"每新增一枚"的边际提升上，而不是整批总分：与基准文档"单点评分 ≤ 阈值不落"语义一致，也避免"前两枚很值、第三枚白送"的批次。
- 初值取 `2 × PowerGain 权重`（对应基准文档 `PASS_THRESHOLD = 2.0`、power 权重 1.0），标注未校准，随 D6 扫档定值。
- 阈值是 AI 配置，不是规则：写入批次配置记录与日志首部，回放按首部重建；旧日志缺该字段按 0 重建。

### D5 成本控制

眼位与活形中性都要在预演副本上跑活形分析。

- 廉价预筛（`frontier-map` 的候选格上限 K）阶段**不算**眼位与威胁，只用既有七维——预筛只为缩小候选，眼位价值高的落点通常同时有 `Safety` 信号；进入完整枚举的 ≤ K 格才算九维。K = 0（标准图）时全部候选算九维。
- 活形分析结果按盘面指纹缓存在单次决策内（同一批次的多个扰动次序会反复到达相同盘面）。缓存 MUST NOT 跨决策、MUST NOT 影响结果。
- 验收：标准图单次 AI 决策耗时中位数不超过本 change 之前的 2 倍；边疆图不超过 1.5 倍。超出则先做缓存，再考虑按空区增量更新，不降低评价精度。

### D6 校准流程

1. 基线：`life-shape` 4.4 的 200 局数据（未校准口径）；`restore-go-core-rules` 只留了 20 局冒烟，仅作参照。
2. 先定结构、后扫数值：九维 + 硬约束 + 阈值全部实现后，固定其余维度，按 `Eye` → `PassThreshold` → `Safety` → `Threat` 的顺序逐个**双向**扫档（每维至少 5 档、跨初值两侧），每档 4 人标准难度、`siege-4p-base-v5`、种子 1–200。
3. 选档准则（按优先级）：截断率 ≤ 5% → 整局无提子占比 ≤ 5% → 平均结束大回合尽量接近 7–10 → 第 3 大回合领先者胜率如实记录（裁决 #7 已接受其可能 > 50%，不作为否决项）。
4. 标准图定值后，在 `siege-frontier-v2` 与 `gen:` 每局换图各跑 200 局复核，只报告不再调参。
5. 每个维度的最终取值、扫档表、数据目录写进 `EvaluationWeights` 的注释与规范「默认评价权重的校准」；其余未单独扫档的维度如实标注"沿用旧值、新规则下未单独扫档"。

### D7 难度分级

| | 简单 | 标准 | 困难 |
|---|---|---|---|
| 评价维度 | 即时势力增量、敌方损失 | 九维 | 九维 |
| 活形硬约束 | ✔ | ✔ | ✔ |
| 停手阈值 | ✔ | ✔ | ✔ |
| 候选点 / 候选批次数 | 6 / 1 | 12 / 8 | 24 / 32 |

简单难度不看眼位，因此不会主动做活，但受益于合法落子范围（不会去填别人的眼）与硬约束（不拆自己碰巧做出的活形）。

## 接口契约

| 方向 | 对象 | 契约 |
|---|---|---|
| 输入 | `life-shape`「活形查询」 | 任意盘面 → 每条棋串的活形状态、眼空间、眼值；玩家 → 禁入格。AI 只经此查询获取眼信息 |
| 输入 | `turn-sequence` 合法落子范围 | 候选格已扣除禁入格，AI 不再自行过滤 |
| 输入 | `restore-go-core-rules` | 即时势力增量已含领地分；Sim 的 `turn_limit` 与截断率指标；权重表的未校准标注 |
| 输入 | `frontier-map` 候选格上限 | 预筛阶段的评价口径见 D5 |
| 输出 → Sim / 日志 | 配置记录与首部 | 九维权重、`PassThreshold`、难度、K；分解值为九项 |
| 输出 → 后续数值 change | 校准报告 | 新规则 + 新 AI 下的对局长度基线，供调整地图可落子格数与信物格数 |

## Risks / Trade-offs

- [九维互相耦合，逐维扫档找不到好点] → 按 D6 的顺序先定对收敛影响最大的 `Eye` 与 `PassThreshold`；若逐维不收敛，再做 `Eye × PassThreshold` 二维小网格（5 × 5），不做全维网格。
- [AI 过早做活后停手，对局变成"各围各的"] → 这是活棋禁入 + 领地计分下的真实均衡风险，属于规则 / 地图层面的问题；报告"整局无提子占比"与"首次跨出生区冲突大回合"，超标则在后续数值 change 里用地图规模与信物布点处理，不在 AI 里硬加进攻欲。
- [数值爆炸使 `PowerGain` 压倒一切] 不封顶倍率下单枚倍增子的势力增量可达数千，`PowerGain × 10` 会淹没眼位与安全 → 校准时观察分解值占比；若确认淹没，对 `PowerGain` 与 `EnemyLoss` 的原始值取整数对数刻度（⌊log2(1 + x)⌋，整数运算）作为备选，须另经用户确认后才启用。
- [回放兼容] 维度数与阈值变化使旧日志的 AI 决策无法逐步重现 → 日志首部记录 AI 评价版本；回放时首部版本与当前不同即在首部报分歧、不重跑；旧版本日志只作数据留档（R17）。
- [简单难度不收敛] 简单难度没有眼位维度 → 校准时单独跑 200 局简单难度，截断率同样要求 ≤ 5%，否则把眼位维度下放到简单难度（仅该维）。

## Migration Plan

1. `restore-go-core-rules`、`life-shape` 归档后开始。
2. 顺序：九维结构与分解 → `GroupSafety` 改用活形查询 + 活形中性 → 硬约束 → 停手阈值 → 性能（缓存 / 预筛口径）→ 校准 → 文档与规范同步。
3. 每步保持"权重与阈值取旧值时，行为可解释地变化"：结构改动与数值改动分开提交。
4. 回滚：`PassThreshold = 0`、`Eye` / `Threat` 权重 = 0 即退回到只有硬约束与活形中性的状态。

## Open Questions（建议裁决）

1. **硬约束"有提子即放行"是否过宽？** 提 1 子而拆掉自己一条 20 子的活形显然不值。建议：放行后交给打分——`Eye` 与 `Safety` 的大幅负增量会压过 1 子的 `EnemyLoss`；若校准中发现 AI 真的这么下，再收紧为"提子规模 ≥ 失活棋串规模"。
2. **`PowerGain` 是否需要对数刻度？** 见 Risks。建议：先按线性校准，观察分解值占比后再决定；启用前须用户确认。
3. **困难难度是否给更大的 `PassThreshold`？** 建议：三档共用一个阈值，难度只差在候选规模，保持"高难度不越权、只是看得更多"的既有原则。
