## Context

用户在 2026-09-19 给出一张参考图：悬空大陆上分布着 8 个红框平台（标注 5×5 / 7×7 / 10×10 / 12×12），中间穿插河、桥、崖、林地；并提出三点——像 LoL 那样用鼠标推动视口；平台大小不一（5×5 到 15×15），每个平台是一个出生点、也是厮杀主区域；选出生点后前三回合只能在出生平台内落子，三回合后全局落子。

对照现状：

- **保护期已经存在**（设计文档 §5.1、`map-definition`「出生区归属与共享」、`match-flow`）：前三大回合限出生区，之后任意合法空格，不要求与己方相邻。用户要的落子规则与现状完全一致。
- **地图模型装不下**：`siege-4p-base-v4` 是 13×13、四个 12–14 格的等大出生区、C4 对称；校验把出生区数 = 人数、可落子 95–110、距离极差 ≤ 1 都写成硬约束。
- **相机是固定的**：俯角 60°、整盘一屏，拾取自检 `--pick-check` 只在这一个位姿下验证过。
- **坐标记法的列字母只有 25 个**（A–Z 跳 I），宽度上限 25 列；行号无上限。
- 三个入口（批量、终端、图形）各自直接构造内置基准图；批量侧已有按标识解析地图的目录，另两个入口没有接上。
- 原型插旗路径里 AI 不"选"区，而是按编号顺排；区数多于人数时会永远挤在前几个编号。

规模放大后节奏、AI 开销、手感都是未知数，用户选择先做缩小版验证（裁决 1）。

## Goals / Non-Goals

**Goals:**

- 一张约 360 格、6 个大小不一平台的可玩地图，三个入口都能选到。
- 图形版能推屏、缩放、回家，任何位姿下点得准。
- 量出三个数：边疆图上的平均大回合数、AI 单步耗时、各平台的被选率与胜率。
- 标准档行为与 897 个既有测试零变化。

**Non-Goals:**

- 小地图、中键拖拽、相机跟随对手。
- 调节奏参数（部署额度 3/4/5、大回合上限 15、碾压起始 7）。
- 最终规模（8 平台、15×15）、突破 25 列。
- 替换 v4、2 / 3 人边疆图、AI 大地图专门策略、设计文档升版。

## Decisions

### D1 规格档字段，而不是新的"平台"概念

地图静态数据加一个规格档（`标准` / `边疆`），缺省 `标准`。规格档只在加载校验时起作用：选哪张预算表、哪几条规则拒绝 / 只报告。对局规则不读它。

"平台"直接复用出生区数据。按用户设定每个平台都是出生点，平台 ≡ 出生区；另立一等概念（名称、尺寸、中立标记）现在没有任何读者。否决程序生成平台——违反 `map-definition`「地图为设计师固定的静态数据」与确定性约束。

接口契约：规格档由地图文件提供 → 校验器读取 → 校验结果（拒绝项 + 报告项）输出；下游（对局、AI、表现层）不感知规格档。

### D2 校验分流的粒度：逐条规则声明"两档共用 / 仅标准档拒绝 / 边疆档另定区间"

| 规则 | 标准档 | 边疆档 |
|---|---|---|
| 可落子总数、信物数、据点数 | 现有预算表 | 边疆预算表（4 人：300–420 / 14–24 / 12–22） |
| 出生区数 | = 人数 | 5–8 且 > 人数 |
| 单个出生区规模 | 现有 12–14 | 20–225 |
| 旋转对称 | 由基准图要求 | 不要求 |
| 五项距离极差 | 超容差拒绝 | 只报告；不可达仍拒绝 |
| 必死口袋、桥在深水、栅栏在邻格、到中央入口可达、据点 / 信物格合法、保护期容量 | 共用 | 共用 |

报告项与拒绝项走同一份校验输出，加一个严重度区分；批量侧的 `map` 子命令打印报告项，供人工判断平台强弱。

### D3 `siege-frontier-v1` 的布局原则

- 25 列 × 28–32 行竖长图。两个 5×5 平台在中央偏两侧，6×6 与 7×7 居中环，8×8 与 9×9 在上下外缘。"大小即取舍"（裁决 2）：小平台离石碑与高档信物近、但只有 20–25 格腾挪；大平台空间足但出门要走更远。
- 平台全部 h=2，四周以崖壁为主，每个平台开 1–2 处 h=1 缓坡（2–3 格宽）下到过渡带。缓坡数量与朝向是平衡旋钮：小平台开 2 处（易攻难守，换取位置优势），大平台开 1–2 处。
- 过渡带（裁决 3，连片大陆）h=0 为主，2–3 格宽，一条主河纵贯，至少两座预置桥；林地与栅栏放在过渡带的交汇口，给匠人留出改造空间。过渡带之外用深水 / 障碍填满外接矩形，把可落子总数压在 300–420。
- 中央入口取地图几何中心附近的过渡带交汇格；咽喉标注各平台缓坡口与桥头。
- 用生成器代码手工摆放并导出 JSON（与 v3 / v4 同样的做法），不要求对称，但要求确定性：同一代码永远导出同一文件。

### D4 AI 选区：独立随机子流，区数 = 人数时走老路径

区数等于人数时保持"按编号顺排"，保证 v4 上所有既有种子的对局逐步不变。区数多于人数时，从对局种子派生一条**新的、独立命名的**随机子流给选区用（`simulation-harness`「随机子流隔离」），在未占用的区里均匀抽取。批量跑局因此能自然覆盖各平台组合，产出"各平台被选率与胜率"。

否决"AI 按面积 / 距离打分选区"：那是策略，需要先有数据才知道该往哪偏；先均匀抽，拿到各平台胜率再说。

### D5 统一选图入口

批量侧已有的"标识 → 地图"解析上移到规则内核可达的位置（或保持在批量侧但由三个入口共用——以不让图形版依赖批量项目为准，具体落点由实现按 `.trellis/spec/core/boundaries.md` 决定）。内置图（v4、frontier-v1）按标识直接给，其余按文件路径读。未知标识报错并列出可用标识。各入口的地图选项在严格命令行解析里登记。

### D6 相机：注视点 + 距离两个状态量，俯角与朝向恒定

状态只有 `注视点(x, z)` 与 `距离 d`；相机位置由二者与固定俯角 60° 推出。输入（贴边、按键、滚轮、空格）只改这两个量，每帧末统一夹取。

- **为什么缩放不改俯角**：现相机注释里的遮挡论证（h=2 高台向远处投 0.70 / tan 60° ≈ 0.40 格，小于半格，崖后低地格心可点）只依赖俯角，不依赖距离。缩放若带俯角变化，这条论证就破了，拾取会在某个缩放档位静默出错。
- **夹取**：可行矩形 = 地图外接矩形向内收缩"当前所见范围的一半"，所见范围按 `d` 线性近似；某方向所见范围 ≥ 地图跨度则锁中线。v4 在最远缩放下两个方向都锁中线 → 初始画面与固定相机逐像素相同，既有截图基线不动。
- **贴边推屏的抑制**：失焦、指针出窗、指针在界面面板上三种情况不推。面板判定复用界面层已有的"指针是否被控件吃掉"的信息，不另画感应区表。
- **逻辑与引擎分离**：注视点 / 距离 / 夹取 / 速度随距离缩放这套纯计算放在零 Godot 依赖的表现层视图模型里，可单元测试；Godot 侧只负责采输入与把结果写到相机节点。

### D7 拾取自检扩成多位姿

拾取函数本身已经以相机为参数，不用改算法；要改的是自检：在 7 个位姿（中心、四角夹取位、最近、最远）下逐格验证。边疆图约 360 格 × 7 位姿，仍是秒级。

### D8 坐标读数代替"标注跟随视口"

讨论阶段提过把四边坐标标注改成跟随视口边缘。落到规格时改为：四边标注原样不动，新增"悬停格坐标读数"。理由：跟随视口的标注要处理透视下的行列对齐、与面板互相遮挡、缩放时字号，三件事都与验证目标无关；悬停读数一行字就能让玩家在任何位置读到与日志一致的坐标。

### D9 出生区编号与着色支持到 8

面向人的出生区编号、终端渲染的区号底色、图形版的出生区着色目前都隐含"≤ 4"（区号底色借用了玩家色）。改为区号独立于玩家色：未被选的平台用中性色，被选中的平台在插旗锁定后才染上主人色。

## Risks / Trade-offs

- [AI 单步耗时随格数超线性增长] → 批量跑局先量；若 Hard 档单步均值超过 2 秒，在本 change 内只加"候选落点数量上限"这一个旋钮（按现有评分取前 N），不改评估函数。超过这个范围的优化另起 change。
- [15 个大回合在 360 格上打不出结果，全靠上限收场] → 这正是要量的数；本 change 只报告"到上限终局的比例"，不调参。
- [小平台开局即被贴脸，体验差] → 保护期三回合本来就是为此而设；缓坡数量是地图层的旋钮，跑局后按各平台胜率再调图，不动规则。
- [贴边推屏在窗口化 / 多显示器下误触发] → 失焦与出窗抑制；另保留按键平移作为不依赖指针的通路。
- [均匀随机选区改变了边疆图上的可复现序列] → 只在区数 > 人数时启用，且用独立子流；v4 上有"选区不扰动其他随机"的回归测试钉住。
- [规格档让校验器出现两套分支，日后漂移] → 每条规则在一张表里声明三种处理之一（D2），测试按表逐格覆盖，不允许散落的 `if 边疆`。

## Migration Plan

无数据迁移。旧地图文件缺规格档字段按 `标准` 读入；旧存档不含新字段也不需要回填（规格档随地图，不随对局）。回滚 = 不选边疆图；缺省入口行为不变。

## Open Questions

- 边疆档预算区间（300–420 等）是为 v1 这一张图量身估的，验证后必须重估。
- 最终规模若要 8 平台 + 15×15，25 列装不下，需要先裁决坐标记法怎么扩（双字母列？），这会波及日志、规格与全部面向人的输出。

## 裁决记录（已确认）

以下全部由项目负责人于 2026-09-19 确认：1–6 在讨论中逐条确认；7–12 是规格落地时补出的判定，派发前一并确认。执行方式：顺序分段、单 agent（段 A → B → C → D，每段实现后检查）。

**方向**
1. **先做缩小版可玩验证**，不直接替换 v4，也不先定"并存"。验证后再裁决最终规模与 v4 的去留。
2. **平台数 > 玩家数，大小即取舍**：小平台挤但靠近中央资源，大平台宽裕但偏远；没人选的平台是中立争夺区；匿名同时插旗与多人同区规则原样保留。否决"平台数 = 人数 + 资源补偿"与"出生平台等大 + 中立平台不等大"。
3. **连接方式取"连片大陆"**：平台是高台，平台之间是可落子的低地过渡带，河 / 桥 / 台阶是过渡带上的地形要素。否决"只靠窄桥连接"与"孤岛空投"。验证版把过渡带压到 2–3 格宽以控制总格数。
4. **落子规则不改**：前三大回合只能在自己平台内落子，之后全图任意合法空格，不要求与己方棋子相邻。"三回合后没有连接这个概念"指落子不受连接限制；**气、连珠、覆盖仍按现有地形规则走**（崖壁、深水、栅栏断气，桥通气）。
5. **相机取最小集**：贴边推屏 + 方向键 / WASD + 滚轮缩放 + 边界夹取 + 空格回出生平台。不做小地图与中键拖拽；相机不跟随对手落子。
6. **验证版不动节奏参数**（部署额度 3/4/5、大回合上限 15、碾压起始 7），跑起来看数据再说。整体设计（规格档方案、6 平台约 360 格、三段实施）已获确认。

**规格落地时的补充判定**
7. 宽度上限 25 列，不扩坐标记法；v1 取 25 × 28–32 的竖长图。
8. 边疆档距离均衡"只报告不拒绝"，不可达仍拒绝；不要求旋转对称。
9. 中立平台上的信物格仍按"出生区"分区取强度预算，不因没人选而改标"公共"（最简；若跑局显示中立平台过肥或过瘦再调图）。
10. 原型插旗路径下 AI 在区数 > 人数时由种子均匀选区、互不同区；区数 = 人数时保持按编号顺排。
11. 四边坐标标注不改，新增悬停格坐标读数（取代讨论时说的"标注跟随视口"）。
12. AI 耗时超标时本 change 只允许加"候选落点数量上限"一个旋钮，阈值为 Hard 档单步均值 2 秒。

**执行中由主会话代定（2026-09-19～20，待负责人追认）**
13. AI 选区判据取"出生区数 vs **地图支持的最大人数**"，不是本局参赛人数：v4 上的 2 / 3 人局因此仍走顺排、逐步不变（`match-setup` 增量已写明）。
14. 对局日志首部加 `ZoneCount` 并进入确定性文本：各区胜率报告固定按区数出行；段 B 之前的旧日志回放只在首部报分歧、其余逐步一致。
15. 实测 Standard 单步均值 2075 ms / Hard 1994 ms、最大 11 s，按裁决 12 加候选格上限 K：大图（可落子 > 150）缺省 K=24，显式配置（含 0）优先，生效值进 `config.json` 与日志首部，回放按首部重建、缺项按不限制（`ai-decision` 增量）。K=24 下均值 0.73 s、最大 2.2 s，提子 / 改造 / 落子数与不限制持平；均值未达 0.5 s 的自定目标，再降需要静态格分，超出"一个旋钮"的范围，不做。
16. 预筛对"代表类型落不下、只有匠人带改造才落得下"的格回退为逐个改造目标预演取最高分，不整格漏掉。
17. 跑局难度枚举没有 Normal，按 Standard 跑。
18. 开局对准改为"**平台整个可见优先于精确居中**"：距离取完整显示平台并四周留约 2 格，注视点经夹取，贴边平台允许偏心；整盘一屏看全的地图上锁定**不动相机**（玩家在插旗阶段拉近 / 推过的画面原样保留）。
19. `--pick-check` 分两层：逐格居中层全严格；7 位姿层把"拾到层数更高且更近的格"记为遮挡、不算失败。D6"遮挡论证只依赖俯角"只在注视点附近成立——透视下画面顶边视线更平，远处崖后低地格心被高台真实遮住是正确结果。
20. `内核与表现层不出现浮点` 守门对 5 个相机几何类型按精确类型名单豁免（相机几何必须用 float，且 v4 位姿要与旧固定相机算式逐位相等）；名单外与同命名空间新类型仍红。
