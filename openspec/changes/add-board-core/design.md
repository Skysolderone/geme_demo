## Context

设计文档 §2、§3 已经把拓扑规则收敛得相当干净：单一四邻接、障碍即边界、棋串跨类型合并。真正的风险不在规则本身，而在于后续 7 个 change 各自实现一份"邻居遍历"，导致围杀、覆盖、领地三处出现不一致的边界处理。

本 change 的价值是把这一层做成唯一实现、纯确定性、无随机、无回合概念的底座。它不知道回合、不知道玩家资源、不知道信物内容，只回答"盘面此刻是什么样"。

本轮规格保持实现无关：不指定语言、引擎、存储或并发模型。

## Goals / Non-Goals

**Goals:**
- 一份权威盘面状态定义，任何模块读同一份数据得到同一答案。
- 唯一的四邻接实现，杜绝斜向语义泄漏。
- 棋串与气的计算可被单元测试逐例验证。
- 确定性盘面序列化，直接服务于 `add-batch-deployment` 的同形禁则。
- 地图数据格式与静态校验，让"地图是否合法"在加载期而不是对局中暴露。

**Non-Goals:**
- 不做落子、提子、合法性判定（`add-batch-deployment`）。
- 不做覆盖、领地、势力（`add-territory-power`）。
- 不做信物内容生成（`add-relic-system`）。
- 不做任何渲染或坐标映射（`add-tactical-ui`）。
- 不做 2/3 人正式地图，本轮只固化预算约束（设计文档 §18.2）。

## Decisions

**D1：盘面用格数组而非棋串对象为权威状态。**
棋串与气是派生量，每次盘面变化后重算，不做增量维护。理由：设计文档 §9.2 明确"棋子与组合状态随当前盘面实时重算，不保留永久成长层数"，§10.1 也要求断连后分数立即下降；增量维护会在批次同时提子的场景下产生难以复现的中间态。
代价：每次结算重算全盘。11×11 约 121 格，四邻接洪泛的量级完全可接受；若后续跑局性能成为瓶颈，再在 `add-heuristic-ai` 引入带脏标记的缓存，而不改变本层语义。
备选：维护并查集增量合并——在"批次同时提子"下需要支持撤销与分裂，复杂度远高于全量重算。

**D2：障碍、越界、敌方棋子三者在气计算中的语义分层。**
障碍与越界完全等价（都不是格）；敌方棋子是"被占据的格"，它不贡献气，但它自己是一条棋串，可以被提走从而重新变成气。三者在实现上必须是同一个判断入口的三个分支，不允许分散判断。

**D3：盘面序列化只含"每格的占用者与棋子类型"。**
严格对齐设计文档 §6.2：不含手牌、征募、信物控制、势力、行动顺序、当前行动者。因此同一玩家在同一位置用不同类型棋子形成的盘面不视为同形。序列化必须按固定坐标顺序遍历，保证逐字节稳定。

**D4：地图校验放在加载期，做硬失败。**
必死口袋、距离失衡、障碍占比这类问题若漏到对局中，表现为"某玩家莫名其妙被迫 Pass"，极难归因。加载期硬失败并给出坐标，是最便宜的定位手段。
"必死口袋"判定采用保守近似：对出生区内每个被障碍/边界包围的连通空区，若其面积小于形成两眼所需的最小格数，即判失败。宁可误报，由设计师显式豁免，也不放过。

**D5：出生区标记只描述归属，不自带落子限制。**
限制的生效时机（前三大回合）属于流程，归 `add-match-flow`。这样本层可以在任意回合被直接查询，不需要知道"现在是第几大回合"。

## 接口契约

本 change 对下游暴露以下只读契约（实现无关，签名示意）：

| 契约 | 输入 | 输出 | 消费者 |
|---|---|---|---|
| `取格子` | 坐标 | 地形 / 出生区归属 / 是否信物格 / 占用（玩家+类型） | 全部下游 |
| `取棋串` | 坐标 | 该格所属棋串的棋子坐标集合；空格返回空 | batch-deployment, territory-power |
| `取气` | 棋串 | 气格坐标集合 | batch-deployment, tactical-ui |
| `枚举玩家棋串` | 玩家 | 棋串列表 | territory-power, heuristic-ai |
| `存在可落子空格` | 无 | 布尔 | match-flow（终局条件 3） |
| `序列化盘面` | 无 | 确定性表示 | batch-deployment（同形禁则）, telemetry |
| `加载地图` | 地图数据 | 校验通过的地图，或带原因的失败 | match-flow |

写入侧本层只提供最小原语（设置/清除某格占用），由 `add-batch-deployment` 在其结算顺序中调用；本层 MUST NOT 自行决定何时提子。

## Risks / Trade-offs

- **[全量重算在高频跑局下累积开销]** → 本层保持纯函数与无副作用，性能优化留给上层缓存；先用批量跑局实测再决定是否优化，不提前设计缓存。
- **[必死口袋判定误报]** → 提供设计师显式豁免标记；误报成本（手工确认）远低于漏报成本（对局中卡死）。
- **[两眼活形的精确判定是个难题]** → 本层只做面积下界的保守近似，不追求围棋意义上的完整死活判定；完整判定不属于原型范围。
- **[基准地图的距离容差目前是拍脑袋的值]** → 先给出初值并记入地图数据，由 `add-heuristic-ai` 的批量跑局回归"出生区随机资源是否造成显著胜率差异"（设计文档 §17）后再校准。

## 裁决记录（已确认）

1. **距离均衡容差 = 1**（最短落子距离两两差值 ≤ 1）。4 人对称图可硬满足；3 人图属后续扩展（§18.2），届时允许逐图放宽，但必须把放宽值与理由写入地图数据。这是本项目最严格的一条地图约束，制图时应优先用对称布局满足它。
2. **"主要咽喉"由设计师在地图数据中显式标注**，不做自动识别。自动识别的错误会静默污染距离均衡校验，而这类错误极难归因。
3. **两眼所需最小格数 = 8**（保守取值）。出生区内被障碍/边界围成的连通空区面积 < 8 即判失败，支持逐图显式豁免。宁可误报由设计师确认，不放过对局中卡死的风险。
4. **坐标采用围棋记法**：列字母 `A`–`L` 跳过 `I`、行数字自下而上从 1 起，左下角为 `A1`。这是日志、规格、错误信息与一切面向人的输出的权威记法；实现内部可用数值索引，但必须提供唯一的双向映射实现。代价是多维护一层映射，换来的是对局记录可直接人工复盘。
