## Context

现在的链接档生成器（设计文档 §3.3）流程是：抽次序 → 抽宽高 5–7 → 每块 2 个信物格 → 全部格设为 `TerrainData.Flat` → 静态校验，不通过就当作生成器缺陷抛异常。校验器链接行把"棋盘内全部是高度 0 的可落子草地"作为清单规则先行执行，并要求出生区等于整块棋盘。地形规则（§3.1、§3.4）完整可用，旧边疆档在 `74fbf28` 之前有平台、坡道、河流和信物难度的算法，已随 `retire-legacy-maps` 删除。

约束：
- 地图只用由地图种子派生的布局子流（`.trellis/spec/core/determinism.md`）；
- 拼接不消费随机数；
- 入口遇到未识别的输入必须报错；
- Core 零 Godot 依赖；
- 同一时间只跑一个任务；冒烟每个配置不超过 20 局。

## Goals / Non-Goals

**Goals：**
- 5 块棋盘各带一个主题和相应地形；盲选能看到主题；拼接几何不变。
- 出生区语义收缩到核心区，所有"要整块棋盘"的使用者改为读棋盘清单。
- 校验器能对每条新约束给出具体的拒绝原因；种子 1–20 穷举全部通过。

**Non-Goals：** 见 proposal 的 Non-goals。这里再强调一条：第一期不建立"地形价值模型"，主题强度靠初始参数加冒烟数据来调。

## Decisions

### D1 出生区 = 核心区，棋盘清单承担"整块棋盘"的语义

`MapData.BirthZones[i]` 改为第 i 块棋盘的 3×3 核心区，原点 = 棋盘原点 + (⌊(W−3)/2⌋, ⌊(H−3)/2⌋)。凡是需要整块棋盘的地方（占位、战场到棋盘的归属、Sim 的 `ZoneSides`、图形版取景）都改读 `Boards`。

- 备选：在 `MapData` 里另加一个 `CoreZones` 字段，`BirthZones` 保持等于整块棋盘。
- 不选它的原因：出生区信物档位、保护期容量、新地表禁入这几条规则说的本来就是"起手阵地"，让 `BirthZones` 指向核心区，这些规则自动作用到正确的范围；另加字段反而要逐条改规则。
- 代价：使用者要逐个复核。实施时用 codegraph 列全 `BirthZones` 的调用者，单独作为一步（tasks 2.x）。

### D2 主题是棋盘清单的属性

`BoardPlate` 增加 `Theme`，地图文件随清单往返；链接档出生棋盘缺少主题要报错。主题只用于生成、校验与呈现，不进入任何结算。

- 备选：把主题放在地图元数据（按棋盘编号的数组）。不选，因为主题跟着棋盘走，放在清单里拼接平移时不用额外维护。

### D3 生成顺序与随机消费

全部随机数来自 `MapRandom.ForLinkLayout(seed)` 这一条流，顺序固定：

次序 → 宽高（6–8）→ 主题排列（Fisher–Yates）→ 按编号逐块生成地形 → 出生区信物 → 公共信物

每块棋盘的地形由一个主题生成函数产生，输入是（棋盘外接矩形、核心区、随机流），输出是该棋盘的地形与"难到达格"候选集。生成后立即做棋盘级自检（连通、改造目标数）；自检失败就在同一条随机流上**重抽该块**，最多 16 次，仍然失败则抛 `MapGenerationException`。穷举测试必须证明种子 1–20 从不走到抛异常。

- 备选：失败直接抛异常，不重抽。不选，因为 6×6 的中间带只有 7 格，按构造保证一次成功会让主题生成过于僵硬。重抽只发生在同一条流上，确定性不受影响。

### D4 各主题的初始参数

| 主题 | 中间带内容 | 难到达格 | 改造目标来源 |
|---|---|---|---|
| 高台 | 高度 2 的平台 2–4 格，四周是高度 1 的坡，保证能从高度 0 走上去；高度 2 的格不与外圈直接相邻 | 高度 2 的格 | 再散布 2–3 格林地 |
| 河流 | 宽 1 的深水贯穿中间带（直线或一次折弯，两端抵到外圈内侧），留 1 座预置桥 | 与核心区隔着深水的那一侧 | 未架桥的深水格 |
| 林地 | 2–3 团林地，每团 2–4 格，可以延伸到外圈 | 三面被林地包围的格 | 林地格 |
| 栅栏阵 | 2–3 段预置栅栏，每段 2–3 条边，只在中间带内部或中间带与核心区之间 | 栅栏围出来的口袋格 | 外圈散布 2 格林地 |
| 混合 | 1 格高度 1 的台、1 段 2 格的深水（带桥）、1 团林地、1 段栅栏 | 高台格或隔水格 | 林地 + 深水 |

另有岩石：每块 0–2 格，只放在中间带。强度按中间带面积成比例缩放（6×6 时取下限）。这些参数都是初值，冒烟后按"各主题棋盘的平均名次"回调，回调幅度记录在 tasks 里。

### D5 公共信物

公共信物用 `(Contested, Standard)` 档，复用 `relic-generation` 中公共区的权重与高阶升级。出生区稀有度均衡只约束出生区信物，不改。全图信物格因此是 10–15 个。

### D6 校验器

链接行按 `map-definition` 的清单规则逐条实现，每条一个失败码（新增 `BOARD_RIM_NOT_FLAT`、`BIRTH_CORE_NOT_FLAT`、`BOARD_SPLIT`、`BOARD_TOO_FEW_EDIT_TARGETS`、`BOARD_THEME_INVALID`、`LINK_SEAM_NO_LIBERTY`，实施中另加 `BOARD_SPECIAL_SURFACE` 拒绝棋盘内的新地表）。删除旧的"棋盘内全部是高度 0 的可落子草地"规则；单区格数改为恰 9，信物格数改为 10–15，可落子格总数和画布尺寸的区间按穷举结果回写。

### D7 与其他 change 的接口契约

| 对方 | 输入 / 输出 | 触发时机 |
|---|---|---|
| `battlefield` | 输入当前地图，输出战场列表；战场到棋盘的归属改为"棋盘内任一可落子格所在的分量"，不再假设左下角格可落子 | 按需导出（不变） |
| `link-map-generation` 拼接 | 输入（两个战场、当前布局），输出新布局；地形、栅栏、信物随格平移（不变），之后多做一次接缝气边校验 | 配对事件之后（不变） |
| `match-setup` / 公开视图 | 插旗阶段的占位 = 棋盘清单的（左下角、宽、高、主题） | 插旗阶段 |
| `relic-generation` | 输入信物格清单（出生区档 10 个 + 公共区档 0–5 个），输出信物内容 | 建局（不变） |
| 日志、回放、存档 | 地图摘要变了，旧 `link:` 日志与存档由现有摘要比对拒绝（`Replayer` 的 `MapMismatch`、存档恢复的摘要核对） | 读取时 |
| AI | 落子候选与评价读地形（现有逻辑）；可落子格 > 150 时候选格上限 K = 24（现有规则，链接档按建局时 5 块之和判定） | 每个小回合 |

## Risks / Trade-offs

- [`BirthZones` 语义收缩，漏改某个使用者] → 用 codegraph 列全调用者，逐个标注"出生区"或"整块棋盘"；占位尺寸、取景、战场归属三处各写一条测试。
- [可落子格总数上升（约 170–320），对局变长、AI 变慢] → 冒烟对比 F.5 基线（大回合 10 / 11 / 15，单小回合中位 47 ms）；单小回合中位超过 150 ms 或对局中位超过 20 大回合时，回到负责人裁决（缩小边长或压低主题强度）。
- [主题强度不均衡] → 20 局只能看方向；`analyze` 输出按主题统计的平均名次与胜场，偏差明显时调 D4 的初值，不在本 change 里建价值模型。
- [`--pick-check` 拾取计数、截图、决策序列基线全部变化] → 按实测回写，在提交说明里逐条列出新旧值；基线变化属于 M10 已接受的 BREAKING。
- [接缝气边校验在合法生成下永远不会触发，看起来像死代码] → 它是给手写地图和以后改外圈规则时用的底线，用手写夹具做拒绝算例保留覆盖。

## Migration Plan

1. Core（生成、校验、战场归属、公开视图）一起落地。链接档的旧地图摘要会全部改变，同一段里重做 `link:1` 决策序列基线与黄金值。
2. Sim 与图形版跟进占位主题和打印。
3. 回滚：回退本 change 的提交即可回到纯平棋盘；没有数据迁移。

## Open Questions

以下是设计文档没有覆盖的判定。**负责人 2026-10-14 裁决：Q1–Q5 全部按建议；派发方式 A（按组顺序派 `trellis-implement`，一次一组，前台复核后提交）。**

- Q1 外圈允许林地吗？**建议允许**：林地可落子、不挡气，不影响接缝气边，还能给匠人提供目标。
- Q2 河流主题的深水能不能延伸到外圈？**建议不能**（外圈必须可落子），所以河流只贯穿中间带，两端抵到外圈内侧。
- Q3 公共信物的难到达格不存在时（比如 6×6 混合主题放不下）怎么办？**建议这块就放 0 个**，不降级成普通格。
- Q4 栅栏阵的栅栏能不能立在核心区和中间带之间？**建议可以**：核心区规则只约束核心区内部的格和边。
- G1（负责人 2026-10-14 裁决 A）：战斗阶段按座位可见的格 = 本战场所含各棋盘外接矩形内的全部格，包括岩石与未架桥深水，否则河流和岩石会在视图里变成空缺；其他战场仍不可见。
- 第 2、3 组实施裁决（2026-10-14）：
  - T1 = A：依赖 AI 实际走法的样本下界断言改为不依赖走法（脚本化落子或手写局面）；做不到的改为"固定种子区间 1–N 内至少出现一次"，N 写死，不挑单个种子。
  - T2 = A：放宽难到达格——林地主题为"至少两面挨着林地的格"，栅栏阵为"至少两条边有栅栏的格"；目标是 6×6 与 8×8 上每个主题 ≥ 80% 的棋盘有公共信物。
  - 另按实施汇报接受：高台在边长 ≤ 7 时平台可挨外圈；有候选即恒放 1 个公共信物；重抽 16 次（共 17 次尝试）；折弯河道两臂朝向核心区；`PlaceOne` 先落核心区；校验器不早停，规格措辞随之修正。
- Q5 图形版新局界面（`map-selection`）的占位轮廓要不要显示主题？**建议本期不显示**：那是开局前的预览，主题在插旗阶段显示就够了；规格不改。
