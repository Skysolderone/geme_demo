## Context

现行对局建立在"一张静态地图、开局全图可见、所有玩家在同一片可落子格上"之上：`MapData` 在对局中不变，`GameBoard` 的邻接覆盖全图，`MatchPublicView` 对全部座位给同一份视图，终局三条件以全盘为范围。棋盘档（`board-map`）已经把可落子格组织成"棋盘 + 通道"，并有棋盘清单（`BoardPlate`）与双字母列标，是本 change 的直接基础。

负责人 2026-10-09 的 13 项裁决（见 proposal）把开局改成盲选隔绝棋盘、把地图改成随链接增长、把终局改成按战场结算，并要求整个游戏只保留这一个模式。

## Goals / Non-Goals

**Goals**：按裁决落实"战场 → 链接 → 战场结算 → 决赛"的全套流程；地图增长、按座位可见性、不可复现配对都在 Core 数据层成立；回放、存档、批量跑局继续可用。

**Non-Goals**：见 proposal。另外本设计不追求旧地图的任何行为兼容——旧地图只作为 Core 测试夹具保留。

## Decisions

### D1 战场 = 可落子格的连通分量，不另建邻接

隔绝棋盘之间全是不可落子的场景格，`GameBoard` 现有的四邻接与气边自然得不到跨棋盘的边。因此**战场**定义为"沿几何邻接相连的可落子格的极大连通分量"，由 `MapData` 按需导出并随地图版本号记忆化（沿用 `ai-turn-speed` 的版本号记忆化做法）。链接只是把新的可落子格写进地图，两个分量随之合并；棋串、气、覆盖、领地、活形、禁手、同形判重都不需要知道"战场"存在。

战场需要稳定标识供日志、存档与界面使用：取该分量内编号最小的出生棋盘编号。

本模式的**不变量**：战场之间的场景格是障碍格，搭桥与烧林以它为目标天然被拒（目标须为深水 / 林地）；立栅不按规格档分流拒绝——段 A 实测"障碍端点立栅即非法"会改变 v5 / board:1 上 AI 的合法改造候选、14 条决策序列基线全红——以场景格为一端的栅栏合法但切不到任何气边、无效果（负责人 2026-10-09 裁决 R5）。三种改造都没有"把不可落子格变成可落子格"的能力，因此除链接之外没有任何途径让两个分量合并。该不变量由测试守住。

备选：显式维护战场对象并给邻接加"同战场"过滤。否决——多一处必须与地图同步的状态，且现有规则代码要逐处改。

### D2 地图增长：固定画布 + 槽位，链接时确定性生成

- 生成器由地图种子在固定画布 **73×73** 上按 4×4 槽位布置 **5 块出生棋盘**（边长 5–7，沿用棋盘档参数），槽位图案只从穷举验证过"全部链接序列都能生成"的 32 种白名单（对角线族及镜像）中选；彼此至少隔开足以放下一块公共棋盘与两条通道的距离；坐标在整局中稳定，双字母列标沿用。（段 A 实测：3×3 槽位、画布 ≤ 50 下没有任何可行图案；负责人 2026-10-09 裁决 R1 / R6 接受 73 与白名单。）通道长度不设上限（R3），可落子格上限 1600（R4）；同一配对事件内多次链接按"含最小出生棋盘编号的一对先"执行（R2）。
- **链接**（战场 X 与 Y）时生成：在 X、Y 距离最近的两块棋盘之间放一块公共棋盘（边长 9–11）并各铺一条 3–4 格宽的直通道。几何由 `(地图种子, X, Y)` 与当前物化状态决定性派生（与链接序号无关：同一对 (X, Y) 无论先后链接都用同一条随机序列），只用整数运算；通道不得穿过已有棋盘，公共棋盘与已有棋盘至少隔 2 格。放置失败时按确定性次序尝试备选位置；全部失败时退化为 X、Y 之间一条直通道（无公共棋盘），并在日志记录。
- `MapData` 增加"已物化棋盘集合"与地图版本号；`MapValidator` 对**当前物化状态**做校验（棋盘清单、通道宽度、信物格），每次链接后重新校验，失败即判定生成器缺陷并以异常中止对局（测试覆盖种子 1–20 × 全部配对组合）。
- 信物格：出生棋盘各 1，公共棋盘按边长 2–3；公共棋盘的信物内容由 `(对局种子, X, Y)` 派生的独立子流生成，与链接序号无关，因此同一配对无论先后链接都得到同样的信物。由于配对本身不可复现，**哪些公共棋盘会出现仍随配对而变**，回放靠记录的配对结果重建。
- 标识 `link:<地图种子>`，没有其他参数。

### D3 配对是输入事件，不是 Core 的随机

Core 不为配对抽随机数。`MatchFlow` 在第 3 大回合结束时进入 `AwaitingPairing` 状态，暴露"首轮配对候选"，由外部（Godot、终端、Sim）调用 `ApplyPairing(pairs, waiter)` 提交结果；Core 校验配对合法（每个候选至多出现一次、不与非候选配对、奇数时恰有一名等待者），然后逐对执行链接。决赛同理（`AwaitingFinalLink`，只有一种合法结果，仍走同一事件以保证日志形态一致）。

**首轮配对候选**定义为：锁定时旗数恰为 1 的出生棋盘上、仍在局的玩家所在的战场。多人同区的棋盘即使在第 1–3 大回合内已经结算、只剩胜者一人，也**不进入**首轮配对（裁决 3a A），胜者原地等待决赛。候选为奇数时（3+1，或 1+1+1+1 中有人在前三大回合弃赛），由配对事件指定等待者，等待者的选择与配对一样来自外部随机源。

配对结果作为**对局事件**写入日志（`pairing` 条目）与存档；回放与恢复按记录结果重建，不从种子推导。`play` 与图形版用真随机；Sim `run` 缺省用由对局种子派生的 `--pairing-seed`（纯工具层，便于批次间对比，待裁 Q10），无人值守自检用脚本固定配对。

这满足"不可复现"的裁决，同时保住回放、存档、黄金值机制。

### D4 可见性在数据层按座位过滤

- `MatchPublicView` 改为 `ForSeat(seat)`：只含该座位所在战场的格、棋子、设施、空格归属、已揭示信物、棋串与活形；其他战场的格一律呈现为"未展开"。地形查询接口对未展开格返回"不可见"而不是地形值。
- 其他玩家的信息：在局 / 出局状态、所在战场是否已结算**可见**；势力数值、势力明细、手牌类型、带入在链接前**不可见**（待裁 Q1）。
- 插旗阶段：公开视图只含 5 个占位（位置与边长）与本座位已选占位的棋盘布局；他人旗帜在锁定前后都不可见，锁定后只公开"本战场内有谁"。盲选下**选中即锁定**，不再允许锁定前更换（更换会让玩家看到第二块棋盘的布局，待裁 Q8）。
- 行动顺序仍全局公开（每个小回合谁在行动必须让所有人知道）。
- 批量分析与遥测用全知视图（`MatchDebugAccess`），不受过滤影响。
- AI 第一版通过 `MatchDebugAccess` 全知决策（proposal Non-goals），候选格由合法落子范围自动限定在自己战场，不需改评价代码。

### D5 阶段与战场结算

对局阶段：`Flagging → Building(第 1–3 大回合) → AwaitingPairing → Fighting → (每当全部多人战场结算且在局人数 ≥ 2) AwaitingFinalLink → Fighting → Ended`。

- **合法落子范围**：任何大回合都是"本玩家所在战场的可落子格 − 禁入格"。第 1–3 大回合因战场就是自己的棋盘，自然等价于现行保护期；第 4 大回合起不再有"全图解禁"。
- **战场结算**判定在**每个**大回合结束时对每个战场检查，第 1–3 大回合也算（2 人同区可能在第 2 大回合就打完）：（a）战场内在局玩家 ≥ 2 且本大回合内全部都 Pass，或（b）战场内无可落子空格。满足即结算：按势力（并列按现行判定链）排序，第一名为胜者，其余以"战场落败"出局。单人战场永不因 Pass 结算（等待者 Pass 不会淘汰自己）。
- **减员结算**：多人战场因弃赛或现行势力归零出局而只剩 1 名在局玩家时，该战场同样标记为已结算、该玩家为胜者，否则决赛触发条件永远不满足。
- **决赛触发**：全部多人战场都已结算，且在局玩家 ≥ 2。单人等待者的战场本来就不需要结算。
- **全局终局**：只剩一名在局玩家；或只剩一个战场且它已结算（含 4 人同区一次结算即终局）。现行"整轮 Pass / 棋盘填满"条件删除。
- **弃赛**沿用现行规则。
- **等待者**（单人战场的在局玩家）每小回合照常征募、可在自己战场落子或 Pass；无对手时势力只增不减，这是已知失衡，v1 不处理（见 Risks）。

### D6 名次

决赛胜者第 1；决赛其他玩家按结算势力依次排名；更早结算的战场落败者按出局先后倒序排在后面，同一次结算中多名落败者按势力及并列判定链排序（待裁 Q3，现行"同时出局共享名次"改为排序）。弃赛者仍排最后。

### D7 带入带出

"战场落败"出局按现行**出局结算**处理：带出 0、补给丢失（待裁 Q2；备选是视为完赛按名次领补给点）。

### D8 旧地图与入口收口

- `MapCatalog` 公开解析只接受 `link:<种子>`；旧标识解析移到 `MapCatalog.Legacy`，仅 Core 测试与 `Siege.Sim map` 调试子命令可用。
- 图形版无 `--map=` 时进入"开始新局"界面：显示随机取好的地图种子与完整标识、可输入种子、"开始"；旧选图清单删除。`--map-select --auto-demo` 的自检步骤改为"输入非法种子、合法种子、换一张、开始"。
- 批量与终端缺省 `link:1`（待裁 Q4）。
- 依赖旧地图的黄金值与决策序列基线测试全部保留并改用 `MapCatalog.Legacy` 加载，作为围棋内核的回归护栏；新模式建立自己的决策序列基线（`link:1` 固定配对脚本）。
- 规格层面：`map-generation` 中边疆档与棋盘档的生成 Requirement **保留**为夹具约束（生成器代码不删、逐字节不变条款继续生效），只把"玩家入口可达"的条款（`map-selection`、`simulation-harness` 各入口选图）改为 `link:`。`map-definition` 的三条基准地图 Requirement 同样保留为夹具约束，并加注"不再由玩家入口可达"。

### D9 表现层

- 只渲染本机座位的战场；未展开的出生棋盘画成低饱和占位轮廓（只有外接矩形），其余区域不画。相机的边界夹取、回家、全局预览都以当前战场范围为准。
- 链接时新增演出节拍"棋盘展开"：公共棋盘与通道从地面升起，随后相机拉远到新战场范围；无人值守零时长，沿用 `settlement-show` 框架。战场结算新增横幅节拍"战场落败 / 战场胜出"。
- 插旗界面：5 个占位可点选，选中后只展开自己那块的布局预览。

### D10 存档与日志

- 日志首部：地图标识 `link:<种子>`、无冒险概率字段。
- 新事件：`pairing`（配对列表、链接序号）、`link`（生成的棋盘与通道几何摘要、信物格）、`battlefield_settled`（战场、名次、胜者）。
- 存档：已物化棋盘集合 + 全部链接事件；恢复时按事件顺序重放链接生成，再校验与保存时的格数据一致。
- 旧存档与旧日志（无 `link:` 标识）直接拒绝读取并给出明确提示，不做兼容。

## Risks / Trade-offs

- [生成器在某些种子 × 配对下放不下公共棋盘] → D2 的确定性备选位置与直通道退化；测试穷举种子 1–20 的全部配对组合（首轮 15 种 × 决赛组合）。
- [信物子流随配对变化，黄金值无法跨配对比较] → 基线一律带固定配对脚本；文档写明。
- [等待者无对手白增势力，决赛不公平] → v1 接受，遥测记录"等待大回合数"，后续按数据裁。
- [AI 在战场结算规则下过早 Pass 会直接落败] → 现行停手阈值 20 可能导致弱势方主动 Pass 送分；v1 只报告，不调权重。
- [三类终局之一"整轮 Pass"删除后，多人战场不会无限拖长] → 战场填满兜底，可落子格有限。
- [按座位过滤后 Godot / 终端大量读取公开视图的代码要改调用方式] → 分段实施，先让全知视图走同一接口再加过滤。
- [旧地图入口移除导致 HANDOFF、自检脚本、截图流程全部失效] → 在本 change 内同步改写；旧截图基线归档不删。

## Migration Plan

分五段实施，每段可独立测试与提交：

- **A Core 数据层**：战场导出、`MapData` 物化集合与版本号、链接生成器与校验、`link:` 标识、`MapCatalog.Legacy`。
- **B Core 对局流程**：盲选插旗（废除 p）、阶段机、配对事件、战场结算、终局与名次、存档 / 日志事件、按座位视图。
- **C Sim 与 AI**：`run` / `play` / `replay` 接配对源、决策序列基线、遥测字段、20 局冒烟。
- **D Godot / Presentation**：新局界面、占位插旗、按战场渲染与相机、展开演出、横幅、`--auto-demo` 自检。
- **E 收尾**：设计文档 §3 / §4 / §12 / §13 改写、HANDOFF、变更记录。

回滚：整段 revert；旧地图数据与测试未删，不需要数据迁移。

## Open Questions（待负责人裁决，缺省值已写入上文）

- **Q1** 链接前能否看到其他玩家的势力数值？缺省**不可见**，只看到在局 / 出局。
- **Q2** 战场落败者的带入带出：缺省按**出局结算**（带出 0、补给丢失）；备选按完赛名次领补给点。
- **Q3** 同一战场多名落败者（3 人同区）的名次：缺省**按势力排序**；备选沿用现行"同时出局共享名次"。
- **Q4** 批量与终端缺省地图：缺省 `link:1`；图形版每次随机取种子。
- **Q5** 公共棋盘放不下时的退化：缺省**直通道**；备选判定生成失败换种子。
- **Q6** 旧存档：缺省**拒绝读取**，不做兼容。
- **Q7** AI 视野：缺省 v1 **全知**（经 `MatchDebugAccess`），只把候选格限定在自己战场；备选给 AI 也套按座位过滤的视图（需要改评价维度中依赖他人势力的部分）。
- **Q8** 盲选能否更换：缺省**选中即锁定**；备选允许更换但只显示占位、不显示布局。
- **Q9** 奇数个候选时谁等待：缺省由配对事件随机指定（与配对同一外部随机源）；备选固定为编号最大的出生棋盘。
- **Q10** 批量 `run` 的配对源：缺省由对局种子派生（纯工具层，不改变 7C"玩家体感不可预测"）；备选 `run` 也用真随机，批次间不可对比。
