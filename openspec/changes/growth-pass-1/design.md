## Context

`cap-multiplier` + `round-cap` 之后的 200 局回归里，§16 还剩两项明显偏离，本 change 只处理数值，不动机制：

| 指标 | 实测 | §16 目标 |
|---|---|---|
| 第 7+ 大回合部署上限 | 均值 3.36，分布 3×3986 / 4×1097 / 5×301 / 6×56 / 7×23 | 5–8 |
| 倍增子选择率 | 86.9%（基础权重只有 12，五种里最低） | 无唯一最优 |
| 首次跨出生区冲突 | 平均第 7.11 大回合（分布：6×63、7×72） | 第 4–5 |

供给侧的算术：4 人基准图共 14 个信物格（出生区 8、公共标准 4、公共高阶 2），实测平均每局只有约 1.4 枚军令，还要四家分。把军令权重翻倍也只能把均值推到 3.7 左右——**部署上限靠信物达不到 §16 的目标**，必须改基础值。

倍增子的 86.9% 是"出现就选"（`cap-multiplier` Open Question 1 已预留降到 4 的口子），降它的出现频率没用，只能降它的边际价值。

## Goals / Non-Goals

**Goals:**
- 部署上限的三段分布落进 §16 的 3 / 3–5 / 5–8。
- 倍增串天花板从 7.59 降到 5.06，观察选择率是否回落。
- 部署上限的来源拆分能区分"分阶段基础"与"军令加成"，界面与遥测可显示。
- 用 200 局回归对照，不跑 2000 局基线。

**Non-Goals:**
- 不改保护期、地图布局、出生区距离：冲突偏晚的一部分原因是每回合只能落 3 枚、扩张慢，先看提速后是否自然达标。
- 不调征募权重表与军令生成权重。
- 不改终局条件（→ `dominance-victory`）。

## Decisions

**D1：基础部署上限按大回合分阶段，而不是提高军令供给。**
备选 A：军令权重翻倍 + 公共区军令默认 +2。否决：估算只能到 4 出头，且会挤掉其它五类信物的出现机会，让"争夺哪一枚信物"的选择塌缩成"都抢军令"。备选 B：改低 §16 目标。否决：§16 的三段曲线是玩法节奏的设计意图（前期建构筑、中期争公共信物、后期爆发），不该因为供给算不过来就放弃。
选定：基础值 3 / 4 / 5（第 1–3 / 4–6 / 7+），军令继续在其上 +1 叠加。这样 §16 的三段目标天然成立，军令从"唯一来源"变成"锦上添花"，反而更健康。

**D2：阶段边界与构筑保护期、§16 的三段完全对齐。**
第 1–3 大回合正好是构筑保护期（§4.2），第 4 大回合全图解禁同时基础值 +1，第 7 大回合进入后期同时再 +1。三个节点都已经是玩家能感知的阶段边界，不引入第四个节奏点。

**D3：分阶段基础值只在效果快照生成时读取一次。**
§5.1 规定信物快照在小回合开始时读一次、小回合内不变；基础值按"生成快照时的当前大回合"取，跨大回合不追溯。这样部署上限在一个小回合内恒定，与既有的"快照内不变"契约一致。

**D4：封顶 5 → 4，仍然只改 `Multiplier` 内部那一个常量。**
`cap-multiplier` 已把封顶做成唯一常量 `MaxExponent`，调整只动这一处与相应算例。倍率上限 `81/16 = 5.0625`。

**D5：先不碰冲突时机。**
D1 会让第 4 大回合起每回合多落 1 枚、第 7 起多落 2 枚，扩张速度提升约 33%–67%，首次冲突预期自然前移。若回归后仍晚于第 6 大回合，再单开 change 评估"保护期缩到 2 大回合"或地图距离。

## 接口契约

**输入：** 当前大回合序号（效果快照生成时）、控制中的军令信物。

**输出：**

| 输出 | 变化 | 消费者 |
|---|---|---|
| 效果快照的部署上限 | 基础值随阶段变化 | `add-batch-deployment` 校验、界面额度显示 |
| 部署上限来源拆分 | 区分"分阶段基础"与"军令 +N" | 手牌面板、批次预演 |
| 棋串军势 | 倍率上限 5.0625 | 势力计算、遥测峰值 |

## Risks / Trade-offs

- **[后期节奏过快，对局反而更短]** → 平均结束大回合当前 12.5，本 change 可能把它压到目标区间以下。回归同时看结束大回合分布，过短就把第 7+ 的基础值退回 4。
- **[部署上限提高放大先手优势]** → 先手方每回合多落的绝对数量增加。回归必须看第 3 大回合领先者胜率（当前 38%，目标 ≤ 50%）。
- **[封顶降到 4 后倍增子仍是最优]** → 说明问题不在倍率而在其它棋子的价值太低，那要调的是基础军势或位置加值，不是继续降封顶。回归后如果选择率仍 > 80%，本 change 不再追加调整，记录事实另开 change。
- **[两项改动同时上，效果归因困难]** → 接受：两项都有独立的直接指标（部署上限分布、倍率峰值与选择率），互不遮蔽。若第三方指标（结束大回合、领先者胜率）异常，再拆开单独跑。
- **[既有算例大面积改写]** → "基础部署上限 3" 写死在很多测试里。要求实现方逐条按所在大回合改写并在提交信息列出，不得为了让测试变绿而改实现语义。

## Migration Plan

1. 效果快照的基础部署上限改为按大回合分阶段 + 来源拆分；改写受影响的既有算例。
2. 倍率封顶常量 5 → 4；改写 `cap-multiplier` 的封顶边界算例。
3. 设计文档 §5.4 / §9.2 / §10.1 / §16 与变更记录。
4. 200 局回归（种子 1–200，Standard，上限 15），与本次基线对照：部署上限三段分布、倍增子选择率、峰值军势、首次冲突大回合、结束大回合、领先者胜率。
5. 回滚：两项各自是一处常量与一组算例，可独立回退。

## Open Questions（建议裁决）

1. **第 7+ 基础值 5 会不会太快** → 建议按 5 实测；若平均结束大回合掉到 7 以下或领先者胜率 > 50%，退回 4。
2. **封顶 4 之后倍增子选择率仍 > 80% 怎么办** → 建议只记录不追加，留给下一轮从"其它棋子太弱"的方向查。
3. **冲突时机** → 本 change 不动，回归后再判。

## 裁决记录（已确认）

1. **基础部署上限分三段 3 / 4 / 5**（第 1–3 / 4–6 / 7+ 大回合），军令在其上继续 +1 叠加（2026-09-15，项目负责人确认）；阶段边界与构筑保护期、§16 的三段完全对齐，不引入新的节奏点。
2. **基础值只在生成效果快照时按当前大回合读一次**，小回合内不变，跨大回合不追溯。
3. **倍率封顶 5 → 4**，仍只改 `Multiplier.MaxExponent` 一处常量；上限 `81/16 = 5.0625`。
4. **本轮不动冲突时机**：部署提速后扩张快 33%–67%，首次冲突预期自然前移；回归后若仍晚于第 6 大回合再单开 change 评估保护期或地图距离。
5. **实现顺序**：在 `dominance-victory` 之后，因此本 change 的回归基线是"碾压胜利已生效"的那一版数据，对照时须注明。
