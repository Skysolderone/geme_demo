## Why

地图元素目前都是纯色方块和内置几何体（方块、圆柱、球）拼出来的：地砖没有厚度感和边角，缓坡和崖壁只有两种侧面颜色，水面像一块平板，浮岛底座和连体棋盘的外框也很简陋。整体读得清楚，但耐看度不够，重复感明显。负责人裁决（2026-10-03）：**保持现在游戏画面的明快配色，只在造型上精修**，并且整套地图元素都要配上对应的模型资源。对应设计文档 §20（视觉风格基准）。

本 change 写于 2026-10-04，早于链接模式、开放地图与新地表投放。2026-10-21 按开放地图重做规划：现行地图只有 `link:<种子>`——5 块 6–8 边长的主题出生棋盘按 3+2 两行紧贴成一张连通地图，锁定后整图可见；场景格不再绘制，棋盘档地图、通道与逐块台面已随旧地图删除。验收载体改为 `link:1` 与 `link:7`。

## What Changes

- 新增程序建模工具 `LowPolyMesh`，基于 Godot SurfaceTool，提供倒角板、分层侧面、多面岩块、细条等函数。顶点抖动和色差全部由变体号或坐标散列决定，不用随机数。
- 部件目录 `TerrainParts` 从现在的 11 类（装饰与设施）扩展为覆盖**链接图上全部地图元素**：
  - 地砖顶板（七种地表共用网格，按底色覆盖材质）、缓坡与崖壁侧面、砖缝衬底；
  - 河床与河岸石沿；
  - 桥、栅栏（重建）；
  - 棋盘内岩石与四种新地表、林地的点缀（重建）；
  - 底座外圈石沿、出生区嵌入亮条、连体棋盘外轮廓边框、浮岛岩层 / 垂岩 / 云团。
- 全部部件由 `--export-parts` 烘成资源，棋盘一律从资源加载；资源缺失时退回程序生成。
- 分五段实施：A 地块、B 水系与设施、C 障碍与装饰（含四种新地表点缀）、D 外框与底座、E 收尾。每段截图交负责人过目后再进下一段。
- **不变**：
  - 配色：沿用 `Visuals` 现有色板，只补少量衍生色；台面与占位颜色仍只取 Presentation 调色板；
  - 几何尺寸：格距、地砖边长、层高、水面下沉量都不动，拾取结果不变；
  - 一切规则、AI、地图生成与视图模型；
  - 判读约束：高度可辨、地表灰度可辨、装饰不遮挡判读、信息层压淡装饰；
  - 插旗阶段的占位轮廓、坐标标注字形与位置、棋盘格线与接缝样式。
- **BREAKING（画面）**：链接图的画面都会改变。既有规格里以"与改动之前逐像素相同"作验收的画面场景，改为只比较与本 change 无关的部分（单字母列标的字形与位置），或改为绘制调用数的前后对照。

## Capabilities

### New Capabilities
无。

### Modified Capabilities
- `visual-style-baseline`：
  - 新增「地图元素部件化」：全部地图元素经同一部件目录取得，有资源就加载，缺失时退回程序生成；
  - 新增「地块、侧面与水系的造型」：地砖顶板倒角与顶点色微差、缓坡和崖壁侧面有分层，深水呈河床与河岸石沿；
  - 新增「外框与底座的造型」：底座外圈石沿、出生区嵌入亮条、连体外轮廓边框与浮岛部件化，不遮挡判读与标注；
  - 修改「双字母列标不重叠」「大图渲染开销」中依赖"改动前画面"或已无对象的场景。

## Impact

- **前置 change**（均已归档）：`board-render-perf`（合批与材质归并）、`terrain-surfaces`（新地表点缀与部件导出）、`board-link-mode` / `open-map`（连体棋盘、外轮廓边框、锁定后整图）、`link-map-terrain`（棋盘内岩石）、`link-map-surfaces`（新地表投放到链接图）。
- **并行、非依赖**：`terrain-barriers`（未实施，改地图生成：河流 / 高台横穿棋盘、湖泊与岩区）。本 change 只按地形种类渲染，不读具体坐标；它合入后链接图的截图需重拍（见 design D8）。
- **受影响代码**：
  - `src/godot/scripts/` 下的 `BoardView`（地砖、侧面、水、底座、外框、浮岛改为取部件）、`LowPoly`（装饰与设施改用 `LowPolyMesh` 建模）、`TerrainParts`（目录扩展）、`PartExport`、`Visuals`（衍生色）；
  - 新增 `LowPolyMesh.cs`；
  - `src/godot/parts/terrain/` 全部重新导出。
- **不受影响**：`Siege.Core` / `Siege.Presentation` / `Siege.Sim` 不改代码；规则测试与决策序列基线不变；源码扫描类守门（Godot 层不含规则计算、占位轮廓灰度、禁手标记、棋子轮廓、坐标标注）照常通过。
- **验证**：
  - 每段截图（彩色 + 灰度）与人工检查清单（`art/map-elements-v2/`）；
  - Godot 四条 headless 自检退出 0，`--pick-check` 在 `link:1` 与 `link:7` 上通过；
  - 窗口模式下 `link:1`、`link:7` 锁定后静止帧的绘制调用数与改前对比不超过 1.2 倍；
  - 不跑批量对局（与对局结果无关）。

## Non-goals

- 不改配色方向，不向基准图的石砌台地风格靠拢（负责人裁决：保持现有画面精修）。
- 不改棋子模型（`PieceSilhouette` / `LowPoly.Piece` / `LowPoly.Prism`），不改 UI 面板。
- 不改水面流纹与瀑布的 shader 算法，只换河床和河岸的几何；瀑布的触发条件不改。
- 不改插旗阶段的占位轮廓。
- 不引入外部建模工具（Blender 等），不做贴图纹理，只用顶点色。
- 不做地形的随对局变化（季节、昼夜）。
