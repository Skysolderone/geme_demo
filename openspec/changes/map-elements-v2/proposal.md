## Why

地图元素目前都是纯色方块和内置几何体（方块、圆柱、球）拼出来的：地砖没有厚度感和边角，缓坡和崖壁只有两种侧面颜色，水面像一块平板，浮岛底座和棋盘外圈也很简陋。整体读得清楚，但耐看度不够，重复感明显。负责人裁决（2026-10-03）：**保持现在游戏画面的明快配色，只在造型上精修**，并且整套地图元素都要配上对应的模型资源。对应设计文档 §20（视觉风格基准）。

## What Changes

- 新增程序建模工具 `LowPolyMesh`，基于 Godot SurfaceTool，提供倒角方块、多面岩块、带顶点色深浅的面、棱柱、条带等函数。顶点抖动和色差全部由变体号或坐标散列决定，不用随机数。
- 部件目录 `TerrainParts` 从现在的 11 类（装饰与设施）扩展为覆盖**全部地图元素**：
  - 地砖顶板：七种地表，各 3 个变体；
  - 侧面：缓坡、崖壁；
  - 砖缝衬底；
  - 河床与河岸石沿；
  - 桥、栅栏；
  - 障碍与四种新地表的点缀（变体加多）；
  - 浮岛底座、外圈坐标板石沿、出生区嵌入亮条、棋盘档台面边框。
- 全部部件由 `--export-parts` 烘成资源，棋盘一律从资源加载；资源缺失时退回程序生成。
- 分五段实施：A 地块、B 水系与设施、C 障碍与装饰、D 外框与底座、E 收尾。
- **不变**：
  - 配色：沿用 `Visuals` 现有色板，只补少量衍生色；
  - 几何尺寸：格距、地砖边长、层高、水面下沉量都不动，拾取结果不变；
  - 一切规则与视图模型；
  - 判读约束：高度可辨、地表灰度可辨、装饰不遮挡判读、信息层压淡装饰；
  - 合批策略：障碍与场景面砖用 MultiMesh，地砖共用网格与材质。
- **BREAKING（画面）**：所有地图的画面都会改变。既有规格里以"与引入本条之前相同"作验收的几个画面场景，改为只比较与本 change 无关的部分（坐标标注字形、棋盘清单为空时不画台面、合批前后画面一致）。

## Capabilities

### New Capabilities
无。

### Modified Capabilities
- `visual-style-baseline`：
  - 新增「地图元素部件化」：全部地图元素经同一部件目录取得，有资源就加载，缺失时退回程序生成；
  - 新增「地块与侧面的造型」：地砖顶板倒角与顶点色微差、缓坡和崖壁侧面有分层，高度差 1 与 2 的侧面仍可区分；
  - 修改「棋盘台面的可视表现」「双字母列标不重叠」「大图渲染开销」中依赖"改动前画面"的场景。

## Impact

- **前置 change**：`board-render-perf`（合批）、`board-map`（棋盘档台面）、`terrain-surfaces`（新地表点缀与部件导出），均已归档。
- **受影响代码**：
  - `src/godot/scripts/` 下的 `BoardView`（地砖、侧面、水、底座、外框改为取部件）、`LowPoly`（各部件改用 `LowPolyMesh` 建模）、`TerrainParts`（目录扩展）、`PartExport`、`Visuals`（衍生色）；
  - 新增 `LowPolyMesh.cs`；
  - `src/godot/parts/terrain/` 全部重新导出。
- **不受影响**：`Siege.Core` / `Siege.Presentation` / `Siege.Sim` 不改代码；规则测试不变，守门测试（Godot 层不含规则计算、新地表判断唯一等）照常通过。
- **验证**：
  - 每段截图（彩色 + 灰度）与人工检查清单（`art/map-elements-v2/`）；
  - `--pick-check` 通过；
  - 窗口模式下的绘制调用数和帧耗时与改前对比不退化；
  - 不跑 200 局（与对局结果无关）。

## Non-goals

- 不改配色方向，不向基准图的石砌台地风格靠拢（负责人裁决：保持现有画面精修）。
- 不改棋子模型（`PieceSilhouette` / `LowPoly.Piece`），不改 UI 面板。
- 不改水面流纹 shader 的算法，只换河床和河岸的几何。
- 不引入外部建模工具（Blender 等），不做贴图纹理，只用顶点色。
- 不做地形的随对局变化（季节、昼夜）。
