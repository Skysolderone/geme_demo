## Context

现行地图只有 `link:<种子>`。锁定后 `BoardView.Build` 搭的是 5 块出生棋盘紧贴成的一整张连体地图；画布四周留白 2 格的场景格，场景格一律不绘制（board-link-mode D-b，自证行 `[batch] … 场景面砖 0 格、MultiMesh 0 个`）。现状拼法：

- **可落子格**：`AddTileStack` 逐格摆盒子——h=1 起每层垫一块铺满整格的侧面盒（第 1 层土色 `SlopeSide`、第 2 层岩灰 `CliffSide`），再垫一层压暗的薄衬底，最上面是 0.9 见方的面砖盒；
- **棋盘内岩石**（link-map-terrain 6.1，`ObstacleArt.BoardRock`）：障碍色地砖 + `rock` 部件，逐格节点；
- **深水**：`AddWater` 摆一块低于地砖的水面板，加流纹 shader；桥是 `bridge` 部件；
- **林地与四种新地表的点缀**：`TerrainParts` 部件，挂在装饰层 `_decoration`；
- **栅栏**：`fence_x` / `fence_z` 部件，立在两格公共边上；
- **出生区描边**：核心区外缘的盒子条，阵营色、不受光（自证行 `[zone] … 12 段`）；
- **连体棋盘**：棋盘内格线与接缝格线是墨色细条；外轮廓边框是中性色盒子条（自证行 `[plates] … 外轮廓边框 N 段，接缝格线 M 段，接缝边框 0 段`）；插旗阶段的占位轮廓另由 `AddPlaceholders` 画；
- **底座与浮岛**：底座是一块大盒子，下面是程序摆的岩层、垂岩、云团；瀑布只在河道通到画布边时挂，链接图画布留白 2 格，所以**现在从不触发**。

相关机制：

- 面砖材质按底色共用（`SurfaceOf`），并登记进压暗表：信息层打开时 `Refresh` 整批改它们的 `AlbedoColor`。
- 出生区淡染、明暗棋盘格是直接改底色实现的，所以会多出几份底色材质。
- 装饰节点在 `Refresh` 里被统一缩放，用来压淡装饰的对比度。
- 场景格的障碍合批（`AddObstacle` / `PartBatch`，board-render-perf D2）代码仍在，但链接图上 0 格。

验收载体（2026-10-21 用 `Siege.Sim map` 核对）：

| 图 | 用途 | 关键格 |
|---|---|---|
| `link:1`（24×18，无人值守缺省） | 主载体 | 缓坡 K4、U4（h1 挨 h0）；崖壁 S4–T4（h2 挨 R4 h0）；一格宽河 D8 E8 G8 + 桥 F8，另一段 K7 + 桥 K6；没有棋盘内岩石；浅滩 D9 G9 K8；岩台 P4 V4 V8；荒漠 K14 M14；沼泽 E15 G12；林地 C11–H16 一带；栅栏 N7–O8、M11–N12、L13–M14 |

## Goals / Non-Goals

**Goals**
- 链接图上的全部地图元素都有对应的部件资源，棋盘一律从资源加载，资源缺失时退回程序建模。
- 地砖有厚度和倒角，侧面分层，水是一道有石沿的沟，底座外沿和连体外框完整：整张地图读起来是一个沙盘。
- 判读、几何约定、拾取、压暗机制、接缝样式都不变。锁定后静止帧绘制调用数不超过改前的 1.2 倍。

**Non-Goals**
- 见 proposal：不改配色方向、棋子、UI、占位轮廓、水面与瀑布 shader，不用外部工具和贴图。

## Decisions

### D1 `LowPolyMesh`：程序建模工具

基于 SurfaceTool 的静态函数，全部输出 `ArrayMesh`，顶点带法线和顶点色：

| 函数 | 用途 |
|---|---|
| `BeveledSlab(size, bevel, shade)` | 顶面四边倒角的板（地砖顶板、外框、石沿） |
| `Strata(size, bands, jitter, seed)` | 侧面分层：按高度分若干条带，每条带顶点色不同，外沿按散列微微凹凸 |
| `FacetRock(radius, facets, jitter, seed)` | 多面岩块（岩石、碎石、垂岩）：低细分球按散列抖动顶点，平直着色 |
| `Ribbon(points, width)` | 细条（裂纹、水纹、芦苇等贴地或立起的条） |

棋子用的 `LowPoly.Prism` 不搬（棋子不在范围内；`六种棋子的轮廓语言Tests` 还钉着 `LowPoly.cs` 的规模）。

确定性：抖动和色差都取自 `Hash(seed, i)`。这里用整数散列，结果再换算成浮点偏移，不用 `Random`。同一 seed 产出逐字节相同的网格；验证方式是两次 `--export-parts` 到不同目录，产物把资源文件里引擎随机生成的外部资源编号、子资源编号与节点 `unique_id` 归一后逐字节相同（裁决 A2）。

顶点色只当**亮度系数**用，取值大约在 0.92–1.0（顶点色每通道 8 位存储，大于 1 的部分被截掉；裁决 A1 接受顶板平均略暗的现状），由 `shade` 和散列给出。材质打开 `VertexColorUseAsAlbedo`，最终颜色 = 材质底色 × 顶点色。这样：

- 按底色共用的材质仍然一色一份；
- 压暗表照常整批改底色；
- 出生区淡染和明暗棋盘格照旧改底色就能生效。

**否决**：把色差烘进顶点色、材质用纯白。这样每种底色都得一个网格，压暗也要改网格，与现有压暗表冲突。

### D2 部件目录扩展

`TerrainParts.Kind` 增加锚点约定，现有装饰类部件不变。新增的部件类如下（变体档数是初值，实施时可调）：

| 部件 | 档数 | 锚点 | 材质 |
|---|---|---|---|
| `tile_top`（七种地表共用网格） | 3 | 地砖上表面中心 | 由 BoardView 按底色覆盖 |
| `side_slope`（第 1 层侧面） | 2 | 该层带的顶面中心 | 内置土色系 |
| `side_cliff`（第 2 层侧面） | 3 | 同上 | 内置岩灰系 |
| `liner`（砖缝衬底） | 1 | 衬底中心 | 由 BoardView 按底色覆盖 |
| `bank_lip`（河岸石沿，一条边一件） | 3 | 水格边中点 | 内置 |
| `rim`（底座外圈石沿，一段一件） | 3 | 段中点 | 内置 |
| `zone_strip`（出生区嵌入亮条） | 1 | 格边中点 | 由 BoardView 按归属色覆盖 |
| `plate_frame`（连体外轮廓边框，一段一件） | 2 | 段中点 | 由 BoardView 按台面边框色覆盖 |
| `island_layer` / `island_spike` / `cloud` | 3 / 4 / 3 | 底座中心 / 尖顶 / 云心 | 内置 |

其余沿用现有部件：`rock`、`trees`、`desert`、`marsh`、`crag`、`shallows`、`fence_x`、`fence_z`、`bridge`，在段 B / C 重建，变体档数可增加（岩石 4→6）。`pines`、`ruins` 只服务场景格，链接图上 0 格，处理见裁决 M3。

"由 BoardView 覆盖材质"的部件，导出时带一个中性白材质；加载后由 BoardView 换成按底色共用的那一份。这保证压暗机制不变。台面边框色仍只取 Presentation 调色板（`BoardPlatePalette`，经 `Visuals.ToColor`），`Visuals.cs` 不手写台面 / 占位颜色字面量。

### D3 地块的拼法

`AddTileStack` 改为三步：

1. 按层取侧面部件：第 1 层取 `side_slope`，第 2 层取 `side_cliff`，变体按坐标散列；
2. 放 `liner`；
3. 放 `tile_top`，变体按坐标散列。

几何边界与现状相同：侧面铺满整格、顶板 0.9 见方、层高不变。崖壁读起来比缓坡陡，靠三件事：

- 崖壁带更深的岩缝；
- 顶边有一圈外突的岩沿（不超出格边）；
- 颜色沿用现有 `CliffSide`。

明暗棋盘格保留，仍然改底色。棋盘内岩石格照旧走 `AddTileStack`（障碍色）+ `rock`。

顶板变体按**全图坐标**散列，不按棋盘内坐标，所以棋盘接缝处不会出现可见的图案断层；棋盘内格线、接缝格线是墨色细条，压在顶板之间的缝上，样式不变。

### D4 水系

水格摆两样（裁决 B1：不加 `water_bed`——水体是铺满整格的不透明盒，水下的河床从任何角度都看不见，露出水面的河道两壁由石沿内侧承担）：

- 现有水面板加流纹 shader，保持不变；
- 每条"邻格不是深水"的边放一件 `bank_lip`。邻格不在本次视图里（连体棋盘外缘、画布留白）也算"不是深水"，河道在那里收口。

判断"这条边相邻的是不是水"，读的是视图模型里的格子地表：Build 时按格坐标建一张 `Dictionary<Coord, Surface>`，±1 查表，和现有瀑布代码的读法一样。这是渲染，不是规则；不调用 Core 的任何邻接 API，`Godot层不含规则计算Tests` 的违禁 token 不涉及。

桥与栅栏在段 B 重建：桥加栏杆、桥墩和板缝，栅栏加柱帽、横杆略下垂。外形尺寸不超过现有的包围盒，栅栏仍然只占边、不占格；对局中改造出的桥与栅栏取同一部件，新旧同形。

`terrain-barriers` 合入后，深水与崖壁会出现在外圈、接缝上，湖泊是 3–5 格成团的深水。上面的规则只看"四邻是不是深水 / 高度差几层"，不看格在棋盘的哪一圈，所以不需要另写分支。

### D5 外框与底座

- **底座外圈石沿 `rim`**：沿底座四周逐段摆放，坐标标注仍在原来的 h=0 平面上，字形和位置不变；石沿放在标注平面之外，或比标注平面低。
- **出生区描边**：改成嵌进地砖边缘的 `zone_strip`，仍用归属色、不受光；段数与 `[zone]` 自证行逐字相同。
- **连体外轮廓边框**：改成 `plate_frame`，高不超过现有 0.07、宽不超过现有 0.14，不遮挡边缘格；外轮廓段数、接缝格线段数与 `[plates]` 自证行逐字相同，接缝上仍然没有边框。单块棋盘的边框分支（链接图恒为一组，走不到）与插旗阶段的占位轮廓都不动——`AddPlaceholders` 里不得出现 `TerrainParts.`（`占位轮廓灰度Tests` 守门）。
- **浮岛**：`AddFloatingIsland` 的岩层、垂岩和云团改用部件。瀑布保留现有 shader、几何与触发条件。

### D6 合批与绘制调用

- 场景格障碍合批（`AddObstacle` / `PartBatch`）代码不动；链接图上 0 格。
- 地砖顶板、侧面、衬底仍是逐格节点，但网格只有"种类 × 档数"那么多份，材质仍按底色共用；每件部件尽量只有一个 surface。
- 验收时在窗口模式下记录 `[perf]` 读数（`link:1`、`link:7` 锁定后全局预览各一组），部件化前后各一次。绘制调用数超过 1.2 倍就要先优化（方式见裁决 M7）。

### D7 验收方式

- **自动**：
  - `dotnet build` 0 警告、`dotnet test` 全绿（含源码扫描守门）；
  - Godot 四条 headless 自检退出 0；`--pick-check` 在 `link:1`、`link:7` 上通过；
  - 搭建日志：资源数 = 全部、程序建模数 = 0；资源目录缺失时退回程序建模；
  - `[zone]`、`[plates]` 两行自证输出与改前逐字相同；
  - 两次 `--export-parts` 产物把资源文件里引擎随机生成的外部资源编号、子资源编号与节点 `unique_id` 归一后逐字节相同；
  - 同参数重复取图逐像素相同（水面区域除外）。
- **人工**：`art/map-elements-v2/README.md` 清单，含改前改后的对照图和灰度图，按规格里的场景逐项核对。
- 不跑任何对局批量统计。

### D8 与 `terrain-barriers` 的关系

`terrain-barriers` 改地图生成，会让所有 `link:<种子>` 变样。两条线互不依赖：

- 本 change 的截图与读数只在本分支内前后自比；
- 部件规则按地形种类与四邻写，不读具体坐标（D4）；
- 处理方式见裁决 M5。

## Risks / Trade-offs
