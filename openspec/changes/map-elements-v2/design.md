## Context

`BoardView.Build` 目前这样搭棋盘：

- **可落子格**：`AddTileStack` 逐格摆盒子——h=1 起每层垫一块铺满整格的侧面盒（第 1 层土色、第 2 层岩灰），再垫一层压暗的薄衬底，最上面是 0.9 见方的面砖盒；
- **深水**：`AddWater` 摆一块低于地砖的水面板，加流纹 shader；
- **障碍与地表点缀**：`TerrainParts` 部件，障碍按变体合成 MultiMesh（board-render-perf D2）；
- **场景格**（棋盘档）：铺满的面砖合成一个 MultiMesh；
- **出生区描边、棋盘台面边框**：盒子条；
- **浮岛底座**：程序摆的岩层、垂岩、云团与瀑布。

几个现有机制与本 change 相关：

- 面砖材质按底色共用（`SurfaceOf`），并登记进压暗表：信息层打开时 `Refresh` 整批改它们的 `AlbedoColor`。
- 出生区淡染、明暗棋盘格是直接改底色实现的，所以会多出几份底色材质。
- 装饰节点在 `Refresh` 里被统一缩放，用来压淡装饰的对比度。

负责人裁决（2026-10-03）：

- 范围：地块、水系与设施、障碍与装饰、外框与底座，四部分全做；
- 方向：保持现有明快配色，只精修造型；
- 做法：在 Godot 里程序建模，再导出成资源。

## Goals / Non-Goals

**Goals**
- 全部地图元素都有对应的部件资源，棋盘一律从资源加载，资源缺失时退回程序建模。
- 地砖有厚度和倒角，侧面分层，水是一道沟，底座和外框完整：整块棋盘读起来是一个沙盘。
- 判读、几何约定、拾取、合批和压暗机制都不变。绘制调用数不超过改前的 1.2 倍。

**Non-Goals**
- 见 proposal：不改配色方向、棋子、UI、水面 shader 算法，不用外部工具和贴图。

## Decisions

### D1 `LowPolyMesh`：程序建模工具

基于 SurfaceTool 的静态函数，全部输出 `ArrayMesh`，顶点带法线和顶点色：

| 函数 | 用途 |
|---|---|
| `BeveledSlab(size, bevel, shade)` | 顶面四边倒角的板（地砖顶板、台面边框、石沿） |
| `Strata(size, bands, jitter, seed)` | 侧面分层：按高度分若干条带，每条带顶点色不同，外沿按散列微微凹凸 |
| `FacetRock(radius, facets, jitter, seed)` | 多面岩块（岩石、碎石、垂岩）：低细分球按散列抖动顶点，平直着色 |
| `Prism(profile, depth)` | 现有 `LowPoly.Prism` 搬过来（棋子不动，仍调它） |
| `Ribbon(points, width)` | 细条（裂纹、水纹、芦苇等贴地或立起的条） |

确定性：抖动和色差都取自 `Hash(seed, i)`。这里用整数散列，结果再换算成浮点偏移，不用 `Random`。同一 seed 产出逐字节相同的网格。

顶点色只当**亮度系数**用，取值大约在 0.92–1.06，由 `shade` 和散列给出。材质打开 `VertexColorUseAsAlbedo`，最终颜色 = 材质底色 × 顶点色。这样：

- 按底色共用的材质仍然一色一份；
- 压暗表照常整批改底色；
- 出生区淡染和明暗棋盘格照旧改底色就能生效。

**否决**：把色差烘进顶点色、材质用纯白。这样每种底色都得一个网格，压暗也要改网格，与现有压暗表冲突。

### D2 部件目录扩展

`TerrainParts.Kind` 增加一个锚点约定，现有装饰类部件不变。新增的部件类如下（变体档数是初值，实施时可调）：

| 部件 | 档数 | 锚点 | 材质 |
|---|---|---|---|
| `tile_top`（七种地表共用网格） | 3 | 地砖上表面中心 | 由 BoardView 按底色覆盖 |
| `side_slope`（第 1 层侧面） | 2 | 该层带的顶面中心 | 内置土色系 |
| `side_cliff`（第 2 层侧面） | 3 | 同上 | 内置岩灰系 |
| `liner`（砖缝衬底） | 1 | 衬底中心 | 由 BoardView 按底色覆盖 |
| `scene_slab`（场景格铺面） | 1 | 上表面中心 | 覆盖 |
| `water_bed`（河床） | 2 | 水格上表面中心 | 内置 |
| `bank_lip`（河岸石沿，一条边一件） | 3 | 水格边中点 | 内置 |
| `rim`（外圈石沿，一段一件） | 3 | 段中点 | 内置 |
| `zone_strip`（出生区嵌入亮条） | 1 | 格边中点 | 由 BoardView 按归属色覆盖 |
| `plate_frame`（台面边框，一段一件） | 2 | 段中点 | 覆盖 |
| `island_layer` / `island_spike` / `cloud` | 3 / 4 / 3 | 底座中心 / 尖顶 / 云心 | 内置 |

其余沿用现有部件：`rock`、`ruins`、`pines`、`trees`、`desert`、`marsh`、`crag`、`shallows`、`fence_x`、`fence_z`、`bridge`。它们在段 C 重建，变体档数可增加（岩石 4→6、松树 7→8、遗迹 4→6）。

"由 BoardView 覆盖材质"的部件，导出时带一个中性白材质；加载后由 BoardView 换成按底色共用的那一份。这保证压暗机制不变。

### D3 地块的拼法

`AddTileStack` 改为三步：

1. 按层取侧面部件：第 1 层取 `side_slope`，第 2 层取 `side_cliff`，变体按坐标散列；
2. 放 `liner`；
3. 放 `tile_top`，变体按坐标散列。

几何边界与现状相同：侧面铺满整格、顶板 0.9 见方、层高不变。崖壁读起来比缓坡陡，靠三件事：

- 崖壁带更深的岩缝；
- 顶边有一圈外突的岩沿；
- 颜色沿用现有 `CliffSide`。

明暗棋盘格保留，仍然改底色。

### D4 水系

水格摆三样：

- `water_bed`：凹槽底，比现有水面略低；
- 现有水面板加流纹 shader，保持不变；
- 每条与非水格相邻的边放一件 `bank_lip`。

判断"这条边相邻的是不是水"，读的是视图模型里的格子地表，和现有瀑布代码的读法一样。这是渲染，不是规则，Godot 守门的违禁 token 不涉及。桥与栅栏在段 B 重建：桥加栏杆、桥墩和板缝，栅栏加柱帽、横杆略下垂。外形尺寸不超过现有的包围盒，栅栏仍然只占边、不占格。

### D5 外框与底座

- **外圈石沿 `rim`**：沿底座四周逐段摆放，坐标标注仍在原来的 h=0 平面上，字形和位置不变。
- **出生区描边**：改成嵌进地砖边缘的 `zone_strip`，仍用归属色、不受光。
- **棋盘档台面边框**：改成 `plate_frame`，凸起高度不超过 0.05，不遮挡边缘格。
- **浮岛**：`AddFloatingIsland` 的岩层、垂岩和云团改用部件。瀑布保留现有 shader 和几何。

### D6 合批与绘制调用

- 障碍继续合批，沿用 `PartBatch`（模板下每个子网格一个 MultiMesh）。
- 场景铺面继续合成一个 MultiMesh。
- 地砖顶板、侧面、衬底仍是逐格节点，但网格只有"种类 × 档数"那么多份，材质仍按底色共用。
- 新增调试开关 `--no-batch`：障碍与场景铺面改为逐格建节点，用来核对规格「合批不改画面」。

验收时在窗口模式下记录 `[perf]` 读数（v5、`board:1`、`board:1:n10`、`gen:12345:s1` 各一组），部件化前后各一次。绘制调用数超过 1.2 倍就要先优化：把同一网格、同一底色的地砖合成 MultiMesh，或者降低变体档数。

### D7 验收方式

- **自动**：
  - 守门测试照常通过；
  - `--pick-check` 在 v5、一张生成图和 `board:1` 上通过；
  - 部件化之后重复取图逐像素相同（水面区域除外）；
  - 搭建日志显示资源数 = 全部、程序建模数 = 0；
  - 资源目录缺失时退回程序建模。
- **人工**：`art/map-elements-v2/README.md` 清单，含改前改后的对照图和灰度图，按规格里的场景逐项核对。
- 不跑任何对局批量统计。

## 已知歧义与建议裁决

| # | 问题 | 建议 |
|---|---|---|
| O-1 | 顶板变体会让明暗棋盘格的规律变弱 | 保留明暗交替（改底色），变体只做 ±4% 的亮度细差，不盖过交替 |
| O-2 | 河岸石沿会不会让一格宽的河看起来变窄 | 石沿只占水格边缘 0.06，水面可见宽度不小于 0.78 |
| O-3 | 外圈石沿会不会压到坐标标注 | 石沿放在标注平面之外，或者比标注平面低；坐标标注不移动 |
| O-4 | 资源缺失时退回程序建模，画面会不会和资源版不一样 | 同一份建模代码，结果只差变体取模，可以接受 |

## 实施修正

实施中对上面的决定做了下列细化，裁决本身没有变。

| # | 对应 | 修正 | 原因 |
|---|---|---|---|
| F-1 | D1 | 亮度系数 1.0 在顶点色里存成 232 / 255，材质底色在线性空间乘回 255 / 232（`LowPolyMesh.Albedo`、`Visuals.Shaded` / `SetShaded`）。系数上限约 1.099 | 顶点色在显存里是 8 位（0–1），存不下大于 1 的系数。这样系数 1.0 的面与不带顶点色时同色（实测只差浮点舍入的 1 级） |
| F-2 | D1 | 压暗表每项多带一个"是否带顶点色"标记，带的经 `Visuals.SetShaded` 改色 | 底色里含 F-1 的增益，不能直接写 `AlbedoColor` |
| F-3 | D2 / D3 | 地块类部件不逐格实例化场景：`TerrainParts.ShapeOf` 每档取一次网格、局部变换与内置材质并缓存，棋盘逐格只建一个网格节点 | 节点数与改前相同（每格仍是侧面 + 衬底 + 顶板），同网格同材质照旧被渲染器合成一次绘制 |
| F-4 | D3 | 顶板与侧面除了按档数挑网格，还按格坐标散列转 0 / 90 / 180 / 270 度 | 朝向不增加绘制调用，3 档网格得到 12 种样子 |
| F-5 | D3 | 崖壁的"外突岩沿"做成最上一条带顶到格边、其余条带向内收进；岩缝是墙面上的深色竖条（共面），不挖几何 | 侧面不得越出整格；共面的色条不会在台阶处漏缝 |
| F-6 | D1 | `FacetRock` 带一个 `scale` 参数，把压扁 / 拉长烘进顶点 | 0.2 实测：带非均匀缩放的部件在 MultiMesh 与逐节点两种画法下受光不同（本机 Metal），段 C 重建岩石时用它消除 |
| F-7 | D7 | 导出时每件部件建两遍、逐项比对顶点数组，不一致记为失败 | 把"同一 seed 逐项相同"做成每次导出都跑的自检 |
| F-8 | — | 新增仅截图用的 `--shot-zoom=<档>`（须与 `--shot-cell=` 同用） | 给负责人看地块造型的近景 |

## Risks / Trade-offs

- **SurfaceTool 自建网格的面数比内置盒子多**：每类部件都要控制面数，比如地砖顶板不超过 40 个三角形；完成后记录总三角形数。
- **部件更细，大图上的帧耗时可能上升**：靠 D6 的读数兜底，必要时把地砖也合批。
- **画面改变会让既有截图类的人工清单失效**（`art/` 下各目录）：本 change 只更新自己的清单，旧目录保留作历史，不追溯重拍。
