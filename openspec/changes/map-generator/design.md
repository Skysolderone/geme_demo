## Context

`frontier-map` 已经具备：地图规格档（标准 / 边疆）与按档分流的静态校验、三个入口共用的"标识 → 地图"解析（`MapCatalog`）、手工边疆图 `siege-frontier-v1`（生成器写法：字符画 + 解析，确定性导出）、可推屏的相机与全局预览、图形版严格命令行。对局日志首部已有地图标识、`ZoneCount` 与候选格上限；回放按首部重建。

负责人要求：地图由种子随机生成，开局可选图。这与 `map-definition`「地图为设计师固定的静态数据」的字面冲突，也与 `frontier-map` design 里"否决程序生成——违反确定性约束"的判断相反。重新审视后，确定性约束要的是"同一输入同一结果、可回放"，并不要求"人手摆"；只要地图种子进公开信息与日志、生成过程满足 `.trellis/spec/core/determinism.md` 的全部条款，程序生成与确定性不矛盾。真正要守住的是：**地图一旦确定就不再变、对局种子不影响地图、地图种子不影响对局随机**。

约束：宽度上限 25 列（坐标记法）；边疆档预算 300–420 可落子格、出生区 5–8、单区 20–225、信物 14–24、据点 12–22；必死口袋、保护期容量、到五类目标可达等共用校验；`Profile` 不得被下游读取。

## Goals / Non-Goals

**Goals:**

- 一个纯函数式的生成器：`(地图种子, 参数) → MapData`，确定性、可测试、1 秒内出图。
- 生成图在三个入口、日志、回放、存档里与内置图一视同仁。
- 图形版开局能看着全局预览挑图、换种子。
- v4 与 `siege-frontier-v1` 行为零变化。

**Non-Goals:**

- 边长 15 的平台、突破 25 列；2 / 3 人生成图；标准档生成。
- 对称或"平衡优先"的生成；按跑局指标筛图。
- 地图编辑器。
- 节奏参数与 AI 针对生成图的调整。

## Decisions

### D1 生成分六步，每步只依赖上一步的结果与随机源

1. **摆平台（三条带）**：按参数取 N 个边长（5–9，从大到小编号）。中间一条带 = 中央广场 + 分居广场两侧、紧贴广场（隔 1 格为主、三成隔 2 格）的两个最小平台；两边各一条外围带放其余平台（每带 1–3 个）。带的走向（横带 / 竖带）、哪几个平台进哪条带、带内次序、带内与带间的余量怎么分、广场落在哪，全部由随机源定；平台两两至少隔 2 格、离地图外缘至少 2 格。边长组合带约束重采（外接面积之和有上限、信物格总数落在 14–24、三条带两个方向都摆得下），取到即必然摆得下——摆位本身不会失败（原因见裁决 11）。
2. **定中央广场**：中间带上一块 5×5 的 h=0 区域，尽量靠近地图中线，中央入口取其中心格。
3. **缓坡与连通**：每个平台 1–2 处 2–3 格宽的 h=1 缓坡（小平台第一处正对广场，其余平台第一处朝广场方向）；以各缓坡口与中央广场为结点，按曼哈顿距离建最小生成树并加 1–2 条冗余边；每条边用带方向状态的整数代价最短路取中线，沿中线刻 2 格（七成）或 3 格宽的 h=0 走廊。**走廊全长至少 2 格宽**：中线不走"怎么拓也拓不到 2 格"的窄缝；刻完逐格检查，不属于任何 2×2 过渡带方块的格就地补刻，补不出则本次尝试作废（1 格宽的走廊一枚子就能堵死）。
4. **主河与桥**（构造次序：缓坡 → 主河 → 走廊与桥，即本步的河道先于第 3 步的走廊）：一格宽的深水带，从一条边经一处"隘口"（两侧 7 格内都有平台或广场的空格）贯穿到对边，只流经尚未决定用途的格，拐弯加价（留出笔直河段），多数时候垂直于三条带流；要求两岸都有缓坡。走廊**只能在河道笔直处垂直过河**，在河上不拐弯，过河处与并排拓宽的那条道一并架桥，桥的两头一并刻开。于是一座桥（相邻桥格连成的一块）沿河的长度 = 走廊宽度 ≤ 3；桥不足 2 座时逼一条不走现成桥的走廊出来；仍不足 2 座、或桥格总数 > 10，本次尝试作废（原因见裁决 12）。
5. **填充与点缀**：平台、走廊、广场、河以外的格，按随机源在深水 / 障碍之间取；在走廊交汇口放 1–2 片林地与 1–2 段栅栏；平台内按 ≤ 20% 撒少量障碍（避免造出必死口袋：撒完即用口袋判定自检，不合格的那一格撤回）。
6. **布点**：营帐（每平台 1，取平台内离缓坡口最远的可落子格）、篝火（数量 = 平台数，放走廊上、优先交汇口与缓坡口外 2–3 格）、石碑（广场内 4 个、非林地）、信物（平台内按边长 1 或 2 个；公共 7 个：桥头优先标准档，广场中心高档）。据点与信物互斥。咽喉标注取全部缓坡口格与桥格（与 `siege-frontier-v1` 同口径）。

否决"噪声高度场 + 阈值"一类的连续地形生成：平台必须是规整矩形（负责人的参考图与"5×5 到 15×15"的表述），而且格数预算、口袋、容量这些离散校验用构造式方法更容易一次过。

### D2 随机源：独立于对局的地图随机源

生成器用一条只由地图种子（与尝试序号）决定的整数随机序列，算法与对局用的随机源同族（同一份实现，避免第二套 PRNG），但**不是** `GameSeed` 的子流——`GameSeed` 属于对局。接口契约：生成器不接收、也拿不到对局种子；对局流程不接收、也拿不到地图种子（它只拿到生成好的 `MapData` 与地图标识字符串）。守门：源码扫描生成器所在文件不出现 `GameSeed`；`MatchFlow` 及其下游不出现地图种子类型。

### D3 地图标识即地图的完整描述

`gen:<种子>[:p<N>]`，N 为缺省 6 时省略（规范化）。`MapData.Id` 就取规范化后的标识，于是日志首部、存档、批次配置、公开视图里现成的"地图标识"字段不用改结构就带上了地图种子。`MapCatalog.Resolve` 加一个分支：以 `gen` 开头的标识交给生成器；裸 `gen` 由调用方先取种子再解析（取种子的地方只有三个入口的最外层，Core 不读时钟）。

存档：若现存档里存的是整张地图数据则不用动；若只存标识，则恢复时按标识重建——由实现核实现状后取其一，规格只要求"恢复出的地图逐项相同"。

### D4 校验闭环与尝试序号

第 k 次尝试的随机源 = f(地图种子, k)，k 从 0 起，上限缺省 64。每次尝试结束跑 `MapValidator`（边疆档），通过即返回。尝试序号不进标识（同一种子永远落到同一个 k）。生成器版本若改动会让同一种子产出不同的图——这是回放的风险，由 D5 的内容摘要兜住。

### D5 日志首部加地图内容摘要

对地图导出文本取哈希，写入日志首部。回放重建地图后先比摘要：不同即报"地图不一致"并停止。内置图同样写摘要（顺带防住"有人改了内置图却没改标识"）。旧日志没有该字段时跳过比对（与 `ZoneCount`、候选格上限的回填口径一致）。

### D6 批量：每局换图与按边长统计

批量配置加"起始地图种子 + 每局换图"。此时平台编号跨局不可比，分析报告改按平台边长分组（5 / 6 / 7 / 8 / 9）统计被选次数与胜率——这正是"大小即取舍"要回答的问题，比在一张手工图上看 6 个平台更有说服力。

### D7 图形版选图：建局之前的一个阶段

`GameRoot` 现在在 `_Ready` 里直接建局。改为：命令行给了 `--map=` → 原路径；否则进入"选图阶段"——持有一个"当前候选地图"，用它搭棋盘（只搭地形，不建局）、相机切全局预览、HUD 显示选图面板；确认后才建 `MatchSession` 进入插旗。选图面板的状态机（当前选项、种子文本、平台数、非法输入提示、完整标识）放在零 Godot 依赖的表现层视图模型里，可单元测试；Godot 侧只渲染与转发输入。地图清单来自 `MapCatalog` 的内置表 + "随机图"这一项，界面不自带清单。

选图阶段要渲染一张没有对局的地图：`BoardView.Build` 现在吃的是默认棋盘视图模型（来自对局世界）。取法：为候选地图建一个"空盘面"的视图模型（与对局开局前的盘面同构），不为预览另写一套渲染。

编辑器运行参数：`project.godot` 里现有的 `--map=siege-frontier-v1` 会让编辑器运行跳过选图界面——本 change 完成时把它删掉，编辑器点运行即进选图。

### D8 种子输入框与相机按键的冲突

`frontier-map` 段 C 检查留过一句：相机键在 `_Input` 里先于控件处理，工程里当时没有文本输入控件；本 change 引入第一个。选图阶段 MUST 暂停相机按键的抢先处理（该阶段相机本来就锁在全局预览），否则 `W A S D` 与空格打不进输入框——虽然种子只有数字，但方向键与退格的行为也要正常。

## Risks / Trade-offs

- [能过校验但不好玩：平台挤在一侧、走廊绕远、某平台只有一个出口且正对大平台] → 本 change 只保证结构合法；出一份"50 个种子的布局速览"（文本图）给负责人过目，必要时在 D1 加软约束（如平台质心分布）。不做按跑局指标筛图。
- [校验通过率低导致生成慢] → 构造式生成本身避开了大部分失败原因（预算靠填充步调节、口袋在撒障碍时自检）；测试钉住"50 个种子中位数 ≤ 1 秒、无一耗尽 64 次"。
- [生成器以后改动会让旧日志回放不了] → D5 摘要让它响亮失败；需要长期保存的图用 `map` 子命令导出成文件。
- [AI 在没见过的布局上表现退化] → 已有候选格上限兜住耗时；质量问题留给后续。批量"每局换图"正好提供数据。
- [选图界面让无人值守脚本卡住] → 命令行给 `--map=` 即跳过；`--auto-demo`、`--pick-check`、`--screenshot` 未给 `--map=` 时缺省用 v4、同样跳过选图（保持既有自检命令不变）。

## Migration Plan

无数据迁移。旧日志、旧存档缺新字段按回填口径处理。回滚 = 不使用 `gen:` 标识；内置图行为不变。

## Open Questions

- 平台边长到 15 与突破 25 列：取决于坐标记法怎么扩，另起 change。
- 是否要"收藏种子"：先靠选图界面显示的完整标识手抄，够用再说。

## 裁决记录（已确认）

以下 1–7 由项目负责人于 2026-09-20 确认；执行方式：顺序分段、单 agent（段 A → B → C，每段实现后检查）。

1. **整张布局都随机**：平台数量 / 大小 / 位置、过渡带走向、河道与桥、林地栅栏、据点与信物布点。平台仍是矩形高台，小平台仍倾向靠中央。
2. **生成后必须通过现有边疆档校验**；不通过就用同一种子派生下一次尝试，全过程确定性——同一种子永远同一张图，跨机器一致。
3. **地图种子与对局种子互相独立**；地图种子进公开信息与日志首部，回放按它重新生成地图。
4. **选图**：图形版加开局选图界面（v4 小图 / 手工边疆图 / 随机图；随机图可输种子、"换一张"；背景用全局预览）；终端与批量用 `--map gen:<种子>`，不给种子就随机一个并打印出来。
5. **可调参数**：平台数 5–8（缺省 6）；平台边长仍 5–9；图尺寸固定 25×30。
6. **手工图 `siege-frontier-v1` 保留**，作为批量跑局的对照基准。
7. **不做对称**，延续"大小即取舍"；每张图生成后仍出各平台的距离报告。

**规格落地时的补充判定（主会话代定，待追认）**
8. 日志首部加地图内容摘要，回放时地图不一致即在首部报错停止（D5）。
9. 批量"每局换图"时，平台统计改按边长分组（D6）。
10. 无人值守模式（`--auto-demo` / `--pick-check` / `--screenshot`）未给 `--map=` 时缺省 v4 并跳过选图；本 change 完成时删掉 `project.godot` 里的编辑器运行参数，编辑器点运行即进选图界面（D7）。
11. **摆位改为"三条带"而非逐个拒绝采样**（段 A 实测）：25×30 扣掉 2 格外缘、平台两两隔 2 格、小平台贴广场之后，跨带方向只剩十几格余量，逐个随机落点九成以上放不下；三条带 + 边长组合约束重采则取到即摆得下。后果：两个最小平台总在广场两侧，其余平台总在两条外围带里。负责人 2026-09-20 接受。
12. **桥长上限与走廊宽度下限**（负责人 2026-09-20 要求，段 A 检查落地）：任一座桥沿河 ≤ 3 格、桥格总数 ≤ 10；走廊全长 ≥ 2 格宽，局部宽于 3 格可以接受。实现上为此把主河挪到走廊之前——走廊网刻好之后再找河道时，带与带之间只有 2 格、整条都是走廊，河只能顺着走廊流（实测"代价 + 硬约束"的做法首次尝试通过率只有 3–17%，且有种子耗尽 64 次）。走廊宽度的可测口径有两条、同时成立：① 每个过渡带格属于某个四格全是过渡带格的 2×2 方块；② 拿掉任何一个过渡带格，每个平台仍能沿气边走到中央入口（含栅栏的阻隔——因此栅栏只放在至少 3 格宽处，放不下时退到中央广场内）。缓坡口与桥头不设豁免。
13. **存档也写地图内容摘要**（段 B 检查落地）：恢复时标识相同再比摘要，不同即抛"地图不一致"；旧存档缺字段跳过并可查知。`map --out` 拒绝写 `maps/` 下与内置图同名的文件（无论是否已存在——不存在时写进去等于伪造权威文件）。取地图种子的时钟来源在 Sim 入口可注入，测试不依赖墙钟。
14. **`--pick-check` 逐格居中层的口径**（段 C 实测、段 C 检查收紧，已写进 `frontier-map` 的 viewport-camera 规格）：25×30 的图在最远缩放下注视点纵深方向被夹取，贴近远边几行居中不了、视线变浅，紧贴 h=2 平台身后的 h=0 格心被真实遮住。只有"纵深被夹取、落在注视点远侧、拾到正前或斜前一行更高更近的格"记为遮挡；并新增兜底"每个可落子格至少在一种缩放下严格选中自身"。对玩家的含义：最远缩放下最上面几行里紧贴高台身后的低地格点不到，拉近即可。多位姿层的角位姿允许空视野。
15. **`--map-select`**：仅用于截图与无人值守自检，是"给了地图选项 MUST 跳过选图"的显式例外；配 `--auto-demo` 自动走一遍选图并核对（含"换一张"8 次后棋盘节点数不变、选图后建局与直接 `--map=` 建局逐行相同）。
16. **内置图的显示名登记在 `MapCatalog` 内置表**（"标准图 13×13"、"边疆图 25×30（手工）"），界面层不带对照表；**地图种子统一经 `GeneratedMapId.FriendlySeed` 折成九位以内**（选图"换一张"、Godot 裸 `--map=gen`、Sim 的时钟取种三处同一函数），不再与对局种子长得几乎一样；无人值守模式下不更新悬停读数。
