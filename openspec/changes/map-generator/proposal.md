## Why

`frontier-map` 给出了一张手工制作的多平台大图 `siege-frontier-v1`。负责人在试玩后提出：地图要能由**种子随机生成**，并且开局时**可以选图**（小图、手工大图、随机图，随机图可换种子）。一张手工图玩几局就背熟了，平台布局、河道与资源位置每局不同，"选出生点即选策略"才立得住。

现行 `map-definition` 写明"地图为设计师固定的静态数据，MUST NOT 随机生成"，`frontier-map` 的设计也据此否决过程序生成。本 change 在边疆档下放开这一条：地图可以由**地图种子**确定性地生成，生成结果仍是一份不可变的静态地图数据，仍须通过边疆档的全部静态校验。

对应设计文档章节：§3（地图与出生区）、§13.1（公开信息）。对局规则不改。

前置 change：`frontier-map`（未归档，两者不冲突：本 change 复用其规格档、校验分流、选图入口、相机与全局预览）。

## What Changes

- 新增**确定性地图生成器**：输入地图种子与生成参数（平台数 5–8，缺省 6），输出一张 25×30 的边疆档 4 人地图——矩形 h=2 平台（边长 5–9，小平台倾向靠中央）、2–3 格宽的过渡带把平台连成一片、一条贯穿的主河与桥、林地与栅栏、按规则布点的据点与信物。同一种子与参数在任何机器上得到逐字节相同的地图。
- 生成闭环：生成结果 MUST 通过边疆档静态校验；不通过则用同一地图种子派生下一次尝试，尝试次数有上限，全过程确定性。
- **地图种子与对局种子互相独立**。地图标识形如 `gen:<种子>[:p<平台数>]`，是完整的、可复现的地图描述；它进入公开信息、对局日志首部与存档，回放按它重新生成地图。
- 三个入口都能用 `gen:<种子>` 选图；`gen`（不带种子）随机取一个种子并打印出来。
- 图形版新增**开局选图界面**：列出 v4 小图、手工边疆图、随机图；随机图可输入种子、"换一张"、调平台数，背景用全局预览显示当前选中的图，确认后进入插旗。命令行给了 `--map=` 时跳过该界面。
- **BREAKING（规格层）**：`map-definition`「地图为设计师固定的静态数据」放宽——边疆档地图允许由地图种子生成；标准档地图与"对局内地形不随机变化"不变。

**Non-goals（明确推迟）**

- 平台边长到 15、突破 25 列 → 先裁决坐标记法扩展，另起 change。
- 生成 2 / 3 人图、标准档小图 → 另起。
- 对称 / 严格公平的生成模式、按平衡指标筛图 → 依据跑局数据另起。
- 地图编辑器、把生成结果手工微调后保存为内置图的工作流（`map` 子命令可导出 JSON，已够用）。
- 生成图上的节奏参数调整 → 与 `frontier-map` 的验证结论一起另起。

## Capabilities

### New Capabilities

- `map-generation`：地图种子、生成参数、确定性、布局规则、校验闭环、地图标识格式。
- `map-selection`：图形版开局选图界面（列表、种子输入、换一张、平台数、全局预览、确认）。

### Modified Capabilities

- `map-definition`：「地图为设计师固定的静态数据」放宽为"内置图由设计师固定；边疆档允许由地图种子确定性生成；任何地图在对局中不变"。
- `simulation-harness`：各入口的地图选项接受 `gen[:<种子>[:p<N>]]`；批量跑局可按"每局一张生成图"配置；回放按日志首部的地图标识重建地图。
- `match-setup`：公开信息包含完整的地图标识（对生成图即含地图种子与参数）。

## Impact

- `Siege.Core/Board/Maps`：新增生成器；`MapCatalog` 解析 `gen:` 标识；`GameSeed` 或独立的地图随机源（与对局的随机子流完全隔离）。
- `Siege.Sim`：`--map gen[:seed]`、批量配置的"每局换图"选项、`map` 子命令打印 / 导出生成图、`Replayer` 重建地图。
- `src/godot`：开局选图界面（新 HUD 面板 + `GameRoot` 在建局前的一个阶段）、`LaunchArgs` 无 `--map` 时进入选图。
- 现有 1085 项测试 MUST 保持全绿；v4 与 `siege-frontier-v1` 的行为零变化。
- 风险：生成器产出"能过校验但不好玩"的图（孤立大平台、过长的过渡带）；校验通过率过低导致生成慢。
