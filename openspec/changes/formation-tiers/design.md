## Context

军势公式 `⌊(基础 + 位置加值) × 1.5^倍增子数量⌋` 已经不封顶，但实测终局棋串规模为 1 枚 46%、2 枚 26%、3–4 枚 20%、5–7 枚 3%、8 枚以上 2%，倍率只放大两三枚子。把四种候选规则套在同一批 10 局终局盘面上的静态推算（棋没有重下）：

| 方案 | 人均势力 | 冠军均值 | 最大单串 | 冠军 / 亚军 |
|---|---|---|---|---|
| 现行 | 65 | 98 | 106 | 1.47 |
| **3 / 5 / 8 / 12，每级 ×1.5，连乘（选定）** | 119 | 227 | 358 | 2.06 |
| 2 / 4 / 6 / 9，每级 ×1.5 | 140 | 277 | 410 | 2.05 |
| 3 / 5 / 8 / 12，每级 ×2 | 215 | 469 | 850 | 2.77 |
| 3 / 5 / 8 / 12，查表 ×1.5 / 2 / 3 / 4 | 112 | 208 | 318 | 1.99 |

约束：计分一律任意精度整数、不经浮点；势力只评价当前盘面；公开视图结构上不含私有字段；规则一变，权重先改标"未校准"；每个配置跑局不超过 20 局；本机 `dotnet test` 原有 11 条日志黄金值为红（平台原因），判据是失败集合不变。

## Goals / Non-Goals

**Goals:** 让连成大棋串产生成档的数值跳升；新旧规则可在同一份代码里对照；旧存档、旧日志与既有回归基线不被改写。

**Non-Goals:** 不做防滚雪球；不重扫权重；不改其他棋子与信物。

## Decisions

### D1 阵型阶数

阶数 = 棋串棋子数达到的门槛个数，门槛 3 / 5 / 8 / 12：1–2 枚为 0 阶，3–4 枚一阶，5–7 枚二阶，8–11 枚三阶，12 枚及以上四阶（封顶）。棋子数按整条棋串、不分类型、不分所有者以外的任何条件。门槛表只有一处定义。

`倍率指数 = 倍增子数量 + 阵型阶数`；倍率仍用精确整数运算（分子 3^指数、分母 2^指数），整体乘在"基础 + 位置加值"之上，逐串向下取整一次。阵型随盘面实时重算：被提子、被立栅分裂后棋子数变少即降阶。

备选：单独一张倍率表再与倍增子相乘（否：规则多一张表，数值结果与连乘相差不大，见上表）。

### D2 计分规则版本

对局配置新增一项"计分规则版本"：v1 = 阵型阶数恒为 0（与本 change 之前逐步相同），v2 = 按 D1。新局缺省 v2；属于始终公开信息；写入存档、日志首部、批次配置；恢复不含该字段的旧存档、回放不含该字段的旧日志按 v1。做法与内容集相同，两者相互独立（四种组合都合法）。

对局内的一切计分——结算后的势力快照、批次预演、禁手预筛里的结算、AI 评价、专家前瞻、终端与图形版的显示——MUST 使用该对局的版本。计算入口保留不带版本的形态时，其语义固定为 v1 并在入口说明里写明；**产品代码不得调用不带版本的形态**（源码扫描守门），它只留给按设计文档旧算例直接构造盘面的测试。

既有的回归与黄金值测试（"与改动前逐步相同""逐字节不变"一类）改为显式指定 v1，不重录；v2 另配自己的算例测试。

备选：全局直接改公式（否：既有算例与黄金值要大面积重写，本机 11 条黄金值本来就是红的、无法在本机重录验证；也失去新旧对照的手段）。

### D3 势力明细与日志

每条棋串的明细新增阵型阶数（0–4）；"倍增子数量"保持原义（倍增子的枚数），"倍率"是总倍率。明细可复算：`⌊(基础 + 位置加值) × 1.5^(倍增子数量 + 阵型阶数)⌋ = 军势`。

日志首部写计分规则版本；棋串条目写阵型阶数（缺该字段的旧日志读作 0）。分析端凡是由倍增子数量还原倍率的地方，改用"倍增子数量 + 阵型阶数"。日志的 Schema 号按既有的"加可选字段"的做法处理，不让旧日志失效。

### D4 AI

评价函数与搜索不改：各维取"结算后 − 开始前"的势力增量，跨过门槛的跳升自然进入势力维。九维权重、停手阈值 20、2 人图专属权重都是在 v1 计分下定的，注释与设计文档改标"未校准（v2）"。AI 不做跨门槛的多步规划，属已知限制。

### D5 算式与呈现

- 完整算式（势力层 / 预演）：`（基础 5 + 位置加值 2）× 1.5 × 阵型 2.25 = 23`；阵型 0 阶时不写阵型因子，文案与现在逐字相同。
- 短算式（军势揭示）：`(5+2)×1.5×2.25 = 23`，倍增因子在前、阵型因子在后；只列非 1 的因子。
- 军势揭示的步骤：基础 →（加值非零）`+加值` →（有倍增子）`×倍增倍率` →（阵型 ≥ 一阶）`×阵型倍率` →（有以上任一项）`= 军势`。档位规则不变（末步取军势的档，往前逐步降一档）。
- 势力层倍率热区的显示档位：`min(倍增子数量 + 阵型阶数, 3)`。
- 终端版的军势算式与图形版同一处生成或同一口径。

全部 `siege-4p-base-v5`、4 名标准 AI、内容集 v2、种子 1–20、每批 20 局：

|---|---|---|
| R1 | v1 | 20 |
| R2 | v2 | 20 |
| R3 | v2 | 10 |
| R4 | v2 | 40 |

报告：截断数、整局无提子局数、平均结束大回合、提子数、终局棋串规模分布、人均 / 冠军势力、冠军 / 亚军、落子所在棋串军势与行动方军势增量的分布（用于重定呈现五档阈值）。停手阈值是否改动、呈现阈值取值，带数据交负责人裁决。

## 与其他 change 的接口契约

- **输入**：`more-pieces-relics` 的对局配置与存档版本做法；`restore-go-core-rules` 的倍率精确整数运算。
- **输出**：势力明细多一项阵型阶数；对局公开视图多一项计分规则版本；日志首部与棋串条目各多一个字段；批次配置多一项。
- **对呈现层的契约**（`tiered-number-show`）：军势揭示从明细读阵型阶数，不自己数棋子；数值档位的阈值仍只有一处，重定只改那一处。
- **不变**：领地分、位置加值七项来源、逐串取整、同形判重、活形、终局判定。

## 已知歧义与建议裁决

| # | 歧义 | 裁决 |
|---|---|---|
| A1 | 弃赛者遗留的棋串是否有阵型 | 有：规则对盘面上所有棋串一视同仁，与其余计分口径一致 |
| A2 | 铁链子（每枚 +棋子数 − 1）与阵型都奖励规模，是否重复 | 接受：铁链是位置加值、阵型是倍率，叠加是有意的；内容集 v1 没有铁链 |
| A3 | 图形版自动演示的 53 帧基线 | 新局缺省 v2，AI 走法会变，帧数变化是预期；重记基线并写明原因。拾取自检不受影响 |
| A4 | 带入带出的名次补给点 | 只看名次，不受数值放大影响 |
| A5 | 出局判据"曾有正势力、之后降到 0" | 不受影响：阵型只放大正数 |
| A6 | v1 的对局里显示什么 | 阵型阶数恒 0，算式与揭示与本 change 之前逐字相同 |
| A7 | 12 枚以上是否继续升阶 | 不升，四阶封顶（负责人确认的初值第 3 条） |
| A8 | 分析端"各棋子势力占比"里，阵型多放大出来的部分归谁 | 不归任何棋子类型（与高地加值同样处理）；倍增子只计它自身放大的那份。按 D3 字面会把阵型部分整块算给倍增子，夸大倍增子。代价：v2 局里未归因的份额上升，各类型占比之和小于全部军势（实施阶段定） |
| A9 | 倍率峰值记录按什么取 | 仍按倍增子数量取峰值，阵型阶数随行记录（实施阶段定） |

## Risks / Trade-offs

- [滚雪球：静态推算冠军 / 亚军由 1.47 升到约 2.06] → 负责人已知并接受；R2 的实测值写进报告。
- [AI 权重失准，对局变长或提子变少] → R1 / R2 对照与停手阈值两档复核；结果差则带数据请裁决，不自行改权重。
- [本机黄金值测试原本就红，无法在本机证明 v1 完全不变] → 既有回归测试显式钉 v1；本机判据为失败集合不变；需在 Windows 机上复核一次全绿。
- [不带版本的计算入口被产品代码误用，悄悄按 v1 计分] → 源码扫描守门 + 变异。

## Migration Plan

旧存档与旧日志缺字段即 v1，无需迁移。回滚：把新局缺省改回 v1 即恢复旧数值，存档与日志格式保持兼容。
