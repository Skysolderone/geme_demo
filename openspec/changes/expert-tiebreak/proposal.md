## Why

`10-21-expert-diagnosis` 在开放地图（`link:1..20`、座位 1、各 20 局，基于 99766f0）上重测专家强度：预设专家（一层前瞻）与高难持平（配对 7 / 7 / 6）；显式打开多样补充 S 8 与两层权重 λ 1000‰ 的专家方向仍为负（4 / 9 / 7，平均名次 2.70 对 2.40）。归因的两条主因都在专家专属的前瞻里：

1. **两层加分量级过大**：λ 1000‰ 时最大两层加分约为首候选自身总分的 61%，157 次改选中 56 次是"一层分数更低、靠两层加分胜出"，且改选后多半少放 1–2 枚（43 少 / 5 多）。
2. **构筑期改选多为噪声**：第 1–3 大回合不可能跨接缝提子，模拟回应几乎不区分候选（18 次构筑期改选中 11 次全部候选的回应相同），改选主要由 S / λ 驱动，只给开局起点加了随机偏移。

负责人 2026-10-21 裁决（修法 A，裁决 1–12 全部按推荐，见 design.md「裁决记录」）：专家在构筑期不前瞻；两层加分不再加进前瞻后分数，改为一层分数**容差带**内的平局裁决项，带宽小扫档后再定是否写入预设。

对应设计文档章节：§15.2（难度分级、专家难度的一层前瞻、近似两层）、§15.1（公平信息边界，不变）、§19 第 4 项（多层搜索仍不做）。

前置 change（均已归档）：`expert-lookahead`（v1.16，一层前瞻、前瞻记录）、`expert-strength`（v1.18，多样候选、近似两层、预设退回一层）、`open-map`（v1.28，构筑期 = 第 1–3 大回合只在自己棋盘落子）、`cycle-stop`（v1.29）、`fence-eye-rule`（v1.32，AI 评价版本 7）。

## What Changes

- **构筑期不前瞻**（全部前瞻宽度 > 0 的专家，含预设）：决策起点的大回合小于构筑期大回合数（3），或等于 3 且本大回合行动顺序中专家之后仍有在局玩家时，专家直接取高难的选择——不做多样补充的排除重跑、不模拟、不做两层扫描；前瞻记录状态为"不前瞻"。第 3 大回合末位的专家（下一名对手在第 4 大回合全图行动）照常前瞻。
- **两层平局裁决**：**BREAKING**（只对显式给出两层权重 > 0 的配置）——两层加分不再与一层分数相加。前瞻后分数即一层分数；新增搜索配置"两层平局带宽" B（非负整数，加权总分单位，缺省 0）：一层分数不低于"最高一层分数 − B"的候选为平局集，平局集内取两层加分最大者，仍并列取前瞻集靠前者。B = 0 时只在一层分数严格相等时由两层加分裁决。两层权重 λ 只作开关与记录口径（λ > 0 才做两层扫描）；原"相加"模式删除，不再可达。B > 0 而 λ = 0 的配置被拒绝。
- **配置与记录**：B 为 0 时不写入批次配置记录与日志首部（三档旧难度与专家预设的首部逐字节不变）；前瞻记录的"前瞻后分数"改为等于一层分数，两层加分照常单独记录；缺 B 的记录按 0 读。
- **AI 评价版本 7 → 8**：专家走法改变；简单 / 标准 / 高难三档决策、随机消费与 5 份决策序列基线**不变**。旧日志（版本 7）回放按既有规则报版本不符。
- **扫档与扩样**：B ∈ {0, 20, 60} 三档各 20 局（座位 1 专家 W 4 / S 8 / λ 1000 / B，其余 3 高难，`link:1..20`，种子 1–20）；同一提交重跑 H（4 高难）与预设专家各 20 局作对照。选档准则：截断 ≤ 1 / 20 → 与 H 配对"好 − 差"最大 → 平均名次 → 单小回合耗时中位数 → B 小。最优档"好 − 差" > 0 且平均名次不高于 H 时，在种子 21–40 上扩样一组（最优档 + H，40 局），方向仍为正才写入专家预设；否则预设只带构筑期不前瞻，S / λ / B 继续只作可配置项。单批不超过 20 局，合计新跑 100 局（触发扩样再加 40 局）。
- 设计文档 v1.32 → v1.33：§15.2 专家段改写（构筑期不前瞻、两层平局裁决、扫档与扩样结果）；`openspec/ROADMAP.md` 第 2 项、`HANDOFF.md` 同步。

## Impact

- **Siege.Core**：`AiSearchConfig`（新字段两层平局带宽、`Validated()` 拒绝负数与"B > 0 而 λ = 0"、序列化为 0 不写出）；`ExpertLookahead.Choose`（构筑期判定、选择规则）；`EvaluationBreakdown.Version` 7 → 8；预设是否改值由扫档结论决定。
- **Siege.Sim**：日志首部与 `config.json` 的新字段读写；分析与回放无新逻辑（前瞻记录字段不变，语义按规格）。
- **测试**：用到第 2 / 3 大回合前瞻局面的既有用例（`前瞻中的下一名对手Tests` 3 处 `AtRound(2)`、`前瞻的近似两层加分Tests` 2 处 `AtRound(3)` 等）按新规格改到全图阶段或改为断言"不前瞻"；钉相加模式的两层用例改为平局裁决断言；专家 G1 黄金值、前瞻记录黄金值、前瞻计时局面集在出现差异时重钉，首个分歧须落在构筑期或平局裁决上。
- **Godot / 终端**：不改；选专家得到新预设。
- **基线**：简单 / 标准 / 高难决策序列 5 份、链接图黄金哈希不得变。

- 对手模型对齐（修法 B：模拟回应改用高难口径）——另开 change，A 之后单独实测。
- 改动多样候选（S 的规则）、前瞻宽度 W、九维权重、停手阈值、停滞 K。
- 多层搜索、征募阶段前瞻（§18.2、§19 第 4 项仍不做）。
- 地图改动：`terrain-barriers` 在本 change 合入 main 之后再实施（两者都要重钉基线，裁决 12）。
- 200 局与超过 20 局的单批。
