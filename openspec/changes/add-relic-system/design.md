## Context

信物层同时承担三件事：对局的唯一随机源、信息的不对称来源（未知 → 永久公开）、以及全部构筑参数的供给。设计文档 §8 给出了权重表，§7.3 给出了发现与控制规则，§5.1 给出了快照时机。三者之间有几条容易被实现"顺手抹平"的边界：

- **揭示与授予是两件事**：第一次被覆盖就永久公开，但只有控制才生效。实现上如果把两者写进同一个分支，很容易写成"揭示者获得效果"。
- **快照是一次性读取**：小回合开始时读一次，本回合内的控制变化不影响已生成的参数。这是"先手玩家夺走后手信物，后手本大回合拿不到"这条规则的来源。
- **先锋的读取时机与其他五类不同**：它在大回合结束时读，因为它的消费者是"下一大回合顺序"而不是"本小回合参数"。

本轮规格保持实现无关。

## Goals / Non-Goals

**Goals:**
- 种子驱动、完全可复现的一次性生成。
- 区域强度预算保证出生区公平，同时不退化为固定组合。
- 揭示 / 控制 / 生效三者语义严格分离。
- 快照读取时机（含先锋的例外）有显式测试。
- 控制判定复用唯一覆盖查询，不出现第二套覆盖语义。

**Non-Goals:**
- 不实现征募面板、手牌槽交互与整类弃牌的账目。
- 不实现先手值公式与顺序生成。
- 不实现信物层 UI 与"将揭示"占位。
- 不引入新信物类型。

## Decisions

**D1：生成分两阶段——先按权重抽类型，再按区域预算校正强度。**
第一阶段对每个信物格独立按其所在分区的权重表抽取类型（含流派徽记绑定的棋子类型）。第二阶段计算各出生区的总稀有度，若差值超过容差，则在该区内做**最小改动的重抽**（优先替换稀有度偏离最大的那一枚），直到收敛或达到重试上限。
理由：纯权重抽取无法保证 §8.2 要求的"各出生区总稀有度接近"；纯预算分配又会让组合固定化，违背"具体组合仍具有随机性"。两阶段是两个约束的最小交集。
代价：生成可能需要多轮重抽。必须设重试上限并在超限时以确定性方式收敛（而非死循环），否则种子复现性会被破坏。

**D2：稀有度用权重的倒数作为基准分。**
出生区权重表中，先锋 5% 最稀有、流派徽记 45% 最常见。以"1 / 权重"作为每类信物的稀有度分，高阶 +2 结构信物按 2 倍计。这样 D1 第二阶段的"总稀有度"是一个可直接比较的标量。具体容差值先给初值，由跑局回归（§17"出生区随机资源是否造成显著胜率差异"）校准。

**D3：揭示状态与控制状态分开存储。**
`已揭示`是单调布尔（一旦为真永不回退），`控制者`是每次结算重算的派生量。把两者放在同一字段（例如用"控制者为空表示未揭示"）会立刻制造 bug：无人控制的已揭示信物无法表达。

**D4：控制判定不自己算覆盖。**
直接调用 `add-territory-power` 的唯一覆盖查询，加上"该格是否被占据"的盘面查询。两个输入之外本层不做任何邻接遍历。这是防止 §7.2 与 §7.3 出现语义分叉的硬约束，需要有交叉一致性测试兜底。

**D5：效果快照是不可变值对象。**
小回合开始时生成一份快照（展示数、选取数、类型槽、部署上限、徽记权重调整），小回合内任何流程只读它，不重新查询信物控制。这样"本回合新占信物不生效"成为结构性保证，而不是靠每个消费点自觉。
先手修正 MUST NOT 放进这份快照——它由大回合结束时的另一次读取产生，放进来只会诱导误用。

**D6：高阶流派徽记表达为"数量 2"而非"强度 2"。**
§8.1 说高阶徽记"等效为两枚普通徽记"，而徽记的权重公式是 `基础权重 × (1 + 0.75 × 徽记数量)`（§9.1）。用数量表达可以直接代入公式；用强度表达则需要在公式里额外处理，容易出错。

**D7：兵站缩水只在快照中标记"超限几种"，强制弃牌由手牌层执行。**
本层不碰手牌账目。快照给出合法槽位数与超限数，`add-recruit-hand` 负责阻断征募直到合法。

## 接口契约

**输入：**

| 输入 | 来源 |
|---|---|
| 信物格坐标与强度预算分区 | `add-board-core`（地图数据） |
| 对局种子 | 对局初始化 |
| 唯一覆盖查询、格占据查询 | `add-territory-power` / `add-board-core` |
| 结算触发点（第 4 步揭示、第 5 步重算控制） | `add-batch-deployment` |
| 小回合开始 / 大回合结束事件 | `add-match-flow` |
| 玩家状态（参赛 / 已弃赛 / 已出局） | `add-match-flow` |

**输出：**

| 输出 | 消费者 |
|---|---|
| `效果快照`（展示数、选取数、类型槽、部署上限、徽记权重调整、超限种数） | `add-recruit-hand`、`add-batch-deployment` |
| `先手修正`（按玩家，大回合结束时读取） | `add-match-flow` |
| `信物公开状态`（每格：已揭示?、类型、强度、控制者/争议/无人） | `add-tactical-ui`、`add-heuristic-ai` |
| `信物生成记录`（种子 + 全部分布） | 遥测（§17） |
| `揭示事件`（格、类型、强度、揭示所在大回合） | 遥测（§17 要求记录揭示时间） |

## Risks / Trade-offs

- **[重抽循环破坏种子复现性]** → 重抽必须完全由种子驱动的确定性伪随机序列推进，且设重试上限；超限时按固定规则收敛。必须有"同种子两次生成逐格一致"的回归。
- **[揭示被误实现为授予]** → 用"揭示者未取得控制 → 参数不变"的用例锁死。
- **[快照被绕过]** → 小回合内任何读取信物控制的代码路径都应视为缺陷；用测试断言快照生成后信物控制变化不影响本回合参数。
- **[控制语义分叉]** → 强制走唯一覆盖查询，并加交叉一致性测试（全盘每个信物格断言两套判定一致）。
- **[稀有度容差是拍脑袋初值]** → 记入地图数据允许逐图覆盖，由批量跑局回归后校准。
- **[无硬上限导致极端部署]** → 属设计意图（§8.1）。风险由遥测承接：记录每局部署上限峰值与出现轮次，对照 §16 的 5–8 目标区间。

## 裁决记录（已确认）

1. **升级判定对全部六类信物统一按 20% 执行**：五类结构信物变 +2，流派徽记变双倍数量（在 §9.1 的权重公式中按数量 2 代入）。这样高阶流派徽记才可能出现，与 §8.1 对它的描述自洽。
2. **稀有度容差 = 8%**（各出生区总稀有度与均值的偏差）。这是一条偏严的约束，会显著提高第二阶段的重抽次数，因此第 3 条的兜底路径必须做扎实并纳入回归。
3. **同一出生区允许出现同类型信物**，但在第二阶段把"同区同类型"计入偏离惩罚以降低其概率。保留"双徽记开局"这类有意思的极端局面，同时避免双军令、双兵站造成的明显开局优劣差。
4. **重抽超出上限时，放弃稀有度约束、保留权重抽取结果，并在对局记录中打标"生成未收敛"**，由遥测统计其发生率。静默接受比死循环或抛错都安全：抛错会系统性丢失一批非随机分布的种子，从而偏移统计结论。鉴于容差取到 8%，这条路径会被经常走到，其发生率本身就是一项需要监控的指标。
5. **弃赛玩家唯一覆盖的信物显示为"由已弃赛玩家控制（封锁）"**，与"无人控制"和"争议"都区分开。对其他玩家而言这是完全不同的战术信息：没人在用它，但你也拿不到，除非围杀那条遗留棋串。
