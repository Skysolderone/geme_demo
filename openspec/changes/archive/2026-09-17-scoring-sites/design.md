## Context

去围棋化改造三轮中的第二轮（总体计划见 `openspec/changes/archive/2026-09-17-terrain-model/design.md` 的 Context 与裁决记录 11–16）。

现行势力公式 `总势力 = 独占空格数 + 棋串军势` 让每个空格均质值 1 分，最优解是铺满盘面。第一轮 v3 回归（`sim-out/terrain-v3/`，200 局）已经暴露了它在新地形上的后果：

| 指标 | v3 实测 | 与领地计分的关系 |
|---|---|---|
| 整局无提子局 | 14%（v2 为 1.2%） | 四家高台各约 20 格自留地，不下山也能靠领地撑到终局 |
| 第 3 大回合领先者胜率 | 17%，显著低于 25% | 早期势力由高台领地撑起，与最终胜负脱钩 |
| 平均结束大回合 | 10.57 | 对局长度由岛上 21 格填满速度决定 |

本轮把分数从"空格"搬到 12 个固定据点上，并落地第一轮定下的"相对高度军势加值"。

现有代码里领地分的消费点：`PowerCalculator` / `PowerSnapshot.TerritoryScore`、`FinalStandings` 并列链、`MatchFlow` 存档、`Siege.Sim` 日志字段 `Territory`、`Siege.Presentation.LayerContents` 势力层、Godot `Hud`。AI 没有单独的领地评估项，它追逐的是势力增量（`PowerGain`），公式一改 AI 自动跟随。

## Goals / Non-Goals

**Goals:**
- 空格领地退出计分；势力 = 据点分 + 军势；空格归属三态保留为控制判定与展示。
- 12 个据点按「出生区营帐 4 + 崖下篝火 4 + 岛上石碑 4」布在 v3 地形上（地图升为 `siege-4p-base-v4`），C4 对称、距离均衡。
- 据点控制与信物控制同口径、复用同一份覆盖数据。
- 高地压制加值：复用覆盖关系，进位置加值，不被倍率放大。
- 默认棋盘可读出据点与控制方；势力层改为据点分。
- 据点分量三档与 AI Safety 九档扫档，出对比表由用户拍板，然后才重定 §16。

**Non-Goals:**
- 匠人与地形改造（第三轮）。
- 据点的专属效果、随机分值、对局内迁移。
- 保护期、部署上限、倍率封顶、落后者补偿、终局种类与优先级。
- Safety 以外的 AI 权重，新增 AI 评估维度。

## Decisions

**D-A：据点是地图静态数据，分值是对局配置（裁决 D9、D12、S-3）。**
位置与档位跟地形一样由设计师固定、C4 对称校验；三档分值放进 `MatchOptions`（标准局 5 / 15 / 45），因为本轮要扫档，把分值写死在地图里就得为每一档导出一张图。备选"分值写进地图数据"否决：同一张图多种分值时地图 Id 不能唯一标识口径。

**D-B：控制判定与信物同口径，复用 `CoverageMap`（裁决 D11）。**
占据 > 唯一覆盖 > 争议 > 无人。不另写覆盖。林地据点只能占据——这是覆盖关系的自然后果，不是特例；本轮布点要求石碑不在林地（S-2），所以 v3 上暂时不会出现。

**D-C：布点 12 = 营帐 4 + 篝火 4 + 石碑 4（裁决 S-1、S-2）。**
C4 对称下据点数只能是 4k 或 4k+1，唯一的中心格 `G7` 已是高档信物，而据点与信物不得重合，所以是 12。
- **营帐**（出生区内，h=2，5 分）：保护期内就有可守的点，开局势力不完全靠抽到什么棋。邻家在崖下仰视覆盖不到，事实上只有主人能控制。
- **篝火**（主人河外低地，恰在邻家高台崖边正下方，15 分）：v3 地形上满足约束的只有一条轨道 `J2 / M9 / E12 / B5`。邻家第 1 大回合在自家崖边（如 `K2`）落子即可居高覆盖；主人保护期内下不了山，所以**前三大回合篝火通常被邻家唯一覆盖控制**，主人第 4 大回合起下山占据或覆盖才能夺回或打成争议。四家对称，开局第一手自然落在崖边、形成跨区对峙。这是 E5「居高临下单向覆盖」第一次直接进入计分（裁决 S-8：接受，扫档观察）。
- **石碑**（岛上非林地，45 分）：唯一的正面战场。
备选"岛上 8"否决：价值过度集中，先上岛者滚雪球、河外低地没有存在感。备选"自家低地 4"否决：别人碰不到，等于白给分，不制造接触。

**D-D：分量初值约三分之一：5 / 15 / 45（裁决 S-3）。**
v3 终局每家平均势力约 148，几乎全是军势，倍增子占 55%。全图据点 260 分，拿下两个石碑 = 90，与中期平均军势相当，"抢点"与"堆倍增串"成为两条同等重要的路。1:3:9 的档差让家门口只是垫底、岛才是胜负手。这是**待校准初值**（Safety=20 的教训），见 D-H。

**D-E：高地压制加值按覆盖关系判定（裁决 D13、E1、默认 3、S-4）。**
棋子 s 的覆盖目标里有更低处的敌子 → s +1，每枚至多 +1，进位置加值，不被倍率放大。覆盖关系天然含跨崖居高临下与隔一格深水，天然排除林地里的敌子。备选"几何四邻"否决：规则里多一种邻接用法，违反 `boundaries.md`"规则只走气边与覆盖关系"。备选"气边"否决：高差 2 没有气边，v3 上每家只有 2 格缓坡，规则几乎不会出现。
澄清：第一轮裁决记录 16 写的是"气边或覆盖关系上相邻"，聊天里说的是几何四邻，本轮以 S-4 为准统一为覆盖关系。

**D-F：界面——默认棋盘有地标，势力层看分，不加新层（裁决 S-5）。**
三档三种低多边形地标（营帐 / 篝火 / 石碑，与用户参考图的营地、篝火气质一致），控制方旗帜 = 主色 + 徽记；势力层把"每格领地贡献"换成据点档位 / 分值 / 控制状态，棋串分数拆出高地加值。备选"新增据点层"否决：与 `merge-board-layer` 合层的方向相反，键位又要顺延。

**D-G：终局并列链里"独占空格数"换成"控制中的据点数量"（常规，主会话定）。**
领地退出计分后，独占空格数不再是"盘面优势"的度量；据点数与计分口径一致。

**D-H：扫档在主会话执行，结果由用户拍板（裁决 S-6）。**
1. 据点分量三档，Safety 固定为 5，各 200 局（种子 1–200）：1/5 = 3 / 8 / 24，1/3 = 5 / 15 / 45，1/2 = 10 / 30 / 90。
2. 在第 1 步推荐的分量下，Safety 九档（3 / 5 / 7 / 8 / 10 / 20 / 30 / 40 / 60）各 200 局。若用户选了别的分量，第 2 步在用户选的分量下重跑。
3. 对比表列：第 3 大回合领先者胜率（目标 ≤ 50% 且不显著低于 25%）、篝火主人控制占比与首次夺回大回合、石碑由相邻桥头那家控制的占比、首次跨出生区冲突（4–5）、终局局平均结束大回合（7–10）、终局原因分布（整轮 Pass / 达上限 / 碾压）与碾压成立平均大回合、不收敛率、整局无提子局、终局据点分占比、三档据点控制率与争议率、高地加值占比、出生区胜率、自杀手 / Pass 率。
4. 用户拍板后改 `MatchOptions` 默认分值与 `EvaluationWeights.Default.Safety`，确认跑一次 200 局，重定 §16。
约 12 批 × 2 分钟 ≈ 25 分钟墙钟。跑局配置要能从命令行或配置文件指定据点分值与权重，未知选项仍被静默忽略的问题（`strict-cli`）在扫档前必须规避：每批跑完核对 `config.json` 里的实际生效值。

## 接口契约

**输入**：地图静态数据（新增据点位置与档位）、对局配置（新增据点分值）、盘面。

**输出**：

| 输出 | 变化 | 消费者 |
|---|---|---|
| `MapData` | 新增据点集合（坐标 → 档位） | 校验器、据点控制、表现层、JSON |
| `MapFile` JSON | 新增 `Sites` 字段；缺字段的旧文件按"无据点"读入（v3 文件不再被默认加载，保留作历史） | 设计师维护 |
| `MapValidator` | 据点数区间、据点在可落子格、不与信物重合、档位必填；距离均衡目标加最近篝火 / 石碑 | 地图加载 |
| `FourPlayerBaseMap` | 地形沿用 v3，加 12 个据点，Id 升为 `siege-4p-base-v4`，导出 `maps/siege-4p-base-v4.json`；`RunConfig` 默认地图随之切到 v4 | 全部对局 |
| `MatchOptions` | 新增据点分值（营帐 / 篝火 / 石碑），校验正整数且单调不减 | 势力计算、跑局配置、日志 |
| 据点控制（新，唯一实现） | 每个据点的状态与控制者；读 `CoverageMap` | 势力计算、表现层、日志 |
| `PieceEffects` 或同层新增的高地加值（唯一实现） | 每棋串高地加值；读 `GameBoard.CoverageTargets` 与高度 | `PowerCalculator` |
| `PowerCalculator` / `PowerSnapshot` | `TerritoryScore` 移除 → 据点分总计与控制据点清单；`GroupPower` 位置加值拆分加高地；`ExclusiveCells` 保留 | 名次、AI、表现层、日志 |
| `FinalStandings` / 存档 | 并列链"独占空格数" → "控制中的据点数量"；存档字段随之改名，旧存档读入时按 0 回填 | 终局 |
| `Siege.Sim` 日志 | `Territory` → `SiteScore`；新增据点控制变化事件；配置记录据点分值 | 分析 |
| `Siege.Sim` 分析 | 新增 §17 第 10 项据点分析；缺据点字段的旧日志整局排除并计数 | 扫档决策 |
| `Siege.Presentation` | 势力层据点项与高地拆分；公开视图含据点 | Godot HUD |
| Godot | 三种地标、控制旗帜、势力层 HUD 文案 | 玩家 |

**与第三轮的接口**：据点只读地形与盘面，第三轮的地形改造（搭桥、烧林）会改变覆盖关系从而改变据点控制，无需本轮预留额外接口；烧林会把林地据点变成可被覆盖——本轮布点不在林地，第三轮若在林地放据点再议。

## Risks / Trade-offs

- **[石碑 45 分让岛成为唯一胜负手，先上岛者滚雪球]** → 扫档第 1 步看石碑控制率与领先者胜率；1/5 档是退路。
- **[篝火开局归邻家、主人下山后长期争议，家门口的分等于送给邻家]** → 据点分析加「篝火控制者是否为所在低地主人」与主人首次夺回的平均大回合；若争议率 > 70% 或主人控制占比过低，第三轮之前考虑把篝火挪离崖边一格（改布点，不改规则）。
- **[营帐事实上无人能争，5 分是白送]** → 这是设计意图（开局垫底），四家等量；若扫档显示它影响领先者胜率，调营帐分值。
- **[高地加值与篝火布点叠加，邻家高台边成为最优落点，出现"只守崖边不下山"]** → 看整局无提子局与高地加值占比；报警线：整局无提子局 > 14%（不比第一轮更差）。
- **[据点分摇摆 45 分使势力碾压过易触发]** → 看碾压胜占比与成立大回合；碾压阈值本轮不动。
- **[AI 追逐势力增量，45 分的跳变让单步评估过度贪点]** → Safety 扫档会暴露；不新增 AI 维度，若九档都压不住再开独立 change。
- **[大量既有测试以"孤立棋子 5 点势力""独占空格计分"为算例]** → 按新公式改写期望并逐条列入提交信息；几何算例改坐标重构。
- **[扫档口径被静默忽略的选项污染（strict-cli 未做）]** → 每批核对 `config.json` 实际生效值，不一致即作废重跑。
