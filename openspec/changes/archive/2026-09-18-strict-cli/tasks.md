# 任务：strict-cli

## 1. 守门测试先行

- [x] 1.1 测试：给出未被任何读取方取用的选项时，跑局子命令以非零退出码结束且不创建输出目录。算例用规格里的 `--matches 200`（合法名是 `--count`）。验证：变异——把结算调用删掉，测试变红。
- [x] 1.2 测试：错误信息里同时出现未知选项名与建议的合法选项名。验证：变异——把建议逻辑改成永远返回空，测试变红。
- [x] 1.3 测试：全部选项都被读取时命令正常执行。这条挡的是"结算过严把正常调用也拒了"。验证：变异——让结算把已消费的选项也算作未知，测试变红。
- [x] 1.4 测试：`Has(key)` 计入消费。算例：只给 `--serial` 这类只被 `Flag`/`Has` 读取的开关，不应报未知选项。

## 2. 实现

- [x] 2.1 `CommandLine` 增加 `_consumed` 集合，在 `Get / GetOrNull / GetInt / GetUInt64 / Flag / Has` 中记录 key。
- [x] 2.2 增加结算方法：返回未被消费的选项名，按字典序稳定排序（错误信息要可复现）。
- [x] 2.3 增加最相近合法选项的建议（编辑距离 ≤ 3，取最小；并列时取字典序靠前者，保证确定性）。合法选项集合取该子命令已消费的 key 加上它声明的可选 key。
  - 落地偏差：**没有子命令需要"声明的可选 key"**，该入参已删。唯一的候选 `replay` 改为对 `--file` 与 `--dir/--seed` 混用直接报错（design D2），合法集合纯由读取动作产生，零白名单。
- [x] 2.4 在各子命令（run / analyze / replay / play / map 等）解析完参数后、创建输出目录与执行之前调用结算。
- [x] 2.5 全量 `dotnet test` 绿。
