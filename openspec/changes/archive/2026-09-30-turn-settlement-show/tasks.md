## 1. 节拍生成（表现层视图模型，不依赖引擎）

- [x] 1.1 定义节拍数据模型：落子节拍、提子节拍、势力重算节拍及其条目（坐标、类型、归属；旧值 / 新值 / 增量 / 旧名次 / 新名次）。验证：单元测试——构造三种节拍并断言字段。
- [x] 1.2 实现节拍生成纯函数：输入结算前快照、结算后快照、可选的结算记录（有则按放置顺序，无则按坐标字典序；被提棋子原归属读结算前盘面），按设计文档 §6.3 顺序输出节拍序列，空节拍省略。验证：单元测试，算例——P1 在 C3、C4 落子并提掉 P2 的 D3，势力 P1 5→9、P2 6→4，期望序列为 落子(C3,C4) → 提子(D3) → 势力(P1 +4, P2 −2)。
- [x] 1.3 覆盖 Pass 两种情形：势力不变得空序列；势力有变只得势力重算节拍。验证：单元测试。
- [x] 1.4 覆盖名次变动、已弃赛 / 已出局玩家名次为空、无变化玩家不出现。验证：单元测试，算例——结算前名次 P2=1、P1=2，结算后互换。
- [x] 1.5 确定性：同一输入两次生成的序列逐项相同。验证：单元测试。

## 2. 演出时间线（表现层视图模型，不依赖引擎）

- [x] 2.1 实现时间线状态机：按传入的时间增量推进，给出当前节拍、节拍内进度、是否播完；节拍时长按 design.md D3（落子每枚 0.25 秒上限 1.0 秒、提子 0.6 秒、势力 0.9 秒）。验证：单元测试——固定增量逐步推进，断言节拍切换时刻。
- [x] 2.2 提速：推进时可带提速标志，时间增量按 4 倍计；节拍顺序与内容不变。验证：单元测试——同一序列提速与不提速经过的节拍相同，提速所需总时间为四分之一。
- [x] 2.3 单次推进跨过多个节拍时逐个报告被跨过的节拍。验证：单元测试——一次推进 10 秒，报告全部节拍且状态为播完。
- [x] 2.4 零时长模式：创建即播完，不占用任何推进。验证：单元测试。
- [x] 2.5 空序列的短停顿（0.3 秒）。验证：单元测试。
- [x] 2.6 势力值整数插值：千分比进度、任意精度整数、先乘后除，进度满时恰为新值。验证：单元测试，算例——12→20 在 500‰ 时为 16；10^30→3×10^30 在 1000‰ 时恰为 3×10^30；15→9 的中间值都在 9..15 之间。
- [x] 2.7 演出遮罩：由时间线状态推出"尚未落下的棋子集合、仍需显示的被提棋子集合、各玩家当前显示势力值"；播完后遮罩为空。验证：单元测试——落子节拍进行中被提棋子仍在遮罩的"仍需显示"集合里。

## 3. 图形版接线

- [x] 3.1 会话层：AI 小回合路径沿用已有的结算前后两份快照（无结算记录）；本机玩家确认 / Pass 路径用确认前已持有的公开快照作"前"、把确认返回的结算记录一并交出。两条路径都生成节拍序列，取代现有"回合高亮"里落子格 / 被提格的单独计算。验证：无人值守自动演示跑通，日志打印每次结算的节拍数。
- [x] 3.2 主循环：时间线未播完时不推进对局（不跑 AI 小回合、不推进本机玩家阶段）；演出时长取代 AI 小回合之间的固定停顿（无人值守下保持现有停顿数值）。验证：人工检查——三名 AI 依次行动时每段演出播完才轮到下一位。
- [x] 3.3 棋盘视图按遮罩绘制：未落下的棋子隐藏、落下时有出现动画；被提棋子在提子节拍内淡出。验证：人工检查 + 定帧截图。
- [x] 3.4 记分显示按遮罩绘制：势力值滚动、带符号增量、名次变动提示；演出结束后增量标记消失。验证：人工检查。
- [x] 3.5 本机玩家自己的结算：落子节拍压缩为一次整体确认闪动（design.md A2）。验证：人工检查。
- [x] 3.6 提速输入绑定：按住生效、松开恢复；演出期间优先认领，不触发确认、Pass 或界面按钮；非演出期间原按键行为不变。按键以 design.md Open Questions 的用户确认结果为准。验证：人工检查。
- [x] 3.7 演出期间镜头平移、缩放与信息层切换可用。验证：人工检查。
- [x] 3.8 演出中弃赛：演出立即以终态结束再处理弃赛（design.md A5）。验证：人工检查。
