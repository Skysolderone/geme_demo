## Context

open-map 之后整张地图是唯一战场，终局 = 全员 Pass / 填满 / 只剩一人。AI 停手只靠停手阈值（候选批次边际收益 ≤ 阈值即 Pass）与决胜一手；同形禁则（`capture-resolution`「盘面同形禁则」）是全局历史比对，但提子循环发生在局部，整张地图其他地方不断变化，盘面永不重复。`run` 有跑局层 `turn_limit`（600 小回合）截断，终端 `play` 与图形版没有。

现有可复用设施：`DefeatReplay` / `PassReviewAnalyzer`（按日志回放到某小回合、复用正式候选与评价）、`BalanceAnalyzer.Stalling`（单子零增长拖延）、`Convergence`（未收敛局计数）、`SettlementReason`（整轮 Pass / 填满 / 减员）、`MatchFlow.Settlement.JudgeAtRoundEnd`（判定链唯一实现，先手预测复用）。

## Goals / Non-Goals

**Goals**：任何配置下对局必然终局（规则层安全网）；AI 在循环提子时主动收手（AI 层）；两者都有数据支撑的参数。

**Non-Goals**：不动同形禁则、停手阈值缺省、评价权重；不改对局长度；不给人类玩家加任何限制。

## Decisions

### D1 第一段诊断：只读日志，不改行为（C1）

- 新增 Sim 分析段「循环提子诊断」（`analyze --review-cycles`，显式开关）：对每局取末段窗口 W（缺省最后 12 个大回合，截断局按截断时刻），输出：
  - 每名在局玩家在窗口内的落子数、提子数、被提数、净势力变化（窗口末 − 窗口首）；
  - 窗口内被提过的格集合 C 及其大小；
  - **局部周期**：以 C ∪ 四邻为局部键（占用者 + 设施），逐小回合求哈希，报告最短重复周期（小回合数）与重复次数；
  - **全局不重复归因**：窗口内 C 之外的新增落子数、被提格之外的盘面变化次数（说明全局同形为何不触发）；
  - 判定：窗口内 ≥ 2 名玩家净势力变化 ≤ 0 且局部周期存在 → 记"循环提子"。
- 诊断批次：终端脚本种子 43（`PlayCommand` 脚本路径复现，`turn_limit` 由测试宿主给 600）+ `run --difficulty Easy` 种子 40–47（≤ 8 局，`turn_limit` 600），合计 ≤ 10 局；报告存任务目录。只报数，不改行为。
- 诊断回传后由负责人裁决 K（停滞大回合数）与是否收窄"候选全是提子"的判定。

### D2 规则层安全网 A（C2 / C3 / C4）

- 对局配置 `RoundCap`（大回合上限，整数 ≥ 0，缺省 100（D4），0 = 不启用），始终公开，入存档、日志首部、批次配置记录；负数建局报错。
- 判定：`JudgeAtRoundEnd` 增第 (c) 条——本大回合结束时 `MajorRound ≥ RoundCap` 且战场未结算、在局 ≥ 2 → 按同一判定链结算，`SettlementReason.RoundCap`（文案"上限"）。排在 (a) 整轮 Pass、(b) 填满之后（同时满足记前者）。先手预测（`MatchFlow.Preview`）复用同一判定，因此上限大回合"假设此刻结束"同样剔除将落败者。
- 终局原因不新增：上限结算触发的终局仍记"最后战场结算"（触发路径未变）。
- 旧存档缺该字段：按 100 回填并留痕（`RoundCapBackfilled`），与 open-map 之前 K 按 0 的做法相反——安全网默认开启。旧日志缺字段：分析按 100 读，不留痕。
- 图形版：每个大回合开始时若 `RoundCap − MajorRound ≤ 5` 出提示条"第 X 大回合结束时按势力结算"（无人值守零时长）；新局界面不加配置项（缺省即可，段 2 可裁决）。
- 基线：冒烟最长 29 < 100，5 份决策序列基线逐字节不变；首部多一个字段 → 日志 / 报告文本哈希类测试重钉（格式变化，走法不变由基线证明）。

### D3 AI 停手 B（C2，参数待诊断）

- `AiSearchConfig` 新增 `StagnationRounds` K（整数 ≥ 0，0 = 不启用；缺省 6（D2）），写入批次配置记录与日志首部，回放按首部重建，缺字段按 0。
- 判定在 `HeuristicTurnController` 的部署决策入口：读本玩家最近 K + 1 个大回合开始时的公开势力（公开快照里的势力历史，或由控制器自己按大回合记忆——只记本人、只读公开量），若连续 K 个大回合势力无净增（每个大回合首 ≤ 前一大回合首），且本次决策的全部候选单点（排序后的前 `CandidatePointCount` 个）要么会提子、要么落在最近 K 个大回合内被提过的格上，则视同"无改善手"→ 按停手阈值 Pass（决胜一手仍优先：若 Pass 会结算且有追平手，决胜一手照旧）。
- 无子豁免沿用：盘上无子不触发停滞判定。
- 守门：信息边界（只读公开量）；AI 评价版本 +1；5 份基线若走法改变则重钉并记录。
- 人类玩家不受影响。

### D4 两者关系

- A 保证终局（任何 AI / 人类组合、任何配置），B 让 AI 对局在正常长度内自然收尾；A 触发率是 B 的效果指标（段 2 验证：简单 ×3 种子 40–47 的上限结算次数应明显低于诊断时的截断次数）。

| 接口 | 输入 | 输出 | 触发时机 |

## 第二段裁决（负责人 2026-10-20，D1–D6 全按推荐；依据第一段 `diagnosis.md`）

| # | 事项 | 裁决 |
|---|---|---|
| D1 | 同形键含改造段（循环局里改造让占用相同的盘面每轮都算新局面） | 不改同形禁则（「设施差异不构成同形」有意保留）；靠安全网 A + 停手 B 兜住；§19 登记"改造让盘面常新"观察 |
| D2 | K | **6**；2.4 验证后可调 |
| D3 | 候选条件 | 按 D3 设计：排序前 N 个候选全部"会提子或落在最近 K 大回合被提过的格"，与停滞同时成立；不加收窄 |
| D4 | 大回合上限缺省 | **100**（简单局自然终局最长 94；安全网只兜不收尾的局）；C2 / C3 / C4 的"60"一律改 100 |
| D5 | R-3 三 AI 局面复现 | 不给 `play` 加日志；2.4 用 `run --config` 四 AI 近似 + 简单 ×3 种子 40–47 |
| D6 | 范围外改动 | 接受 `可复现回放Tests` 补 `[Collection(ConsoleRedirect.Collection)]` |

## 已知歧义与风险

- "候选全是提子"的判定可能误伤正常的收官提子（对手死子）——由 K 连续无净增条件兜底；诊断数据决定是否收窄。
- 上限 100 对未来更大棋盘可能偏紧：作为对局配置可改，不随地图自动变化。
- 旧日志（open-map 段 A/B 冒烟）缺上限字段，分析按 100 读；不拒绝。
