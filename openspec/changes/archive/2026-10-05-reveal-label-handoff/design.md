## Context

常驻标注取自结算后的势力明细，演出一开始（落子节拍）就已经是新军势；军势揭示条目标在同一格（`GroupPowerLabels.AnchorOf`），末步写出同一个数。两者同时显示即负责人看到的重复。

## Goals / Non-Goals

**Goals:** 同一条棋串的军势在同一时刻不以"揭示结果"与"常驻标注"两种形式同时完整显示；揭示之前不剧透结果。

**Non-Goals:** 不改揭示的时长、档位与画法；不加位移动画。

## Decisions

### D1 遮罩给出"被揭示棋串的常驻标注显现进度"

演出遮罩新增一项：落点 → 显现进度（‰）。纯函数、整数，由时间线状态推出：

1. 演出尚未播到军势揭示节拍（落子 / 提子 / 信物节拍期间）：该节拍的全部条目都列出，进度 0。
2. 军势揭示节拍进行中及之后：条目尚未到末步，进度 0；已到末步，按结果年龄 a（‰）取 `max(0, (a − 500) × 2)`——结果停留的前半段保持隐藏，后半段（结果淡出时）线性淡入。
3. 结果年龄满（条目消失）之后不再列出，标注完全显示。
4. 演出播完或零时长：遮罩为空，标注完全显示。

未列出的落点一律完全显示。这一项计入"遮罩是否为空"。

备选：揭示结果消失后标注才出现（否：最后一条的结果通常被演出结束截断，标注会在演出结束那一帧硬弹出来）。备选：演出期间隐藏全部常驻标注（否：未涉及的棋串没有理由消失）。

### D2 引擎层

画常驻标注时查这一项：进度 0 不画，其余按进度取透明度；不在表里的照常。演出逐帧刷新时，表里有内容或上一帧有内容，就重画常驻标注；其余时候不重画。

## 接口契约

- 输入：`tiered-number-show` 的军势揭示节拍与条目落点（与常驻标注同一落点算法）。
- 输出：遮罩多一项；常驻标注的落点、文案、档位不变。
- 不变：零时长遮罩恒空；无人值守帧数与截图基线。

## 已知歧义与建议裁决

| # | 歧义 | 裁决 |
|---|---|---|
| A1 | 结算前就存在的棋串（如 31 → 111），揭示之前要不要先显示旧值 | 不显示：盘面视图已是终态，旧落点与旧值都不在手里；隐藏到揭示结果淡出为止 |
| A2 | 淡入期间两个数都半透明可见 | 接受：这是交接过渡（上浮的结果淡出、原位的标注淡入），不是同时完整显示 |
| A3 | 演出被结束截断时标注还没淡完 | 接受：演出结束即完全显示，至多从半透明跳到不透明 |
| A4 | 全局预览 | 常驻标注本来就不画，不受影响 |

## Risks / Trade-offs

- [演出期间多重画一层] → 只在表非空时重画，标注数量是棋串数量级。
