## Context

`HeuristicTurnController.ChooseByCandidates`：k = 0..M−1 次 `Greedy`（k = 0 用不扰动排序，其余用种子扰动排序），按键去重后 `CandidateSelection.Best` 选总分最高者（专家交给前瞻）。`Greedy` 逐枚加入，边际提升 ≤ 停手阈值即撤回。决胜一手已有"强制贪心批次"（阈值 −∞、前 N、至部署上限），只在落后 + 整轮 Pass 前一刻启用。

诊断数字见 proposal「Why」（569 个局面，探针代码已还原，结果文件在主会话 scratchpad，不入库）。

## Goals / Non-Goals

**Goals**：补上"逐枚为负、整批为正"的组合；零随机；开关关闭时逐步不变；新增预演小（中位 +≈2%，最坏一次决策 +255 次预演）。

**Non-Goals**：三枚以上组合；改权重 / 阈值 / N / M；改决胜一手与停滞停手。

## Decisions

### D1 机制（裁决 1）

两个整批候选，追加在既有候选之后（去重键相同即不加）：
- **剪枝候选**：`Greedy(ranking, …, int.MinValue)`（与决胜一手的强制批次同一实现）→ 留一法剪枝：每轮对当前批次每一枚算"拿掉它后总分下降"（拿掉后不合法 / 被活形硬约束淘汰视为 +∞；拿到空批次时以 Pass 总分为准），下降最小者 ≤ 阈值即拿掉（并列取批次次序靠后者），直到全部 > 阈值或为空。
- **配对候选**：单点排序前 N 中"单点总分 − Pass 总分 ≤ 阈值"的落点两两组合（格不同），合法、通过活形硬约束、且两枚留一法下降都 > 阈值者为有效配对；取组合总分最高者（并列按坐标序列、类型序列），以它为起点按不扰动排序继续 `Greedy` 式逐枚加入（同一阈值、跳过已占格）至部署上限。
- 选择照旧：`CandidateSelection.Best`（专家：基础候选含整批候选，前瞻集第一个仍是高难选择）。

### D2 阈值口径（裁决 2）

整批候选的每一枚满足"留一法下降 > 阈值"；配对候选起点之后的追加落点仍按逐枚口径。实际生效阈值（无子豁免 / 落后者豁免）与贪心同一个 `EffectivePassThreshold`。

### D3 适用难度（裁决 3）

标准、高难、专家生成；简单不生成（`ImmediateOnly` 一档）；`ExpertLookahead.SimulatedConfig` 把开关清零（模拟对手不生成，保持修法 B 的口径与开销）。

### D4 开关与记录（裁决 4）

`AiSearchConfig.WholeBatch`（int，0 / 1，`JsonIgnore WhenWritingDefault`；`Validated()` 拒绝 0 / 1 以外的值）；跑局层 `RunConfig.WholeBatch` 与命令行 `--whole-batch`（缺省 1），与 `StagnationRounds` 同一派生路径（只作用于未显式给 `Search` 的玩家；首部缺字段的旧日志按 0 重建）。终端 `play` 与 Godot 经预设派生，缺省开（不改 Godot 代码；若 Godot 侧需要显式传值，实施时只在 Core 预设层解决，不动 `src/godot`）。

### D5 版本、守门与重钉（裁决 5、6）

- AI 评价版本 9 → 10。
- MUST 不变：简单基线 `decisions-link1-easy-seed1.txt`；开关为 0 时全部 5 份基线与各黄金值逐步相同（新守门：以开关 0 重跑基线比对）。
- 预计重钉：标准 3 份、高难 1 份决策序列基线；链接图黄金哈希、严格提高哈希、`SmallMapGoldenHash`、专家 G1、前瞻记录、平衡报告等依赖走法的黄金值——以实测为准，每份写首个分歧，判据：首个分歧处被选中的是整批候选（剪枝或配对来源），或其前一手相同而本手候选集多出整批候选。记录写任务目录 `rebaseline.txt`。
- 门控：专家前瞻代理与计时两条照常 ≤ 4。

### D6 验证跑局与采纳准则（裁决 7、8）

同一构建、开关 on / off 对照，`--map link:1 --map-per-match --seed 1 --count 20`，其余缺省（阈值 20、停滞 6、上限 100、截断 600）：
- S0 / S1：4 标准，`--whole-batch 0 / 1`；
- H0：4 高难 off；H1：座位 1 高难 on（显式 `Search` 带开关 1）+ 3 高难 off，与 H0 同种子配对。
共 80 局，每批 20。指标：截断、上限结算、大回合中位、Pass / 停滞次数、整批候选被选次数（按来源）、单小回合耗时中位、配对名次。

预登记采纳准则：S1 / H1 截断 0、上限结算 0；S1 大回合中位 − S0 ≤ 2；S1 单小回合耗时中位 / S0 ≤ 1.15；H1 对 H0 配对"好 − 差" ≥ 0 → 采纳提交；否则停下回报、代码不提交。

### D7 分段与派发（裁决 9）

一段：1 个 trellis-implement（Core + Sim + 测试 + 变异 + 重钉 + 门控）→ 主会话前台复核 → 1 个 trellis-check → 主会话跑 80 局并汇总 → 文档 v1.38 → 归档提交。同一时间只一个 dotnet 进程。

## Risks / Trade-offs

- [对局变长 / 少 Pass] → 整批候选只在真有大收益时被选；准则卡大回合中位 +2、截断 0。
- [配对枚举最坏 C(24,2)] → 只枚举次阈值点，诊断中位 0、全局 +9%；准则卡耗时 1.15。
- [评价伪收益被放大] → 整批候选与既有候选同一评价器，若评价有偏，逐枚贪心同样会被它引导；不在本 change 处理。
