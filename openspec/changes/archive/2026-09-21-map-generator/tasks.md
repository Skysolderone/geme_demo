## 1. 段 A——生成器与校验闭环（Siege.Core）

- [x] 1.1 地图随机源：只由（地图种子, 尝试序号）决定的整数随机序列，复用对局随机源的同一份 PRNG 实现但不经 `GameSeed`。验证：单元测试——同输入同序列；不同尝试序号序列不同；守门（源码扫描）：生成器文件里不出现 `GameSeed`，`Siege.Core/Match` 下不出现地图种子类型；变异验证。
- [x] 1.2 生成参数与标识：平台数 5–8（缺省 6），越界报错不夹取；标识解析 / 规范化 `gen:<种子>[:p<N>]`。算例：`gen:42:p6` 规范化为 `gen:42`；`gen:987654321:p7` 往返不变；`gen:abc`、`gen:1:p99` 报错并说明格式与范围。验证：单元测试逐条。
- [x] 1.3 生成六步（design D1）：摆平台（最小两个优先中央带、外接矩形两两隔 ≥ 2 格、离外缘 ≥ 2 格）→ 中央广场与中央入口 → 最小生成树 + 冗余边的 2–3 格宽 h=0 走廊、每平台 1–2 处 2–3 格宽 h=1 缓坡口 → 一格宽贯穿主河、跨河处为桥（≥ 2 座）→ 填充深水 / 障碍、林地与栅栏、平台内无障碍（平台留白，裁决 17；原为 ≤ 20% 障碍）→ 篝火（= 平台数）/ 石碑 4（平台内不放营帐，裁决 18）/ 信物（平台内按边长 1 或 2，公共 7）与咽喉标注。全程整数运算、集合按坐标序遍历。验证：`map-generation`「布局规则」四个 Scenario 的测试（种子 1–50 × 平台数 5–8 全过校验；平台规整；任意两平台连通；平台数 6 时篝火 6 / 石碑 4 / 无营帐（裁决 18，原为营帐 6）/ 公共信物 7 且无重合）。
- [x] 1.4 校验闭环：每次尝试后跑边疆档 `MapValidator`，不过则尝试序号 +1，上限缺省 64；耗尽报错并带最后一次的失败原因；实际尝试序号可查询、不进标识。验证：单元测试——注入极小上限时报错不返回地图；同一种子两次生成落到同一尝试序号；种子 1–50 无一耗尽；单张生成耗时中位数 ≤ 1 秒（计时断言取宽松上界，避免机器抖动假红）。
- [x] 1.5 确定性：同种子同参数两次生成的导出文本逐字节相同；种子 1–20 的平台布局至少 19 种互不相同；生成图 `MapData.Id` 为规范化标识、规格档为边疆档。验证：单元测试 + 变异（把某处集合遍历改成依赖哈希次序的写法应红——若做不到稳定复现，改为守门扫描 `HashSet` / `Dictionary` 的直接遍历）。
- [x] 1.6 `map-definition` 增量：标准档请求生成报错；生成图与内置图走同一套校验；内置图行为零变化。验证：单元测试；`siege-frontier-v1` 与 v4 的既有黄金值 / 字节不变测试保持绿。
- [x] 1.7 出一份"种子 1–50 布局速览"（每张一幅文本图 + 可落子格数 + 各平台边长与到中央入口距离），放 `sim-out/` 下供负责人过目，路径写进 implement 记录。验证：人工检查。
- [x] 1.8 全量回归：`dotnet test -c Release` 既有 1085 项全绿、零警告。

## 2. 段 B——入口、日志、回放、批量（Siege.Core / Siege.Sim）

- [x] 2.1 `MapCatalog.Resolve` 接生成图标识；裸 `gen` 由入口最外层取种子后再解析（Core 不读时钟）；未知标识的报错清单里说明 `gen:<种子>` 写法。验证：单元测试——`gen:12345` 解析出的地图与直接调生成器逐项相同；裸 `gen` 不会进入 Core。
- [x] 2.2 终端版与图形版的地图选项接受 `gen[:<种子>[:p<N>]]`，裸 `gen` 启动时打印解析后的完整标识。算例：`play --map gen:12345` 插旗提示列出该图全部平台，日志首部地图标识为 `gen:12345`。验证：脚本化终端测试 + 图形版 `--auto-demo --map=gen:12345` 退出码 0。
- [x] 2.3 公开视图、存档与日志首部带完整地图标识，地图种子与对局种子分开显示与记录；在生成图上存档 → 恢复后地图逐项相同（先核实现存档存的是整图还是标识，取其一实现）。验证：`match-setup` 增量三个 Scenario 的测试；旧存档恢复测试保持绿。
- [x] 2.4 日志首部加地图内容摘要（对地图导出文本取哈希）；回放重建地图后先比摘要，不同即在首部报"地图不一致"并停止；旧日志缺该字段跳过比对。验证：往返测试；人为改一格后回放在首部报错的测试；旧日志回放测试保持绿；内置图同样写摘要。
- [x] 2.5 批量"每局换图"：配置起始地图种子与平台数，第 i 局用 `起始 + i`；批次配置记录写明；分析报告在该模式下按平台边长（5–9）分组统计被选次数与胜率。算例：起始 100、20 局 → 首部标识依次 `gen:100`…`gen:119`。验证：单元测试（小局数）+ 实跑 20 局全部正常终局，统计表记入 implement 记录。
- [x] 2.6 `map` 子命令打印任一生成图的文本图与校验报告，并可导出为地图文件；导出文件按路径加载的结果与按标识生成的地图逐项相同；查看生成图不覆盖 `maps/` 下任何权威文件。验证：单元测试 + 人工看文本图。

## 3. 段 C——图形版选图界面（Siege.Presentation / src/godot）

- [x] 3.1 选图视图模型（零 Godot）：选项清单来自 `MapCatalog` 内置表 + "随机图"；状态含当前选项、地图种子、平台数、种子输入文本、非法输入提示、当前完整标识；操作：选择、输入种子并确认、换一张（新种子由调用方注入，视图模型不读时钟）、调平台数、确认开局。验证：单元测试覆盖 `map-selection` 全部 Scenario 的逻辑部分（非法种子不改变当前图；同种子同平台数同标识；换一张后标识变化）；守门：视图模型与 `src/godot/` 不自带地图清单、不直接调生成器（只经 `MapCatalog`）。
- [x] 3.2 `GameRoot` 建局前的选图阶段：未给 `--map=` 且非无人值守时进入；为候选地图建"空盘面"视图模型并用现有 `BoardView.Build` 渲染，相机切全局预览（一屏看全的图保持初始位姿）；该阶段不接受落子与插旗；确认后建局进入插旗。无人值守模式未给 `--map=` 时缺省 v4 并跳过选图。验证：`--auto-demo`、`--auto-demo --pick-check`、`--screenshot` 三条既有命令在 v4 与 `--map=siege-frontier-v1`、`--map=gen:12345` 上退出码 0；v4 插旗阶段截图与改动前逐像素相同。 （v4 截图：水面着色器随时间变，水面之外逐像素相同，噪声基线见 implement 记录）
- [x] 3.3 HUD 选图面板：三项列表、种子输入框、"换一张"、平台数 − / +、完整标识显示、"开始"；沿用现有深色半透明面板风格。选图阶段暂停相机按键的抢先处理，方向键 / 退格 / 数字在输入框里行为正常（design D8）。验证：人工检查清单（写入 implement 记录）+ 选图界面截图（新增一个仅用于截图的启动选项或复用 `--screenshot`，由实现定）。 （自动部分完成；人工检查清单留给负责人，见 implement 记录「段 C」；选图界面截图用新增的 `--map-select` 启动选项）
