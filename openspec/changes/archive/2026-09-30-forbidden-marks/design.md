## Context

合法性预演八步（`BatchRehearsal.Rehearse`）是整批判定，唯一实现。默认棋盘视图的阻断类别现有 无 / 地形 / 活棋禁入 三种，只有活棋禁入画叉。自杀手、同形、破坏活形只在确认时由预演报出。

## Goals / Non-Goals

**Goals**：玩家在落子之前就能在盘面上看到哪些格是禁手及原因；全局视角下仍可辨。

**Non-Goals**：不改规则；不标范围外的格。见 proposal。

## Decisions

### D1 查询口径：在当前暂放批次之上再加一子

对候选格 c：把"当前暂放批次 + 在 c 落一枚普通子"交给完整预演的第 3–8 步；若失败原因是自杀手 / 同形 / 破坏活形，c 即禁手，原因取预演给出的那一个（预演步骤的先后即原因的优先级）。暂放为空时就是"单独落这一子"。

候选格集合 = 合法落子范围内、未被暂放占用的空格。额度与库存（预演第 2 步）不参与：禁手是盘面性质，不因手里没子而改变。棋子类型固定用普通子——三类判定都与类型无关；匠人改造不在候选子上发生。

备选：只按空盘面单独判定——否决，暂放两子后原自杀点可能已合法，标记会误导。

### D2 唯一实现

查询是 Core 的只读纯函数，内部调用预演的既有实现，MUST NOT 另写一份气 / 提子 / 同形逻辑。Presentation 与 Godot 只读结果。

### D3 预筛

逐格跑完整预演在 900 格的图上太贵。允许预筛：候选子落下后若自身有空的气位、四邻没有只剩一口气的敌串、不在他人眼空间里、也不贴他人已确定活形棋串，则不可能自杀、不可能提子、不可能破坏活形——跳过第 3–7 步。但同形不要求提子（多人循环、送二还一都能不提子而重复盘面），所以这类候选仍要逐格过第 8 步的同形比对（实施时纠正：原稿"不提子即不可能同形"不成立）。其余候选跑完整预演。暂放批次自身不合法时不预筛。预筛 MUST 与"全部候选都跑完整预演"的结果逐格相同，由测试对照守住。

破坏活形的预筛需谨慎：不提子也可能因填掉对方眼位相关格而改变活形判定。若实施时无法证明预筛对破坏活形安全，则凡与对方已确定活形棋串或其眼空间相邻的候选一律跑完整预演。

### D4 呈现

| 类别 | 标记 | 原因文案 |
|---|---|---|
| 活棋禁入（既有） | 压暗底 + 所有者阵营色方框 + 叉 | 活棋禁入（玩家 X） |
| 破坏活形 | 压暗底 + 所有者阵营色方框 + 叉 + 角标 | 破坏活形（玩家 X） |
| 自杀手 | 红色叉，无方框 | 自杀手：落下后无气 |
| 同形 | 橙色叉 + 圆环 | 同形：与第 N 次提交的盘面重复 |

形状各不相同，色弱也能区分。

### D5 全局预览下放大

标记的线宽与尺寸随相机距离放大，全局预览下每个叉至少占所在格的大半；近景保持现状。

### D6 刷新时机

盘面变化、当前行动玩家变化、暂放变化时重算；不逐帧算。没有当前行动玩家（插旗、终局）或当前行动玩家不是本机玩家时不显示——AI 回合里显示别人的禁手没有意义。

### D7 列标

双字母列标用较小字号，使相邻列标之间留有空隙；单字母列标外观不变。

## Risks / Trade-offs

- **性能**：预筛后需完整预演的候选通常是个位数到几十个 → 任务里实测 `board:1:n10` 中盘局面的查询耗时，超过 50 ms 即报告。
- **整批语义的认知负担**：暂放后标记会变 → 原因文案写明"落下后"，并在暂放变化时即时刷新。
- **同形判定依赖历史**：查询需要已提交盘面集合；它是公开信息，不涉及可见性。

## Migration Plan

纯新增的只读查询与绘制。回滚 = 不绘制新三类标记。
