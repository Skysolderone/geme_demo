## Context

流程层目前的终局检查发生在每次结算与 Pass 之后（条件 1–3），终局原因是一个三值枚举；对局配置（地图、种子、名册）在开局时固定并入存档。跑局层为了让 AI 互打能停下来，自己加了 `MaxMajorRounds` 硬停，并把"达上限"记为跑局层的终局原因——这意味着同一局在 Sim 里和在将来的 UI 里会有不同结局，且 §16 "结束大回合数" 指标在规则层没有定义。

设计文档 §18.2 把"固定轮数"列为暂不实现；§16 又写"多数标准局在第 7–10 大回合结束，但规则允许更长拉锯"。本 change 在两者之间取"上限兜底"：不固定轮数，只封住无限拉锯。

## Goals / Non-Goals

**Goals:**
- 上限是对局配置、公开、入存档；检查点唯一（大回合结束、生成下一顺序之前）；优先级低于条件 1–3。
- 终局原因枚举新增一值，名次规则复用条件 2/3 的唯一实现。
- 跑局层不再有自己的"达上限"语义：`MaxMajorRounds` 直接写进对局配置；上限为 0 时跑局层保留一道防死锁保险。
- 存档往返、公开视图、日志首部三处都能读到上限。

**Non-Goals:**
- 不做固定轮数、不做按人数/地图的差异化上限、不做运行中修改上限。
- 不改条件 2 的保护期语义。

## Decisions

**D1：检查点放在大回合结束，而不是每个小回合。**
备选：第 N 大回合的任意小回合后即检查。否决：会让同一大回合内先手玩家多一次行动、后手玩家少一次，破坏"大回合 = 每名参赛玩家各一次小回合"的定义（turn-sequence）。放在大回合结束、下一顺序生成之前，所有参赛玩家在上限轮内行动次数相等。

**D2：条件 1–3 优先。**
条件 1–3 是"立即"，在最后一名玩家结算的瞬间已经判过；上限检查在其后。同一时刻同时满足时原因记条件 2/3，因为它们描述的是盘面事实，上限只是兜底。测试要钉住"第 15 大回合整轮 Pass → 原因为整轮 Pass"。

**D3：上限进对局配置，跑局层只传值。**
备选：保留跑局层 `MaxMajorRounds` 与规则上限两套。否决：两套语义迟早分叉（Sim 报"达上限"而规则说"进行中"）。跑局层 `--max-rounds` 直接设置对局配置；上限为 0 时跑局层用一个远大于合理值的硬停（如 1000 小回合）纯粹防死锁，并以异常而非终局记录。

**D4：上限值 15 作为标准局初值，单一常量。**
§16 目标是 7–10 结束；15 给"更长拉锯"留了 50% 余量，又不至于像 30 那样让指数膨胀阶段主导统计。与 `cap-multiplier` 归档后的 200 局回归一起校准；调整走规格变更。

**D5：不收敛率口径改为"达上限终局占比"。**
heuristic-ai 裁决 13 的口径是跑局层硬停占比；规则化后同一件事由终局原因表达，分析报告继续单列，指标含义不变。

## 接口契约

**输入：** 对局配置（新增大回合上限）；turn-sequence 的"大回合结束"事件；elimination-endgame 的名次计算。

**输出：**

| 输出 | 变化 | 消费者 |
|---|---|---|
| 终局原因 | 新增「达大回合上限」 | `match-telemetry` 终局原因分布、`add-tactical-ui` 结算画面 |
| 公开视图 | 新增大回合上限字段 | `add-tactical-ui` 顺序层（"第 x / 15 大回合"）、AI（可用于评价，非必需） |
| 存档 | 新增字段 | 持久化往返 |
| 对局日志首部 | 新增字段 | `Siege.Sim` 分析 |

触发时机：大回合结束事件之后、下一大回合顺序生成之前，仅当上限 > 0 且当前大回合序号 = 上限。

## Risks / Trade-offs

- **[与"固定轮数不实现"冲突]** → 设计文档 §18.2 加一句区分；上限为 0 保留原行为，证明这不是固定轮数。
- **[AI 在上限轮的行为变化]** → 上限公开后，AI 理论上可在最后一轮全力抢势力（无未来成本）。本 change 不改 AI；若 200 局回归显示末轮行为畸变，记录为 heuristic-ai 的调参项。
- **[存档兼容]** → 旧存档无该字段：恢复时按标准局初值 15 回填并在日志里注明；不做无字段即 0 的默认，否则旧局会变成不限轮。
- **[大回合结束事件的时序]** → match-flow 的 `MajorRoundEnded` 事件发出时序号已推进（heuristic-ai 阶段 B 踩过），上限比较要用"刚结束的那一轮"的序号，测试钉住第 15 轮而非第 16 轮。
- **[跑局层硬停与规则上限双重存在]** → 只在上限为 0 时启用硬停，且硬停以异常记录而非终局原因，避免混入终局分布。

## Migration Plan

1. 对局配置 + 存档字段 + 公开视图字段（含旧存档回填）。
2. 终局原因枚举 + 大回合结束处的检查 + 名次复用。
3. 跑局层 `--max-rounds` 改为写配置；硬停改为仅上限为 0 时生效；分析报告口径切换。
4. 设计文档 §12.3 / §18.2 / 变更记录。
5. 与 `cap-multiplier` 都归档后跑 200 局回归。
6. 回滚：回退提交；日志向后兼容。

## Open Questions（建议裁决）

1. **上限初值 15 还是 12** → 建议 15；200 局回归后若 > 90% 的局都跑满 15，说明规则仍不收敛，问题不在上限值。
2. **旧存档回填值** → 建议 15（标准局初值），不建议 0。
3. **§18.2 "固定轮数" 的措辞** → 建议改为"固定轮数（对局恰好 N 轮）仍不实现；大回合上限只是兜底，可配置为 0 关闭"。

## 裁决记录（已确认）

1. **上限初值 15，旧存档回填 15，§18.2 按建议措辞**（2026-09-14，项目负责人确认 C1 方案）。
2. **turn-sequence「无固定轮数」限定为上限 0**（实现阶段发现与默认上限冲突）：补一条 MODIFIED，既有测试 `大回合的定义与推进Tests.无固定轮数` 相应改为上限 0。
3. **名次 MODIFIED 必须完整抄录基线 Scenario**：初稿漏抄「出局者倒序」、改写了「多名弃赛者互比」的 THEN，归档会删除 / 改写基线；已恢复原文。
4. **跑局配置默认上限 30 → 15、防死锁硬停 `MaxTurns` 10000 → 1000**：与对局规则默认一致；上限不一致时 `MatchSession` 抛异常，杜绝两套语义。
5. **旧 Sim 日志里的 `MaxMajorRoundsReached` 不再计入不收敛**：该原因已从枚举删除，heuristic-ai 归档时的 36 局日志只作历史对照，不再参与新口径统计。
6. **恢复时轮次已超过上限：维持现状**（check 后主会话判定）：上限检查用 `completed >= 上限`，在当前大回合结束时终局，`Result.MajorRound` 为实际轮次而非上限。只会出现在"旧存档回填 15 但已进行到第 16 轮以后"或调试接缝摆盘，目前没有真实玩家存档；不为此加恢复时立即终局或拒绝恢复的分支。
7. **check 实测**（seed 300，6 局，Standard，上限 15）：`AllPassed` 3 局（均第 13 轮）、`MajorRoundLimit` 3 局（均第 15 轮），不收敛率 50%；峰值军势平均 583、最高 812。上限 0 时种子 303 于第 17 轮 `AllPassed`——封顶后部分对局不靠上限也能收尾。
8. **200 局回归**（2026-09-14，cap-multiplier + round-cap 均归档后，Standard，上限 15，种子 1–200，`sim-out/regress`）：
   - 不收敛率 **25.0%**（50/200，95% 区间 19.5%–31.4%），heuristic-ai 归档时 75–100%；终局原因 AllPassed 150 / MajorRoundLimit 50。
   - 终局局平均结束于第 **12.51** 大回合（分布 8–15，峰值在 12–13），§16 目标 7–10，高 25%。
   - 第 3 大回合领先者胜率 **38.0%**（口径 A，31.6%–44.9%），达标 ≤ 50%，但显著高于基线 25%；第 4 大回合先手位玩家最终平均名次 2.03，末位 3.03。
   - 首次跨出生区冲突平均第 **7.11** 大回合，§16 目标 4–5，高 42%；每批次提子 0.29（heuristic-ai 归档时 1.63）；峰值串被摧毁 1.5%（原 25%）——绞肉循环基本消失，冲突偏晚偏少。
   - 部署上限第 7 大回合后中位数仍为 **3**，§16 目标 5–8，未改善。
   - 结论：终局问题已解决到可以跑基线的程度；残余偏离（部署成长、冲突时机、先手滚雪球）是数值问题，不是结构问题。
