## Context

专家（`AiSearchConfig.Expert` = 高难 N 24 / M 32 + 前瞻宽度 4）的前瞻对前瞻集每个候选 c 预演得 B1，再模拟下一名对手在 B1 上的回应得 B2，以 B2 重打一层分数。现行模拟对手的配置是 `ExpertLookahead.SimulatedConfig = AiSearchConfig.Standard with { CandidateBatchCount = 1, CandidateCellLimit, PassThreshold, LookaheadWidth = 0 }`，即标准预设的 N 12。实际对手在扫档里是高难。`expert-tiebreak` sweep：E0 对 H 配对 3 / 9 / 8、改选 38 / 291、模拟命中约 1 / 3。

改前实测（HEAD 4013dd1，本 worktree，Release）：
- 预演次数代理（`预演次数代理计入新增部分`，S 8 / λ 1000 专家 vs 高难，48 局面）：比值 2.948；模拟对手 15575 次（14.6%）、两层扫描 51.1%、多样补充 0.3%。
- 计时（`专家前瞻耗时计时Tests`，SIEGE_PERF=1）：高难中位 115.0 ms、专家 418.7 ms，比值 3.639。

临时改为"专家本人配置派生"后（已还原）：代理 2.948、模拟对手次数逐一相同（代理的探针局面来自 4 名标准 AI 对局，在这些局面上模拟对手从未需要单点排序第 13 名以后；专家对局中模拟对手前 12 名填不满部署上限时，N 24 会多预演第 13–24 名，见实施记录）；计时比值 3.339（噪声内）；专家 G1 黄金值种子 1、3 的前瞻记录哈希变化、种子 3 决策序列变化、种子 2 不变。

## Goals / Non-Goals

**Goals**：模拟对手与专家本人的高难口径对齐；信息边界、确定性、随机消费不变；三档旧难度逐步不变；门控仍守 4 倍。

**Non-Goals**：模拟高难的扰动选择（对手私有随机流，不可读、不得新增子流）；改任何预设值、权重、阈值；多对手 / 多层搜索。

## Decisions

### D1 模拟对手配置的来源（裁决 1、2）

`SimulatedConfig = _config with { CandidateBatchCount = 1, LookaheadWidth = 0, DiverseSupplementLimit = 0, TwoPlyWeightPermille = 0, TwoPlyTieBand = 0 }`。N、`ImmediateOnly`、`CandidateCellLimit`、`PassThreshold`、`StagnationRounds` 随专家本人。

- `TwoPlyTieBand` 必须同时清零：`Validated()` 拒绝"带宽 > 0 而 λ = 0"，否则显式带宽的专家一前瞻就抛异常。
- "同一停手阈值"精确指 `PassThreshold`（无子豁免与落后者豁免按 B1 与模拟对手本人判定，与现行同一实现）。`StagnationRounds` 虽随专家本人，但模拟对手每次新建、停滞记忆为空，循环提子停手在模拟中不会触发——行为与改前相同。
- `ForSimulation` 的守门（M = 1、W = 0、S = 0、λ = 0）不变；传入的难度标签 `AiDifficulty.Standard` 只是控制器构造参数，配置已显式给出，不影响走法；若它进入前瞻记录或日志文本则改为 `Hard` 并在重钉记录说明（实施时核对）。
- 不加配置开关，旧"标准口径"删除（裁决 2）。

### D2 版本与记录

AI 评价版本 8 → 9（`EvaluationBreakdown.Version`）。日志首部、配置记录、前瞻记录格式不变（模拟对手配置不入记录）。旧版本 8 日志回放按既有规则报版本不符。

### D3 守门与重钉（裁决 4）

- MUST 不变（变了即缺陷）：5 份 `decisions-link1-*` 基线（简单 / 标准 / 高难，不含专家）、链接图黄金哈希、严格提高哈希、`SmallMapGoldenHash`、`构筑期专家与高难逐步相同`、`前瞻宽度为1且关闭多样候选时与高难逐步相同`。
- 重钉：专家 G1 黄金值（`link:1` 种子 1–3，`专家难度的一层前瞻Tests.G1Golden`）、前瞻记录黄金值（`专家前瞻的记录Tests.一层配置的记录与改动前相同`，种子 6 整局）。每颗种子写明首个分歧（小回合、记录条目、改前 / 改后模拟回应键或模拟预演次数），首个分歧 MUST 在已前瞻决策的前瞻记录上（模拟回应键或模拟预演次数不同）；构筑期记录逐字相同。
- 实施中修订（主会话 2026-10-22，未越出裁决 4"首个分歧落在已前瞻决策上"）：原文多写的"模拟回应键必须不同"过严——种子 1 / 6 的首个分歧只是模拟预演次数增加（N 24 多预演第 13 名以后的单点、结果批次不变），属本改动的直接后果，放宽为"回应键或预演次数不同"。
- 只因版本号而改的字面量：`专家前瞻的记录Tests.非专家没有前瞻记录` 的还原字面量与 `":8"` 断言、`启发式评价维度Tests.日志首部写入AI评价版本且分解值为九项` 期望值（哈希值本身不变）。
- 记录落在 Trellis 任务目录 `rebaseline.txt`（格式同 `expert-tiebreak`）。

### D4 门控（裁决 5）

两条门控测试（预演次数代理默认套件；计时 `SIEGE_PERF=1`）在实现后重测并记录数字。超过 4 倍停下回报负责人，不私自降 N / W。

### D5 验证跑局与采纳准则（裁决 6、7）

- 三臂各 20 局，口径同 `expert-tiebreak` sweep：`--map link:1 --map-per-match --seed 1 --count 20`，座位 1 被测、其余 3 高难，停手阈值 20、停滞 6、候选格上限 24、上限 100、截断 600。H = 四座 `Hard`；E0 = 座位 1 `Expert`（改前 HEAD 构建）；EB = 座位 1 `Expert`（改后构建）。H 与 E0 在派 agent 之前于改前 HEAD 串行跑完；EB 在质检通过后跑。
- 汇总：`.trellis/tasks/10-21-expert-diagnosis/research/analyze.py` / `analyze2.py`（`PYTHONIOENCODING=utf-8`；版本 ≥ 8 读 `After`，对版本 9 同样成立）：配对名次 好 / 同 / 差、胜、平均名次、截断、改选 / 已前瞻、模拟命中率、单小回合耗时中位。
- 预登记采纳准则：EB 截断 ≤ 1 / 20、两条门控 ≤ 4、EB 对 H 的"好 − 差"不低于 E0 对 H 的"好 − 差" → 采纳并提交；否则停下回报负责人，代码不提交。
- 风险已知：N 12 → 24 在多数局面不改变贪心结果（代理不变即旁证），命中率与名次的改善可能很小；高难的 M 32 扰动选择不可建模。

### D6 分段与派发（裁决 9）

一段。主会话：H / E0 跑局 → 派 1 个 trellis-implement（Core 改动 + 新守门 + 变异验证 + 重钉 + 门控重测，不 commit、不改 openspec/）→ 主会话前台复核（sln Release 构建 + 全量测试）→ 1 个 trellis-check → EB 跑局与汇总 → 设计文档 v1.37、HANDOFF / ROADMAP → archive → 提交。同一时间只一个 dotnet 进程。

## Risks / Trade-offs

- [改进幅度小] → 预登记准则兜底；不达标即停下回报，不扩样（扩样需负责人另批）。
- [20 局噪声大] → 只看方向，与 E0 同口径对比，不下显著性结论。
- [耗时] → 实测代理不变、计时噪声内。
