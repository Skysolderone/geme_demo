## Context

专家（`AiDifficulty.Expert`）= 高难的候选生成 + `ExpertLookahead.Choose` 重排。前瞻集来自基础候选（多样补充上限 S > 0 时按格集合去重、排除重跑补足），每个候选预演得 B1，模拟下一名对手（标准启发式）得 B2，一层分数以决策起点为"前"、B2 为"后"；两层权重 λ > 0 时再加 ⌊λ‰ × max(0, 专家下一手最佳单点增量) / 1000⌋，取前瞻后分数最高者。预设 W 4、S 0、λ 0。

诊断（`.trellis/tasks/10-21-expert-diagnosis/report.md`，基于 99766f0）给出两条主因：两层加分的量级与候选间差距同级（自身总分极差中位 322、两层加分极差中位 200），常压过一层分数；构筑期（第 1–3 大回合，`PublicRules.BuildProtectionRounds` = 3）各人只在自己棋盘落子、不可能跨接缝提子，模拟回应几乎不区分候选，改选主要由 S / λ 驱动。

约束：专家决策须完全确定、不消费新随机（「专家前瞻的确定性与耗时」）；只读公开信息（「前瞻模拟的公平信息」）；三档旧难度逐步不变；单批 ≤ 20 局。

## Goals / Non-Goals

**Goals：**
- 构筑期专家与高难逐步相同（不前瞻、不补充、不扫描）。
- 两层加分只在一层分数的容差带内裁决，不再改变一层分数明显更优的选择。
- 小扫档带宽 B，按准则选档，有条件地写入预设；结果如实记录。

**Non-Goals：**
- 对手模型（修法 B）、多样补充规则、W / 权重 / 阈值 / K 的校准、多层搜索、征募前瞻。
- 任何非专家难度的行为变化。

## Decisions

### D1 构筑期判据（裁决 1）
以**决策起点的公开快照**判定，不看候选：设 R = 构筑期大回合数（`BuildProtectionRounds`，3）、r = 当前大回合。`r < R`，或 `r = R` 且本大回合行动顺序中专家之后仍有在局玩家（未弃赛、未出局）时，本次决策为**构筑期决策**。等价于"按决策起点的名册，下一名对手的行动大回合 ≤ R"。
- 理由：构筑期内候选不可能提光任何对手（不可跨接缝提子），候选间的下一名对手不会因 B1 而不同，用决策起点判定与逐候选判定结果相同，且不需先预演。
- 备选：r ≤ 3 一律不前瞻——会误伤第 3 大回合末位（下一名对手在第 4 大回合全图行动，前瞻有交互），不取。

### D2 构筑期决策的处理（裁决 2、3）
构筑期决策：候选生成照常（与高难完全相同，含扰动消费）；候选只有空批次时照常 Pass（前瞻记录 `Pass`）；否则直接取高难的选择（`CandidateSelection.Best(基础候选)`，即「前瞻集」第一个），**不调用排除重跑、不模拟、不做两层扫描**，前瞻记录状态"不前瞻"，候选表只含该候选（前瞻前后分数相同，来源原排序）。不新增日志字段或状态值。对全部前瞻宽度 > 0 的配置生效（含预设）。
- 判定位置：在 `ExpertLookahead.Choose` 入口、建前瞻集之前（这样排除重跑一次都不跑，预演次数代理随之下降）。
- 备选：新增状态 `BuildPhase`——要改记录格式与解析，分析可按大回合区分，不取。

### D3 两层平局裁决（裁决 4、5）
前瞻集已模拟（状态"已前瞻"）时：
1. 一层分数 s_i（不变：B2 上的九维加权总分，含"被提走的己方棋子按危险计入"修正）。
2. 两层权重 λ > 0 且前瞻集中至少一个候选有下一名对手时，按原规则计两层加分 t_i（公式与输入不变：⌊λ‰ × max(0, 最佳单点增量) / 1000⌋）；否则 t_i = 0 且不扫描。
3. 基准 s* = max s_i；平局集 T = { i | s_i ≥ s* − B }。
4. 选 T 中 t_i 最大者；t 并列时取其中 s_i 最大者；仍并列取前瞻集下标最小者（段 A 实施后负责人裁决：t 打平时不退回自身总分次序）。λ = 0（t 恒 0）时退化为"取一层分数最高、并列取靠前者"，与现行一层配置逐步相同。
5. 前瞻后分数 = s_i（不再加 t_i）。

- B 为非负整数（加权总分单位，与停手阈值同量纲），缺省 0；`Validated()` 拒绝负数，并拒绝 **B > 0 而 λ = 0**（B 无作用的配置按"入口不得静默接受无效输入"拒绝，与 HANDOFF 规范要点"数据口径"一致）。
- 原"一层 + 两层相加"删除。λ 的数值除 0 / 非 0 外只影响 t 的取整；扫档与预设一律取 λ = 1000（t = max(0, 增量)，不丢精度）。
- 备选 ②（封顶相加，扫 λ）：仍可能翻转一层分数差距接近上限的选择，且上限取"一层极差"会随候选集自适应放大，不取；备选 ③（只严格平局）：即 B = 0，作为扫档的一档保留。

### D4 配置、记录与版本
- `AiSearchConfig` 新字段"两层平局带宽"（JSON 名 `TwoPlyTieBand`），紧接 `TwoPlyWeightPermille` 之后；为 0 时不写出（首部与 `config.json` 对 B = 0 的配置逐字节不变）；缺字段按 0 读。
- 前瞻记录：字段不变；`After` 的语义改为一层分数（= `Before` 经回应修正后的值），`TwoPlyBonus` 照写 t_i。match-telemetry「一层分数 SHALL 可由前瞻后分数减去两层加分推得」改为"前瞻后分数即一层分数"。
- `EvaluationBreakdown.Version` 7 → 8。旧日志（≤ 7）回放按 `Replayer` 既有规则报版本不符；不做旧语义兼容（v7 专家日志的两层相加结果无法在新实现上复现）。

### D5 接口契约
- 输入：`ExpertLookahead.Choose(候选, 批次, 预演, 排除重跑?)` 不变；新增读取决策起点公开快照的大回合、行动顺序与参赛状态（`MatchPublicView` 已有，属公开信息）与配置的 B。
- 输出：被选候选与前瞻记录（结构不变）。
- 触发时机：`HeuristicTurnController.ChooseByCandidates` 在 W > 0 时调用，位置不变；停滞停手（cycle-stop）在其前、决胜一手在其后，次序不变——构筑期决策不改变停手、停滞、决胜一手的判定。

### D6 守门与重钉（裁决 10）
- 新守门：
  - 「构筑期专家与高难逐步相同」：`link:1` 对局种子 1–3、1 专家（分别以预设与 W 4 / S 8 / λ 1000 / B 20 两种配置）+ 3 标准，截到第 2 大回合结束，专家每一步决策、`ai-<玩家>` 子流消费与同座位高难相同；且第 1–2 大回合的前瞻记录全部为"不前瞻"或"Pass"，排除重跑与两层预演计数为 0。
  - 「第 3 大回合末位照常前瞻」「第 3 大回合非末位不前瞻」：合成局面，断言状态。
  - 容差带：带内 / 带外 / B = 0 严格平局 / λ = 0 退化 / 全部无对手不计两层，各一个合成局面（复用 `SyntheticCandidates` 或现有两层用例的局面）。
  - 配置：B 为 0 不写出、缺字段按 0 读、负数与"B > 0 而 λ = 0"被拒。
- 变异：构筑期判定改成 `r ≤ R`（第 3 大回合末位用例应红）、改成只看 r（"专家之后仍有在局玩家"失效）、平局集用 `>` 代替 `≥`、平局集内改回相加，逐项应红。
- 不得变：简单 / 标准 / 高难 5 份决策序列基线、链接图黄金哈希、严格提高哈希、`SmallMapGoldenHash`。例外只有一种：某哈希或夹具的输入含日志首部的 AI 评价版本号时，可以只因版本号 7 → 8 重钉，但须同时证明把版本号改回 7 后与原值逐字节相同（差异只在版本号）。
- 可能重钉：专家 G1 黄金值（`link:1` 种子 1–3、1 专家 + 3 标准、截到第 12 大回合）与前瞻记录黄金值、前瞻计时局面集——首个分歧须落在构筑期决策或平局裁决上，逐份记录首个分歧小回合。

### D7 扫档、扩样与预设（裁决 6–9）
- 配置从 `sim-out/expert-diagnosis/configs/E8.json` 复制，只加 `TwoPlyTieBand`；运行前核对首部只差 B（档间）或只差 W / S / λ / B（对 H）。
- 批次：`H`、`E0`（预设，构筑期不前瞻）、`B0`、`B20`、`B60`，每批 20 局，`link:1..20`、种子 1–20、座位 1；单进程串行。
- 报告：与诊断同口径（`analyze.py` / `analyze2.py`），另报构筑期决策数、平局集大小分布、"两层加分改变选择"的次数、单小回合耗时中位数与高难比。
- 选档：截断 ≤ 1 / 20 → 配对"好 − 差"最大 → 平均名次 → 耗时 → B 小。
- 扩样（条件触发）：最优档"好 − 差" > 0 且平均名次 ≤ H → 种子 21–40、`link:21..40` 跑最优档与 H 各 20 局；合并 40 对仍"好 − 差" > 0 才把 S 8 / λ 1000 / B* 写入专家预设；否则预设 = 现预设（W 4、S 0、λ 0、B 0）+ 构筑期不前瞻，扫档结果如实写入设计文档。

## Risks / Trade-offs

- [20 局噪声] 三档差异可能在噪声内 → 只按准则选档，扩样门槛"好 − 差" > 0 且合并方向仍正才改预设；结论只报告方向。
- [构筑期不前瞻可能丢掉少量有用改选] 预设在诊断中构筑期改选 1 / 20 局 → 影响可忽略；由守门保证构筑期与高难一致。
- [B 量纲随局面放大] 中后期势力与分数变大，固定 B 在后期相对变窄 → 接受（等价于"后期只在严格接近时裁决"）；若扫档显示 B 大档更好，另议相对带宽。
- [语义变化破坏旧日志回放] 版本 7 → 8，回放如实报不符；诊断与 expert-strength 的旧数据只作参照，不复现。
- [与 terrain-barriers 的先后] 两者都重钉基线 → 裁决 12（改判）：terrain-barriers 先实施并归档（main 0852daa，设计文档 v1.33），本 change 以其后的 main 为底开工；诊断数字在新地图上复跑后再派段 A；本分支不改地图。

## Migration Plan

无存档迁移。配置文件缺 `TwoPlyTieBand` 按 0；显式写了 λ > 0 的旧配置（如 `expert-strength` 的 E5 / E6 口径）在新实现上语义变为 B = 0 的平局裁决，跑出的数字不再与旧报告可比（设计文档注明）。回滚：还原本 change 的提交，版本回到 7。

## Open Questions（建议裁决已随裁决 1–12 定，下列为实施中可能遇到的判定）

1. **构筑期判定里"专家之后仍有在局玩家"是否计已 Pass 者**：本大回合已 Pass 的玩家在构筑期仍会在本大回合后续位置行动吗？建议：按 `ActionOrder` 与参赛状态判定，不看 Pass 名单（Pass 不移出顺序，下一名对手照「前瞻中的下一名对手」第 2 步取）。
2. **构筑期的前瞻记录候选表**：建议只含高难选择一项（与"前瞻集只有 1 个候选"的不前瞻记录同形），不列其余基础候选。
3. **B > 0 而 λ = 0 拒绝的入口文案**：建议 `Validated()` 抛 `ArgumentException`："两层平局带宽只在两层权重 > 0 时生效"，三处入口（`run --config`、日志首部回放、`play` 不涉及）同一实现。
