## Context

这一层的产品价值不是"AI 下得好"，而是"能不能在两天内跑完 5000 局并告诉我第 3 大回合领先者的胜率是多少"。设计文档 §16 的六个指标与 §17 的七个分析方向，才是首轮原型真正要交付的东西。

AI 强度只需要"足够暴露规则问题"——太弱会让所有局面退化成随机噪声，太强则会掩盖规则本身的缺陷。启发式 + 可配权重是这个区间里成本最低的选择，也正是 §15.2 的要求。

信息边界是这里唯一的硬约束：§15.1 要求正式 AI 只读公开信息。必须在数据层做到，因为"AI 自觉不读"在跑局迭代中必然会被某次图省事的改动破坏。

本轮规格保持实现无关。

## Goals / Non-Goals

**Goals:**
- 正式 AI 的信息边界在数据层成立、可测试。
- 七维评价函数，权重全部可配置，便于跑局调参。
- 高部署上限下的候选剪枝，让单局时间可控。
- 批量跑局可并行、可复现、失败局可单独重跑。
- 日志覆盖 §17 的全部七类记录，且可离线分析。
- 报告直接对照 §16 的六个数值目标，偏离必须显式指出。

**Non-Goals:**
- 不做完整博弈树 AI。
- 不做联网托管与断线接管。
- 不做 AI 难度的玩家面 UI。
- 不在本 change 内调整玩法数值——本 change 只测量与报告。

## Decisions

**D1：正式 AI 与调试 AI 走两条不同的状态视图，不是同一个视图加开关。**
正式视图只包含公开信息 + 该玩家私有信息；调试视图是完整权威状态。两者是不同的类型，正式 AI 的代码在类型上就拿不到隐藏字段。用运行时开关的做法迟早会因为一次"临时调试"泄漏到正式路径。
调试视图的构造入口必须显式标记测试专用，且在非测试模式下不可达。

**D2：评价函数产出分维度的分解，而不是单一标量。**
打分结果保留七个维度各自的贡献值。理由：调参时需要知道"这一手是因为提子分高还是因为先手位分高"；没有分解就只能盲调权重。代价是内存与日志体积增大，可接受。

**D3：候选生成分两步——先单点筛选，再组合。**
第一步对每个合法空格做单点评价，取前 N 个高价值落点（N 按难度配置）。第二步只在这 N 个落点中组合出不超过 M 个候选批次（M 按难度配置）。这正是 §15.2 要求的做法。
组合策略建议：贪心（按单点分依次加入，每加一枚重算冲突）+ 少量随机扰动的多次采样，而不是完整枚举。随机扰动必须由种子驱动，否则破坏可复现性。

**D4：并列用确定性规则打破，不用随机。**
候选评分并列时按落点坐标字典序选择。理由：跑局复现是整个分析体系的地基，任何不受控随机都会让"失败局单独重跑"失效。若需要行为多样性，通过种子驱动的扰动引入，而不是通过不受控随机。

**D5：日志是"事件流 + 每回合快照"的混合。**
纯事件流重建状态成本高，纯快照体积大。取舍：每个小回合结束记一份关键快照（各玩家势力明细、结构参数、控制信物、手牌类型），期间的细粒度动作（征募候选、批次尝试、提子）记为事件。这样大多数分析只读快照即可，需要细节时再读事件。

**D6：分析在日志上离线做，不在跑局过程中做。**
跑局只负责产出日志；分析是独立的一步。理由：分析口径一定会反复调整，把分析逻辑嵌进跑局意味着每次改口径都要重跑几千局。

**D7：默认排除调试局与人工接管局。**
这些局的决策来源与正式 AI 不同，混进统计会污染胜率类指标。默认排除并在报告中说明排除数量；需要时可显式要求包含。

**D8：性能预算先测量再优化。**
§16 要求 4 人完整大回合平均不超过 3 分钟——那是**玩家**的体验目标，不是 AI 跑局的目标。AI 跑局的目标应是"单局墙钟时间足够小，使 5000 局在可接受时间内完成"。先用占位策略实测单局耗时，再决定是否需要优化 `add-board-core` / `add-territory-power` 的全量重算。

## 接口契约

**输入：** 全部六个前置 change 的输出（盘面查询、预演结果、势力明细、效果快照、手牌视图、流程事件与阶段状态）。

**输出：**

| 输出 | 消费者 |
|---|---|
| `AI 决策`（征募选择、批次部署或 Pass） | `add-match-flow`（在决策请求点消费） |
| `评价分解`（七维贡献值） | 日志、调参 |
| `对局日志`（事件流 + 每回合快照） | 离线分析 |
| `批量跑局汇总` | 平衡分析报告 |
| `平衡分析报告`（§16 指标 + §17 七个方向） | 设计决策 |
| `人工接管入口` | `add-tactical-ui`（调试界面） |

## Risks / Trade-offs

- **[信息边界泄漏]** → 用类型分离（D1）而非运行时开关；加测试断言正式视图的结构中不存在隐藏字段。
- **[AI 太弱使分析失去意义]** → 分析报告必须同时给出"AI 决策质量"的旁证指标（如平均每批次提子数、自杀手尝试率）；若这些指标显示 AI 近乎随机，则数值结论不可信，必须先提升 AI。
- **[AI 太强掩盖规则缺陷]** → 保留简单难度作为对照组，关键指标在两档难度下分别回归；若结论只在某一难度成立，说明结论脆弱。
- **[候选剪枝丢掉关键手]** → 剪枝参数 N/M 可配置；用一组人工构造的"必须找到的妙手"局面作为回归集，验证剪枝后仍能找到。
- **[日志体积失控]** → 5000 局 × 每局数十小回合的事件流可能很大。缓解：事件流可选压缩、可选只保留失败局与抽样局的完整事件，全量局只保留快照。
- **[并行执行引入不确定性]** → 每局独享自己的种子与状态，局间零共享；加"串行与并行结果一致"的回归。
- **[指标不达标时在本层打补丁]** → 明确约定：修改发生在权重/生成预算/地图，不在测量层。报告只陈述事实。

## 裁决记录（已确认）

1. **"两眼潜力"用启发式近似**：棋串的气数、气的分布是否分散、是否存在两个互不相邻的单点气。不做完整死活判定——那是围棋引擎级的工作量，且本游戏的批次落子使传统死活结论并不直接适用。该维度在评价分解中单列，便于观察其贡献是否合理。
2. **候选批次数量上限 M：简单 1 / 标准 8 / 高难 32**，先作为初值，跑完单局耗时实测后校准。简单难度只贪心一条，作为对照组用于检验结论是否脆弱。
3. **"第 3 大回合领先者" = 第 3 大回合结束时势力值最高的玩家**；并列时**同时给出两个口径**的数字：组内任一人获胜即计为领先者获胜、以及必须是该具体玩家获胜。开局前期势力并列并不罕见，排除这些局会丢掉一批有代表性的样本。
4. **征募决策与批次决策分两步**，不做联合搜索。征募时用"手牌供给与部署能力匹配度"维度做前瞻估计，部署时再优化。联合搜索会让搜索空间乘法级增长，跑局成本失控。
5. **胜率类指标默认跑 2000 局并给出置信区间**，200 局作为快速回归的下限。4 人局基础胜率 25%，200 局的 95% 置信区间约 ±6%，分辨不出"50% vs 56%"这种恰恰是结论所在的差异。
