## Context

地图是设计师固定的 JSON 数据（`maps/*.json`，字段同 v5：尺寸、`MaxPlayers`、障碍、出生区、信物格与预算分区、咽喉、中央入口、距离容差、`MinTwoEyeArea`、口袋豁免、高度、地表、桥、栅栏）。加载时「地图静态校验规则」与「人数适配预算」全量校验。内置图经三个入口共用的"标识 → 地图"解析登记。

## Decisions

### D1 手工作图 + 对称性由测试守门

两张图手工编写 JSON。2 人图 C2（绕中心 180°），3 人图竖直中轴镜像（一个出生区跨中轴位于上方，另两个在下方左右互为镜像）。对称性、规模、地形要素、三区距离公平各用一条测试钉住（与 v5 的"旋转对称"测试同法），改图即红。

### D2 布局沿用 v5 的地貌语言

出生区在 h=2 高台（12–14 格、各含 2 信物格），经缓坡 / 崖壁下到 h=1 过渡带，中央 h=0 低地含一格宽深水与预置桥，桥头与中央为高档信物预算分区；栅栏与林地点缀在咽喉处。出生区内必须能活形（沿气边连通空区 ≥ `MinTwoEyeArea`）。

### D3 参赛人数缺省取地图人数上限

批量配置 / 终端 / 图形版在未指定人数时用 `map.MaxPlayers`。4 人图行为不变；显式给人数时仍按给定值（在 4 人图上开 2 / 3 人局照旧可用）。

### D4 两段实施

段 A：2 人图 + 入口接线（D3、内置表、选图界面）+ 2 人图冒烟；段 B：3 人图 + 冒烟 + 文档。段间由负责人过目截图。

## Risks / Trade-offs

- [手工图观感不佳] 截图交负责人过目，段 B 前可返工段 A 的图。
- [AI 在小图上表现未知] 冒烟只报告；若对局明显失控（大量截断 / 首回合即终局），记为待决，另开校准。
- [预算区间是估值] 冒烟后报告"是否需要重估"，不在本 change 改区间。
