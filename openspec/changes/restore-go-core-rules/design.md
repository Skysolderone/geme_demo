## Context

基准文档 `siege-rules-and-ai.md`（与设计文档 v1.0 同源）描述的是"围棋式抢地 + 数值爆炸"的原型；本仓库在 09-13 之后为压平曲线叠加了七个数值类 change。2026-09-21 逐项裁决后，计分、出局、终局、征募四块回归基准，地图生成、地形、匠人、分阶段部署上限保持仓库现状。本 change 是三段式回归的第 ①段；`life-shape`（活形 / 活棋禁入）与 `ai-eye`（AI 并入眼位并重新校准）在其后。

约束：`Siege.Core` / `Siege.Sim` 零 Godot 依赖、计分不得使用浮点、邻接与覆盖语义各只有一处实现（`.trellis/spec/core/`）。

## Goals / Non-Goals

**Goals**
- 军势、总势力、出局、终局、征募来源五处规则与基准文档逐条一致。
- 据点概念从规范、数据、代码、表现层完整摘除，不留无功能残余。
- 摘除三个对局配置项（大回合上限、碾压起始、落后补偿开关）后，`MatchOptions` 与存档格式保持自洽。
- 回归完成后能跑出一份新规则下的 200 局基线，作为 `ai-eye` 调参与后续地图规模调参的起点。

**Non-Goals**
- 不引入活形判定与活棋禁入（`life-shape`）。
- 不调 AI 权重、不加停手阈值（`ai-eye`）；本 change 只保证 AI 能编译、能跑完对局。
- 不动地形、匠人、高地加值的判定，不动分阶段基础部署上限。
- 不校准对局时长。

## Decisions

### D1 军势的计算顺序与精确运算

`棋串军势 = ⌊(基础军势总和 + 位置加值) × 3^n / 2^n⌋`，`n = 倍增子数量`，不封顶。

- 位置加值 = 连珠 + 协同 + 高地，三项先求和，再与基础军势相加，最后整体乘倍率、对每条棋串各取整一次。
- 倍率保持分子 / 分母两个整数，取整用整数除法。`n` 的上界是地图可落子格数（边疆档可达数百），`3^n` 远超 64 位整数，因此倍率分子、棋串军势、总势力 MUST 使用不会溢出的整数表示；规范只要求"精确、不溢出、不引入二进制浮点"，实现选任意精度整数。
- 备选：饱和到某个上限——否决，等于变相封顶，违背裁决 #1。
- 倍率显示值仍给精确十进制；`n` 很大时显示层可用科学计数，但比较与排序 MUST 用精确值。

### D2 领地分复用空格归属

总势力 = 独占空格数 + 棋串军势之和。独占空格直接取 `coverage-territory`「空格归属三态」的结果，MUST NOT 另写一套覆盖统计。

- 只有**空的可落子格**参与归属：障碍、未架桥深水不计；林地格不是覆盖目标（`terrain`「覆盖关系」），空林地格恒为中立、不计分。
- 棋子所在格只算军势，不算领地。领地分不参与倍率。
- 跨崖居高临下、隔水覆盖等地形覆盖规则照常生效——高处棋子能"看住"低处空格，这是地形保留后的自然结果。

### D3 出局判据与"曾有正势力"标记

每名玩家维护一个单调标记 `曾建立正势力`：任意结算后其总势力 > 0 即置位，永不复位，随存档往返。

- 检查时机：每次合法批次结算后、每次 Pass 完成后，对**全部**参赛玩家检查（不只是行动者）。
- 判据：标记已置位且当前总势力 = 0 → 立即出局。手牌是否有子不影响判定；保护期不豁免。
- 有子必有军势 ≥ 1（基础军势 ≥ 1、倍率 ≥ 1、位置加值 ≥ 0），所以"势力为 0"等价于"盘面无己方棋子且无独占空格"；无子时不产生覆盖，独占空格也为 0，因此实际等价于"盘面无己方棋子"。
- 行动者本人不会在自己的批次结算中出局（自杀手非法、至少落 1 子）。同一次结算使多名玩家同时归零时同时出局，出局次序相同、共享名次。
- 删除的旧机制：保护期暂停检查、第 4 大回合逐玩家解除、"盘面与手牌同时为空"判据。

### D4 终局只剩三类

只剩一名参赛玩家 > 棋盘填满 > 整轮 Pass。删除势力碾压（候选 / 待回应名单 / 公开状态 / 存档字段）与大回合上限终局。

- `MatchOptions` 去掉：大回合上限、碾压起始大回合、落后补偿开关。对应公开视图字段、存档字段一并删除。
- 并列判定链：势力 → 控制中的信物数 → 独占空格数 → 盘面棋子数 → 并列。

### D5 Sim 的技术性截断

批量跑局配置保留"小回合数截断"（默认 600，对应基准文档的 `MAX_TURNS`）。触发时该局以结束原因 `turn_limit` 记录，MUST NOT 产生名次与胜者，MUST NOT 计入胜率类指标，但 MUST 在报告中单列触发局数与占比。它只存在于 `Siege.Sim` 的跑局循环，`Siege.Core` 的对局流程不知道它；人机对局不受其约束。

### D6 据点摘除的边界

- 数据：地图数据去掉据点集合；`maps/*.json` 去掉据点字段。加载到含据点字段的旧地图文件时 MUST 拒绝并明确报错（不静默忽略），仓库内地图随本 change 一次性改完。
- 校验：去掉据点数区间、据点落点、据点与信物重合、到据点距离均衡四类检查；人数适配预算表去掉"据点数"列。
- 内置图：内容变了标识就变（沿用 v3→v4 的先例）——`siege-4p-base-v4` → `siege-4p-base-v5`，`siege-frontier-v1` → `siege-frontier-v2`，地形与信物格逐格不变，只去掉据点；缺省地图随之改为 v5。旧标识不再可用，请求时报"未知地图"。
- 生成器：去掉据点布置步骤。布点消耗过随机子流、也占过填充格，摘除后**同一个 `gen:` 标识生成的图会与此前不同**。`gen:` 标识不含生成器版本段，本 change 不为此扩展标识格式：原型阶段接受这次不兼容，此前日志里的 `gen:` 标识不再能重放，生成确定性测试的基准值随本 change 重建。
- 计分与明细：势力明细由"据点分 / 棋串"改为"领地分 / 棋串"。
- 表现：势力层改显示独占 / 争议格与领地分；删除三档地标与控制旗。
- AI：`BatchEvaluator` 中据点估值项删除；领地变化已包含在"即时势力增量"维度里，不新增维度。默认权重在 `ai-eye` 完成前显式标注为**未校准**口径。

### D7 征募与快照

效果快照不再读取势力名次；展示数 / 选取数 = 默认值 + 信物。部署上限仍为"分阶段基础值 + 军令"，快照仍需读取当前大回合序号。来源拆分只剩"基础（按阶段）""各枚信物"两类。

### D8 实施分段（顺序执行，每段结束 `dotnet build` 零警告 + `dotnet test` 全绿）

- 段 A：军势公式 + 领地计分 + 势力明细（`Scoring`）。
- 段 B：据点摘除（`Board` / 地图文件 / 校验 / 生成器 / `Scoring` / `Preview`）。
- 段 C：出局、终局、`MatchOptions` 与存档（`Match`）。
- 段 D：征募补偿摘除（快照、来源拆分、面板）。
- 段 E：`Siege.Sim`（配置、截断、日志、分析、报告）、`Siege.Presentation`、Godot 表现。
- 段 F：设计文档同步、200 局新基线、`.trellis/spec` 如有新约定则补。

## 接口契约

| 方向 | 对象 | 契约 |
|---|---|---|
| 输入 | `coverage-territory` 空格归属 | 每次结算后给出每个空可落子格的归属（独占者 / 争议 / 中立）；本 change 只消费、不改判定 |
| 输入 | `terrain` 覆盖关系 | 高地加值与覆盖目标判定不变 |
| 输入 | `frontier-map`、`map-generator`（须先归档） | 提供地图规格档、边疆档地图、生成器与 `gen:` 标识；本 change 在其上摘除据点并递增两张内置图的标识 |
| 输出 → `life-shape` | 合法性预演、结算顺序 | 结算第 6 步为"信物控制 → 空格归属 → 棋串军势 → 总势力"；`life-shape` 在预演中插入活棋禁入检查，不改本顺序 |
| 输出 → `ai-eye` | 势力明细、`EvaluationWeights` | 即时势力增量已含领地变化；权重表标注未校准，`ai-eye` 负责重新校准并解除标注 |
| 输出 → 后续数值 change | Sim 报告 | 新规则下的部署曲线、势力曲线、对局长度、`turn_limit` 触发率、领先者胜率 |

## Risks / Trade-offs

- [对局不收敛] 删掉上限与碾压后，现有 AI 没有停手阈值，批量跑局可能大面积触发 `turn_limit` → 这是预期内的中间状态；段 F 的基线如实记录触发率，由 `life-shape` + `ai-eye` 解决，不在本 change 内打补丁。
- [数值爆炸失控] 不封顶 + 位置加值被放大，单串军势可达天文数字，势力排名被一条倍增串决定 → 裁决 #1 明确接受；报告保留单串峰值与倍增子选择率，供后续判断。
- [领先者滚雪球] 落后补偿删除后第 3 大回合领先者胜率大概率回到 50% 以上 → 裁决 #7 明确接受；指标保留、只报告不拦截。
- [大数运算性能] AI 每个候选都要重算势力 → 任意精度整数只在 `n` 大时才变慢；若跑局耗时显著上升，在 `ai-eye` 内评估增量计算，本 change 不优化。
- [一次性删改面大] 40+ 文件 → 按 D8 分段，每段独立可编译可测；据点摘除单独成段，便于回看。
- [未提交的工作区] 当前工作区有 `frontier-map` / `map-generator` 的未提交改动，且段 B 会改同一批文件 → 先提交并归档这两个 change，再开始实施。

## Migration Plan

1. 提交并归档 `frontier-map`、`map-generator`。
2. 按 D8 段 A → F 顺序实施；每段结束跑全量测试。
3. 旧存档、旧地图 JSON、旧 `gen:` 标识不迁移，加载时明确报错。
4. 回滚：本 change 全部为规则替换，回滚即 `git revert` 对应提交；被删的 change 仍在 `openspec/changes/archive/` 可查。

## Open Questions（建议裁决）

1. **空林地格是否计领地分？** 建议：不计。林地不是覆盖目标，归属恒为中立；要占林地只能落子。
2. **同一结算多名玩家同时归零的名次？** 建议：同时出局、共享名次，出局次序相同。
3. **`turn_limit` 的默认值？** 建议：600 小回合，可在跑局配置中覆盖；0 表示不截断（仅供调试）。
4. **势力值很大时 HUD 如何显示？** 建议：≥ 10^6 起用 K / M / B 缩写，悬停或明细面板给精确值；排序始终用精确值。表现细节不进规范。
5. **`EvaluationWeights` 校准守门测试在过渡期如何处理？** 建议：守门保留，但校准记录改写为"未校准（restore-go-core-rules 起失效，待 ai-eye）"，由该维度的"未校准"显式标注满足规范，不删测试。
