## 四条贯穿全局的硬约束

1. **单一四邻接**——连接、气、覆盖、围杀共用同一实现，任何斜向语义都是缺陷。
2. **一切实时重算**——不保留成长层数、历史峰值或已失效加值；棋串断开、倍增子失联、连珠断线后分数立即下降。
3. **随机可复现**——信物生成、征募抽取、流程初始化各走独立的种子子流；改变其中一个子流的消费次数不得影响其他子流。§17 的全部平衡分析都建立在此之上。
4. **围棋记法坐标**——列字母 `A`–`L`（跳过 `I`）+ 行数字（自下而上，从 1 起），左下角为 `A1`。日志、规格、错误信息与一切面向人的输出都用该记法；内部数值索引只允许存在一处双向映射。

## 已确认的关键裁决

37 条 Open Question 已全部裁决，完整记录在各 change 的 `design.md` 末尾"裁决记录（已确认）"一节。其中影响面最大的几条：

| 裁决 | 出处 | 影响 |
|---|---|---|
| 坐标用围棋记法，左下 `A1` | board-core | 全项目记法；内部映射唯一 |
| 出生区距离容差 = 1 | board-core | 最严格的一条地图约束；3 人图可逐图放宽并记录理由 |
| 两眼最小格数 = 8 | board-core | 必死口袋校验偏保守，靠逐图豁免兜底 |
| 稀有度容差 = 8% | relic-system | 偏严，"未收敛兜底"路径会被经常走到，必须做扎实 |
| 同形禁则全局生效 | batch-deployment | 不区分提交者，跑局监控误伤频次 |
| 倍率不设上限 | territory-power | 超标时改征募权重或生成预算，不在计分侧截断 |
| 连续 Pass 计数器 | match-flow | 规避"参赛人数中途变化"的分桶歧义 |
| 胜率默认 2000 局 + 置信区间 | heuristic-ai | 200 局分辨不出 50% vs 56% |
| 信息层一次只显示一层 | tactical-ui | 避免为 31 种叠加组合设计视觉优先级 |

## 最高危的三个实现陷阱

| 陷阱 | 出处 | 后果 |
|---|---|---|
| 提子写成顺序循环而非集合操作 | §6.1 第 4 步 | 两条互相供气的敌串因遍历顺序不同得到不同结果 |
| 出局保护按全局回合号统一解除 | §4.2, §12.1 | "开局被围死就再也回不来"的体验事故 |
| 手牌只存总数而不分两段账 | §5.5 | Pass 撤销无法区分本轮新增与回合前已有，反拖延护栏失效 |

## 不在本轮范围（设计文档 §18.2）

金币与付费刷新、棋子升级、固定轮数、历史积分、通用击杀奖励、统帅与阵营、
正式联网同步与匹配、2/3 人正式地图、带入带出与局外成长、完整博弈树 AI、
超出玩法验证所需的正式美术与演出。

## 用法

```bash
openspec list                        # 列出全部 change
openspec show add-board-core         # 查看某个 change
openspec status --change add-board-core
openspec validate --all              # 校验全部
```

实现某个 change 时运行 `/opsx:apply`（或直接按其 `tasks.md` 推进）；完成后 `openspec archive <change>` 把其 spec 合并进 `openspec/specs/`。
