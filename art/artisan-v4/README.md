### 16 条边同屏的读法（为什么是"贴边不收缩"）

裁决 T-11 后一枚匠人的候选边有 16 条。它们**恰好**是"以匠人格为中心的十字五格区域"的 12 条外轮廓边
加上匠人格自身的 4 条边——屏幕上就是**一个十字轮廓套一个小方框**，中心正是匠人，读法自解释。

否决"把边高亮朝匠人落点一侧收缩"：判断一条边的哪一端靠匠人需要四邻判定，而 `FenceEdge` 构造即按字典序归一、
端点角色已经丢掉；表现层与 Godot 都禁止自己算邻接（`Adjacency` 在表现层禁表里、`.Neighbors(` 在 Godot token 表里），
为此改 `TerrainEditRules` 的返回形状属于越界。

多枚匠人同时暂放时**只显示一枚**的候选（光标停在哪枚显示哪枚，否则显示最后暂放的那枚），
避免两个十字叠在一起；**已选**目标不受此限，全部匠人的一直都画——它是要提交的动作。

### 选目标的操作

`E` 键（手柄左肩键）在"不改造 → 目标 1 → … → 目标 N → 不改造"之间轮换当前匠人的目标；
HUD 预演面板的「改造」一节列出每枚匠人的"落点 → 已选动作与目标（可选 N 个，[E] 轮换）"。
不做"点边选目标"：拾取原语是格（`BoardGeometry.TryPick` 的数学投影），边要再做一次消歧，代价不值。
