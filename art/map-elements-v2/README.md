## 实施方决策清单

| # | 决策 | 理由 |
|---|---|---|
| 1 | 全程在这台 Mac 上做，前后对照只用本机基线 | 负责人指定；截图与读数跨机器不可比 |
| 2 | 自行装了 Godot 4.7.2 .NET（`~/Applications/godot-4.7.2-mono/`），构建时用仓库外的 NuGet 配置，不改仓库里写死 Windows 路径的 `nuget.config` | 本机没有这个版本；不影响 Windows 机 |
| 3 | 不派子 agent，主会话直接实现 | 派发前要先确认而未获确认；同一时间只跑一个进程 |
| 4 | 段 A 的地块方向按现状通过（倒角 0.045、小面色差 ±3.5%、崖壁四条带两道岩缝），没有再调 | 负责人授权自行决策；近景与默认镜头下都读得清、不显碎 |
| 5 | 前置段与段 A 合成一个提交，B / C / D / E 各一个 | 前置的 `--no-batch` 与段 A 的改动落在同一批文件的相邻位置，拆不干净 |
| 6 | 0.2 的逐像素差异不单独修，留到段 C 重建岩石时把缩放烘进顶点 | 根因是 MultiMesh 实例的非均匀缩放；重建后自然消除（已验证 0 像素差） |
| 7 | 亮度系数 1.0 存成 232 / 255、材质底色乘回（design F-1） | 顶点色是 8 位，存不下大于 1 的系数；这样原色逐位不变 |
| 8 | 地块类部件不逐格实例化场景，只取网格（F-3）；变体之外再加四个朝向（F-4） | 节点数不增加；朝向不增加绘制调用 |
| 9 | 一件部件里同一材质合成一个网格，明暗靠亮度系数（F-12） | 子网格 96 → 29，绘制调用降到改前之下 |
| 10 | `water_bed` 就是水体本身，全图水格共用一份水色材质（F-9） | 水不透明，另放一层河床看不见；共用材质后生成图绘制调用 1317 → 728 |
| 11 | 桥按通行方向摆放、桥墩探到桥面之下（F-10 / F-11） | 有栏杆之后两侧与两头不再对称；桥墩只能在桥面下 |
| 12 | 外圈石沿放在底座最外 0.30，不动标注平面（F-13） | 设计 O-3 的两个选项里取"放在标注平面之外" |
| 13 | 台面边框改为受光材质、凸起 0.05（F-15） | 倒角要受光才看得出；规格要求凸起不超过 0.05 |
| 14 | 加了两个仅调试 / 截图用的命令行选项：`--no-batch`（tasks 要求）、`--shot-zoom=`（拍近景） | 严格 CLI 都认；不影响对局 |
