## 2. 复盘如何复用正式实现、随机子流如何隔离

- **同一条路径**：`ReviewBestMove` 与 `Deploy` 共用同一 AI 对象的观察委托与预演口径（`RehearsalView`）、`CreateEvaluator`、`EffectivePassThreshold`（含无子豁免与 C15）、`ScorePoints`（候选格预筛 K、格 × 类型 × 改造枚举、预演、活形硬约束 `TryEvaluate`）、`Rank`（单点排序）与 `Greedy`。没有第二套评价；"本可翻盘"的势力走 `BatchEvaluator.PowerOf`（与评价器"即时势力增量"维同一份 `PowerCalculator.Compute(board, roster, 已揭示信物)`）。
- **最好一手 = 单点排序第一名**；评价收益 = 其加权总分 − Pass 加权总分，正是贪心加第一枚时与停手阈值比较的量。排序第一名不过阈值 ⇔ 任何扰动次序的贪心都从空批次起步且每枚不过阈值 ⇔ 正式决策 Pass。因此复盘**只需 k = 0 的无扰动排序，完全不消费扰动子流（也不需要副本）**——"等价的确定性方式"。`BestMoveReview.ImpliesPass` 把这条等价写成可检的自检量：诊断批次 58/58、基线种子 3 的全部部署逐次一致。
- 另给"强制落子批次"：同一排序前 N、同一 `Greedy`，阈值放到 `int.MinValue`（合法且未被活形硬约束淘汰即保留，直到部署上限），回答"若不许 Pass，AI 自己的首选落法能否翻盘"。
- **不改对局**：复盘只在**影子批次**（同盘面、同 `BatchContext`）上暂放，预演走 `BatchRehearsal.Rehearse(board, ctx, placements, match.History)`（与 `MatchFlow.Rehearse` 同一入口），正式暂放批次及其被拒留痕、`Decisions`、`Last*` 留痕一概不碰。
- **回放**：`DefeatReplay` 与 `Replayer` 同一组输入（首部配置、种子、首部带入、日志配对事件 `RecordedPairingSource`），先核地图摘要与 AI 评价版本；逐小回合推进并与原日志同序号快照核对（玩家 / 大回合 / Pass / 落子 / 提子），分歧即整局记"未能复盘"。日志未加任何字段。

### 3.1 战场落败复盘

- 整轮 Pass 结算落败 **58** 人次，复盘到 58（未能复盘 0，找不到 Pass 快照 0）；复盘时实际停手阈值 **0×58**（全部是本战场落后者，C15 已生效）；复盘结论与实际 Pass 一致 **58/58**。
- **本可翻盘**（最好一手、对手不回应）：**2/58（3.4%）**；合法候选中存在单点翻盘手：**4/58**；强制落子批次可翻盘：**5/58**；三者并集 **5/58（8.6%）**（种子 3 R7、C R6、C R9、D R5、12 R8；其中 4 例在种子 11–20，1 例——种子 3 R7，仅强制批次可翻盘——在 F.5 子集，F.5 子集为 1/28）。
- **无任何合法落子：28/58（48.3%）**，全部是"有空格但每个候选都落选"（NoLegalCandidate×28；无手牌 / 无额度 / 无空格均为 0）。这 28 人的落选单点合计：活形硬约束 734（填自己单格眼 / 破坏己方活形且不提子）、预演不合法 Suicide 212、Superko 10。
- 有合法候选的 30 人：最好一手收益**全部为负**——最小 −1344，P10 −836，P25 −378，中位 −304，P75 −113，P90 −90，最大 −12；分段 ≤−500×6，(−500,−100]×18，(−100,−20]×5，(−20,0)×1，0 与正值 0。
- 能提子：最好一手提子 **8/58**；候选中存在提子手 8/58（提子手都不足以翻盘）。
- 复盘时势力差（本战场最高者 − 己方）：最小 1，P10 6，P25 23，中位 84，P75 439，P90 1351，最大 6469。

**判断（错过翻盘手 vs 确无有用手）**：以"确无有用手"为主。48% 的落败者此刻根本没有合法落子（盘上只剩自己的眼与自杀点，像围棋收官后）；另 43%（25/58）有合法手但没有任何一手（单点或强制批次）能追平本战场最高者；只有 **5/58（8.6%）** 存在翻盘手，且这是"对手不回应"的乐观上界。C15 零效果的原因由此清楚：58 人的阈值本来就是 0，而所有候选的评价收益都 < 0（最大 −12）——阈值从未起作用，挡住落子的是评价本身（眼位 / 安全等维度把落子评为劣于 Pass）与可落空间耗尽。5 例错过翻盘手里有 2 例最好一手本身就能翻盘但收益为负（如 12 R8 的 Y7:Multiplier 势力 77→160 反超 156，收益 −252；C R9 的 AC3:Multiplier 68→96 反超 75，收益 −1070），即"势力上翻盘、评价上不划算"。

## 5. 第二段 P5 各方案的预期效果（只据数据分析，不替负责人裁决）

- **A 落后且存在翻盘手时不得 Pass**：可作用的样本上界 5/58（8.6%），而且是"对手不回应"的乐观口径——对手随后还能回应，实际能改写战场结果的更少。对 28 名无合法落子者和 25 名无翻盘手者无效。实现要在每次落后者决策里对全部候选多做一次预演 + 势力计算（复盘的同一路径），开销约翻倍。是 AI 配置，不动规则。若采用，"存在翻盘手"宜直接用"势力反超"判（5 例里有 2 例评价收益为负但势力反超）。
- **B 连续两整轮全员 Pass 才结算**：全员 Pass 的一轮盘面不变，确定性 AI 下一轮通常再 Pass；变化只来自多一次征募（新类型、部署上限 3→4→5、匠人改造）。28 名"无合法落子"者多半仍无手可下，预期结果基本不变、每次战场结算推迟 1 个大回合（对局变长约 1–3 个大回合，等待者多等 1 轮、劣势可能加深）。这是规则改动，人类玩家同样受影响。
- **C 延长构筑期**：落败分布在第 4–21 大回合（第 4–5 大回合 8 人次）。延长构筑期推迟首轮配对、给每块出生棋盘更多独立成长时间，但不触及"盘面下满 → 全员 Pass"的机制，预期对"落败时无手可下"无直接作用；对等待者劣势的影响方向不明（本诊断没有可直接推断的量），只能另跑对照批次才能看。
- **D 维持现状**：数据支持"落败时 Pass 多数是确无有用手"（91% 无翻盘手、48% 无任何合法落子），整轮 Pass 结算相当于收官后按势力判胜负，结果合理；C15 零效果是因为阈值从不是约束（全部收益 < 0）。代价是保留 5/58 的"势力可反超但 AI 评价不划算"个例。
