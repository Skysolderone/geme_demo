## 实现清单

## 1. 信息边界

- [x] 1.1 定义 `公开视图` 与 `当前玩家私有视图` 两个独立结构。验证：公开视图结构中不存在未发现信物内容、征募面板、对手手牌数量、对手暂放批次四类字段。 — （阶段 A）`MatchPublicView`（沿用 Core，与 heuristic-ai 同一类型）+ `PublicSupplement`；私有侧为 `HandPrivateView` / `BatchPreview`。闭包守门：`必须隐藏的信息Tests.数据层边界`。
- [x] 1.2 实现 §13.1 六类始终公开信息的完整暴露。算例（设计文档 §13.1）：A 落下倍增子 → 所有玩家可见其玩家与类型；B 查看 A 的势力 → 可见领地分与每条棋串的基础军势/位置加值/倍率/最终军势；任意棋串的气数与气位可推导。 — （阶段 A）`始终公开的信息Tests` 三条 Scenario。
- [x] 1.3 实现 §13.2 四类隐藏信息在数据层的排除。算例：未覆盖的信物格 → 仅"未知信物"标记；B 查看 A 手牌 → 仅类型；A 暂放中 → 他人界面无任何提示。 — （阶段 A）`必须隐藏的信息Tests` 四条 Scenario。
- [x] 1.4 与 `add-heuristic-ai` 共用同一套公开视图定义。验证：两者引用同一结构，不存在两份定义。 — （阶段 A）`PublicWorld.View` 的类型就是 AI 闭包里的 `MatchPublicView`，无第二份定义。

## 2. 批次预演

- [x] 2.1 约定预演结果载荷必须包含六项信息（落点/类型/手牌消耗、部署上限与已用数、预计被提棋串、己方棋串与气与自杀风险、各棋串军势预览、势力与排名变化）以及失败类别与坐标、"将揭示"标志。验证：载荷结构断言，缺项即失败。 — （阶段 A）`Siege.Core.Preview.BatchPreview`：六项 + 失败类别/坐标 + 将揭示；`MatchFlow.PreviewCurrentBatch()`。
- [x] 2.2 实现 UI 只消费预演结果，不做任何规则计算。验证：UI 层不依赖棋串/气/军势的计算模块。 — （阶段 A）IL 调用扫描守门 `UI层不含规则计算Tests`。
- [x] 2.3 实现预计提子的呈现。算例（设计文档 §14.1）：暂放将使敌方 5 枚棋串无气 → 明确标示该棋串将被提走。 — （阶段 A）`显示预计提子`。
- [x] 2.4 实现自杀风险呈现。算例：暂放组合使己方某棋串结算后仍无气 → 标示风险并高亮该棋串。 — （阶段 A）`显示自杀风险`。
- [x] 2.5 实现军势预览呈现。算例：暂放倍增子接入某棋串 → 显示该棋串提交后的基础军势、位置加值、倍率与最终军势。 — （阶段 A）`显示军势预览`。
- [x] 2.6 实现势力与排名变化呈现（含他人名次被挤动）。算例：势力 45→62、排名 3→2 → 完整显示变化。 — （阶段 A）`显示势力与排名变化`（含被挤动的他人名次）。
- [x] 2.7 实现部署额度呈现。算例：上限 5、已暂放 3 → 显示"3 / 5"。 — （阶段 A）`显示部署额度`。
- [x] 2.8 实现"将揭示"标志的呈现，不提前显示信物内容。算例（设计文档 §14.1）：暂放使某未知信物格首次进入覆盖范围 → 显示"将揭示"，不显示类型与强度。 — （阶段 A）`将揭示提示`：只给坐标；同种子换内容投影逐字相同。
- [x] 2.9 实现七类非法原因的说明与高亮。算例（设计文档 §14.1/§6.1）：自杀手 → 高亮结算后仍无气的己方棋串；同形 → 指出重复的历史提交；预占腾空格 → 文案为"该格当前已被占据"。 — （阶段 A）`自杀手高亮` / `同形说明` / `预占腾空格的文案` + `八类失败标题互不相同`。
- [x] 2.10 断言预演零副作用。验证：反复暂放/撤销/换位并多次查看预演 → 正式盘面与全部玩家状态序列化不变。 — （阶段 A）`预演无副作用`：部署阶段逐项指纹 + 孪生局 Serialize 逐字节。
- [x] 2.11 实现 Pass 确认前的撤销警示。算例（设计文档 §5.5）：本轮新征募 3 枚且暂放为 0 → 确认前提示"确认 0 落子将撤销本轮新征募的 3 枚棋子"。 — （阶段 A）`Pass确认前警示撤销本轮新征募`。

## 3. 战术信息层

- [x] 3.1 实现领地层（弱化棋子演出，呈现占据/独占/争议/中立四态）。验证：四态可区分。 — （阶段 A 数据层）`领地层三态可辨`；弱化棋子的着色归阶段 B。
- [x] 3.2 实现气层（棋串轮廓、全部气、危险棋串），危险阈值可配置（初值：气 ≤2 危险、气 =1 紧急）。算例：只剩 1 口气的己方棋串 → 标示为紧急。 — （阶段 A）`气层标示危险棋串`，阈值 `LibertyThresholds` 可配置。
- [x] 3.3 实现势力层（每格领地贡献、各棋串分数、倍率热区）。验证：显示内容与 `势力明细` 一致，不自行重算。 — （阶段 A）`势力明细公开`：读 `PowerSnapshot`，不重算。
- [x] 3.4 实现信物层（内容、强度、控制者、失效原因），未发现内容继续隐藏。算例（设计文档 §14.2）：争议信物 → 标示争议并说明不向任何玩家提供效果；未发现信物 → 仍显示为未知。 — （阶段 A）`信物层不泄漏未知内容` / `信物层说明失效原因` / `弃赛者封锁的信物可辨`。
- [x] 3.5 实现顺序层（势力名次、先手修正、先手值、预测的下一大回合顺序）。验证：玩家可据此解释下一轮排序，数据来自 `先手值明细`。 — （阶段 A）`顺序层可解释下一轮排序`：预测与实际生成的明细逐项一致。
- [x] 3.6 实现信息层互斥（一次只显示一层，切换即自动退出当前层）与默认棋盘上的统一"未知信物"标记（不区分预算分区，分区信息仅在信物层可见）。验证：切换后前一层退出；两个分属不同分区的未发现信物格在默认棋盘上显示相同。 — （阶段 A）`切换即互斥` / `默认棋盘不显示分区` / `分区信息在信物层可查`。
- [x] 3.7 实现按住进入 / 松开退出的临时信息模式。验证：按住期间显示，松开立即恢复默认棋盘。 — （阶段 A 数据层）`按住进入松开退出`；按键事件由阶段 B 的 InputMap 喂给状态机。
- [x] 3.8 实现键鼠与手柄分别配置战术视图键。验证：两套配置互不影响。 — （阶段 A 数据层）`键鼠与手柄分别配置`：`TacticalViewBindings` 两套表；接 Godot InputMap 归阶段 B。
- [x] 3.9 实现辅助设置的"点击切换"，与"按住显示"共用同一可见性状态机。验证：两种模式下信息层内容与行为完全一致。 — （阶段 A）`辅助设置切换为点击`：与按住共用同一状态机。
- [x] 3.10 断言信息层在自己部署期间与他人行动期间均可查看。验证：两种时机各有用例。 — （阶段 A）`他人行动时可查看`。
- [x] 3.11 断言信息层为纯读视图、零副作用、不越权。验证：任意次开关后对局状态序列化不变；任意信息层均不显示四类隐藏信息。 — （阶段 A）`查看无副作用` / `信息层不越权`。

## 4. 手牌信息面板

- [x] 4.1 实现面板开关（点击按钮打开，再次点击或返回关闭）。验证：开关状态不影响对局。 — （阶段 A）`开关面板`。
- [x] 4.2 实现自己区域（类型、准确数量、槽位占用、本轮新征募未提交数量）。算例（设计文档 §14.3）：持普通子×6、堡垒子×1 → 显示准确数量；本轮新征募普通子×2 → 标示其中 2 枚为本轮新增；3 种类型/上限 5 → 显示已占 3、余 2。 — （阶段 A）自己区域三条 Scenario。
- [x] 4.3 实现敌方区域只显示类型。算例：A 持普通子×6、堡垒子×1 → 他人只见两种类型，不见数量、征募与暂放。 — （阶段 A）敌方区域两条 Scenario。
- [x] 4.4 实现公开结构参数与信物来源（展示数、选取数、手牌槽、部署上限及各自来源）。算例（设计文档 §14.3）：B 部署上限 5，其中 +2 来自两枚军令 → 显示数值并标注来源。 — （阶段 A）`显示参数与来源` / `参数对全体公开`；数值来自账本副本上的效果快照，来源与之对账不一致即抛出。
- [x] 4.5 实现弃赛玩家的表现（保留最后公开手牌类型 + 清楚标记不再行动）。算例：D 弃赛时持普通子与连珠子 → 保留展示并标记已弃赛。 — （阶段 A）`弃赛者标记`。

## 5. 视觉风格基准

- [x] 5.1 建立风格基准文档，引用 `art/style-exploration/siege-style-03-low-poly-fantasy.png`，并明确其只用于确定材质、色彩、轮廓与信息层级。验证：文档中明确写出"不代表最终地图布局与固定 UI 尺寸"，以及 `ROUND 7` 仅表示当前大回合。 — （阶段 A）`art/style-exploration/README.md`，含 9 张参考图清单与人工检查清单。
- [x] 5.2 实现四方势力的红/蓝/金/紫主色 + 旗帜图形 + 棋子轮廓三重区分。验证：去色条件下四方势力仍可区分。 — （阶段 B）`src/godot/scripts/Visuals.cs` 取 `FactionTable` 主色；`Emblems.cs` 一份多边形同时喂 HUD 的 `EmblemIcon`（2D `_Draw`）与棋子底座的 3D 网格，四方图案三角/塔楼/太阳/莲花，用近白高亮墨色压在阵营主色底座上拉开明度差。**待人工看截图确认去色可辨。**
- [x] 5.3 断言方格边界始终清晰、装饰不遮挡判读。验证：在含树木/遗迹/水面/高低差的地块上，合法落点、气与领地归属仍清晰可辨。 — （阶段 B）地砖 0.90 边长 + 1.00 格距，缝隙露出深色底板即网格线，恒可见；障碍格用低多边形岩石，挂在 `Decoration` 节点、且打开信息层时按 `DecorationContrastPercent` 缩小压低；判读标记（归属着色 / 气位 / 轮廓环 / 预览）全部贴在地砖上方、渲染在装饰之上。**待人工看截图确认。**
- [x] 5.4 实现五种棋子的轮廓语言（圆润 / 塔楼体块 / 连接关系 / 放射状 / 多节点聚合）。验证：去色的小尺寸缩略图中五种轮廓彼此可区分。 — （阶段 B）`LowPoly.Piece` 按 `PieceStyleTable.For(type).Silhouette` 分派，Godot 侧不含第二份类型判断：圆头兵=球+锥柱、塔楼=八棱柱+雉堞、双球连杆=两球+横杆、金字塔=四棱锥、多瓣水晶=主晶柱+四根外倾副晶。**待人工看缩略图确认。**
- [x] 5.5 实现默认 UI 风格（深色半透明面板、克制金色边框、高对比信息色、PC 策略游戏信息密度）。验证：不存在手游式大按钮与夸张弹窗。 — （阶段 B）`Ui.cs` 的面板与按钮工厂全部读 `UiTheme`：面板 `PanelFill` + 1px `PanelBorder` 金边，按钮高度恒为 `ButtonHeightPx`（30，远低于 `MobileStyleButtonHeightPx` 56），无弹窗动画；HUD 按裁决 6 布局：左上回合旗标、顶部中央顺序条、右上排名、左下手牌、底部中央五个信息层按钮、右下确认与 Pass。
- [x] 5.6 实现批次预览的半透明发光与预计提子的虚线/轮廓提示，两者视觉可区分。验证：同屏出现时可分辨。 — （阶段 B）`BoardView.DrawPreview` 按 `VisualLayering.StyleOf(kind)` 分派：暂放 = 整枚棋子半透明 + 自发光（`TranslucentGlow`），预计提子 = 断成三段的红色虚线环（`DashedOutline`），自杀风险 = 双层实线警示环，将揭示 = 悬浮徽章，非法落点 = 红叉。**待人工看同屏截图确认。**
- [x] 5.7 实现信息层的临时降饱和处理。验证：打开势力层时场景饱和度与装饰对比被压低，退出后恢复。 — （阶段 B）`TacticalLayerState.Treatment` 的三个百分比直接驱动：饱和度接 `WorldEnvironment.Environment.AdjustmentSaturation`，装饰对比缩放岩石并压地砖底色，棋子弱化按 `PieceEmphasisPercent` 把棋子色拉向中性灰；退出层即回到 `SceneTreatment.Default`（100/100/100）原样。
