# 09-16-ai-safety-weight

> 规格权威：`openspec/changes/ai-safety-weight/`。本文件只承载目标、验收映射与范围边界。
> 设计文档来源：`2026-09-10-siege-core-gameplay-design-v1.md` §16、§17

## Goal

`EvaluationWeights.Default.Safety = 20` 是 v1 基准图上凭 5 局与 2 颗种子试出的初值，它自己的 doc 注释就标着"阶段 B 的首个校准项"，校准从未做过。`denser-map` 把可落子格压到 85 之后，这个未校准的值开始主导结果：不收敛率 11.5% → 27.5%，第 3 大回合领先者胜率 46.5% → 64.5%（`catch-up-recruit` 的成果被抹平），60/200 局整局没有发生过一次提子。

v2 上九档各 200 局的扫档已经做完（见 design.md §2）。本任务把 `Safety` 改为校准值 **5**，并补上守门，防止再出现"未校准的初值被当基线"。

## Acceptance

| 验收项 | 目标 | 对应规格 |
|---|---|---|
| 默认权重七维被逐一钉住 | 任一维度改动即变红 | `ai-decision`「默认评价权重的校准」Scenario 1 |
| `Safety` 默认值 | 5 | 同上 Scenario 2 |
| 不收敛率 | 9.5%（±3 个百分点） | design.md D1 |
| 第 3 大回合领先者胜率 | 51.0%（±3 个百分点） | §17，design.md D1 |
| 首次冲突大回合 | 4.68（±0.3） | §16 目标 4–5 |
| 整局无冲突局数 | 3（±5 局） | design.md §2 |
| 终局局长度 | 10.23（±0.3） | §16 目标 7–10 |

## Out of scope

- 其余六维默认权重（无扫档证据，各自独立成轮）。
- `GroupSafety.Score` 算式与 `DangerLiberties = 3`。
- 重跑 `sim-out/` 历史批次（改为标注权重口径）。
- 落后者"无处可下"的问题：第 3、4 名在第 5 大回合后有一半回合直接 Pass，落子数不到部署上限的五分之一。`Safety=5` 已把领先者胜率带回 51.0%，但该机制仍在，属独立的一轮。

## Notes

- 扫档曲线**非单调**，且调高更糟。注释里"取 40 一半收敛"的旧经验来自 v1，在 v2 上方向相反，重写注释时不要保留。
- `Safety=3` 看似更好（无冲突局 0、首次冲突 4.05），但领先者胜率掉到 16.0%，远低于 25% 的随机基线，已在 D2 排除。不要"顺手再往下试一档"。
