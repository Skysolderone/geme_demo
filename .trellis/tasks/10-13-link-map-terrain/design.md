# design：link-map-terrain

裁决编号见 prd.md（M1–M11）。本文只写技术方案；数值标"初值"的，按穷举与冒烟结果回写。

## 1. 数据模型

- `BoardPlate` 新增 `Theme`（枚举 `BoardTheme { Highland, River, Forest, Palisade, Mixed }`）。只有链接档出生棋盘有值，其他 `Kind` 一律为空。`MapFile` 的 `BoardDto` 增加 `Theme` 字段；读入时链接档缺这个字段要报错，不能静默取缺省（数据口径规则）。
- `MapData.BirthZones[i]` 改为第 i 块棋盘的 **3×3 核心区**（M1）。核心区的原点 = 棋盘原点 + (⌊(W−3)/2⌋, ⌊(H−3)/2⌋)。宽或高是偶数时偏西 / 偏南，这是确定性规则，不抽随机数。
- 棋盘与出生区不再相等。凡是"要整块棋盘"的地方改读 `map.Boards`，凡是"要出生区"的地方继续读 `BirthZones`。已知要改的使用者：
  - `SeatPublicView.cs:146`：占位的原点和宽高现在从 `BirthZones` 推出，必须改成从 `Boards` 取，并带上 `Theme`（R6）；
  - `Battlefields.cs:130`：棋盘归属改为"棋盘内任一可落子格所在的分量"（R5）；
  - `MapValidator.cs:511`：出生区 = 棋盘全部格的检查，改成"出生区 = 棋盘核心区"；
  - Sim `Program.cs` 打印地图与 `BoardRenderer` 的占位、`MatchSession.cs:891` 的 `ZoneSides`（应该取棋盘宽高）；
  - 图形版的占位与取景：开工时用 `codegraph_callers BirthZones` 全量复核。
- `RelicCellSpec`：核心区内用 `(BirthZone, Birth)`；核心区外的公共信物用 `(Contested, Standard)`（初值，`High` 留作冒烟后再议）。`RelicGenerator` 的公共区路径沿用旧夹具已经验证过的实现。

## 2. 生成（`LinkMapGenerator.Layout`）

顺序不变，只在中间插入步骤，全部用 `MapRandom.ForLinkLayout(seed)` 这一条子流：

1. 次序（Fisher–Yates）→ 2. 宽高 6–8 → 3. **主题排列**：5 个主题对 5 块棋盘做一次 Fisher–Yates → 4. **逐块填地形**（按编号顺序，每块一个独立的局部生成器）→ 5. 信物 → 6. 组装 + 校验，不通过就抛 `MapGenerationException`（生成器缺陷，不重抽）。

棋盘内分三个环带：**外圈**（R3：高度 0、可落子、无栅栏，只允许林地）、**核心区**（平坦草地）、**中间带**（其余格，主题地形主要放在这里）。6×6 的中间带只有 7 格，8×8 有 27 格，所以主题强度按中间带面积成比例取（初值见下表），同时保证 M7 保底。

| 主题 | 中间带内容（初值） | 难到达格（公共信物候选） | 匠人目标来源 |
|---|---|---|---|
| 高台 Highland | 一块高 2 的平台（2–4 格），四周是高 1 的坡，保证从高 0 能一路走上去，不形成孤岛 | 高 2 的平台格 | 外圈或中间带散布 2–3 格林地 |
| 河流 River | 一条宽 1 的深水贯穿中间带（直线或一次折弯，两端抵到外圈内侧），留 1 座预置桥 | 河对岸、离核心区更远的那一侧的格 | 未架桥的深水格 |
| 林地 Forest | 2–3 团林地（各 2–4 格），可以延伸到外圈 | 被林地三面包围的格 | 林地格 |
| 栅栏阵 Palisade | 2–3 段预置栅栏（各 2–3 条边），只在中间带和核心区之间、或中间带内部，不碰外圈的外沿 | 栅栏围出来的口袋格 | 外圈散布 2 格林地 |
| 混合 Mixed | 各取一小份：1 格高 1 的台、1 段 2 格宽的深水（带桥）、1 团林地、1 段栅栏 | 高台格或隔水格（任选其一） | 林地加深水 |

- 岩石：每块 0–2 格，只放在中间带，而且放了以后可落子格仍然连通（M5）。外圈本身全部可落子且连成一圈，所以中间带的格只要不被岩石 / 深水完全围死就一定连通；生成时逐格检查，校验器再兜底。
- 高差约束：外圈高度恒为 0。中间带里高 2 的格不能和外圈直接相邻（否则就是外圈旁边的崖壁，对接缝无害，但会让核心区和外圈之间的通行太难；这条是初值，可以放宽）。
- 公共信物：主题有难到达格候选就放 1 个，没有就是 0（M8）。出生区信物：核心区 9 格里取 2 个互不相邻的格，规则沿用现在的"尽量不同行不同列"。
- 价值拉平（M2）：第一期**不建价值模型**，只靠上表让各主题强度相近，再看冒烟里"各主题棋盘的胜率 / 平均名次"（≤ 20 局只作方向参考），偏差明显就调表格里的初值。

旧边疆档的坡道连通、河流桥位、信物难度评分可以从 `74fbf28` 的 `FrontierMapLayout.Ramps.cs` / `.River.cs` / `.Relics.cs` 取回参考，只借鉴算法，不恢复文件。

## 3. 校验（`MapValidator` 链接行）

| 规则 | 失败码（新增的写在括号里） |
|---|---|
| 外圈：高度 0、可落子、无栅栏 | （`BOARD_RIM_NOT_FLAT`） |
| 核心区 = 3×3、平坦草地、无设施 | 复用出生区校验 + （`BIRTH_CORE_NOT_FLAT`） |
| 棋盘内可落子格几何四邻连通 | （`BOARD_SPLIT`） |
| 每块可改造目标 ≥ 2 | （`BOARD_TOO_FEW_EDIT_TARGETS`） |
| 出生区信物恰 2 个、都在核心区；公共信物 ≤ 1 个、在核心区外 | 复用 `RELIC_ZONE_MISMATCH`，加上数量检查 |
| 主题两两不同、链接档出生棋盘都有主题 | （`BOARD_THEME_INVALID`） |
| 拼接后每条共享边至少 1 条气边 | （`LINK_SEAM_NO_LIBERTY`），放在已有的拼接后校验里 |
| 可落子格总数、画布宽高区间 | 改为按种子 1–20 穷举的实测值回写 |

删掉旧规则"棋盘内全部可落子、高度 0、草地"（`MapValidator.cs:420-425`）。保护期容量（≥ 9）对 3×3 核心区刚好成立，保留不动。

## 4. 公开视图与入口（M3）

- `BoardPlaceholder` 加一个 `Theme` 字段，原点和宽高取自 `Boards`；插旗前对全体公开，不含布局与信物（`information-visibility` 规格补一个 Scenario）。
- 终端版：占位行显示"2 号 · 河流 · 7×6"。图形版：占位面板或旗位上显示主题名（字样复用 `Labels`）。
- AI 的 `flag-pick` 不变（仍然均匀随机，不读主题），确定性不受影响。

## 5. 规格影响（opsx:propose 时落）

- 修改：`link-map-generation`（主题、尺寸、地形、信物）、`map-definition`（链接档出生区 = 核心区、校验表）、`battlefield`（棋盘归属）、`match-setup` / `information-visibility`（占位带主题）、`relic-generation`（链接档公共信物）、`terrain`（§3.1 出生区规则只约束核心区，原文不用改，补一句说明）。
- 设计文档：§3.3 改写，升到 v1.21；HANDOFF 的"现行规则速览·地图"同步更新。

## 6. 兼容与回滚

- 同一个 `link:<种子>` 出来的图会变（M10）。现有机制已经能挡住旧的日志和存档，不需要改格式：
  - 回放：`Replayer.cs:59` 比对日志首部的 `MapDigest`，不一致时报 `MapMismatch`；
  - 存档：`MatchFlow.Persistence.cs:46` / `Persistence.Link.cs:91` 也按摘要把关。
  - 要补一条测试：用旧生成器的摘要构造一个日志首部，断言会被拒绝。
- 回滚：整个 change 只改生成器、校验器、视图与入口，回退 commit 就能回到纯平棋盘。
