# 信物系统重设计：地图刷新争夺 + 带入与保险

## 目标

用户原话（2026-10-26）：「需要重新设计信物系统，地图上会随机刷新提供棋子效果的信物，让玩家进行争夺。信物这块玩家可以选择带入，最多 5 个，两个是保险，无论是输了还是弃盘，这两个信物都会保留。」

把"固定信物格 + 覆盖控制 + 玩家参数效果"和"补给带入"两套旧系统，统一替换为一套**挂在棋子上的信物**：地图中途刷新、落子拾取、被提掉落；局外可带入至多 5 件、其中至多 2 件保险；按"搜打撤"结算带出。

## 背景（被替换的现状）

- 地图信物（openspec/specs/relic-generation、relic-effects、relic-control；代码 `src/Siege.Core/Relics/`）：位置来自地图静态数据，开局一次生成、整局不刷新；占据或唯一覆盖即控制、多人覆盖即争议；效果为十类玩家参数（展示数 / 选取数 / 类型槽 / 部署上限 / 先手修正 / 征募权重 / 连营 / 犄角 / 驿站 / 工坊），经 `RelicLedger.BuildSnapshot`（RelicLedger.cs:248）进小回合快照，结算第 5、6 步由 `SettlementDriver`（SettlementDriver.cs:119-123）驱动揭示与控制重算。
- 补给带入（openspec/specs/carry-in-out；代码 `src/Siege.Core/Carry/`）：三种补给只改开局手牌，每局至多 1 件；名次换补给点；弃赛返还 + 50% 点数；出局 / 中途退出丢失；档案 `%APPDATA%\Siege\profile.json` v1。
- 设计文档 `2026-09-10-siege-core-gameplay-design-v1.md:914` 把"跨局累积的对局内优势"列为不做 —— 本任务按 R3 撤销。
- 唯一战场结算下，终局时仍在局的只有胜者，其余人此前已出局或弃赛（设计文档 :1007）；只有整轮 Pass / 填满 / 回合上限终局才会有多名完赛者。
- 影响面：`src` 下 80 个文件、`tests` 下 157 个文件引用 Relic；AI 有专门的 `RelicEstimate`（src/Siege.Core/Ai/RelicEstimate.cs）与评价维度 `EvaluationWeights.Relic`。
- 并行约束：10-26-map-expand-25（多平台浮空岛）进行中，其 R5 仍按静态信物格设计。

## 需求

- **RQ1 信物层**：盘面每格至多 1 件信物；格上有子即"挂在该子上"，空格即"地图信物"。落子到有地图信物的格即拾取；持物棋子被提走后信物留在原格成为地图信物。
- **RQ2 刷新与预告**：按 R8–R11 刷新与预告，确定性可复现。
- **RQ3 效果**：按 R12 / R13 进入势力计算与覆盖计算；R23 旗手子、R24 同分比较同步修改。
- **RQ4 带入**：插旗前选至多 5 件、勾至多 2 件保险；部署时按 R14 挂出；AI 按 R21 带入。
- **RQ5 结算**：按 R16 / R17 / R19 与 D6 细则结算，写档案；中途退出与截断沿用现行口径（截断局不结算）。
- **RQ6 档案**：v2 格式、兑换（R18）、新档案赠送、v1 迁移（R20）；损坏 / 缺失 / 高版本处理沿用现行。
- **RQ7 删除旧系统**：旧十类信物、补给、快照中的信物加成、先锋先手修正、流派徽记征募权重、工坊扩大改造范围全部删除，回到默认基础值。
- **RQ8 AI**：`RelicEstimate` 按新信物重写，AI 会拾取 / 夺取 / 挂出信物。
- **RQ9 呈现**：终端与 Godot 按 R22 / R25 显示与操作。

## 验收标准

- [ ] AC1（RQ1）落子到地图信物格后，该信物挂在新子上；该子被提后信物留在原格；同一棋子不能挂第 2 件。
- [ ] AC2（RQ2）同种子同地图同人数，两局每批刷新位置与类型逐项相同；第 1–3 大回合无刷新；刷新格全在出生区域外、预告时离棋子 ≥ 2；刷新批次落位后场上未拾取件数不超过 n+2（R17 出局 / 弃赛掉落件不受此限）；预告比落位早 1 大回合，落位只少不多（被占格跳过）。
- [ ] AC3（RQ3）五种效果各有计分测试（含与倍增子 / 阵型倍率叠加、棋串分裂后重算）；望台覆盖与岩台一致；旗手子按挂件数计分；同分比较读持有信物数。
- [ ] AC4（RQ4）带入 6 件或保险 3 件被拒；未挂出的带入信物不产生效果；保护期内可挂出。
- [ ] AC5（RQ5）D6 归属细则逐条有测试：保险件被敌方完赛者持有时仍归原主；原主出局时非保险件不回库存；同一件信物不会被两人同时带出；同局结算只发生一次。
- [ ] AC6（RQ6）v1 档案读入后补给按原价折点、version 写为 2；新档案含 3 件普通信物；8 点兑换 1 件普通、稀有不可兑换。
- [ ] AC7（RQ7）代码中不再有旧十类信物与补给类型；快照只含默认基础值。
- [ ] AC8（RQ8）小样本（≤ 20 局，不跑 200 局）中 AI 有拾取信物的行为（遥测可数）。
- [ ] AC9（RQ9）Godot 能完成：带入选择 → 部署挂出 → 地图拾取 → 结算面板全流程；`--auto-demo` 等自动化模式不读写档案。
- [ ] AC10 全部测试通过。

## 不在范围

- 效果数值校准与扫档（初值未校准）。
- 首批 5 种以外的效果，以及改气 / 提子规则的效果（如免死）。
- 信物美术资源（只用简单图标）。
- 旧存档 / 回放兼容。
- 信物经济校准：AI 同等件数带入是净流入来源（4 人局每人带 5 件时 AI 共 15 件入场），初值未校准，另起任务。
