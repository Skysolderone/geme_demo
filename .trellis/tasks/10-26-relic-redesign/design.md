# 设计：信物系统重设计

需求与裁决见 prd.md（R1–R26）。本文件只记架构、契约与取舍。

## D1 信物层挂在盘面上（RQ1）

`GameBoard` 新增一层动态数据：每格至多 1 个 `RelicToken?`。

```
RelicToken { int Id; RelicKind Kind; PlayerId? Origin; bool Insured }
```

- `Id`：本局内唯一，按**公开**顺序递增：刷新落位、带入挂出、R17 掉落时才分配，与刷新共用游标；开局不给带入件编号（R40，否则刷新件编号暴露全员带入总件数）。终局仍未挂出的件在结算时刻临时编号，不写回对局状态。用于结算归属与遥测。
- `Origin`：带入者；地图刷出的为 `null`。`Insured` 只对带入件有意义。
- 格上有子 = 挂在该子上；空格 = 地图信物。**不另存"持有者"**：持有者永远等于该格棋子的主人，拾取 / 掉落都不需要额外操作——
  - 拾取 = `Board.Place` 落到有信物的空格（信物不动，自然变成"挂上"）。
  - 掉落 = `Board.RemoveStones` 移走棋子（信物不动，自然变成"地图信物"）。
  - 带入挂出 = `Placement` 新增可选字段 `AttachCarried: int?`（带入清单下标），放置时写入该格。落在已有地图信物的格上时不能再挂带入件（R13 每子 1 件），预演判非法。
- **同形禁则不比较信物层**（信物不改变棋形）。序列化拆成两种：`SerializeShape()`（棋子 + 地形，不含信物层）只给 `BoardHistory` / 同形比较；`Serialize()`（含信物层）给存档与 `SettlementDriver.cs:109-112` 的"正式盘面 vs 预演副本"一致性核对——否则挂出只在一侧生效时核对抓不到。
- 预演副本 `Board.Clone()` 复制信物层，预演即可看到拾取 / 掉落后的势力。

取舍：放在盘面而不是独立账本，能让提子 / 放置 / 克隆 / 预演零改动地带上信物；代价是 `GameBoard` 多一层状态，存档格式要变（R26 已接受不兼容）。

## D2 刷新与预告（RQ2）

新类 `RelicSpawner`（替换 `RelicGenerator`）：

- 子流 `relic-spawn`（由对局种子派生，新子流，不扰动征募 / 流程 / AI 的既有子流）。
- 时机：落位轮为第 4、6、8……大回合，在该大回合开始时落位；每批在落位前 1 个大回合开始时预告（第 3、5、7……大回合开始时公开位置与类型）。预告时即抽好位置与类型，落位时不再抽。
- 数量：`min(⌈n/2⌉, (n+2) − 场上未拾取件数)`，≤ 0 则本批空。n 取开局参赛人数（不随出局变化，保持可复现）。
- 位置：候选 = 可落子空格 − 出生区域 − 与任一棋子切比雪夫距离 < 2 的格 − 已有信物的格；按坐标字典序排列后用子流抽。**落位时**若预告格已被占或已有信物，则跳过该件（不重抽，保持预告与落位一致）。
- 类型：85 / 15 普通 / 稀有，普通四种等权。
- "出生区域"抽象为 `IMapRegions.IsBirthArea(coord)`：现行实现 = 出生棋盘；map-expand-25 完成后 = 平台。
- R17 掉落：出局 / 弃赛者手里未挂出的非保险带入件，按同一候选规则、用子流 `relic-drop` 立即落位，不占上限。

## D3 效果进入计分与覆盖（RQ3）

- 新枚举 `RelicKind { WarDrum, Command, Watchtower, Chameleon, Banner }`，`RelicKinds` 静态表给档位与常量（显式标注未校准）。
- `PowerCalculator`：逐棋串读信物层——
  - 战鼓：该子基础军势 +3；
  - 号令：棋串位置加值 + ⌊棋串棋子数 / 2⌋（每件）；
  - 百变：棋串位置加值 +2；该串每枚协同子计算"除协同子外的类型种数"时，每件百变额外 +1 种（不论百变挂在哪种棋子上，包括挂在协同子自己身上）；
  - 军旗：棋串倍率指数 n += 件数。
  上述加值与基础军势一起进入 `(基础 + 位置) × 1.5^n` 再向下取整，与现行顺序一致。
- `CoverageMap.Compute`：望台挂件的子按岩台规则额外覆盖四方向距离 2 —— 复用现有岩台覆盖分支，条件改为"站在岩台上 **或** 挂望台"。站在岩台上又挂望台不再扩大。沼泽上的子仍不提供覆盖（沼泽优先）。
- 旗手子（R23）：所在棋串每挂 1 件 +3，不再看信物格位置。
- 同分比较（R24）：`elimination-endgame` 的第一比较项改读"挂在己方棋子上的件数"。
- 删除 `ScoringRelicCounts`（连营 / 犄角）。

## D4 删除旧系统（RQ7）

- 删除 `src/Siege.Core/Relics/` 下旧生成 / 控制 / 揭示 / 快照代码，`EffectSnapshot` 只保留默认基础值（展示 5、选取 3、类型槽 5、分阶段部署上限）；`SettlementDriver` 第 5 步"揭示"删除，第 6 步不再重算信物控制。
- 先手：只按势力名次，无先锋修正。征募权重：只按基础权重，无徽记。匠人：改造范围固定相邻，无工坊。
- 地图静态信物格（`GameBoard.MapTables.Relic`、`RelicZone`、`MapFile.RelicDto`、链接图生成里的出生 / 公共信物格）删除。**map-expand-25 的 R5 随之作废**——本任务实施时一并删掉其放置代码。

## D5 带入、保险与 AI 带入（RQ4 / RQ8）

- `CarrySetup` 改为 `CarryLoadout { ImmutableArray<(RelicKind Kind, bool Insured)> Items }`，校验：件数 ≤ 5、保险 ≤ 2、库存足够。
- 对局创建时从库存扣除全部带入件、写在途记录。每名玩家的"未挂出带入件"列表随对局存档。
- R22：带入清单只对本人可见；对外只公开"已挂出的信物"（含保险标记）。
- AI 带入（R21）：件数 = 本机玩家带入件数；用子流 `carry-ai` 从普通四种等概率抽，再随机选 min(2, 件数) 件为保险；AI 部署时按"挂在本批势力增量最大的落点"挂出，前几批挂完。
- `RelicEstimate` 重写：对每个地图信物格估"拾取后势力增量"，对敌方持物棋子估"提走后掉落可被拾取"的价值；保留 `EvaluationWeights.Relic` 维度、重标权重。

## D6 带出结算归属（RQ5，R16 / R17 的定稿细则）

终局（或某玩家出局 / 弃赛的结算时刻）对每件带入件按序归属：

1. 保险件 → 原主（任何结局）。
2. 挂在某**完赛者**棋子上 → 该完赛者。
3. 其余 → 原主若完赛则归原主，否则消失。

地图刷出的信物只按第 2 条带出。出局 / 弃赛者的结算在其出局 / 弃赛时立即完成：只拿回保险件（+ R19 的点数）；其未挂出的非保险件按 D2 掉落。因为保险件始终归原主，**带入者出局后其保险件仍可能在场上被别人挂着用**——这是 R6 的本意，局内效果照常，只是带不走。

每件信物在一局结算中只归属一次：结算以 `Id` 去重，在途记录以对局标识去重（沿用现行）。

## D7 档案 v2（RQ6）

```json
{"version":2,"points":17,"inventory":{"WarDrum":1,"Command":0,"Watchtower":2,"Chameleon":0,"Banner":1},
 "inFlight":{"matchId":"…","carried":[{"kind":"Banner","insured":true}]}}
```

- 兑换：普通 8 点 / 件；稀有（军旗）不可兑换。
- 新档案：3 件普通，按固定次序 战鼓 / 号令 / 望台 各 1（不随机，便于说明）。
- v1 迁移：补给库存按原价（备用子 3、征召签 2、换型令 4）折入 points；v1 残留 inFlight 按中途退出结算（补给丢失、带出 0）后清除；写回 version 2。原子写、损坏备份、高版本不写回沿用现行。

## D8 呈现（RQ9）

- 终端：开局显示档案与带入选择（选件、勾保险、兑换）；部署命令增加挂出参数；盘面图例标地图信物 / 预告 / 持物棋子；结算打印每件信物的去向。
- Godot：带入面板替换补给面板；暂放棋子时可从"带入栏"拖 / 点选一件挂上；信物层改为三种标记；结算面板列每件去向。只用现有控件 + 简单图标。
- 自动化模式（`--auto-demo` 等）不读写档案，地图刷新照常。
