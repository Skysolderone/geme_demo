# 围杀 Siege 首轮原型 — 父任务技术设计

## 分层与依赖

```
board-core                      拓扑与地图（无回合、无资源概念）
  ├── batch-deployment          批次合法性与结算顺序（驱动下游各步）
  ├── territory-power           覆盖/领地/棋子效果/势力（纯派生量）
  │     └── relic-system        唯一随机源之一；效果快照
  │           └── recruit-hand  第二个随机源；手牌两段账
  │                 └── match-flow   顶层状态机：时机的唯一裁决者
  │                       ├── heuristic-ai   AI + 跑局 + 遥测
  │                       └── tactical-ui    信息边界 + 表现
```

## 贯穿全局的三条结构性决策

**全量重算而非增量维护。** 设计文档 §9.2 / §10.1 要求棋子与组合状态随盘面实时重算、不保留成长层数。一次提子可能同时改变覆盖、棋串分裂、连珠断线与倍率，增量维护的组合爆炸不可控。11×11 约 121 格 × 4 人的全量重算开销可忽略；性能优化必须等到批量跑局有实测数据后再做，且不得改变语义。

**结算顺序在一处实现。** 设计文档 §6.3 的六步顺序由 `batch-deployment` 独家驱动，下游（信物揭示、势力重算、排名/出局/终局）只作为被调用的步骤。任何下游模块"就近"自行决定时机，都会产生无法复现的时序 bug。

**信息边界在数据层成立。** 公开视图与私有视图是两个不同的结构，而不是一个结构加权限标志。这同时服务 §13 的玩家信息对称性与 §15.1 的 AI 公平性——靠"约定不去读"在迭代中必然被破坏。

## 技术栈（已确定）

**Godot 4 / C#（.NET）**，但规则内核与引擎严格分离：

```
siege.sln
├── src/Siege.Core/          net8.0 类库 —— 零 Godot 依赖，子任务 1–6 的全部规则
├── src/Siege.Sim/           net8.0 控制台 —— 子任务 7：批量跑局、遥测、平衡报告
├── tests/Siege.Core.Tests/  xUnit —— 125 条 Requirement 逐条对应
└── godot/                   Godot 4 .NET 项目 —— 子任务 8：仅表现层，引用 Siege.Core
```

**为什么内核必须零 Godot 依赖。** 首轮原型的唯一产出目标是 §16 六项数值指标与 §17 七个分析方向的实测结论，这要求跑数千局并可完整重放。若规则写在 `Node` 派生类里、依赖场景树与 `_process`，批量跑局就必须起引擎实例，并行与确定性都会变得极难。把规则做成纯 .NET 类库后：`dotnet test` 直接驱动 125 条 Requirement；`Siege.Sim` 用普通 `Parallel.For` 跑局，局间零共享；Godot 只负责把内核的只读视图画出来。这条边界是硬约束——`Siege.Core` 与 `Siege.Sim` MUST NOT 引用任何 `Godot.*` 命名空间，用编译期检查守住。

**关键实现约定：**

- **倍率用整数运算**：`⌊(基础+加值) × 1.5^n⌋` 实现为 `(基础+加值) × 3^n / 2^n` 的整数除法，禁止 `double`/`float`。跨平台结果一致是跑局可复现的前提。
- **随机子流隔离**：`relic-gen` / `recruit` / `setup` 三条独立的确定性序列，各自从对局种子派生，互不影响消费次数。
- **坐标**：对外围棋记法（`A1`–`L11`，跳过 `I`，行号自下而上），内部数值索引，双向映射只允许一处实现。
- **测试组织**：每条 Requirement 一个测试类，每个 Scenario 一个 `[Fact]`/`[Theory]`，测试名直接引用 Requirement 名，便于与 openspec 逐条对账。

**环境现状：** .NET SDK 8.0.412 已安装；Godot 尚未安装，到子任务 8 时需装 **.NET 版**的 Godot 4 编辑器（非标准版）。子任务 1–7 全程不需要 Godot。

## 兼容性与回滚

- 无线上形态，回滚即回退提交。
- 契约变更必须同步 `openspec/changes/<change>/design.md` 的接口契约表与受影响子任务的 `prd.md`。
