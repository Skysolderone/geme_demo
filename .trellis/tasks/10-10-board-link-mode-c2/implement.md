## 1. 3b.1 剖析（改前）

### 方法

- 剖析驱动放在 scratchpad，不入库：
  - 程序集名取 `Siege.Core.Tests`，借既有的 `InternalsVisibleTo` 调用 `MatchSession.Create(..., pairing)`；
  - 引用 Release 构建的 `Siege.Core.dll` / `Siege.Sim.dll`。
- 推进到指定局面后，对接下来的 N 个小回合计时（`MatchSession.RunTurn` 的墙钟），同时：
  - 记录 GC 分配量与暂停时间；
  - 在进程内用 `DiagnosticsClient` 开 EventPipe CPU 采样，只覆盖测量段；
  - 用 `dotnet-trace convert` 转成 speedscope，再按方法汇总"包含时间 / 自身时间"。
- 单线程、Release。

5. 整画布字符串合计 12.3%：
   - 序列化 `Serialize` 5.1%；

## 6. 偏离与需裁决事项

已按以下口径实施（供知悉）：
1. **装了全局工具 `dotnet-trace` 10.0.750501**（`dotnet tool install -g`），用于把 EventPipe 采样转成 speedscope。剖析驱动和 NuGet 包 `Microsoft.Diagnostics.NETCore.Client` 只在 scratchpad 里，不入库。
2. **剖析驱动的程序集名取 `Siege.Core.Tests`**，借既有的 `InternalsVisibleTo` 调内部建局接口。只在 scratchpad 里用。
3. **新增两处响亮失败**：覆盖目标不是可落子格、活形分析遇到不可落子格上的棋子或气边。这两种状态按现有规则不可达：落子要求可落子，改造与链接只增不减可落子格，`Adjacency` 的接收条件也要求可落子。改动前遇到这种状态会静默按"障碍 / 空"处理，现在改为抛出。
4. **空集合的 `RemoveStones` 不再推进突变版本号**。类注释与 boundaries.md 同步说明了"什么都没写不算写入"。
5. **对照局的"改前"文件按要求只存去掉耗时字段后的文本**（压缩后 52 KB）和它的哈希，规范化脚本一并存在 `before/`。

## 7. 遗留与风险

1. **`MapTables.Derive` 的正确性依赖局部性**：改造只影响周围 2 格（覆盖目标最远到距离 2）。
