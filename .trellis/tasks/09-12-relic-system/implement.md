## 实现清单

## 1. 信物数据与生成

- [ ] 1.1 定义信物数据结构：格坐标、类型（六类）、强度（+1/+2）、流派徽记绑定的棋子类型、所属强度预算分区、已揭示标志、当前控制者。验证：已揭示与控制者为两个独立字段，可表达"已揭示且无人控制"。
- [ ] 1.2 实现种子驱动的确定性伪随机序列，供生成阶段独占使用。验证：同种子两次生成推进序列的取值完全一致。
- [ ] 1.3 实现第一阶段按分区权重抽取类型。算例（设计文档 §8.2）：出生区权重 徽记45/探勘20/兵站15/征召8/军令7/先锋5；公共区 徽记30/探勘15/兵站10/征召15/军令15/先锋15。验证：10000 种子统计频率与权重表偏差在容差内。
- [ ] 1.4 实现公共区约 20% 升级，判定对全部六类统一执行（五类结构信物 → +2，流派徽记 → 双倍数量），并断言出生区不生成任何高阶信物。验证：大样本统计升级比例收敛于 20%；出生区样本中 +2 计数为 0。
- [ ] 1.5 实现稀有度评分（按权重倒数，高阶按 2 倍计）与第二阶段区域预算校正（最小改动重抽，设重试上限）。算例：四个出生区总稀有度与均值偏差 ≤ 8%；同区同类型计入偏离惩罚，概率显著降低但不为零。
- [ ] 1.6 实现重抽未收敛时的确定性兜底（放弃稀有度约束、保留权重结果、记录"生成未收敛"标记）。验证：构造极端容差使其必然不收敛 → 不死循环、不抛错、标记被写入对局记录。
- [ ] 1.7 断言组合不退化。验证：100 个不同种子下，出生区之间至少出现两种不同的信物类型组合。
- [ ] 1.8 断言中央区与咽喉区的强度预算严格高于出生区。验证：地图数据分区与生成结果的交叉检查。
- [ ] 1.9 实现信物生成记录输出（种子 + 每格坐标/类型/强度/分区）。验证：仅凭记录即可离线复现同一次生成。

## 2. 发现与揭示

- [ ] 2.1 实现揭示触发：信物格首次进入任意玩家覆盖范围时永久公开类型与强度。验证：揭示标志单调，一旦为真不再回退。
- [ ] 2.2 把揭示挂到结算顺序第 4 步（提子之后、重算控制与势力之前）。算例（设计文档 §6.3/§7.3）：批次同时提走敌串并使己方覆盖某未知信物格 → 揭示基于提子后的覆盖关系。
- [ ] 2.3 断言争议不阻止揭示。算例（设计文档 §7.3）：结算后该格同时被 A、B 覆盖 → 内容仍揭示，同时进入争议状态。
- [ ] 2.4 断言揭示不可撤销。算例：揭示者棋串随后被围杀、该格无人覆盖 → 内容仍公开。
- [ ] 2.5 断言揭示不授予收益。算例（设计文档 §7.3）：A 揭示军令但未控制 → A 的部署上限不变。
- [ ] 2.6 输出揭示事件（格、类型、强度、所在大回合）供遥测。验证：对局日志中可读出每枚信物的揭示轮次（设计文档 §17）。

## 3. 控制判定

- [ ] 3.1 实现控制判定四态：直接占据 → 控制；空格唯一覆盖 → 控制；空格多人覆盖 → 争议；空格无人覆盖 → 无人控制。算例（设计文档 §7.3）：A 占据该格、B 两枚棋子覆盖 → A 控制，不进入争议。
- [ ] 3.2 强制复用 `add-territory-power` 的唯一覆盖查询与 `add-board-core` 的占据查询，本层不做任何邻接遍历。验证：全仓搜索确认本层无邻居遍历代码。
- [ ] 3.3 实现交叉一致性测试：对全盘每个信物格，断言本层控制判定与领地层的覆盖判定不矛盾。验证：随机盘面 1000 例全部一致。
- [ ] 3.4 把控制重算挂到结算顺序第 5 步，结果只依赖当前盘面。算例：B 围杀占据信物格的 A 棋串且唯一覆盖该格 → 结算后控制者为 B；某信物第 3 大回合由 A 控制、第 7 大回合无人覆盖 → 第 7 大回合为无人控制。
- [ ] 3.5 实现弃赛者遗留棋子参与覆盖与占据判定。算例（设计文档 §7.3/§12.2）：弃赛者 D 与参赛者 A 同时覆盖 → 争议，A 不得效果；D 唯一覆盖军令 → 显示由 D 控制但 D 无任何收益。

## 4. 效果与快照

- [ ] 4.1 实现六类信物效果映射（探勘→展示数、征召→选取数、兵站→类型槽、军令→部署上限、先锋→先手修正、流派徽记→征募权重），高阶结构信物 +2、高阶徽记表达为数量 2。算例（设计文档 §8.1/§9.1）：高阶徽记在权重公式 `基础×(1+0.75×数量)` 中按数量 2 代入。
- [ ] 4.2 实现同类叠加且无统一硬上限。算例：2 枚普通军令 + 1 枚 +2 军令 → 部署上限 `3+1+1+2 = 7`；推高到 9 不被截断。
- [ ] 4.3 实现默认基础值（展示 5 / 选取 3 / 类型槽 5 / 部署上限 3 / 先手修正 0）。验证：无信物玩家的快照等于默认值。
- [ ] 4.4 实现不可变效果快照对象，在小回合开始时生成一次，小回合内只读。验证：快照生成后修改信物控制，本回合参数不变。
- [ ] 4.5 断言先手修正不在小回合快照中。验证：快照结构不含该字段，或小回合流程不消费该字段。
- [ ] 4.6 断言"本回合新占信物不生效"。算例（设计文档 §5.1）：本回合批次占领军令 → 本回合部署上限不变，下一小回合生效。
- [ ] 4.7 断言"先手夺走后手信物，后手本大回合拿不到"。算例（设计文档 §5.1）：先手在本大回合夺走后手的探勘 → 后手本大回合快照不含该加成。
- [ ] 4.8 断言"快照期间丢失不影响本回合"。算例：小回合开始时控制征召、本回合结算中失去 → 本回合选取数仍按快照执行。
- [ ] 4.9 断言争议与失控信物不提供效果、效果不残留。算例（设计文档 §7.3）：控制→失去→夺回同一军令 → 三个大回合部署上限依次为 含/不含/含。

## 5. 先锋与槽位缩水

- [ ] 5.1 实现先锋的独立读取：仅在大回合结束、生成下一轮顺序时读取全部玩家的先锋信物并输出先手修正。算例（设计文档 §8.1）：玩家在本大回合最后一个小回合占领先锋 → 本大回合结束生成下一轮顺序时即计入。
- [ ] 5.2 实现兵站缩水判定：快照给出合法槽位数与"超限几种"。算例（设计文档 §5.2）：持有 6 种类型、槽位降为 5 → 快照标记超限 1 种。
- [ ] 5.3 断言本层不执行弃牌。验证：本层无任何修改手牌的路径，强制弃牌由 `add-recruit-hand` 消费该标记实现。

## 6. 契约与回归

- [ ] 6.1 固化对下游的五个输出契约（效果快照、先手修正、信物公开状态、生成记录、揭示事件）。验证：契约级测试覆盖正常与边界输入。
- [ ] 6.2 建立信物回归用例集，覆盖：同种子逐格一致、出生区无高阶、20% 升级比例、稀有度均衡、组合不退化、提子先于揭示、争议不阻止揭示、揭示不授予、快照时机三例、先锋读取时机、弃赛者封锁。验证：全部通过并纳入持续回归。
- [ ] 6.3 为遥测暴露部署上限峰值与其出现的大回合序号。验证：跑一局后日志可读出峰值与轮次，供 §16 的"第 7 大回合后 5–8 部署"区间回归。
