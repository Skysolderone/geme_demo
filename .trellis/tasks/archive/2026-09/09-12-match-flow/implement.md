## 实现清单

## 1. 对局初始化与插旗

- [x] 1.1 定义对局顶层状态：地图、对局种子、玩家列表与状态（参赛/已弃赛/已出局、保护中?）、当前大回合、当前行动玩家与阶段、行动顺序、连续 Pass 计数、已提交盘面历史引用。验证：状态可完整持久化与恢复。
- [x] 1.2 实现插旗阶段的信息公开范围（地形/出生区/信物格公开，信物内容隐藏）。验证：插旗期读取信物内容的路径不可达。
- [x] 1.3 实现匿名同时插旗（可配置超时默认 15 秒、只显示位置不显示身份、锁定前可更换、允许多人同区）。算例（设计文档 §4.1）：A 先选区 1 再改区 3 → 锁定为区 3；A 与 B 同选区 2 → 均接受。
- [x] 1.4 实现原型依次插旗路径，产出与正式插旗等价的状态。验证：两条路径产出的对局状态逐字段一致。
- [x] 1.5 实现由 `setup` 子流驱动的首回合随机顺序。验证：同种子同插旗结果 → 首回合顺序一致。

## 2. 小回合阶段机

- [x] 2.1 实现五阶段显式状态机（信物快照 → 整理手牌 → 私人征募 → 批次部署 → 确认/Pass），当前玩家与当前阶段可查询。验证：阶段不可跳过或调换，有顺序断言测试。
- [x] 2.2 在阶段切换点发出 `小回合开始 / 结束` 事件；禁止其他模块自行发出流程事件。验证：全仓搜索确认事件只有一个发出点。
- [x] 2.3 实现强制弃牌门：超限状态未解除则征募阶段不开始。算例（设计文档 §5.2）：持 6 类、槽位 5 → 停在整理手牌阶段。
- [x] 2.4 断言快照在小回合内不变。算例（设计文档 §5.1）：本回合占领军令 → 本回合部署上限不变。
- [x] 2.5 为调试提供任意阶段的人工接管介入点。验证：可在任一阶段替换决策来源（设计文档 §15.3）。

## 3. 大回合与保护期

- [x] 3.1 实现大回合定义与推进（全部参赛玩家各完成一次小回合 → 大回合结束 → 生成下一轮顺序），不设固定总轮数。算例：第 15 大回合终局条件均未满足 → 继续。
- [x] 3.2 实现出局者不再进入行动序列。算例：玩家第 6 大回合出局 → 第 7 大回合序列不含他。
- [x] 3.3 实现保护期合法落子范围（第 1–3 大回合限于锁定出生区，共享区玩家共享范围）。算例（设计文档 §4.2）：第 2 大回合越区暂放 → 拒绝并说明违反合法落子范围。
- [x] 3.4 断言保护期内围杀/覆盖/信物发现/势力计算照常。算例：第 3 大回合共享出生区内互相围杀 → 提子、揭示、势力更新全部执行。
- [x] 3.5 实现第 4 大回合全图解禁与空盘面玩家的重新进入。算例（设计文档 §4.2）：第 4 大回合盘面为空的玩家完成征募后可在全图任意合法空格落子。
- [x] 3.6 实现 `当前合法落子范围` 契约下发。验证：第 3 与第 4 大回合分别返回出生区集合与全图集合。

## 4. 先手与行动顺序

- [x] 4.1 实现势力名次（排除已弃赛与已出局玩家）。算例（设计文档 §11.1）：势力 80/55/40/12 → 名次 1/2/3/4；4 人局 1 出局 1 弃赛 → 名次只有 1、2。
- [x] 4.2 在大回合结束时向 `add-relic-system` 单次拉取先手修正，不缓存。验证：本大回合最后一手抢到的先锋立即计入本次顺序生成。
- [x] 4.3 实现先手值公式 `(参赛人数 − 势力名次) + 先手修正`。算例（设计文档 §11.2）：4 人局名次 4 无先锋 → 0；名次 4 且 +2 → 2，与原第 2 名（先手值 2）竞争；剩 2 名参赛者时名次 1 无先锋 → 1。
- [x] 4.4 实现三级同值判定链（先手修正 → 势力值 → 上一大回合行动更晚者优先）。算例：先手值同为 2，修正 +2 优先；修正同则势力 60 优先于 45；再同则上轮第 3 位优先于第 1 位。
- [x] 4.5 实现首回合种子兜底。验证：全部条件相同时按种子给出稳定顺序，同种子重放一致。
- [x] 4.6 断言排名不转换为累计积分。算例（设计文档 §11.1）：连续 5 轮第 1 → 无任何累计收益。
- [x] 4.7 输出每大回合的先手值明细（名次、修正、先手值、生成顺序）。验证：遥测可读出明细，供滚雪球分析（设计文档 §17）。

## 5. 出局与保护解除

- [x] 5.1 实现保护期暂停出局检查。算例（设计文档 §4.2）：第 2 大回合棋子被清空且手牌为空 → 不出局，下一小回合正常征募。
- [x] 5.2 实现逐玩家的开局出局保护状态（每玩家一个布尔），解除仅在"该玩家完成第 4 大回合小回合"时触发。验证：禁止任何按全局大回合号统一解除的实现。
- [x] 5.3 断言先手行动不误伤未行动玩家。算例（设计文档 §12.1）：第 4 大回合先手清空玩家 C 的棋子且 C 手牌为空 → C 不出局，仍将获得自己的小回合。
- [x] 5.4 断言同一大回合内玩家保护状态可不同。算例：第 4 大回合 A 已完成小回合（已解除）、C 未行动（仍保护中）。
- [x] 5.5 实现出局判定（盘面无棋子 **且** 手牌无棋子），在每次结算完成与每次 Pass 完成后检查已解除保护的参赛玩家。算例：盘面为空但手牌 2 枚 → 不出局；两者同时为空 → 立即出局。
- [x] 5.6 断言出局者不再获得小回合、不参与获胜判断。验证：出局后行动序列与最终获胜判定均排除该玩家。

## 6. 弃赛

- [x] 6.1 实现主动弃赛（立即失去胜利资格，不再获得小回合、征募与先手效果），允许保护期内弃赛。验证：弃赛后下一大回合序列不含该玩家，其先锋不再提供修正。
- [x] 6.2 断言遗留棋子继续生效且可被围杀。算例（设计文档 §12.2）：弃赛者 D 与参赛者 A 同时覆盖某空格 → 争议格，A 不得分；B 使 D 的棋串无气 → 照常提走。
- [x] 6.3 实现弃赛者势力继续显示并标记"已弃赛"。验证：势力可见但不参与顺序生成与获胜判断。
- [x] 6.4 实现弃赛快照记录（手牌两段账、效果快照、控制信物列表、盘面序列化）。验证：快照足以完整重建弃赛时刻的玩家私有状态（设计文档 §12.2）。

## 7. 终局与名次

- [x] 7.1 实现连续 Pass 计数器（任一玩家落子 ≥1 枚即清零），达到当前参赛人数时触发终局条件 2。算例（设计文档 §12.3）：前两人 Pass、第三人落子 1 枚 → 计数重置，对局继续。
- [x] 7.2 断言计数器对参赛人数变化健壮。验证：某玩家出局导致参赛人数变化后，计数器与新人数重新比较，无误判。
- [x] 7.3 实现终局条件 1（只剩一名参赛玩家直接获胜）与条件 3（盘面无可落子空格）。算例：2 出局 + 1 弃赛 → 剩余唯一参赛者直接获胜；一次结算后无可落子空格 → 立即结束。
- [x] 7.4 实现终局名次比较链纯函数（势力值 → 控制信物数 → 独占空格数 → 盘面棋子数 → 并列）。算例（设计文档 §12.3）：势力同为 42、信物 3 vs 1 → 前者名次高；前三项同、棋子数 11 vs 8 → 前者名次高；四项全同 → 并列。
- [x] 7.5 实现三类玩家分组排序：完赛者 > 弃赛者（组内按弃赛时势力值）> 出局者（按出局先后倒序）。算例：弃赛者势力 60 仍排在完赛者势力 20 之后；D（弃赛势力 60）高于 E（弃赛势力 35）；第 8 大回合出局的 G 高于第 5 大回合出局的 F。
- [x] 7.6 输出终局结果（终局原因、最终名次、并列信息）供遥测与 UI。验证：三类终局原因各有独立用例。

## 8. 契约与回归

- [x] 8.1 固化对下游的六个输出契约（合法落子范围、阶段状态、流程事件、玩家状态、行动顺序+先手值明细、终局结果）。验证：契约级测试覆盖正常与边界输入。
- [x] 8.2 实现对局顶层状态的持久化与恢复。验证：任意时刻存档恢复后，阶段、顺序、保护状态、Pass 计数与出局/弃赛状态完全一致。
- [x] 8.3 建立流程回归用例集，覆盖：先手误伤后手、同回合保护状态不同、整轮 Pass 重置、出局改变人数、最后一手抢先锋、弃赛者覆盖、四级名次比较、三类终局。验证：全部通过并纳入持续回归。
- [x] 8.4 端到端跑通一局 4 人 AI 对局（AI 可用占位随机策略），验证全流程无死锁、无非法状态。验证：连续跑 100 局无异常终止。
