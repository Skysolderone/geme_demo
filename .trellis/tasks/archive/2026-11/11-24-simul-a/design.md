# 设计：新玩法段 A（simul-a）

裁决表见 prd.md。以下 J 编号是主会话给出的实现决策。实现 agent 可以提修订，但必须在回传里写明理由。缺口裁决 K1–K6 在末节，用户确认后生效。

## J1 结构：另起一条回合流程，现有流程零改动

- 新代码放在 `src/Siege.Core/Simul/`（命名空间 `Siege.Core.Simul`）。主类 `SimulFlow` 是新模式的唯一阶段机。
- **不改** `MatchFlow*`、`SettlementDriver`、`BatchRehearsal`、`MatchRunner`、`PublicRules`、`PowerCalculator`、`CoverageMap`、`HandLedger` 的现有行为。
  - 复用方式是调用：`GameBoard`（放置、移除、整体、气、克隆、序列化）、`CaptureResolver.FindCaptured`、`LifeShapeReport.Analyze`、`PowerScoreboard.Recalculate`（`ScoringVersions.Default`）、`FinalStandings.Compute`、`FlagPlanting` / `PrototypeZoneAssignment`、`PublicRules.LegalRange` / `EditScope`、`HandLedger`（征召与手牌）、`PieceEffects` 基础军势。
  - 如果复用确实需要在共享类上**新增**成员（例如把某个 `private` 的纯函数改成 `internal`，或者给 `HandLedger` 加一个允许多人同时处于准备阶段的入口），只能是增量，现有调用路径逐字节不变。每一处都要在回传里列出。
- 判据：现有快测和全部黄金哈希、决策序列基线**一个都不重钉**。变了就是缺陷。

## J2 一回合的状态与计算顺序

状态：`FlagPlanting → InProgress(Prep / Resolving) → Ended`。只支持链接小图（Q16、K4），插旗沿用 `PlantPrototype` 盲选或人工选座。

1. **回合开始**（v0.1 §7.1）
   - 固定结算顺位（Q05）：第 1 回合用 `setup` 子流洗牌，与现有 `LockFlags` 同一做法；之后按上回合结束时的势力排名；同势力先看上回合顺位，再看种子名次（`SeedRank`）。
   - 记下回合开始盘面 S0（`Board.Clone()`）。本回合的校验和战力都只读 S0。
   - 按结算顺位依次给每名参赛玩家开准备：效果快照沿用 `EffectSnapshot.Defaults`，部署上限 3。征召候选在此刻**一次生成**（K5），因此和界面的操作先后无关。
2. **准备**（Q09）：每名参赛玩家各自整理手牌、征召、暂放。暂放可以随意改，提交后锁定；未提交前可以撤回到可编辑状态。只有本人能看到自己的暂放；公开视图对每人只给"未提交 / 已提交"。
3. **部署校验**（Q02 / G2 / G3），按 S0 和本人批次判定，**不判自杀，不判同形**：
   1. 落点在 `PublicRules.LegalRange` 内。前 3 回合只能部署在出生区，第 4 回合起全图。
   2. 落点在 S0 上是空格。
   3. 不在任何活形的内部禁入格里，**包括本人的活形**（G2 双方禁入）。现有 `LegalRange` 只扣对手的禁入格，本人的部分在新模式里另外扣，不改 `LegalRange` 本身。
   4. 枚数 ≤ 部署上限；每种类型的枚数 ≤ 手牌库存。
   5. 八邻禁落：本人同一回合的任意两个落点，如果在同一"区"内（区的划分见 K3），切比雪夫距离必须 ≥ 2。
   6. 地形改造：只有匠人能带，范围是 `PublicRules.EditScope`，合法性沿用现有改造规则，按 S0 判定。
   
   非法批次不能提交，也不消耗手牌。提交 0 枚视为"本回合不部署"，**不撤销**本回合征召（G2；不调用 `Hands.OnPass` 的撤销语义）。
4. **揭晓**：全员提交后，一次性公开所有批次。所有提交的单位都从手牌扣除，冲突落败的也扣（v0.1 §8.2）。
5. **冲突**（Q06 / Q14 / v0.1 §9）：两名及以上玩家选了同一格，就发生冲突。
   - 每名投入者的战力 = 该单位类型的基础战力（G1：堡垒 4，其余 1）+ 在 **S0** 上与该格四邻相接的本人单位数（每个 +1）。本回合其他新部署一律不算。数值用 `BigInteger` 或 `int` 都行：战力不进计分，但不准用浮点。
   - 最高战力唯一者胜出。
   - 最高战力并列时，只有这几人掷 d6，点数低的出局；最高点仍然并列，只让这几人重掷，直到决出一人。
   - 骰子用新子流 `simul-dice`。消费顺序：冲突格按坐标字典序，同一格内按玩家编号升序，每次 `NextInt(6) + 1`。没有平局时不消费。
   - 落败者的单位不落下，牌照样扣；如果带了地形改造，改造作废（K2）。
6. **落下**：所有存活的部署同时放上正式盘面，再应用存活的地形改造（改造先于围杀，同现有 §6.3 顺序；同格改造冲突见 K2）。
7. **围杀**（Q03）
   1. 按结算顺位，对每名参赛玩家 P 依次执行：`FindCaptured(board, P)`，移除全部**非 P** 的无气整体。已认输玩家没有顺位，不执行这一步，但他们的整体会被别人提走。
   2. 孤立自绝：所有顺位都走完后，移除仍然无气的整体，不论属于谁。这一步通常已经没有可移除的（前面的顺位会提走），保留它是为了对齐规则表述，不另加断言。
   
   每一步都记录被移除的整体，以及是在哪名玩家的顺位上被移除的，供日志和界面使用。
8. **活形锁定与势力**：`LifeShapeReport.Analyze` → `PowerScoreboard.Recalculate`。Q06 要求活形内部空格算所有者领地：先核对现有独占空格是否已经覆盖这一点（被单一玩家的整体围住的空格，通常本来就是独占空格）。
   - 已经覆盖：只加测试守住。
   - 没有覆盖：在新模式的势力计算外层加一个修正，只对新模式生效，现有 `PowerCalculator` 不动。修正方法写进回传。
9. **终局判定**（Q10 / Q11 / v0.1 §10），按以下顺序判，先命中的为准：
   1. 参赛中玩家（未认输）≤ 1 → `LastPlayerStanding`。
   2. 占满：S1（本回合结算后）上不存在"非活形锁定的空可部署格"→ `BoardFull`。活形内部格不需要补。
   3. 本回合无人提交任何单位 → `NoDeployRound`。
   4. 达到大回合上限（小图沿用现有缺省 100）→ `RoundCap`。
   
   终局排名沿用 `FinalStandings.Compute`（Q08：势力 → 信物数 → 独占空格 → 单位数 → 种子）。认输者固定排在末位（Q11）。胜利名额 2 / 3 / 4 人局取 1 / 1 / 2 名（Q07），结果里标出胜者。
10. **回合结束**：更新势力排行，生成下回合顺位，进入下一回合。**没有**任何淘汰：全灭的玩家照常参赛（v0.1 §10.1）。

认输（Q11）：任意时刻都可以认输。认输者在本回合未揭晓的暂放直接作废，不扣牌。单位留在场上，可以被围杀；不再有顺位，不再征召。

## J3 对外接口（供 AI、Sim、Godot 使用）

- `SimulFlow.Create(map, seed, players, options)`，插旗入口与现有一致。
- 准备阶段每人一个句柄：手牌整理、征召、暂放（加、撤、换位、换类型、挂改造）、预检（返回失败原因）、提交、撤回提交。
- `ResolveRound()`：全员提交后才可调用，返回 `SimulRoundReport`，内容包括：顺位、揭晓的各家批次、冲突列表（每格的投入者、战力构成、每轮骰点、胜者）、落下的单位、围杀按顺位分步的移除记录、本回合势力、终局原因。
- 公开视图（`SimulPublicView` 或复用 `MatchPublicView` 的字段子集，由 agent 按 Godot 现有 `ViewerWorld` 的需要选择，并说明理由）：盘面、势力、手牌公开部分、提交状态；不含别人的暂放内容。
- 规则只在 Core。AI、Sim、Godot 都不做第二套合法性或冲突判定。

## J4 AI（G6，最简贪心）

- 每名 AI 玩家只读 S0、自己的手牌和公开信息，按顺序做三步：
  1. 征召：沿用现有最简选法，例如按权重取前几张，或复用现有启发式里的征召逻辑。
  2. 选点：逐个候选格模拟"只有自己落下"时的势力增量，贪心取最好的，并满足八邻禁落和上限。
  3. 提交。
- 不读别人的暂放；不新增随机子流（如果必须用随机，新开 `simul-ai:<玩家>` 子流，并写进 `determinism.md`）。
- 单个 AI 一个回合的决策耗时在小图上应在秒级以内。性能问题和下棋质量问题只记录，不修（"AI 放最后"）。

## J5 Sim 与 Godot

- Sim：在现有 CLI 上加新模式入口。参数名由 agent 看现有 `play` / `run` 的结构来定，比如 `--mode=simul`。全 AI 对局，支持 `--rounds=N`、种子、人数；日志写顺位、冲突（战力与骰点）、围杀分步、势力、终局原因。
- Godot：
  - 新局面板加"新玩法"选项，与现有模式并列（G5）；选中后地图尺寸锁定为小图（K4）。
  - 新建会话类（例如 `SimulSession`），不往 `MatchSession` 里加分支。尽量复用现有盘面渲染和暂放交互。
  - 流程：人类暂放 → 提交 → AI 依次决策 → 揭晓 → 冲突格逐个显示文字和飘字（"A 3 : B 2，A 胜"或"掷骰 5 : 2"）→ 落下与围杀 → 势力刷新 → 下一回合。
  - 对手状态只显示"已提交"。终局弹出排名和胜者。
  - 文案经 `Labels`（或现有文案入口）取，不写"棋盘 / 棋子"。
- Godot 部分在阶段 A3 开工前先回传调研结论：复用哪些视图、新建哪些类、预计改动的文件清单。主会话确认后再动手。

## 算例（每条至少对应一个测试；坐标以夹具实际为准）

- **E1 冲突比战力**：A、B 同回合都在 X 部署普通单位。S0 上 A 在 X 的四邻有 2 个单位，B 有 1 个。A 战力 1+2=3，B 战力 1+1=2，A 胜。B 不落下，B 的手牌照样少 1 张。
- **E2 本回合新部署不支援**：接 E1，B 本回合同时在 X 的另一个四邻格 Y 部署（无冲突，成功落下）。B 战力仍然是 2，不是 3。
- **E3 堡垒基础战力**：A 投堡垒（4），四邻无己方单位；B 投普通单位，四邻有 2 个己方单位（3）。A 胜。
- **E4 多人并列掷骰**：A、B、C 争同一格，战力 2 / 2 / 1。C 先出局；A、B 掷骰，第一次 3 : 3，重掷 5 : 2，A 胜。骰点由 `simul-dice` 子流给出，测试用种子钉住。另加一条：没有平局时，这条子流一次都不消费。
- **E5 八邻禁落**：A 在同一座岛上暂放 X 和它的斜邻 → 拒绝；暂放 X 和隔一格的格 → 接受；两格分属不同的岛 → 接受。B 在 A 的 X 的斜邻暂放 → 接受（不同玩家）。撤回其中一枚后重新判定。
- **E6 互相堵死按顺位**：A 的整体 GA 与 B 的整体 GB 相邻，各只剩一口气。A（顺位 1）堵 GB 的最后一口气，B（顺位 2）堵 GA 的最后一口气。落下后两者都无气。A 的顺位先提走 GB，GA 因此重获气并保留。顺位对调时结果相反。
- **E7 自杀式部署**：A 把一个单位部署到四邻全是 B 单位、而且不提任何子的格里。提交合法（不判自杀）；结算后这个单位被移除，A 的牌照样扣，B 不受影响。
- **E8 全灭不判负**：A 场上的单位全部被围杀。下一回合 A 仍是参赛中，能征召、能部署；全程没有出局事件。
- **E9 终局**：
  - (a) 夹具里剩下的空格全是活形内部格 → `BoardFull`。
  - (b) 某回合全员提交 0 枚 → `NoDeployRound`；只要有 1 名玩家部署了 1 枚就不触发。
  - (c) 4 人局终局，前 2 名为胜者；认输者排末位，即使他的势力更高。
- **E10 活形禁入双方**：A 有活形，其内部格对 A 和 B 都不能暂放；被拒的原因可读。
- **E11 冲突落败的改造作废**：A 的匠人在冲突里落败，它带的改造不生效。

## K 缺口裁决（2026-11-24 用户确认：全部按默认）

| 编号 | 拟默认 |
