## 实现清单

## 1. 批次暂放状态

- [x] 1.1 定义批次暂放结构（落点坐标 + 棋子类型 + 批次内落子顺序），与正式盘面完全分离。验证：单元测试断言任意暂放操作后正式盘面序列化逐字节不变。
- [x] 1.2 实现暂放/撤销/换位/替换操作，次数不限且不扣手牌。算例（设计文档 §5.4）：暂放 `E5` → 移到 `F5` → 换成另一类型，暂放数量始终为 1，手牌库存不变。
- [x] 1.3 实现部署上限约束（消费外部整数，无全局硬上限）。算例：上限 3 时暂放第 4 枚被拒；上限 9 时可暂放 9 枚（对应 §8.1 无硬上限）。
- [x] 1.4 实现手牌库存约束（每类型暂放数 ≤ 库存数）。算例：手牌 2 枚连珠子，暂放第 3 枚被拒并说明库存不足。
- [x] 1.5 实现"禁止暂放到当前已被占据的格"（含预计将被本批次提空的格）。算例（设计文档 §5.4）：批次将提走 `G7` 的敌串，仍拒绝把棋子暂放到 `G7`。
- [x] 1.6 断言未使用的部署额度不跨小回合保存。验证：上限 5 只落 2 枚，下一小回合上限仍由该回合快照决定。

## 2. 合法性预演流水线

- [x] 2.1 实现第 1 步：落点为空 + 地形可落子 + 符合当前合法落子范围。验证：三类失败各返回独立类别与坐标。
- [x] 2.2 实现第 2 步：数量与库存校验（复用第 1 组约束，在确认路径上再校验一次）。验证：绕过 UI 直接提交超量批次时仍被拒绝。
- [x] 2.3 实现第 3 步：在盘面副本上模拟放置整个批次。验证：副本变更后正式盘面序列化不变。
- [x] 2.4 实现第 4 步：**一次性**求出全部无气敌串的并集后同时移除。算例：两条互相提供气的敌串在同一批次后同时无气 → 两条均被移除。
- [x] 2.5 实现顺序无关性回归：以随机化的棋串遍历顺序重复执行同一批次 100 次，断言提子集合与结算后盘面完全一致。
- [x] 2.6 实现第 5 步：提子后重算当前玩家全部棋串的气，仍有无气棋串即判自杀手。算例（设计文档 §6.1）：最后一枚落子自身暂无气，但整批提走相邻敌串后获得气 → 合法；未造成任何敌串无气的填入单点包围 → 自杀手。
- [x] 2.7 实现第 6 步：盘面同形比对（见第 3 组）。
- [x] 2.8 实现预演零副作用断言。验证：任意预演（通过或失败）后正式盘面序列化逐字节不变，纳入持续回归。
- [x] 2.9 实现确认时强制重跑完整预演（不信任缓存的预演结果）。验证：篡改缓存结果后确认，仍以重跑结果为准。

## 3. 盘面同形禁则

- [x] 3.1 实现已提交盘面集合：内容哈希 + 提交序号 + 完整内容，哈希命中后必须按内容再比对一次。验证：构造哈希碰撞桩，断言不误判。
- [x] 3.2 实现同形判定与失败信息（返回重复的历史提交序号）。算例（设计文档 §6.2）：结算后盘面与第 12 次提交相同 → 拒绝并返回序号 12。
- [x] 3.3 断言比对内容只含每格占用者与棋子类型。算例：占用者全同但某格普通子→堡垒子 → 不同形；逐格全同但手牌与信物控制不同 → 仍同形。
- [x] 3.4 断言预览中间态不入集合。算例：暂放过程中经过与历史相同的预览态，最终确认盘面不同 → 合法，且集合中未新增该中间态。
- [x] 3.5 实现已提交盘面集合的持久化与恢复。验证：第 20 次提交后存档恢复，再提交会重现第 12 次盘面的批次 → 仍被拒绝并报序号 12。

## 4. 正式结算顺序

- [x] 4.1 实现结算驱动器，严格按 §6.3 六步执行：扣手牌 → 加入盘面 → 同时提子 → 信物揭示 → 重算控制/归属/军势/势力 → 更新排名并检查出局与终局。验证：步骤顺序有显式测试，调换任意两步即失败。
- [x] 4.2 定义第 4/5/6 步的下游驱动接口（信物、势力、流程各一个回调点），本层不实现其内部计算。验证：用桩实现断言三个回调各被调用一次且顺序正确。
- [x] 4.3 实现结算原子性。算例（设计文档 §6.3）：批次提走唯一覆盖某未知信物格的敌串，同时己方进入其覆盖范围 → 揭示与控制判定基于提子后的覆盖关系。
- [x] 4.4 断言外部观察者无法看到中间态。验证：在每一步之间采样盘面对外快照，断言只存在结算前与结算后两种状态。
- [x] 4.5 断言提子不产生任何资源奖励。算例（设计文档 §6.3）：一次提走 7 枚敌子 → 手牌、征募参数与任何资源计数均不变。

## 5. Pass

- [x] 5.1 实现"确认 0 落子 = Pass"，完成小回合并触发与正常结算相同的出局与终局检查。验证：Pass 后 `结算完成` 回调仍被调用。
- [x] 5.2 实现 Pass 事件发出（供 `add-recruit-hand` 撤销本轮新征募）。验证：桩消费者收到事件且携带当前玩家标识。
- [x] 5.3 断言"至少落 1 枚即全保留本轮征募"。算例（设计文档 §5.5）：本轮征募 3 枚只部署 1 枚 → 另 2 枚保留在手牌。

## 6. 失败原因与可定位性

- [x] 6.1 实现失败类别枚举：落点不可落子 / 落点已被占据 / 违反合法落子范围 / 超出部署上限 / 手牌库存不足 / 自杀手 / 盘面同形。验证：七类各有独立用例。
- [x] 6.2 自杀手失败必须附带仍无气的己方棋串全部坐标；同形失败必须附带历史提交序号。验证：断言返回载荷字段非空且坐标可直接用于高亮。
- [x] 6.3 断言"禁止预占腾空格"的拒绝文案为"该格当前已被占据"，而非泛化的非法落点。验证：文案级断言，避免 UI 表达含糊。

## 7. 遥测与回归

- [x] 7.1 输出提子记录（被提棋子坐标、所属玩家、类型、批次内落子顺序）。验证：记录可完整重建被提棋串；落子顺序字段为将来的击杀归功预留。
- [x] 7.2 建立批次回归用例集：提子后获气的合法批次、真自杀手、两串同时提子、禁止预占、换类型不同形、中间态不入集、存档后同形仍生效。验证：全部通过并纳入持续回归。
