# 确定性

对局必须能仅凭种子 + 决策序列完整重放。§17 的全部平衡分析都建立在这一点上。

## 随机子流隔离

从对局种子派生四条**互相独立**的确定性序列：

| 子流 | 消费者 |
|---|---|
| `relic-gen` | 信物内容生成（开局一次性） |
| `recruit` | 每小回合的征募候选抽取 |
| `setup` | 插旗后的首回合顺序、以及其他流程初始化 |
| `zone-pick` | 原型插旗路径的 AI 选区（frontier-map）。**只在出生区数 > 地图支持的最大人数时派生**；相等时走按编号顺排、不消费任何随机——v4 上的既有对局因此逐步不变（`PrototypeZoneAssignment` 是三个入口共用的唯一实现） |

改变其中一条子流的**消费次数**，MUST NOT 影响其他子流的取值。

**为什么。** 若共用一条序列，玩家改一个征募决策就会让后续所有随机取值偏移，"改一个决策重放整局"立刻失效，调试与回归都会变得极难。

回归测试：改变某玩家的一次征募决策后，断言该局信物生成结果逐格不变。

## 禁止浮点参与计分

倍率 `1.5^e` 与棋串军势 MUST 用整数运算（multiplier-rebalance 之后：倍率只放大基础军势，封顶 3）：

```
棋串军势 = 基础军势总和 * 3^e / 2^e + 位置加值     // e = min(倍增子数, 3)；整数除法即向下取整，位置加值不进倍率
```

禁止 `double` / `float` 出现在任何计分、倍率、取整路径上。唯一例外是 `Siege.Presentation.Camera` 下的相机几何类型（frontier-map）：守门 `内核与表现层不出现浮点` 按**精确类型名单**豁免它们，不按命名空间放行——往该命名空间里新塞一个带浮点的类型仍会红。相机不进规则、不进日志。

**为什么。** 取整对边界值极其敏感——`16.499999` 与 `16.5` 的 `Math.Floor` 结果不同。整数运算让跨平台、跨架构结果完全一致，这是跑局复现的地基。

注意取整位置：**逐棋串各取一次**，不在求和阶段或对总势力二次取整。两条未取整军势各 16.5 → 分别取整为 16+16=32，不是先求和 33 再取整。

## 并列必须确定性打破

任何排序、选择、候选评价出现并列时，MUST 用确定性规则打破（如坐标字典序），MUST NOT 使用不受控随机。

需要行为多样性时，通过种子驱动的扰动引入，而不是通过 `Random.Shared`。

## 集合操作不得依赖遍历顺序

同时提子（设计文档 §6.1 第 4 步）必须先**一次性算出**全部无气敌串的并集，再统一移除。

写成"遍历敌串，无气就移除，然后继续遍历"，两条互相供气的敌串会因遍历顺序不同得到不同结果。

强制回归：以随机化的遍历顺序重复执行同一批次 100 次，断言提子集合与结算后盘面完全一致。

## 持久化文本必须容忍行尾差异

`BoardHistory.Deserialize` 曾对 `\r\n` 零容忍：`\r` 会混进盘面串，让同形比对**静默失效**——比抛异常更糟，因为对局照常进行、规则却悄悄失守。任何解析持久化文本的地方都要 `TrimEnd` 行尾，其余偏差仍抛 `FormatException`。守门测试要含一条 CRLF 往返。

## 全量重算与受影响子集等价的论证（自杀手检查）

每次合法结算后全盘棋串都 ≥1 气（第 4 步移除无气敌串、第 5 步保证己方有气）。下一批次中只有落点会减气，减的是**邻接格**的气；己方棋串若因此失去最后一口气，那口气所在格上放的是己方子，与该串四邻接即合并为同一串——所以"无气的己方串"必然包含本批落点，全量重算 ≡ 只查受影响子集。全量的额外价值只在防御被绕过规则写入的脏盘面。结论：**按裁决 2 保持全量**，不做"收窄"优化，它没有收益。

## 大数用 `Int128` checked，不用 `BigInteger`

倍率 `3^n / 2^n` 的整数运算曾用 `BigInteger`：语义对，但每次重算全盘每条棋串都分配，批量跑局下纯浪费。改为 `Int128` checked：零分配，`value × 3^n` 到 n≤80 不溢出，结果装不进 `long` 时抛 `OverflowException`——同样是响亮失败。注意 `checked long` 不够：`value × 3^n` 在 n≈32–39 就先溢出，会把失败阈值提前。`BigInteger` 只留在纯显示路径（`ToString` 打印精确十进制）。
