# 测试组织

## Requirement → 测试类，Scenario → 测试方法

`openspec/changes/<change>/specs/<capability>/spec.md` 是验收基准。映射方式：

```
Requirement: 棋串构成
  Scenario: 跨类型合并棋串
  Scenario: 敌我相邻不合并
        ↓
tests/Siege.Core.Tests/<Capability>/棋串构成Tests.cs
  [Fact] 跨类型合并棋串()
  [Fact] 敌我相邻不合并()
```

测试名直接用 Scenario 名（中文方法名在 C# 中合法），便于与 openspec 逐条对账。

多组数据的 Scenario 用 `[Theory]` + `[InlineData]`。

## 算例必须来自设计文档

涉及数值的测试，其输入与期望值 MUST 取自 `2026-09-10-siege-core-gameplay-design-v1.md` 或 openspec spec 里写明的算例，并在测试上注明出处：

```csharp
// 设计文档 §10.1：普通子×3 + 堡垒子×1 + 倍增子×2 → 基础 9、倍率 2.25、军势 20
```

不要自己编期望值——编出来的期望值会把实现的 bug 一起固化。

## 新守门测试必须做变异验证

写完一个测试，**改实现的一行让它本该红**，看它是不是真的红。不红就是假测试，删掉重写。

board-core 阶段先后被自审（`邻接实现唯一`，提交 25b5f4d）与 `trellis-check`（`共享气去重` / `共享出生区` / `信物格只记录位置`，提交 b2f6854）抓出 4 个假测试，全部出自同一个作者（主会话），每个都通过了"看起来在验证 Scenario"的自审。变异验证是唯一可靠的过滤器。

### 假测试的常见形状（都在本项目真实出现过）

| 形状 | 实例 | 为什么恒真 |
|---|---|---|
| 比较被测方法与它的委托目标 | `Assert.Equal(Adjacency.Neighbors(...), board.Neighbors(c))`，而后者实现就是 `return Adjacency.Neighbors(...)` | 两边是同一个调用 |
| 同一表达式读两次再比较 | `var a = Map.BirthZones[1]; var b = Map.BirthZones[1]; Assert.Equal(a, b)` | 读的是同一个对象 |
| 对只有两个成员的枚举断言 `is A or B` | `Assert.True(spec.Zone is BirthZone or Contested)` | 枚举没有第三个值 |
| 用例几何上触发不到被测路径 | 用直线相邻的 `D4`+`D5` 测"共享气去重" | 四邻接下直线相邻的两枚棋子**不可能共用邻格**（中间那格就是棋子本身），去重从未发生；要触发必须用拐角串如 `D4-D5-E5`，`E4` 同时邻接 `D4` 与 `E5` |
| 期望值恰好等于哈希表的插入序 | `障碍减少气` 断言 `["F5","E6","G6"]`——单子棋串的邻居本就按字典序插入 `HashSet`，枚举顺序与字典序重合 | 作为集合断言没问题，但作为"排序"守门是假的：去掉 `Order()` 也过。要钉住排序得挑一个插入序与字典序不同的用例，如 `共享气去重` 的拐角串（`F5` 与 `D6` 会换位） |

### 变异验证的记录方式

在测试的注释或提交信息里写清：改了实现哪一行、改成什么、红了几个。没有记录的变异验证等于没做。

### 变异还原不要用 `git checkout -- 文件`

check 阶段做变异时工作树里还有实现方**未提交**的改动，`git checkout -- file` 会把它们一起冲掉。规则：变异前 `cp` 备份，还原后 `cmp` 逐字节校验；主会话用 Edit 工具做变异也一样——还原后 `git diff -- 文件` 应与变异前一致，而不是为空。

### 还原后必须刷新时间戳，否则下一次"全绿"是假的

`cp -p` / `shutil.copy2` 会把备份的 **mtime 一起还原**，于是源文件比上一轮用变异源编译出的 DLL 还旧，MSBuild 判定"最新"直接跳过重建——接下来那次 `dotnet test` 跑的仍是**变异后的二进制**。段 A 收尾就踩了这个：内容已逐字节还原、`git diff` 干净，全量测试却红 53 条，与最后一条变异的失败数分毫不差。

规则：还原后 `touch`（`os.utime(path, None)`）被动过的每个源文件，再跑确认；或者干脆用不保留 mtime 的 `shutil.copy` / `cp`（不带 `-p`）。**逐字节校验只证明内容对，不证明构建产物对。** 判断信号：确认跑的失败数恰好等于上一条变异的失败数。

### 同一个量存在于结果对象与活对象，两处都要断言

终局轮次既在 `MatchResult.MajorRound` 里，也在 `match.MajorRound` 里。round-cap 的 check 变异 M-RC1（终局后仍推进 `MajorRound`）只靠活对象那条断言才红。凡是"快照 / 结果"与"权威状态"并存的量，测试两边都钉住。

### 统计口径测试必须放一个被排除的样本

不收敛率、胜率这类 `x / 纳入局` 的指标，测试数据里如果没有被排除的局（污染局、失败局），分母写成"全部局"也算得一样——M-RC4 原本 0 红。口径测试至少放一个会被排除的样本。

### 不在解决方案里的工程对守门测试完全隐身

IL 扫描、反射闭包守门只能覆盖"被编译进测试的程序集"。`src/godot/` 不在 `siege.sln`（tactical-ui 裁决 10：`dotnet test` 不依赖 Godot SDK），所以它对这两类守门一律隐身。实证：把 Godot 侧 `BoardGeometry.Center` 换成本地第二份公式且 Z 写反，`--build-solutions` 零警告、无头演示终局输出逐字相同、退出码 0——没有任何自动手段会红。

规则：凡"唯一实现 / 唯一映射"这类硬约束，**每个游离工程都要补一条源码级文本扫描**，并且扫描本身要配：样本口径下界（扫到的文件数与字符数不得低于阈值，防止扫了个空目录还绿）+ 反面断言（判据在唯一实现所在文件里确实命中）。

### `--pick-check` 分两层，换相机参数 / 层高 / 地图必须在每张图上重跑

frontier-map 起相机可动，自检 `--headless --path src/godot -- --auto-demo --pick-check [--map=<标识>]` 分两层：

- **逐格居中层**：把注视点移到每个可落子格上，最近与最远两种缩放各点一次格心。夹取后**确实居中**的格必须选中自身，无一例外（v4 105/105 ×2，边疆图 411/411 ×2）。25×30 的图在最远缩放下注视点纵深方向被夹取，贴近远边几行居中不了、视线变浅到约 48°–52°，紧贴 h=2 平台身后的 h=0 格心会被真实遮住（map-generator 段 C 在 `gen:987654321:p8` 等生成图上实测）——这类格只在"纵深被夹取、落在注视点远侧、拾到的是正前或斜前一行更高更近的格"时记为遮挡；横向夹取与同一行邻格不算（放宽到那里会放过"缩放带俯角变化"的真错误，段 C 检查用变异抓到过）。另有一条兜底：**每个可落子格至少在一种缩放下严格选中自身**，否则失败。
- 多位姿层的四个角位姿在随机图上可能整屏无可落子格，打印"无可验"不算失败；注视地图中心的位姿画面内必须有格。
- 生成器一旦改动，同一 `gen:` 标识会产出另一张图：`gen:12345` 的导出摘要黄金值会先红；旧日志回放与旧存档恢复会在首部 / 恢复时报"地图不一致"。这是预期的响亮失败，不要为了让旧日志能回放去绕开摘要比对——要长期保存的图用 `map --out` 导出成文件。
- **多位姿层**：中心、四角夹取位、最近、最远共 7 个位姿逐格验证。拾到"层数更高且水平距离更近的格"记为**遮挡**并打印，不算失败——透视下越靠画面顶边视线越平（Fov 54° 时顶边射线俯角只有约 33°），远处崖后的低地格心会被高台顶面真实遮住，这是正确结果。已知盲区：把"拾到身前更高的邻格"这类真错误也会记成遮挡，只有逐格居中层能抓到，所以两层缺一不可。
- 自检中途抛异常 MUST 以非 0 退出（曾经被引擎吞掉、自动演示接着跑完并报 0，等于没跑却报通过）。
- `--auto-demo` 终局另有一行 `[camera] 开局对准自检`：出生平台每格四角都在视口内、开局对准之后位姿变化 0 次，任一不符退出码 1。

以下是单位姿时期的实证，结论仍然成立。实证（段 C 变异 M-C5）：把 `Center` 的层高抬升写成 0，只有远半盘第 10–13 行的 h=2 格失败（26 个），近半盘偏移 0.40 格仍落在同一格。所以：

- 它能抓"层高 / 相机改坏了"，抓不到近半盘的小偏差与非格心点击；
- 换地图、改相机、改 `LayerHeight` 必须重跑，且**看失败分布**不只看退出码；
- 高台边缘显示为侧面的像素是拾取死区（返回 false），不是误拾——这是设计，不要为了"点哪都有响应"把它改成取最近格。
- 它也证明不了"改造之后的盘面还能拾取"：`--pick-check` 在第 2 帧就跑完，此刻一处改造都没发生（artisan-terrain-edit 段 C 检查）。拿 105/105 给"新桥格可被拾取"当证据是无效的。

### 截图取图要等本帧绘制完成，并先收起会遮挡的面板

artisan-terrain-edit 段 C 的 8 张截图全部作废重拍，三处系统性缺陷：

1. **差一帧**：在 `_Process` 里直接 `GetViewport().GetTexture()` 拿到的是**上一帧已绘制**的画面，控制台打印的视图模型读数与图像因此系统性错位一帧——一张标着"暂放匠人 + 15 条候选边"的图上，一枚暂放匠人和一条候选边都没有。修法：`await ToSignal(RenderingServer.Singleton, FramePostDraw)` 之后再取画面，并在取图期间冻结驱动与刷新，让打印的读数就是图像所示。
2. **面板遮挡**：无人值守演示每个部署回合都会开一次手牌信息面板，整块盖住棋盘，两张"落成后"的图全被盖住。修法：取图前先把可关的面板（信息层、手牌面板）收起再刷一帧；并在截图那一行另打"面板 开/关"，让每张图自证取景。
3. **关不掉的面板要靠选帧**：终局结算面板与征募面板是**对局状态**不是按键开关，取图代码不该去动它们——改成选一帧没有它们的（本例由第 96 帧改到第 91 帧），并同样打一行"中央面板 开/关"。

规则：产出"给人看图作判据"的截图时，MUST ① 等本帧绘制完成再取；② 取图前收起所有可关的遮挡；③ 让每张图的控制台读数包含取景自证字段。验收不要靠肉眼——用脚本数像素：面板底色在紧中心框（x 35–65%、y 30–70%）的占比、候选色像素数、"前后"两张图的局部差分块，三项就能把差一帧与遮挡都抓出来。

### "共用同一套状态机"最容易在最外层被复写

复写不是禁用调用——把 `Active == x ? Back() : Press(x)` 在引擎侧多写一遍，IL 守门与闭包守门都抓不到，它只是把判断多了一份。对策：让状态机把**完整语义**暴露成方法（`Toggle(layer)` 而不是让调用方自己拼），再写一条"两条入口逐步等价"的序列断言。tactical-ui 的 check 就是这样抓出 `GameRoot.ToggleLayer` 复写了 D5 的点击语义。

### `A || B` 形状的条件，要把 `||` 改成 `&&` 做变异

如果 B 在 A 为真时也必然为真（例如"弃赛者一定不在满足者集合里"），删掉 A 分支测不出任何变化——A 分支从没被单独触发过，删它就是等价变异。dominance-victory 的 check 就是这样发现"候选弃赛即取消"这条分支零覆盖。规则：对 `||` 组合条件，变异要把 `||` 改成 `&&`（或单独反转 A），逼出"只有 A 成立"的用例。

### 默认值改了，测试注释里的"变异红 N 条"要重跑

变异验证记录里的红数依赖默认配置。碾压起始大回合默认值从 4 改成 7 后，M-DV5 从"红 23"变成"红 13"。check 阶段抽查变异时一律重跑，不照抄注释里的数；改默认值的提交要顺手刷新受影响的记录。

### 带等号的比较式先拿退化局面算一遍

"本人 ≥ 其余之和"这类判定，写规格前先代入"全员为 0"与"只有一人落子"：dominance-victory 首版在开局第 1 个小回合就判胜，原因正是 `X ≥ 0`。算例清单里必须包含退化局面。

### 源码扫描守门的正则不要以 `\b` 开头匹配复合标识符

`\bdeploy` 要求 deploy 前是词边界，抓不到 `BaseDeploy = 3` 这种驼峰复合名——growth-pass-1 的"阶段表唯一实现"扫描因此是假守门（在 Presentation 注入 `internal const int BaseDeploy = 3;` 全套 0 红）。规则：扫描正则用 `(?i)目标词\w*` 这类不依赖词边界的形状，并至少用"前缀 + 目标词"的变体做一次变异。另：用 Bash heredoc 生成含 `\b` 的 Python / C# 字符串时，`\b` 可能被转义成退格符 0x08，写完扫一遍文件里有没有 0x08。本条规范本身第一次写入时就中了招，且第一次修复用的替换字面量又被转义吃掉——修这类问题时用字节码 `bytes([92, 98])` 表示反斜杠加 b，不要再写转义序列，修完用字节计数复核。

### "可复算"守门必须用测试内独立算式，已是第二次踩坑

"明细可复算总势力 / 棋串军势"这类守门，若调用组装函数本身（`GroupPowerOf`、`Apply`）去复算，就是"比较被测方法与它的委托目标"，恒真。cap-multiplier 之后 multiplier-rebalance 又出现一次。规则：复算一律在测试里写独立的整数算式，或把显示串解析成分数自己算；再用"公式改错"的变异证明守门会红。

### 真实跑局覆盖不到的写入路径，要补真实盘面端到端测试

Easy 难度的跑局从不出现连珠成线，Sim 快照"连珠计数"的写入路径只被合成日志覆盖。合成日志绕过了写入函数，写反计数也测不出。规则：统计类写入端要有一条"真实盘面 → 写入函数 → 日志往返 → 报告"的测试。

### 降封顶会让往返测试的"非回填值"变成新回填值

回填值随默认值变化（生效指数缺失时按当前封顶回填）；封顶从 4 降到 3 后，原先选作"非回填值"的 3 恰好成了新回填值，往返测试随之变假。改默认值、改封顶时，逐条复查所有往返测试选的样本值。

### 违禁 token 清单挡不住"照抄一份算式"

把唯一实现的类型名列进违禁 token（`不得出现 CatchUpCompensation`）只能阻止"调用"，阻止不了"在表现层重写一份同样的算式"。catch-up-recruit 的 check 实证：在 Godot 的 `Hud` 里注入 `rank > (participants + 1) / 2 ? 1 : 0`，既有 token 黑名单与 IL 扫描全部 0 红。规则：凡"唯一判定实现"，除 token 黑名单外**再配一条算式形状扫描**（本例扫 `(… + 1) / 2`），并同样配反面命中断言（判据在唯一实现文件里确实命中）与样本文件数下界。

### 带回填兜底的字段，写入路径要用"非回填值"证伪

字段缺失时按公式回填（如生效倍率指数缺失 → `min(数量, 5)`），那么"写入路径漏写"和"回填算出同一个值"在测试里不可区分——往返测试必须写入一个与回填值**不同**的数再读回（cap-multiplier 变异 M-M6 的形状），否则漏写恒真。

### 红测变绿后必须整段复审

一条测试的第一个红断言会挡住后面所有断言，后面那些**从未被执行过**。match-flow 的 `小回合边界存档恢复后状态完全一致` 修好第 30 行的前提错误后，第 61 行才暴露出一个恒假断言（见下）。规则：修红测不是"让它绿"，而是把该测试从头到尾当新测试审一遍，并对新暴露的断言补变异验证。

同类根因：测试注释里"P0 落 E5 使 P2 出局"这种**因果声明必须用断言钉住**（`Assert.Equal(PlayerStatus.Eliminated, match.StateOf(P2).Status)`），否则前提错了（P2 其实在 B8 还有子）只会在很远的下游断言以莫名其妙的数字失败。

## 持久化守门

### 含 `ImmutableArray` 的 record 不能直接 `Assert.Equal`

`ImmutableArray<T>` 是结构体，但它的 `Equals` 是**底层数组引用相等**。所以任何含 `ImmutableArray` 字段的 record（`PlayerPower`、`PowerSnapshot` 等）在 `Assert.Equal(a, b)` 下对两个独立构造的等值对象**恒假**，而对同一对象引用恒真——两种情况都不是在守门。

```csharp
// 恒假：Players 里的 ExclusiveCells / Groups 是 ImmutableArray
Assert.Equal(match.Scoreboard.Latest!.Players, restored.Scoreboard.Latest!.Players);

// 正确：投影成值再比
Assert.Equal(PowerText(match), PowerText(restored));   // 把每个字段拼成确定性字符串
```

规则：比较持久化前后的复合对象，一律投影成基本值/字符串/序列后比较；`Assert.Equal(json, restored.Serialize())` 这种逐字节比对可以并列做，但不能替代字段级比对（见下一条）。

### "存档→恢复→再存档逐字节相等"抓不到漏字段

`Serialize` 漏写一个字段（变异 M-C4：不写 `Protection`），恢复对象的该字段就是默认值，再次 `Serialize` 仍然不写它——两份 JSON 逐字节相等，百局往返测试全绿。只有拿**活对象**的字段和**恢复对象**的字段逐个比才会红。持久化守门测试必须两条腿都有：

| 断言 | 抓什么 |
|---|---|
| `Assert.Equal(match.X, restored.X)` 逐字段（含私有视图、子流消费位置） | 漏写 / 漏读某个字段 |
| `Assert.Equal(match.Serialize(), restored.Serialize())` | 恢复过程本身引入的差异 |
| 恢复后**续跑同样决策**，再比一次面板与存档 | 随机子流位置、快照等"存起来了但没用上"的状态 |

"含 `ImmutableArray`" 应读作"含任何集合字段"：`List<T>`、数组同病，heuristic-ai 阶段 B 因此两条测试假红。

### 逐字节文本比对必须钉住覆盖范围

"串行与并行结果一致"、"凭种子复现"这类测试如果只比对日志文本，而文本首行含种子 / 标识，那么把日志砍到只剩首行，两边照样相等——断言恒真。heuristic-ai 的 check 用变异 M-C5（`DeterministicText` 只输出 header）抓到两条这样的假守门。规则：逐字节比对必须配**行数下界**（或条目计数）与至少一处**字段级投影比对**（快照 / 事件 / 名次逐条），让"内容缺了一大块"也能红。

### 反射闭包守门要对非根类型做变异

信息边界一类的"类型闭包里不得出现 X"测试，闭包展开是否真的深入到字段 / 参数 / 返回类型，只有给**非根类型**加一个泄漏成员（M-C1：`BatchEvaluator` 加 `RelicGenerationRecord? Leak` 属性）看它红不红才知道；只在根类型上加是测不出遍历深度的。

## 强制回归

下列测试是硬约束，不得以"太慢"为由跳过：

| 回归 | 内容 |
|---|---|
| 提子顺序无关性 | 随机化遍历顺序跑同一批次 100 次，结果一致 |
| 预演零副作用 | 任意预演后正式盘面序列化逐字节不变 |
| 随机子流隔离 | 改变征募决策后信物生成逐格不变 |
| 出局判据（restore-go-core-rules 裁决 #3，取代原「出局保护逐玩家」） | 结算 / Pass 后检查**全部**参赛玩家：他人批次提光曾有势力的未行动玩家 → 立即出局（保护期不豁免、手牌不影响）；从未落子者连续 Pass 不出局；同一批次同时归零者共享名次（`EliminationEndgame/出局判定Tests`） |
| 手牌两段账 | 回合前 4 + 本轮新增 2 → Pass 后剩 4 |
| 倍率取整边界 | n=0..8 各阶，恰为整数的值必须取到该整数 |

## 提交前的测试必须用真实退出码把关

`dotnet test ... | tail -1 && git commit` 这种写法，`&&` 看到的是 `tail` 的退出码，永远为 0——红测试会被原样提交。relic-system 收尾时就这样把一条过期断言连同归档一起提交了，靠事后肉眼才发现。

规则：把 `dotnet test` 单独执行并保存退出码（`dotnet test > log; RC=$?`），提交语句用 `[ $RC -eq 0 ] &&` 把关；要看摘要就 `tail` 那个日志文件，不要把 `dotnet test` 接进管道再 `&&`。变异验证同理：先记录基线退出码，变异后看失败数，还原后再确认退出码为 0。

## 提交信息用 `-F` 文件，不内联

提交信息里出现英文双引号（如 `"落 1 子规避 Pass"信号`）会截断 shell 的双引号字符串，`git commit -m` 把后半段当 pathspec 报错——而链式命令里后面的归档照跑，把源码吞进别的提交。recruit-hand 收尾时发生过一次，靠 `git reset --soft` 重拆。规则：先把提交信息写进临时文件（heredoc 用引号定界符 `<<'EOF'`），再 `git commit -F 文件`；并且提交与归档之间用 `&&`，不用 `;`。

## 标着"待校准"的初值不是基线，别在上面盖楼

`EvaluationWeights.Default.Safety = 20` 是 heuristic-ai 阶段用 5 局和 2 颗种子试出的初值，注释里白纸黑字写着"并列为阶段 B 的首个校准项"。校准一直没做，而此后每一轮的 200 局基线都建立在它之上。等到 denser-map 改了地图，它开始主导结果：不收敛率翻倍、领先者胜率把上一轮的成果整个抹掉，60/200 局整局没打起来——全部记在了地图头上。

真正的代价不是这个值不对，是**几轮基线数据的归因都错了**。

规则：任何标注为"初值 / 待校准 / 暂定"的常量，MUST NOT 被当作基线数据的依据。要么在用它产出基线之前先校准，要么在引用那份数据时注明口径。代码里的校准标记是一张欠条，不是一句免责声明。

## 调参要双向扫，"朝一个方向试探"会得出反的结论

Safety 权重的旧注释记着"取 3 不收敛、取 10 仍不收敛、取 20 好转、取 40 一半收敛"，读起来是一条单调曲线，于是初值定在 20 并且此后无人怀疑。v2 上把九档各跑 200 局才看清真相：3→10.0%、5→9.5%、7→3.5%、8→13.0%、10→31.5%、20→27.5%、40→42.0%、60→57.5%。曲线**非单调**，而且大方向是调高更糟——旧结论的方向是反的，因为它只在一个方向上试了几个点，每个点只有几局。

规则：调一个数值参数时，MUST 在当前值的两侧都取点，且每个点的样本量要足以支撑结论（比例类指标 200 局起）。只朝一个方向试探得到的"越调越好"，很可能是在局部爬坡。另外，同一个参数换了环境（地图、规模、其他参数）之后，旧的调参经验 MUST 重新验证而不是继承——旧注释若已被推翻，要整段删掉，留着它下一个人会照着它继续往错的方向调。

## 静默忽略的输入会产出口径错误的数据

`Siege.Sim` 的 `CommandLine` 把没人认领的 `--key value` 直接丢掉。用 `--matches 200` 跑回归（真名是 `--count`），程序正常启动、打印"跑局：1 局"、正常写出 summary.json。这份 1 局的数据差点被当成 200 局的回归结论。

规则：凡是产出"要拿来做裁决的数据"的入口，未识别的输入 MUST 报错退出，MUST NOT 回退到缺省值继续跑。判据是"失败必须可见"：命令跑通了但参数没生效，是最难发现的一类错误，因为它的产物看起来完全正常。见 change `strict-cli`。

## 规格里写不成守门的条目，就别写成 Scenario

`ai-safety-weight` 初稿在规格里挂了一条 Scenario：「把安全权重由 5 依次调高到 10、20、40、60 各跑 200 局 → 达上限比例随之上升」。它是一次已经做完的实验的结论，不是可验收的行为：落成测试要跑 800 局，不落测试就是空条——写在规格里却没有任何东西保证它，比不写更糟，因为它看起来像被守住了。

规则：Scenario 的位置留给能被守门钉住的行为。实验结论、调参纪律、设计取舍属于 Requirement 正文或 design.md 的裁决记录。判据很简单：**这条 Scenario 我能写出让它变红的变异吗**？写不出就换位置。

换上去的那条要挡真实风险。这次换成了"默认值与其校准依据必须同时成立"：`Safety = 20` 之所以能一路沿用，正是因为它的依据写在注释里却没有东西强制它与取值同步，于是值被沿用、依据被无视。

## 扫档必须核对 config.json 里的实际生效值

`Siege.Sim run` 只要给了 `--difficulty` 或 `--players`，就会重建整个玩家列表，`--config` 文件里各玩家的 `Weights` 被静默丢弃（重建后 `Weights = null`，AI 回落到 `EvaluationWeights.Default`）。scoring-sites 的 Safety 扫档若照"配置文件写权重 + 命令行给难度"的习惯跑，九档会全部跑成默认值，产物看起来完全正常。

规则：
- 扫权重一律只用配置文件指定 `Players[].Difficulty` 与 `Weights`，不传 `--difficulty` / `--players`。
- 每批跑完 MUST 打开该批 `config.json`（写的是 `Effective()` 实际生效配置）逐项核对每名玩家的权重与地图标识，不一致即作废重跑；不以启动行或目录名为准。

## 计分口径一变，默认权重必须重扫；临界区要加密档

`Safety = 5` 是 v2 地图 + 旧计分上扫出来的校准值。scoring-sites 把计分换成据点分之后沿用 5：第 3 大回合领先者胜率 95.5%、不收敛 49.5%——校准值失效了，但没有任何测试会红。重扫九档后发现领先者胜率在 20（95.5%）与 30（17.0%）之间陡变，九档粗扫里没有一档可用；补 22 / 25 / 27 三个加密档才找到 27（25.5%、不收敛 6.5%）。

规则：
- 计分公式、地图、终局条件任一变更后，凡"校准值"（`EvaluationWeights.Default` 等）MUST 视同"待校准"重扫，不得继承（与上文"换了环境旧调参经验要重新验证"同源，这次是计分口径）。
- 相邻两档指标跳变超过判据量级（如领先者胜率跨过 25%–50% 目标带）时，MUST 在两档之间加密再下结论。

## "写出时漏字段"要用往返测试抓，磁盘一致性测试抓不到

段 A1 检查变异 M-C1：`MapFile.ToJson` 写出前把 `Sites` 清空。往返测试（对象 → JSON → 对象，逐字段比）红了 4 条；而"磁盘上的基准地图文件与代码一致"**没红**——它两边都经同一个 `ToJson` 序列化再比，写路径漏掉的字段两边一起漏。

规则：新增序列化字段时，MUST 有一条"活对象 → 写出 → 读回 → 逐字段比活对象"的往返测试钉住它；"磁盘文件 = 代码序列化结果"只防数据漂移，不防漏写，不能当作字段覆盖的证据。

## 期望值是 0 / null 的遥测断言抓不到"写入端漏写"

段 A2 变异 M-T10～12：日志里玩家据点分恒写 0、快照据点控制者恒写 null、终局名次据点数恒写 0——原测试盘面上恰好没人控制据点，断言期望本来就是 0 / null，三条变异全绿。补一个被 P0 占据的营帐 `E4`（期望非零 / 非 null）后三条都红。

规则：遥测 / 存档写入字段的测试，样本 MUST 让该字段取**非默认值**（非 0、非 null、非空集合），并与活对象逐条比对；默认值期望只能证明"读得出来"，证明不了"写进去了"。与"带回填兜底的字段要用非回填值证伪"是同一类问题。

## "只改测试不改实现"的变异，专治测试抄实现

钉常量的测试最容易变成照抄：把实现里的七个默认值抄进 `InlineData`，看起来钉得很死，其实实现改成什么它就跟着是什么。常规变异（改实现）能抓到这一类，但抓不到"测试与实现同源"的情形。

规则：钉常量表的测试，要额外做一次**只改测试不改实现**的变异——把两个维度的期望值对调，测试必须红。若测试是照抄实现的，对调后它仍与实现一致，不会红。

## 批量变异脚本：还原放 finally，备份名不可被重复运行覆盖

本轮写了个脚本一次跑五条变异，每条"备份 → 改 → 跑测试 → 打印 → 还原"。打印那行因为 GBK 编码抛了异常，而还原写在打印之后，于是**第一条变异留在了工作树里**。更糟的是重跑：脚本开头 `shutil.copy(路径, bak)` 用固定文件名，第三次运行把"变异态"备份成了 bak，唯一一份干净副本就此消失。最后只能靠人工确认差异改回来。

规则：
- 还原 MUST 放在 `try/finally` 的 `finally` 里，打印、断言、统计一律放在还原之后。
- 备份文件名 MUST 带本次运行的唯一后缀（时间戳等），不得被下一次运行覆盖。
- 还原后 MUST 与"改之前读到的原文"逐字符比对，不要只比对备份文件——备份本身可能已被污染。
- 这些文件的改动往往尚未提交，`git checkout` 会连同本轮工作一起抹掉，**不是**退路。
- 读写 MUST 用二进制模式（`open(p, 'rb')` / `'wb'`），比对也比字节串。文本模式读会把 CRLF 归一成 `\n`，`open(p, 'w', newline='')` 再把整份文件写成 LF——本仓源码是 CRLF，一次变异就能把整个文件的行尾换掉。
  这个错误的隐蔽之处在于**三道防线同时失效**（strict-cli 检查阶段实测）：脚本里"还原后与变异前读到的原文比对"两边都是文本模式，一起被归一，恒为 `True`；`core.autocrlf=true` 下 `git diff` 对 LF 工作树文件输出为空（只在 stderr 给一句 warning）；编译与测试对行尾无感，全绿。只有二进制读写或 `cmp` 才看得见。

### 锚点按「每个文件实际的行尾」归一，并断言命中次数恰为 1

上一条写的"锚点串里的换行写成 `\r\n`"还不够严：**本仓 CRLF 与 LF 混用**（artisan-terrain-edit 段 A 检查实测：295 个 `.cs` 里 181 个纯 CRLF、114 个纯 LF，无单文件内混用；`MatchFlow.cs`、`PieceEffects.cs`、`VisualBaseline.cs`、`ConsoleController.cs`、`Siege.Sim/Running/MatchSession.cs` 与部分测试文件都是 LF）。把 `\r\n` 写死进锚点，在 LF 文件上一样匹配不到、一样静默不变异、一样假绿——只是把假绿从一半文件换到了另一半。

规则：多行锚点 MUST 先读该文件的字节、探测它实际的行尾，再把锚点与替换串里的换行归一成同一个行尾；并且 MUST `assert data.count(anchor) == 1`——命中 0 次（没变异）与命中多次（改了不该改的地方）都要响亮失败，不能只看 `replace` 的返回值。

```python
def detect_eol(data):
    crlf = data.count(b"\r\n")
    lf = data.count(b"\n") - crlf
    if crlf and lf:
        raise SystemExit("文件内部混用行尾")     # 本仓目前没有，出现了要先查清楚
    return b"\r\n" if crlf else b"\n"

eol = detect_eol(original)
anchor = text.replace("\r\n", "\n").replace("\n", eol.decode()).encode("utf-8")
assert original.count(anchor) == 1
```

判据："这次变异到底改没改到文件"必须由脚本自己证明，不能靠事后看红了几条来反推——变异本来就该红，不红时你无法区分"守门缺失"与"锚点没匹配上"。

### 变异 MUST NOT 用 `if (false)` 短路——`TreatWarningsAsErrors` 会把它变成"编译失败的假红"

artisan-terrain-edit 段 B 的初版 M-B4 / M-B6 / M-B11 都写成 `if (false) { …原逻辑… }`。本仓开着 `TreatWarningsAsErrors`，CS0162「检测到无法访问的代码」直接变成编译错误：`dotnet test` **EXIT 1，但一条测试都没跑**。按"红绿以退出码为准"的口径，这看起来是守门生效，实际是假红——它证明不了任何测试会红。

规则：

- 变异一律用**运行时恒假**的条件（`_edits.Count > 0 && Height < 0`、`log.Turns.Count < 0`、`e.Sequence < 0`）、直接删掉整个检查块，或直接替换实参，**不得**用编译期可判定为常量假的条件。
- 变异脚本必须解析测试输出里的统计行（`Passed!` / `Failed!` 的条数）；抓不到统计行时打印输出尾部并响亮失败，免得把编译失败当成守门生效。

### 样本口径断言必须有下界：Easy 难度的 AI 一枚匠人都不会落

`各棋子势力占比Tests.真实跑局快照的类型计数与明细自洽` 在加入匠人后本该红（反证算式漏了一项），实测没红。第一次归因是"这个样本恰好没匠人"，于是把匠人补进算式——变异 M-C1a / M-C1b（把两处改回去）**全绿**，补进去的是死代码。真因是**结构性**的：共用样本是 Easy 难度，`HeuristicTurnController.RecruitScore` 在 `ImmediateOnly` 下只看基础军势，匠人 1 分在平手里排枚举末位，实测 4 局 × 12 大回合 **2718 条棋串含匠人 0 条**（Standard 难度同参数下 1707 条里有 92 条）；匠人会进征募面板（日志里出现 1376 次）却一枚都不落盘。

这与"文件扫描要配文件数下界"是同一类问题，换了个维度：那一条管的是**扫描口径**，这一条管的是**跑局样本口径**。

规则：凡断言依赖"样本里存在某种东西"（某类棋子落了盘、某个动作发生过、某字段取到非默认值），MUST 显式写一条**样本口径下界**断言（`含匠人的棋串 > 0`、`Assert.Contains(records, r => r.CausedCapture)`）。样本不含它时要响亮失败，而不是让下游断言静默恒真。选样本时先确认该难度 / 该种子真的会产生它，必要时另起一份 Standard 小样本与 Easy 样本合并统计。

### 依赖"AI 实际怎么走"的断言要把权重写死，不跟随默认值

artisan-terrain-edit 段 D 把 `EvaluationWeights.Default.Safety` 由 27 改成 35，`地形改造日志与分析Tests.回放日志改造可重建终局地形并与对局逐项一致` 当场红——它的样本下界断言"样本中确实有致提子的改造"依赖 AI 在那三颗种子下的实际走法，而走法随默认权重变。

这类测试钉的是**日志保真度**（写进去的和跑出来的一致），不是校准值。两者耦合在一起，每次调参都要重挑种子，还会让人误以为"调参把日志写坏了"。

规则：断言依赖 AI 实际走法的测试，MUST 在测试内把 `EvaluationWeights` 写死（本例写死 Safety 27），不读 `EvaluationWeights.Default`；反过来，钉校准值本身的测试（`默认评价权重的校准Tests`）才读默认值，并与注释里的校准依据、数据路径一起改。校准与保真度分离。

## 跑 dotnet test 的脚本要强制英文输出

`dotnet test` 在本机是中文本地化且 GBK 编码，脚本里用 `失败` 之类的中文做正则会匹配不到（`errors='replace'` 已经把中文换成了替换字符），于是"红 0 条"看起来像守门失效，实际是抓取失效。

规则：脚本里跑 `dotnet test` 一律带 `DOTNET_CLI_UI_LANGUAGE=en`，用 `Failed` 抓失败名；红绿判据以**退出码**为准，不以能否匹配到文本为准。Python 侧还要 `sys.stdout.reconfigure(encoding='utf-8')`，否则打印中文测试名本身就会抛异常。
